# MiniDSH Architecture

MiniDSH is one runtime composed from plugins over a tiny kernel. Everything the model can see is derived from an append-only session log. Everything the model can do goes through a guarded tool pipeline and is fenced at the effect boundary by an authority the log records. The model itself is a capability the runtime routes to, not the agent: the route is a durable fact, a purpose may take a different one, and a delegated child runs under an authority it cannot widen. Bytes the model was shown live beside the log, content-addressed, never in it. Every surface only renders the log — by the page, because no client may be handed a whole one — and drives the agent registry; a session survives its process. The reference it re-derives from is DeepSeek Harness (DSH); §12 lists where MiniDSH deliberately differs, §13 what it knowingly lacks.

## 1. Layers and dependency direction

```
src/app/           application assembly + surfaces: compose.ts (rows + patches + catalog), config.ts (disk layers),
                   settings.ts, headless.ts, cli.ts, serve.ts (stdio protocol host), web.ts + web/ (the browser
                   host and its plain-JS client), present.ts (the one event→line projection), terminal/, home.ts
src/capabilities/  providers and consumers over core seams (never import each other, never app)
src/core/          the spine: Service Definitions + default drivers as plugins
src/kernel/        composition substrate: Context, plugin lifecycle, services, effects, events
src/test-support/  scripted adapter, replay-from-log adapter, composition harness
```

Three rules, enforced by `scripts/check-deps.ts` (part of `pnpm check`):

| from | may import |
|---|---|
| `kernel` | nothing internal |
| `core/<x>` | `kernel`, other `core` contracts — **except `core/loop`, which nothing imports but `app`** |
| `capabilities/<x>` | `kernel`, `core` (Definitions only; providers never import other providers or consumers) |
| `app` | anything |
| `test-support`, `*.test.ts` | their own layer and below; `test-support` may import `app` to mount real compositions |

Second, an event payload outside tests is read through `matches(event, KIND)`, never `event.data as {…}`, so a renamed field is a type error rather than a `NaN` on a screen. Third, **core is acyclic at file level**: core packages depend on each other freely (agent ↔ sandbox, session ↔ llm, sandbox ↔ shell), and what keeps that sound is that each package's vocabulary — `events.ts`, `types.ts` — sits below its service, so no file's value imports close a loop. A deeper tree is not more architecture: the layers are the whole topology, and a capability is a directory, not a package. The browser client shares no code with the host — plain JS, no build step, only the wire between them.

## 2. Kernel (`src/kernel`)

The kernel realizes the two composability properties from the Cordis paper with the smallest mechanism set DSH actually relies on:

- **Context** — a non-mutating tree. `child({scope?})` derives a context carrying a scope tag; registrations made through a context are attributed to it and unwound with it (registration context = visibility = lifetime). Scopes are flat: a child beneath a scoped context inherits that scope and cannot be re-tagged. Root-derived scopes read any service; a scope derived from a plugin context reads *through* that plugin's declared and provided keys and may widen only its own set by providing, never the plugin's.
- **Services** — `provide(key, value)` is an effect; a key is claimed once per context chain (a child may shadow). `get(key)` is strict: a plugin may only read keys it declared in `inject` or provided itself; `tryGet` is the optional read. Keys are typed tokens (`serviceKey<T>('sessions')`), not declaration merging. Deployment-global registries (`llm.registerAdapter`, `invariants.register`) refuse a scoped owner.
- **Plugins** — `{ name, inject?, config?, apply(ctx, config) }`. `config` is a structural `{parse(unknown) → C}` contract (a zod schema qualifies; the kernel imports none): the kernel parses a row's config BEFORE `apply`, so a malformed row fails loud at load as `PLUGIN_CONFIG` naming the plugin. An instance is `pending` until every injected key is provided, then `loading → active`; when a dependency disappears the plugin unloads, when a provider is replaced it reloads. Transitions are serialized per instance. A provider's effects unwind before its dependents unload, so a disposer must not read the services its plugin injected. `settle(filter?)` waits for root-wide quiescence and reports pending plugins with their unmet keys and failed ones with their errors, so boot fails loud naming the row and the reason.
- **Effects** — `effect(fn → disposer, label?)` pushes onto the owning instance's disposer stack; disposal is strict reverse order. A disposer runs its synchronous part eagerly, so `off(); register(sameName)` in one tick is legal.
- **Events** — typed tokens carry their dispatch mode: `emit` (sync, exceptions contained), `waterfall` (around-middleware; `next()` is single-shot, so no middleware can run a tool body twice against one durable record), `serial` (awaited in order), `parallel` (`allSettled`). Dispatching with the wrong method is a compile error. A dispatch may carry a `scope`: it reaches unscoped listeners, `global: true` listeners, and the listeners of that same scope. `observe(hook)` sees every dispatch in the preflight, before any listener is selected — the seam runtime invariants hang on, because a listener can always be ordered behind another (`prepend` is an unshift) and an observer cannot; `prepareEmit` splits that preflight from delivery so an observer can reject a fact before it is committed.

There is no loader, HMR, isolate realm, proxy, mixin, or accessor. Registries take the owner context explicitly (`tools.register(ctx, def)`).

**Scope contract** (`core/scope.ts`). Registration origin decides visibility and lifetime together: through an unscoped context → deployment-global; through an agent's `ctx` (or a plugin mounted on it) → that agent's layer, unwound with it. Tool definitions, guards, prompt sections and variables are layered: a view is the globals plus exactly one agent layer, a local entry shadows a same-named global, and there is no inheritance between scopes. Every event about an agent's operation is dispatched in that agent's scope — `agent/*`, `tools/*`, `approval/request`, `system-prompt/assemble`, `fs/*` — so a listener registered through agent A's context never sees agent B. Subject-less seams (`llm/stream`, `session/*`) and registry-membership notifications (`tools/change`, `agent/created|disposed`) are unscoped and reach only unscoped (or `global`) listeners. Consumers receive the agent as the operation subject and never read services through `agent.ctx`. A per-agent execution world is composed by mounting plugins on `agent.ctx` during `setup(agentCtx, agent)`; `agent` is the unpublished agent, and its session is appendable there — the slot a creator seeds durable opening facts into before the first effect. A scope tag must be an object (the `Agent` itself).

## 4. Canonical facts: the session log

The log is the single source of truth. Envelope `{type, seq, time, data}`, `seq === log.length`, data JSON-lossless and deep-frozen at append. **It has three tiers.** The three **surface** events — `user/message`, `assistant/message`, `tool/result` — carry `surfaceOp: 'append' | {op:'replace', start, end}` and `sourceEventSeqs`; model history is the fold of surface nodes through `deriveEventMessage`, which is what lets a compaction provider replace a range without mutating history. Every other event is a log-only **fact** the runtime folds — except the **trace** tier (`TRACE_TYPES`, today `assistant/chunk`), recorded for streaming fidelity and replay and never folded at runtime. A trace kind is the bulk of a long session by two orders of magnitude, so every runtime fold walks `Session.facts` — the log without its trace, seqs preserved — while persistence, replay and the wire keep `events`; a seq in hand indexes `events[seq]` in O(1).

Vocabulary: `turn/start`, `turn/end{reason}` (`completed | blocked | cancelled | error{code, message} | max-tokens | max-steps | interrupted`), `step/start`, `step/end`, `user/message`, `agent/options{options, reason: initial|change|resume}` (the BASE route and limits), `request/header{provider, model, reasoningEffort?, maxTokens?, temperature?, system, tools; reason}` (logged only when it changes, so the provider prefix cache survives restarts), `request/context{provider, model, contextWindow?, inputModalities?}` (the EFFECTIVE route plus the window and input modalities its adapter advertises; `inputModalities` absent MEANS text only), `assistant/chunk{turn, step, attempt, chunk}` (trace), `assistant/message{message, usage?, interrupted?}`, `tool/call`, `tool/result`, `inbox/spliced`, `approval/asked{id}`, `approval/decided{id, outcome}`, `approval/policy{policy, reason}`, `sandbox/mode{mode, enforcement, reason}`, `authority/preset{name}` (intent; the knob events that follow are the truth), `composition/applied{hash, layers, rows}` (written only when it differs from the log's last; configs hashed, never inlined), `llm/aux-call{purpose, provider, model, maxTokens?, inputSeqs?, usage?, outcome}` (a model call that is not a turn), `compaction/start` / `compaction/applied` / `compaction/end` (§6), `subagent/start{callId, childId, depth, provider, model, sandbox, approval}` / `subagent/end{callId, childId, reason, usage?}` (in the PARENT's log; the child's steps live in the child's), `session/title{title, messageSeqs, source: fallback|provider|user}` (log-only, last-wins; §8), `session/end-seed`. The header `{version, id, createdAt, cwd, parentId?, seedLength?, delegatedBy?, delegationDepth?, agentPreset?}` lives beside the log. `SESSION_FORMAT_VERSION = 0`; adding a field or a kind is additive (a stored log with a NEWER version refuses loudly at load and attach). An unknown event type loads as an opaque log-only record and is skipped by derivation; a plugin that needs durable state adds a log-only kind, never a surface kind.

**The route is one durable fact, in two records.** `agent/options` is the BASE: written at creation, by `Agent.configure`, and by an override at resume, folded by `findLast`. `request/context` is the EFFECTIVE route of the next request, written by the driver before the step's `agent/pre-step` listeners and only when the WHOLE record differs from the last one (a field added to it must be written on a resumed session whose route never changed, or it would be inherited as absent for that session's life). It sits outside header equality, so a capacity change never forces a header snapshot, and every reader learns the window from the log instead of from a live adapter. An adapter that cannot resolve a model records neither the window nor the modalities, and the next successful step rewrites the record rather than latching the route into "text only". A role rewriting `{provider, model}` on `agent/request` moves the header and the context record, never the base — so a resume rebuilds from the base rather than adopting whatever the last request happened to use.

**What a session opens with.** Agent creation, before publication, writes `agent/options{initial}` (the factory), `approval/policy{initial}` and `sandbox/mode{initial}` (each knob's own service, at `agent/created`) and `composition/applied` (the recorder). A resumed session whose log already says writes nothing; an older log gets them at pickup. A DELEGATED child's creator stamps both knobs explicitly inside `setup` (`reason:'delegation'`). So a stored log always states what its session started under, and under whose authority, before its first effect.

**The durable inbox.** `inbox/spliced` is op-shaped — `{op:'insert', queue, message, waking?} | {op:'claim', steps, turns} | {op:'clear'}` — never positional: claim drains counts from the front. Inserts and clears log at mutation time; the claim record is committed after the entered `user/message`s (a crash inside the pre-step window re-delivers a prompt on resume — a rare double-delivery, never a loss) or with the block/stop that consumed it; a disposed-cancel does not durably clear (teardown preserves the queue for the next resume); an empty clear logs nothing. The driver restores the fold silently at attach, and a RESUMED agent is woken at publication iff a waking insert is still queued (a fork is a passive branch and is never woken by creation).

**Arrival versus rewrite.** A `user/message` that ARRIVES must sit inside an open turn. One that REPLACES a range is a surface rewrite, not input, and may land between turns — which is what makes `/compact` legal on an idle session. `Surface.apply` throws on a replace naming a node that is not live, in the fold as well as at append, so a reader folding a stream it did not write fails instead of rendering a plausible wrong history.

**Crash repair closes the surface.** The driver commits an assistant message with ALL its tool-call blocks and logs each `tool/call` only when that call's turn comes, so `repairInterruptedTail` answers every tool-call block of the open step's assistant message — `TOOL_OUTCOME_UNKNOWN` for a logged call, `TOOL_NOT_STARTED` for one never dispatched — cancels every approval asked in the open turn and never decided, then closes the step and the turn as `interrupted`. A resumed history is one every OpenAI-compatible wire accepts.

**A `session/event` listener may not append synchronously.** Delivery is where `persistence-jsonl` writes its line and the protocol streams its frame, and where the relational invariant commits the trace its pre-commit observer staged. A nested append therefore reaches the file, the wire and the invariant BEFORE the event that caused it — a stored log whose seqs run N+1, N is `damaged` on the next resume, and the staged trace is dropped. A listener that must append (the authority switch note, `context-runtime`) queues it on a microtask, which still runs before its caller resumes.

**Model-visible ⟺ logged.** Every request the loop sends equals `deriveMessages()` plus the folded `request/header`; a runtime invariant rebuilds both in the `llm/stream` preflight and fails on any divergence. Persistence is a subscriber, stored under `MINIDSH_HOME` (default `~/.minidsh`) as `sessions/<id>.jsonl` with the header as line 1. **A session materializes on its first conversation fact**: publication takes the write lease and decides the write mode, but a fresh or forked session is written only when its first surface event lands, so a `chat` opened and closed leaves nothing behind. A `resumed` session attaches to its file append-only at publication (a torn final line moves to a `<id>.jsonl.torn` sidecar; deeper corruption marks the store `damaged` on read and refuses attach). Later events append through one descriptor held per session. `session/flush` is awaited at every durability checkpoint, where a remembered write error is rethrown — and keeps being rethrown.

**Single writer per stored session.** Publication takes a `<id>.jsonl.lock` lease (exclusive create; `{pid, host, acquiredAt}`) held until disposal, so a second process resuming the same id is refused before it appends a byte. A holder is stale only when provably dead on THIS host (`ESRCH`); everything else refuses naming the holder, degrading to a manual `rm` — never to two writers. Reclaiming a stale lock runs under its own exclusive-create `.steal` mutex. Attach compares the stored log against the seed the session resumed from (`liveStart`) plus a tail-identity check, so a foreign append in the read→publish gap is refused. Reads never lock. Because publication effects run in a contained emit, the loop factory flushes a resumed publication inside the creation transaction, so a held lease or a damaged attach rejects `agents.resume` before any paid work.

Prefix stability is a corollary: because the log is append-only and the header is written only when it changes, consecutive requests are append-extensions of their predecessors, which is what the providers' prefix caches reward.

## 5. LLM vocabulary and the two adapters

`Message{id, role: system|user|assistant, content: ContentBlock[], source}` where a tool result is a user-role message with `source{kind:'tool', callId}` and an assistant message's source carries `{provider, model, replayState?}`. `ContentBlock = text | reasoning | image{attachment: AttachmentRef, text} | tool-call{id, name, arguments} | tool-result{toolCallId, content, isError?}`. The stream is a closed union `block-start | text-delta | reasoning-delta | tool-call-delta | block-end | usage | finish{reason, replayState?}` with `reason ∈ stop | tool-calls | max-tokens | aborted{failure} | error{failure}` and `LlmFailure{message, code, status?, retryAfterMs?, requestId?}` — codes, never message text, are what policies route on. Protocol invariants: usage before finish, exactly one finish, deltas only into open blocks. `TokenUsage` counts are DISJOINT: `inputTokens` is uncached input; billed prompt is it plus `cacheReadTokens` plus `cacheWriteTokens`.

**Replay state.** A provider that signs its reasoning needs that state back verbatim. It travels as an opaque `ReplayEnvelope{response, blocks?}` on the terminal `finish`; `BlockAssembler` prunes it in step with any block it drops and discards a misaligned envelope whole. The driver stores it on the assistant message's source, and `LlmRuntime` strips it from every message bound for a provider other than the one that produced it — inside the terminal continuation, after the reconstruction observer, so the log still records exactly what the model was shown.

`LlmRequest.purpose` joins `signal` and `sessionId` as a field the provider never sees: it says why a call is being made when it is NOT a loop step and is therefore absent from `RequestHeader`. **A model call that is not a turn** is `runAuxCall` (`core/llm/aux-call.ts`): it streams, assembles, and appends ONE log-only `llm/aux-call` carrying route, usage and the answer — a failure recorded before it is thrown. It writes no `assistant/chunk` (the replay script groups chunks by turn and step) and does not copy the request's messages (`inputSeqs` names them). A cancellation landing before the adapter is entered is normalized by the seam, not left to each adapter.

Adapters implement `stream(request)` and `resolveModel(model) → {contextWindow, defaultMaxTokens, reasoning:{efforts, defaultEffort?}, inputModalities?}`; effort ids are adapter-owned and opaque elsewhere; a catalog is ADVISORY (an unlisted id is accepted under conservative defaults). **An option the provider cannot honour is refused BEFORE any I/O** — `UNSUPPORTED_OPTION`, `UNSUPPORTED_REASONING_EFFORT`, `UNSUPPORTED_CONTENT` — never dropped, aliased or clamped: the request the log records must be the request the provider served. Retry is a capability on `agent/request-error`, so failed attempts are durable.

- **`llm-deepseek`** speaks the OpenAI-compatible `POST /chat/completions` with `stream: true`, `stream_options.include_usage`, `thinking` + `reasoning_effort` (refusing an effort outside the provider's set), keys tool-call fragments by wire index, defers block ends, usage and finish to the `[DONE]` sentinel, subtracts cache hits out of `prompt_tokens`, and always sends `reasoning_content` — empty when a turn had none, because in thinking mode with tools attached the provider refuses an assistant tool-call turn that omits it.
- **`llm-anthropic`** speaks the Messages API: named SSE events, thinking blocks that arrive with one `signature_delta`, tool input as `input_json_delta` fragments, usage split across uncached / cache-read / cache-created. Its catalog carries genuinely different facts (1M windows and adaptive thinking for the 5 family, 200K and manual `budget_tokens` for Haiku 4.5, `temperature` refused where the API returns 400; the short `claude-haiku-4-5` id is an alias), and its serializer rebuilds strict user/assistant turns with tool results first, echoing a signed thinking block only when this provider produced it.

**Images are a reference plus a descriptor.** An `image` block carries an `AttachmentRef` and never bytes, plus `text`: the descriptor computed once when the block is built and STORED, because it is what a text-only route is actually sent, and freezing it means a later change of wording cannot rewrite what an old log says the model saw. `core/llm/content.ts` is the one block→text projection (`blockText`, exhaustive with a `never` default); every serializer and surface goes through it. An image is user- and tool-side only: `validateStream` refuses an assistant stream that opens one, and it lives there rather than in `BlockAssembler` because the driver appends `assistant/chunk` and only then pushes to the assembler.

**Refuse at admission; substitute at projection — both.** A producer refuses to create an image block when the STEP's route lacks `image`, before any I/O. An adapter serializing an image for a model that cannot take it sends `block.text`, because durable history outlives the model that first consumed it. **Each adapter resolves refs itself**, per request, through `ctx.tryGet(ATTACHMENTS)`: a text-only route gets the descriptor; an image-capable route with no store mounted is `UNSUPPORTED_CONTENT` before any I/O; bytes that are missing or corrupt are `ATTACHMENT_UNREADABLE`, deliberately not retryable. Array-shaped wire content is emitted ONLY for a message that holds an image, so the prefix cache survives for every image-free turn. The meter charges an image as `estimateImageTokens(w,h) = min(⌈w·h/750⌉, 1600)`, measured against Anthropic's `count_tokens` and the conservative side of DeepSeek's bucketed cost.

## 6. The loop and the tool pipeline

```
followup(m) → next-turn FIFO (wakes)   steer(m) → next-step (wakes)   inject(m) → next-step (no wake)
turn/start
  claim → resolveCallConfig (agent/request) → request/context when changed
        → agent/pre-step (waterfall: reject | enter{messages})   reject ⇒ turn/end{blocked}
  step/start → user/message per entered message
  prompt.assemble → request/header when changed
  CHECKPOINT → llm.stream(frozen request) → assistant/chunk{attempt}* → assistant/message{usage}
       finish error ⇒ agent/request-error (waterfall) → retry (next attempt, same request) | turn/end{error}
  tool calls in model order: tool/call → CHECKPOINT → tools.execute → tool/result
       (cancel ⇒ ABORTED_BEFORE_DISPATCH results; a lost write ⇒ DURABILITY_LOST results, none run)
  step/end → next step while tools owe a request or next-step input exists (≤ maxSteps)
  agent/turn-stopping (serial) → re-read inbox
turn/end{reason} (exactly once) → session/flush → next turn or idle
```

**Durable before every action.** A CHECKPOINT is `session.flush()`: a provider that remembered losing a write says so there, and the turn ends as `turn/end{error, code:'DURABILITY_LOST'}` before the next paid request or tool effect, with every remaining call answered and none run — the same shape as a cancellation, so the surface stays balanced.

**The route is resolved once per step, before the pre-step listeners**, and `request/context` is written immediately after, so a pressure check measures against the route and window THIS step will use. The resolved config is fixed for the step: every retry attempt uses it, so a header and its context record can never describe different requests — and a switch takes effect at the NEXT step, which is why a producer's route check (§5) needs no admission lock: a tool body's check-then-use cannot be raced inside its own step. The driver builds its request per ATTEMPT: a recovery listener may legally change the log between attempts, and re-deriving `messages` keeps model-visible ⟺ logged true for every one.

**Context management.** `core/metering` is the one definition of pressure, shared by the compaction trigger, the terminal and the CLI: a pure fold over facts the log already holds. It prefers what the provider charged (`inputTokens + cacheReadTokens + cacheWriteTokens`, plus that step's output) plus a ~4-chars/token estimate of every surface node appended since; a `replace`, or a `request/header` landing after the priced call, invalidates the anchor and the whole surface is re-estimated. Session totals additionally fold `llm/aux-call` usage. Estimating low right after a compaction is the safe direction.

Compaction has three ways in and one implementation (`compaction-basic`): **pressure** on `agent/pre-step` (the only hook inside an open turn with no step open and no request built); **context-overflow** on `agent/request-error` for `CONTEXT_WINDOW_EXCEEDED`, answered with `{kind:'retry'}`; and **explicit** `compactNow` from `session/compact` over the wire — deferred to the next step boundary when the agent is running, and drained at `agent/turn-stopping`. Its budget is the window the log names for the route the next step will use, or a configured `budgetTokens`; its summary goes through `resolveCallConfig` with `purpose: 'compaction'`, so a model role may send it down a cheaper route. The summary replays the shadowed conversation verbatim under the CURRENT system prompt and tool schemas, so the prefix is byte-identical to what the loop has been sending. It writes `llm/aux-call`, then `compaction/applied`, then ONE `user/message{source:{kind:'plugin', form:'summary'}, surfaceOp:{op:'replace'}}` citing every shadowed seq. The planner's cut never leaves the retained tail beginning with a `tool/result`, moving forward first and backward when forward runs out. The summary's code-written frame names the log seqs every applied compaction in the session has shadowed — the union, because a second compaction shadows the first summary and the note that carried its range — and names the recall tool when one is mounted.

**Bounded recall** (`capabilities/tool-history`). `history_read{fromSeq, toSeq}` renders shadowed nodes through `deriveEventMessage`, restricted to the union of `compaction/applied.shadowedSeqs` for THIS session minus its own prior results: not a log reader, not a session search, and it cannot reach another session. It is registered in the deployment globals — so a summary can name it by tag without knowing which capability provides it — and hidden from each agent by a `TOOLS.restrict` on that agent's own scope, lifted at its first applied compaction, so a session that never compacts never carries the schema and can never spend a step on a tool with nothing to read. Two budgets, because recalled text re-enters the live surface and unbounded recall would undo a compaction one call at a time: a call over `maxCallTokens` is REFUSED rather than truncated, so the recorded arguments always describe what came back, and the per-session spend is a FOLD over the log (this tool's `tool/call`s joined to their `tool/result`s) rather than counter state — durable across a resume, exact on replay, and monotonic, so recall cannot refill itself by compacting. `blockText` projects a tool-result envelope to nothing by design, and a shadowed span is mostly tool results, so the tool unwraps them itself, exhaustively over the block union.

**Every attempt is bracketed.** `compaction/start` opens once a plan exists and BEFORE the paid call, and `compaction/end{startSeq, outcome}` closes it with `applied` or a decline from a closed union: `summary-failed | summary-empty | summary-not-smaller | turn-started | plan-stale | agent-gone | cancelled`. The applied record carries three numbers in two units: `projectedTokens` is what the threshold compared, provider-priced when the meter had usage; `surfaceTokensBefore`/`surfaceTokensAfter` are estimator units and the only pair it is valid to compare — a subtraction across the two is not a quantity, which is why there is no single "saved" figure. **A summary at least as large as the span it would replace is refused.** The automatic triggers give up after `maxSummaryFailures` consecutive summaries that produced no compaction, counted by `foldCompactionFailures` — a fold over the bracket records bounded to this lifecycle (`liveStart`) and cleared by an applied compaction; a summary lost to a race neither counts nor clears. `/compact` is a human asking again and is never disabled. An orphaned start means the attempt did not close — a crash, a disposal, or a fork boundary.

**The hazard is the await, not the mutation.** A summary call takes seconds, and a session can start a turn inside that window. Two answers, both required: an explicit compaction on a RUNNING agent is deferred to the next step boundary, and the plan is re-validated against the live surface (`planIsLive`) plus the agent's status in a window with no `await` in it — with the registry identity check first, because it alone says whether an append is legal at all. There is no durable lock bracket because the mutation is a single append.

**Spill.** Output too large to be conversation goes to `core/spill` — only output with NO OTHER HOME. A shell command's stdout is gone when the process exits, so it is saved under `$MINIDSH_HOME/spill/` and the model gets a head/tail excerpt plus the path; a file the model asked to view is already on disk, so the viewer answers with a line range. The shell executor's cap is a MEMORY bound; what the model sees is the tool's decision. Retrieval needs no new tool and no authority change: reads are never fenced.

**Workspace instructions.** `AGENTS.md` (and `CLAUDE.md`) enter as a durable `user/message`, never a prompt section — sections must be stable within a session, and a repository file is not the composition's to guarantee. Discovery is least-specific first (the home file, then project root down to cwd); when the byte budget is tight, broad files are dropped whole before the nearest one is truncated. The guard against re-entry folds the LIVE SURFACE, not the log, so a compaction that shadowed the entry re-enters it. It enters only into a non-empty first-step batch.

`agent/status` is emitted only on real `idle ↔ running` transitions; one `AbortController` per turn; `cancel(cause)` clears the inbox and aborts; `whenIdle()` is quiescence; dispose = cancel → whenIdle → unwind scope → detach agent → detach session. The driver promise is fire-and-forget and reports (`agent/error`) instead of rejecting unobserved.

Tool execution (every event in the acting agent's scope): validate args → `tools/pre-execute` (`allow | deny | ask`) → monotonic deny-only guards (globals, then the agent's) → `ask` → `approval.request`, anything but `allowed-once` denies → **deadline armed** → `tools/execute` (around-middleware over the body) → body → validate + freeze value → `render` → `tools/post-execute` (`accept{content?} | block{feedback}`) → normalized `ToolExecutionResult` → `tools/result`. Guards run BEFORE the ask: a call they would refuse anyway never interrupts a person. Every throw becomes an `isError` result with `Error: …` content and `{name, code}`. Only `{name, description, parameters}` of a tool ever reaches the model.

**Deadlines are the pipeline's.** `ToolDefinition.timeoutMs` declares a budget (omitted takes the registry default, `null` opts out) and the registry enforces it, because the kernel waterfall passes `next()` no arguments. The clock starts *after* the gate. A body whose registry deadline runs out ends as `TOOL_TIMEOUT` with its signal aborted so it can release what it holds, and a late result is discarded. Consent taken INSIDE a body (the shell's escalation) waits on `ToolExecution.callSignal`, the caller's cancellation without any deadline, and such a tool owns its whole clock (`timeoutMs: null`).

## 7. Authority

The model proposes, policy decides, the effect boundary enforces, and every decision is a fact in the log. Authority is one plane with four parts.

**One stamp.** `SandboxExecutionPolicy{mode, workspaceRoot}` is resolved per call from `ctx.sandbox`, never assembled by a caller, and shared by every execution world. The mode vocabulary governs FILE EFFECTS only — network and process visibility are outside it. The workspace boundary needs no event of its own: the immutable `SessionHeader.cwd` recorded at creation IS the root for every call in that session, which is why the wire may not choose it freely (§8). `writableRoots(policy)` is the one allow-list both families derive from, and it is a CEILING rather than an equality: a family may grant LESS, never more, so what both keep is "no host file outside these roots is modified". That is what lets the bwrap profile mount private tmpfs mounts over `/dev` and `/tmp` without widening anything — nothing written there reaches the host or the editor. Precedence: an approved one-shot escalation > the session's folded `sandbox/mode` > the composition default.

**Enforcement lives at the effect, not at the gate.** `fs-local` fences `writeText` in process: canonicalize, contain, refuse with `FS_SANDBOX_DENIED` before ANY effect (creating a parent directory is already one), then canonicalize and contain again immediately before the write. Canonicalization decides existence with `lstat` and follows links itself, including dangling ones. It is a check in trusted code over a model-controlled path, with one stated edge: a HARD link has no link to follow. Reads always pass. Because the fence is inside the provider, no tool can be the boundary and no tool needs to know about one; there is no policy plugin at `tools/pre-execute` at all.

**Kernel-grade isolation of untrusted CODE is the shell's problem, and the backend is a spawn wrapper inside the shell provider.** `shell-stdio/confine/` picks one mechanism by platform — `bwrap` on Linux, `sandbox-exec` on macOS, none on Windows — and PROBES it functionally before claiming anything: it runs the real `read-only` profile around `true`, from the same builder a real wrap uses. Never a `which` and never a version, because a backend that is installed and cannot enforce is the case that matters, and MiniDSH probes even a sole candidate where DSH does not: `enforcement` is RECORDED in the log at agent creation, before any command exists to fail closed. What the probe answers is what `enforcementFor` reports and what the stamp carries. A host with no usable mechanism REFUSES a confined policy with `SANDBOX_UNAVAILABLE` rather than running unconfined.

Both mechanisms apply only at spawn and are inherited across `execve`, so the persistent child is wrapped once and every command it will ever run is confined by that wrap. The child is bound to the SESSION's policy, and the two ways the effective policy can differ get different answers: a durable `setMode` replaces the child and the result says `restarted` (never `reset`, which tells the model its own command killed the shell), while an approved ONE-SHOT escalation is not a session fact at all and runs in a throwaway child (`oneShot`) that leaves the persistent one its policy and its state. DSH reaches the same binding and answers the first case by refusing the switch while a shell is open; it never meets the second, because its persistent shell has no escalation.

The bwrap profile is `--ro-bind / / --dev /dev --unshare-pid --proc /proc --die-with-parent --new-session`, plus `--tmpfs /tmp` and a `--bind` per ceiling root under `workspace-write`. Two of those flags close escapes that need no write at all: without `--unshare-pid` a confined command follows a procfs magic link out of the read-only bind, and without `--new-session` it reaches the harness's controlling terminal and pushes a line into the user's own shell with `TIOCSTI`. The Seatbelt profile is `(allow default)` `(deny file-write*)` and one re-allowed subpath per ceiling root, with roots passed as `-D` PARAMETERS so no workspace spelling can close the profile string and widen its own grant. `TMPDIR` is pointed at whatever writable temp the profile granted, because a shell otherwise inherits one that sits outside the ceiling.

The refusal, where it still happens, is a reported fact, not a tool failure, and it carries the one legitimate move: the model may retry the SAME command once with `sandbox_permissions` (strictly wider, and only a mode this host could actually run under) and a `justification`; `ctx.approval` is the consent step, and the grant covers that one call — never recorded as a session switch, so the audit reads it as the `approval/asked{callId}` → `tool/call{callId}` join it is. A shell whose binary cannot be started, or that exits before answering its first command, refuses too — as a coded error result (`isError`, `SHELL_UNAVAILABLE`, naming the binary and the remedy), never as a command that printed nothing; a WRAPPER that fails to start is `SANDBOX_UNAVAILABLE` instead, so the model keeps the escalation path on exactly the host that has a backend. **On a confined host the kernel refuses the write instead, and that reads like any other failing command** — so the mounted backend's own denial dialect (never a cross-backend union) earns the same escalation hint a refusal carries. A hint and never a classification, and deliberately incomplete: under bwrap a path beneath the ephemeral `/tmp` is invisible rather than read-only, and that denial is indistinguishable from a missing directory.

**The plane records; a capability speaks.** No service here writes model-facing prose: a switch IS its event, and `context-runtime` turns that event into the durable message the model reads (one per agent per microtask, so a preset moving both knobs says it once). The runtime-context section is a fold of the log and of nothing else — it states the stamp THIS lifecycle opened under, `enforcement` included, so a shell world swapped under a live agent cannot rewrite the prefix a provider's cache is keyed on, and a session resumed after a switch is no longer told the mode the session it was resumed from started with.

**Every decision is durable, and every session says what it opened with.** `sandbox/mode{mode, enforcement, reason}` and `approval/policy{policy, reason}` are log-only, folded by `findLast` (and by `openingSandboxStamp`/`openingApprovalPolicy` where a lifecycle's opening is what matters): the OPENING value at agent creation (`initial`, before publication), a change only when it changes (`change`), and for the sandbox a `resume` stamp when a resumed session's host enforces differently. `enforcement` on the stamp is what the SHELL world reports — the fs fence is in-process and always complete, so it has nothing to report. A switch IS its event; nothing mutates authority out of band, and a resumed session keeps what it recorded rather than inheriting the deployment default. `ApprovalPolicy` is `ask | never`, and `never` decides `rejected` inside the service before dispatch. `approval-headless` answers `allowed-once` only under `--approve` — otherwise the fail-closed `unavailable` stands, and `context-runtime`'s section says so: under `ask` the model is told an action outside the sandbox needs an approval, and that a refused or unanswered request means the action did not run. `minidsh sessions show <id> --audit` projects the whole plane back out of any stored log.

**A fork carries the fence with it.** A boundary that would cut below a delegated session's opening stamps is refused.

**A delegated child opens under a ceiling.** A child agent (`capabilities/tool-subagent`) is created with its parent's authority captured BEFORE the first await, and both knobs are stamped explicitly inside `setup`, before publication, with `reason: 'delegation'`. That first stamp is a CEILING, held three ways: approvals are pinned `never`, enforced before dispatch; `setMode`, `setPolicy` and the escalation path refuse to widen past it (`SANDBOX_CEILING`, `APPROVAL_PINNED`); and the authority invariant rejects a widening stamp pre-commit. Narrowing stays legal — a delegation ROW may narrow it too (`sandbox` config, applied where the authority is captured, so `subagent/start` records the mode the child actually opens under). The ceiling is durable, so a resumed child comes back under it.

**Presets select, the knobs decide.** `apply(session, name)` validates against a delegated session's ceiling and pin, appends the log-only intent, then writes through `setMode`/`setPolicy`. The current preset is DERIVED from the two folds; `custom` is what a non-matching pair displays as. The shipped table is two entries — `workspace-write` = workspace-write + ask, `danger-full-access` = danger-full-access + never — replaceable from the row's config. There is no `defaultPreset`: the deployment default lives on the sandbox/approval row configs.

**Consent-by-composition.** A per-agent preset (§9) mounts plugins on the agent scope, and `approval/request` dispatches in the asking agent's scope — so a preset-mounted answerer CAN auto-approve for its own agent. That is not a bypass: whoever writes the composition already holds code-equivalent trust, and the audit still records every pair. What a preset structurally CANNOT do is widen enforcement — a `SANDBOX` provided in the scope shadows only scope-mounted plugins, while the fs fence and the shell resolve the global one — nor reach a deployment-global registry.

The `core-authority` invariant rejects a forged `sandbox/mode` or `approval/policy` before it enters the log, holds every approval to exactly one decision, and holds a delegated session to its ceiling and pin; the presets capability registers its own invariant rejecting an `authority/preset` that names no table entry.

## 8. Surfaces

A surface is a plugin (or app entry) that injects only `agents` and `sessions` — plus `llm` for the catalog handshake and `sandbox`/`approval` for the authority control plane — owns transport and process exit, and renders from `session/event`. It holds no authority state of its own: a switch it asks for becomes a durable event it then reads back like any other. Every plain-text surface renders through ONE projection, `app/present.ts` (`describeEvent`, `transcriptLines`, `auditLines`); the browser renders structured DOM per event type — a different projection, not a second copy, and it duplicates no fold. Both render an image block's descriptor on the `tool/result` that carries it, and both render the compaction bracket, because a decline's reason is otherwise visible nowhere.

- **The headless CLI**: `minidsh run "<task>"`, `minidsh resume <id> "<task>" --headless`, `minidsh fork <id> "<task>" [--at seq] --headless` — boot → `settle()` → create/resume/fork → `followup` → `whenIdle` → `flush` → last assistant text on stdout, exit 0 iff the turn completed; a failed turn prints its code and message. Every command boots through one preamble (`prepareBoot`: flags, settings, the disk layers layered ONCE, `--preset`, `--agent-preset`), so `config`, `--preset` validation and `sessions` read exactly the rows a boot mounts. One flag table decides which flags take a value, which each command accepts (a flag a command does not list is refused, never ignored) and every usage line; `--help`/`-h` anywhere print the usage and exit 0, and `--version`/`-v` anywhere print `minidsh <version>` and exit 0 before help, boot-free — one string, read from `package.json` by `app/version.ts` and passed to both protocol hosts, where `initialize` and the terminal banner used to say a hard-coded second one. A preamble failure — a bad flag value, a broken `settings.json`, a malformed layer — is exit 2 on every command; `sessions` alone downgrades a broken settings file to a warning, because reading a stored log must not depend on it. `--json` streams `{sessionId, event}` frames; `--sandbox`/`--ask`/`--preset` set this run's authority (given explicitly, they are applied as a durable switch, so they also govern a resumed session; `--preset` is exclusive with the pair, validated pre-boot, and refused on commands that cannot apply it; `sessions` refuses all three); `--patch <file>` (repeatable) layers over the composition and `--agent-preset <name>` composes the agent's world on every command that creates one; `minidsh config [--json]` prints the *effective* composition with per-row provenance, flagging authority-sensitive rows a layer changed (by capability, so an inserted row is flagged too) and parsing every enabled row's config against its plugin contract (exit 1 naming the row); `minidsh sessions list/show` read through the effective persistence row on a bare composition, `list` printing id, time, cwd and NAME (the fourth column, so the three that were there keep their places) and `show` a `title:` line folded over the whole log, `show --audit` projecting the authority timeline.
- **The client protocol** (`capabilities/protocol`): JSON-RPC 2.0, DSH's SDK-protocol shape — newline-delimited on a stream carrier, one text message per frame on a socket. Malformed frames are ignored, unknown methods answer `-32601`, stdout is reserved for frames. **One plugin, ONE host, N carriers** — `minidsh serve` mounts a stream carrier on process stdio; the terminal mounts the same plugin on an in-process duplex pair; `minidsh web` mounts a WebSocket one. Agents created over the wire are owned by the plugin's context.

| method | params → result | rule |
|---|---|---|
| `initialize` | `{} → {serverInfo, providers, defaultAgentOptions, defaultAuthority, workspaceRoots, workspaces}` | the catalog handshake; defaults read LIVE from the settings store where one is mounted |
| `session/prompt` | `{sessionId?, text, mode?: followup\|steer\|auto, agentOptions?, cwd?, workspaceId?, path?} → {sessionId, messageId}` | absent id creates; live id delivers (with `agentOptions` applied as a durable switch); stored id resumes (racing prompts share one resume). `cwd` must be an absolute, existing directory inside the host's `workspaceRoots` — the wire may choose WHERE inside the host's policy, never the policy; `workspaceId`+`path` names it instead; all three refused alongside a `sessionId`. `auto` is resolved by the host against the live agent in the tick it delivers. The RESOLVED route must name a provider this host has an adapter for |
| `session/attach` | `{sessionId, limit?} → {header, view, page, cursor, damaged?}` | the paged attach (below); subscribes the connection BEFORE the page is cut; narrows an un-narrowed client |
| `session/page` | `{sessionId, throughSeq, beforeSeq?, limit?} → {page}` | walks backwards beneath the attach cut; `throughSeq` past the cursor is refused |
| `session/detach` | `{sessionId?} → {}` | no id narrows to NOTHING |
| `session/events` | `{sessionId, fromSeq?, toSeq?, limit?, omitTrace?} → {header, events, damaged?}` | the raw archival read, every tier; bounded at both ends it is the gap repair |
| `sessions/list` | `{workspaceId?} → {sessions}` | live and stored, newest first; a stored one from a bounded prefix read, a live one folded from its facts, and the live half wins the union. Each carries a `title` — derived, never on the header |
| `session/cancel` | `{sessionId, keepQueued?} → {}` | `keepQueued` leaves the durable inbox alone (one client's cancel is not licence to discard another's prompts) |
| `session/compact` | `{sessionId} → {kind: compacted{…} \| scheduled \| nothing-to-do{reason?}}` | a HUMAN command, never a model-facing tool; `scheduled` when mid-turn |
| `approval/answer` | `{sessionId, id, outcome} → {outcome: accepted \| not-pending}` | keyed by the durable `approval/asked` id; first answer wins across clients |
| `session/authority` | `{sessionId, sandbox?, approval?, preset?} → AuthorityView` | no arguments reads; each switch IS its durable event; `preset` exclusive with the pair |
| `session/model` | `{sessionId, provider?, model?, reasoningEffort?} → AgentOptions` | no fields reads the base route; each given field merges as one `agent/options{change}`, effective at the next step |
| `settings/describe`, `settings/get`, `settings/set` | `{ns, patch, expectedRevision, replace?}` | `expectedRevision` REQUIRED; a stale or invalid write is the caller's error |
| `shutdown` | `{} → {}` | dispose-to-idle, host-wide, carrier-gated: stdio and the loopback pair may call it, a socket may not |

Notifications: `session.event {sessionId, event}` (the durable event verbatim), `session.status`, `session.view {sessionId, view}`, `settings.changed {ns, revision}`. **Approval frames are the durable events**: `approval/asked`/`approval/decided` streaming over `session.event` are the answerable frames. There is no DTO layer and no protocol version until a client ships independently of the host; clients ignore unknown event types.

- **The attach contract.** `session/attach` answers with the header, a **message-aligned tail page**, the **cursor** it was cut against, and a `SessionView`; `session/page` walks backwards beneath that cut. Only `user/message` and `assistant/message` that ARRIVED spend the page budget — a `tool/result` is not a message and a compaction summary is not an arrival — and the cut is pulled back to the message's own `min(seq, ...sourceEventSeqs)`, so a message is never split from what produced it. A replacement's citations are deliberately NOT honoured (a summary cites every node it shadowed). Two ceilings: a client-supplied `limit` is clamped, and an event ceiling bounds a page beside the message budget, cutting at a message-group boundary where one has been walked and at the current event's own group start where none has. **Pages never carry the trace tier**, so `Session.facts` IS the page source and a bare seq is a sufficient dedup key. There is **no lower-bound cursor**, by design: a reconnecting client re-attaches and replaces its window; a hole inside one connection is repaired with `session/events` bounded at both ends. A cold read never resumes the session (a small parsed LRU serves backward paging).
- **`SessionView`** is the live control plane widened to exactly what a client holding one PAGE cannot fold: `{status, context?, pendingApprovals, authority, options?, route?}`, each a projection of durable facts computed by whoever owns that fold; `pendingApprovals` is empty for a session read COLD, because a cold read never resumes and repair has not closed its undecided asks. **No surface node list crosses the wire, because no client folds the surface.**
- **Multi-client.** The host is per-DEPLOYMENT; a `ClientConnection` owns only its frame sink and its watch set. A fresh connection receives every session and narrows on its first attach. A disconnect disposes nothing. Approvals are broadcast and the first answer wins; who could answer is recomputed from the LIVE connections after every watch-set change, and a question no connected client can see any more is settled `unavailable`. A request asked while NO connection could see it is not parked at all: the host delegates down the waterfall to the next answerer (`approval-headless` under `--approve`, else the fail-closed default).
- **A delegated child is its parent's while the parent is running it.** One predicate — the header names a `delegatedBy` that is still live, and this host did not itself resume the child — carries two rules: the child is READ-ONLY over the wire (`prompt`, `cancel`, `compact` and the switching forms of `model`/`authority` are refused naming the parent; reads stay open), and its stream reaches only a client that attached to it by name. A child this host RESUMED is the host's to drive, under the ceiling its log records.
- **Backpressure is tier-aware.** `session/event` is a synchronous contained emit, so a listener cannot suspend the loop: over a per-connection soft limit the TRACE tier is dropped (`assistant/message` carries the same text durably a moment later); facts and surface events are never dropped, and past a hard limit the socket is closed as `slow-client` so the client reattaches. Liveness is a WebSocket ping; there are no host-side per-method deadlines and neither shipped client implements a request timeout.
- **The interactive terminal** (`app/terminal`): a protocol *client* — streaming render straight from durable `assistant/chunk` text deltas, every other line from the shared projection, typed input steers a running turn, `y/N` answers approval frames (the first ask prints one tip naming the session-scoped answer, `/preset` or `/sandbox danger-full-access`), `/sandbox`, `/ask` and `/preset` switch authority over the wire, `/model [<provider>/]<model> [effort]` switches the route, `/compact` shrinks context, `/history` pages back, `/sessions` lists the newest twenty by NAME and says how to open one (switching in place is a capability, not a listing), `/cancel`, Ctrl+C cancels then exits. It shows context pressure as `[ctx 34% · 12.4k/32k]` from `session.view` and **retains nothing of the session**. Typed input is sent as `mode: 'auto'`, so the host decides steer-vs-followup in the tick it delivers. `minidsh chat` opens a fresh session; interactive `resume`/`fork` are prepared host-side by the app assembly (there is no wire-level fork method — a stored id in `session/prompt` resumes; upstream ships `session.fork` with `atSeq`), and the client renders a `session/attach` PAGE first — a longer session prints `… earlier events remain (/history shows the page before this one)`.
- **The browser** (`minidsh web`, `app/web.ts` + `app/web/`): the same protocol over a WebSocket, plus a static client of plain hand-written ES modules (no build step). It renders structured DOM per event type, lists sessions and workspaces, pages backwards, streams, prompts, answers approvals, switches authority, compacts, and edits settings (the default route); a per-session route switch is terminal- and wire-only. **Its transcript GROWS rather than being rebuilt**: the log is in seq order, so `SessionWindow` reports which of four shapes it performed — `reset` (a fresh page replaces the window), `append` (a live event or a repaired range), `prepend` (a backward page), `view` (no row at all) — and a compaction's `replace` rewrites nothing, appending one note above the messages it shadowed. Scroll ownership is sampled just BEFORE each mutation and never stored, so an append follows a reader at the bottom and leaves one who is not, and a prepend restores `scrollTop` by the height it added; a streamed row is removed by the durable message that replaces it, not by the next render. **It is an authority surface** — a client there can write files and run commands — so it binds loopback unless `--host` says otherwise, and `GET /?token=…` exchanges the one-shot launch token for a signed HttpOnly SameSite=Strict cookie before redirecting to a clean `/`; every later request and the upgrade check that cookie behind a Host/Origin fence. The token is spent by the first exchange that succeeds, so a URL left in a shell history is not a standing credential. The Host allow-list is built from what was actually bound; a WILDCARD bind has no authority of its own, so there the fence falls back to "an Origin must match the Host it was sent to". There is no per-user identity: many windows, one principal.

## 9. Composition and configuration

What MiniDSH *is* is data: the built-in rows plus declarative layers on disk, one algorithm, one record. Four planes stay distinct — **composition** (which plugins, their config), **settings** (user defaults over app assembly), **credentials** (named secrets), **authority** (never configuration: recorded events beat composition defaults by fold precedence, always).

**Home layout** (`MINIDSH_HOME`, default `~/.minidsh`): `sessions/*.jsonl(.torn|.lock|.lock.steal)` · `spill/<session>/*.txt` · `attachments/v1/objects/<xx>/<sha256>` (image bytes, content-addressed, no sidecar — the LOG is the metadata store) · `composition.json` · `settings.json(.lock|.writing)` (the only CONFIGURATION file the runtime writes, and only through the settings store) · `credentials.json` · `AGENTS.md` (the user's global instructions — model-facing context, never configuration). Paths resolve in `app/home.ts` only and travel down as plugin config; nothing below `app` may import the home.

**Composition.** `Row{id, plugin, config?, disabled?}`; `Patch = {id, config?|disabled?} | {insert: Row[]}`; `applyPatches` replaces a row's whole config, warns and skips unknown ids, appends inserts. `applyLayers` runs it once per named layer, records per-row provenance (a row is marked by a layer only when the patch CHANGED it), and refuses duplicate ids. Layer order is fixed: **built-ins** (`compose()`, plus rows a surface contributes to the base — serve's protocol row, which a disk layer may target but may neither disable nor reconfigure, since its config carries live streams) → the programmatic **app** layer → **home** `composition.json` → repeatable **`--patch` files**. Direct authority flags are inputs to `compose()`, so a disk layer can override them; what makes an explicit flag win on `run`/`resume`/`fork` is `applyAuthority`, a durable per-session switch after creation. On disk a row's `plugin` is a builtin catalog name (every shipped plugin by kernel name except `protocol`, whose config carries live streams a surface contributes, and `composition-record`, which the boot alone mounts outside the layers — `tool-view-image` is in the catalog and is enabled by an inserted row, not mounted by default; `tool-history` IS mounted by default, because it costs an agent nothing until that agent's first applied compaction) or a module specifier resolved against the file's directory and imported (Node type-strips out-of-repo `.ts`; the module exports exactly one plugin; authors use erasable syntax and import repo modules by absolute `file://` URL or not at all). **Every shipped plugin with a config declares its contract**, so a stale key fails boot naming the row. **composition.json is code-equivalent trust** and an input, never a persistence target. There is deliberately no workspace-level layer: a repository may say how it likes its code and may not say what the harness is allowed to do. The home layer may patch even authority-sensitive rows — it IS the deployment — but never silently: `minidsh config` flags them by capability.

**The composition record.** Every boot appends a `composition-record` row *outside* the layers. On agent creation, pre-publication, it appends log-only `composition/applied{hash, layers, rows}` iff it differs from the log's last — so a resume under an unchanged composition logs nothing and a fork inherits its parent's stamp. Configs are hashed (canonical key order, sha256/16), never inlined; a config that cannot snapshot to JSON hashes by presence. A surface's own rows (serve's protocol row) and per-run flags are part of the effective composition, so a session resumed under a different surface legitimately re-stamps.

**Runtime recomposition.** `mount()` returns the `Composition` handle (an app-only service): `insert`, `remove` (the kernel cascade parks dependents pending), `reconfigure` (validate the new config against the row's contract FIRST, then dispose and remount). Row changes are serialized. A fixed spine set `{session, llm, tools, prompt, agent, loop, persistence}` refuses removal or reconfiguration while agents are live — `persistence` because its leases and descriptors die with the plugin instance.

**Agent presets.** `composition.json` may declare `agentPresets: {name: DiskRow[]}` — named per-agent worlds mounted on the agent scope during creation (`--agent-preset` on run/chat/resume/fork/serve/web; `ProtocolConfig.setup` for agents the wire creates), recorded as `agentPreset` in the session header so a resume or a child composes the same world. Registrations and services live and die with the agent; the factory's scoped fail-loud settle gates unmet deps and bad configs; a preset row that reaches into a deployment-global registry fails its agent's setup.

**Settings.** `settings.json` `{agent: {provider?, model?, reasoningEffort?, maxSteps?, maxTokens?, temperature?}, revisions?}`, zod-validated, resolved ONCE at process entry with precedence flags → `MINIDSH_MODEL` → file → the pure built-ins, then passed down as `BootOptions.agentDefaults`. On resume it sits in the *defaults* tier: the log's folded base route wins. **At runtime** (`core/settings` + `settings-local`) the boot claims the `agent` namespace with the PURE BUILT-INS as its base (the store re-applies the file as its own user layer); what outranks the store (`MINIDSH_MODEL`) travels separately and is applied above whatever it resolves. The store owns the document: every write re-reads it inside a lock, validates the merged value before persisting, and replaces the file by rename. `initialize` and the create path read the store LIVE, so editing the default edits what the next session gets. The model-role table stays a capability row's config, not settings.

**Retention: content is never swept; an affordance may expire.** An attachment is content (a log names it as something the model saw), content-addressed and shared across resumes and forks. A session log is content AND the only script its arc replays from; deleting one needs an authority above the append-only seam that this system does not have, so nothing here infers deletion from disposal. A spill file is an affordance (the excerpt beside it is already the truth of what the model saw), so it is the one store a sweep may touch, and `spill-local` sweeps it: **one pass at load**, started there and awaited at disposal so shutdown is quiescent — never ON disposal, because a fork inherits its parent's locators. Per file and STRICTLY older than one cutoff snapshotted before the walk (a file exactly at it stays). Names are matched against the exact shapes this store generates, never by prefix: a directory against the MINT's own pattern (`SESSION_ID_PATTERN`, beside `newSessionId`), a file against `<callId>-<label>.txt`'s two bounded segments — so a backup a person put here is not eligible, and a name the sweep cannot recognise is left alone. `lstat` everywhere, so a symlink is skipped rather than followed; `unlink` per file plus a non-recursive `rmdir` of a directory that is empty AND itself older than the cutoff (mtime read before any delete, since deleting bumps it — otherwise one process's sweep takes a directory another has just created and not yet written into). One knob, `cleanupPeriodDays` (default 30; `0` disables), and every failure is contained, the `logger.warn` included: a store's housekeeping may not fail a boot.

| store | class | lifetime |
|---|---|---|
| `sessions/` (including delegated children) | content, and the replay oracle | never removed by the harness |
| `attachments/v1/objects/` | content, shared by address | never removed |
| `spill/<session>/` | affordance | age-swept at load, `cleanupPeriodDays` (default 30) |

The shipped authority default is `workspace-write` + `ask`, and on a host with a confinement backend an ordinary task under it costs zero prompts. Which mechanism confines the shell is one knob on the `shell` row — `confinement: auto | none | bwrap | seatbelt`, default `auto` — and `shell-stdio` is already an authority-sensitive plugin, so a disk layer that changes it is flagged by `minidsh config` like any other. `none` is not a weakening but a name for what every host without a backend already does, which is how a test about that host stops depending on the machine it runs on. Environment: `DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY` (credential *references* resolved through `ctx.credentials`, from the environment first and then `credentials.json`), `DEEPSEEK_BASE_URL` / `ANTHROPIC_BASE_URL`, `MINIDSH_HOME`, `MINIDSH_MODEL`.

## 10. Verification

Tests mount real compositions through the kernel; only the model is scripted (`test-support/scripted-adapter`) or replayed from a recorded session log (`test-support/llm-replay`, which derives the script from `assistant/chunk` groups per (turn, step), replays EVERY terminally-finished attempt by default so a recovery that changed the log happens again, serves out-of-loop calls from their `llm/aux-call` records keyed by `purpose` through a second cursor, and asserts every recorded call was consumed). **A live session log is its own test oracle** for the session that WROTE it: a delegated child replays from its own log, and sessions are matched to logs in first-request order. The protocol is tested byte-level over an in-memory duplex pair; the terminal's render folds are pure functions plus scripted runs over the loopback carrier; the browser client's window rules (dedup, gap repair, re-attach) have unit tests, its rendering does not.

Runtime invariants — the session relational trace (pre-commit), agent status no-repeat, and request reconstruction (an `observe`r in the `llm/stream` preflight) — run in every test *and* in live runs, because `compose()` mounts them by default. **Cross-capability claims are tested against the full composition** (`app.test.ts` over `bootComposition`), because a partial composition is where such claims were found false. End-to-end verification asserts the world (re-run the test suite, byte-compare untouched files), never the agent's self-report.

Gates: `pnpm check` = `tsc --noEmit` + `oxlint` + `check-deps` (dependency direction, payload discipline, core acyclicity) + `vitest`, run by `.github/workflows/check.yml` on ubuntu, macos and windows. The Linux and macOS legs additionally exist to prove confinement and set `MINIDSH_EXPECT_CONFINEMENT=1`, which turns a self-SKIPPED confinement test into a failure — a leg that exists to prove something may not go green having proved nothing, and in a summary a skip and a pass look identical. `live.yml` runs the arcs on `workflow_dispatch` only, refusing to start without both provider secrets for the same reason. `pnpm test:e2e` runs the eight live arcs (gated on `DEEPSEEK_API_KEY`; the routing arc also on `ANTHROPIC_API_KEY`). Seven drive a `minidsh serve` child over real stdio JSON-RPC (`test-support/serve-process.ts`); the eighth drives a `minidsh web` child over a real WebSocket (`test-support/web-process.ts`):

- `live` — complete a task, SIGKILL mid-turn, resume in a second process (crash repair + byte-prefix attach asserted), finish the work, replay keylessly.
- `authority` — no `--approve`: an edit inside the workspace lands; one outside is refused and probed ABSENT; then the shell, where the arc BRANCHES on the enforcement `initialize` reports, because the two hosts fail in different places and neither branch stands in for the other. Unconfined: the command is refused, the model escalates, the client approves, it runs. Confined: an ordinary command runs having cost nobody a decision, and then a command that tries to write outside the workspace leaves no host file while every approval is answered `rejected` — with the attempt scoped to that turn and required to name its target, since an absent file that never existed proves nothing on its own. Finally a switch to `read-only` refuses the next write.
- `composition` — a from-disk composition inserting a module-loaded tool and a settings.json choosing the route; the tool's output, the recorded header, the `composition/applied` stamp and a wire preset switch asserted from the log.
- `context` — a disk `budgetTokens` low enough to cross for real; the workspace's AGENTS.md demands a header the written file carries; a command's output spills and the model reports a value present only in the omitted middle; the compaction record's shadowed seqs are exactly what the replace cites. Its prompts name the editor tool and forbid a shell search, because "reply with the marker token" is otherwise answerable in one cheap line; it raises `maxSummaryFailures` because at that budget a compaction is often worth nothing.
- `routing` — a session starts on DeepSeek, switches to Anthropic mid-session, and the log proves the route is one fact; a `compaction` role sends the summary down DeepSeek; the mixed log replays with both providers served from one script.
- `delegation` — the parent delegates a bounded search; the child completes it in its own session under `reason: 'delegation'` stamps; every approval it asked for was refused without a client being consulted; a wire attempt to widen the resumed child is refused.
- `verification` — a delegated child sees an image its parent cannot: the parent's `view_image` is refused `UNSUPPORTED_CONTENT`; the child, routed to the vision model by one `model-roles` entry, reads a PNG the TEST drew (so the expected answer is a fact, not an assumption about the model) and the binding is asserted before any answer, because `model-roles` passes an unknown purpose through silently.
- `web` — the token-for-cookie sign-in, two clients on one host, a real consent granted over the wire, the transcript paged to seq 0 losing nothing, the socket killed mid-turn with the host still serving and a fresh connection finishing the work.

Every session close requires all eight arcs green. Run them on an idle machine, and do not let that stand in for a diagnosis: two failure shapes are latency-shaped, but the cause has also been the model taking a cheaper route than the arc assumed. When an arc stalls, `serve-process`/`web-process` name what the session was parked on; every count an arc asserts says what produced it. **A live arc's premise is an assumption about the model, and it decays silently** — when an arc has ONE assertion separating the working system from the broken one, ask what the model would answer knowing nothing.

The repository also carries one guard that is not part of MiniDSH: `.claude/hooks/guard-repo.mjs` refuses to link anything to a `node_modules` tree and refuses a recursive delete of a path that is such a link or holds one (CLAUDE.md §8).

| a model-facing capability | `capabilities/tool-<x>`: register on `tools` (+ a prompt guidance section) |
| a plugin's configuration | a strict zod schema on `Plugin.config`; the kernel parses it before `apply`, and `reconfigure` validates before it disposes |

Add one there and to the platform chain; nothing above the provider changes, and `writableRoots` stays the ceiling it derives from |
| an authority knob | a log-only event with a `findLast` fold, an `open` at `agent/created`, and a setter that IS the event; never a field a surface holds |
| a bundled authority selection | an entry in the presets table; validates against a delegated session's ceiling and pin BEFORE writing its intent |
| a capability without a code edit | a row in `composition.json`: builtin name or module specifier; disable/reconfigure by patch; the session records the change via `composition/applied` |
| a user-adjustable default | a `core/settings` namespace registered by the boot if a WIRE client should change it; the row's config via a patch if it is capability config — never both, and never authority |
| a secret | a `CredentialRef` (env-var name) in config; the value comes from `ctx.credentials` per operation |

| a policy or approval answerer | listeners on `tools/pre-execute` / `approval/request`; guards |
| durable state | a new session event type (a fact, or a trace kind if nothing folds it), rendered and replayed from the log |
| a human-facing line for an event | one branch in `app/present.ts`, narrowed with `matches()` |
| context for the model | `agent.inject()` or an `agent/pre-step` listener — never ad-hoc prompt text; prose about authority belongs to the capability that owns the runtime-context section, never to the service that owns the knob |
| a surface | `app/` or a new package: consume `session/event`, drive `agents`; zero semantics; owns only the live control plane |
| a carrier | a `Carrier` variant in `capabilities/protocol` beside the stream and WebSocket ones; the host and its ownership plane are shared, so a carrier owns framing and flow control alone |
| a named place to work | a `workspaces` entry on the protocol row's config — addressing only, it grants nothing `workspaceRoots` does not |
| a remote client | speak the protocol (§8): attach for the header, view and a page; page backwards; dedup by seq; repair a hole with a both-ends-bounded `session/events`; re-attach after a reconnect |
| a per-agent variant | registrations or plugins through `agent.ctx` — during `world` when a child should inherit it, during `setup` when only this agent should, and later through a `TOOLS.restrict` the owner lifts (how recall is gated) |

| context management | BUILT (§6): `core/compaction` + a provider. A new policy is a different provider; a new trigger is a listener that calls it; a model-free pruner is a second surface writer and must carry the pairing rule with it |

| oversized tool output | `core/spill` + a store, consumed by the TOOL that produced it. Output that is already a file is not spill |
| an attachment kind | `core/attachments` + `attachments-local`: a media-type family and a header probe, not a seam |
| a producer of non-text content | a tool that refuses on the STEP's route before any I/O, bounds itself against `imageLimits` over the live surface, commits durably, and only then returns a block (`tool-view-image`) |
| a verifier | BUILT: a second `tool-subagent` row with its own `toolName`, `purpose`, `description` and a narrowing `sandbox`, plus the matching `model-roles` entry — patched TOGETHER, because an unknown purpose passes through silently |
| a model role | a `purpose → route` entry in the `model-roles` row's config; the base route is never rerouted |
| a model call outside the loop | `resolveCallConfig(agent, {purpose})` for the route, then `runAuxCall` |
| a recall of shadowed history | BUILT (§6): `capabilities/tool-history`. A tool over `deriveEventMessage(session.events[seq])` restricted to the seqs `compaction/applied` records name, registered globally and hidden per agent until its first applied compaction |

| a store's lifetime | the retention table (§9): content is never swept, an affordance may expire; a new store is a visible row there before it is code |
| a session's name | BUILT (§8): the log-only kind and its last-wins fold are `core/session/title` (both readers are capabilities, which may not import each other); the WRITER is a capability row, so a different policy — a model-written title, a rename — replaces one row and the log format does not move |

If a new thing has no row here, that is an architecture question to settle before implementation.

## 12. Divergences from DeepSeek Harness (the ones that still shape decisions)

- Own kernel instead of Cordis; a structural `{parse}` config contract per plugin instead of a schema-library dependency in the kernel.
- One package with a dependency gate instead of several hundred packages; a capability is a directory.
- Sequential tool execution; one foreground child at a time; no background jobs (DSH's `minimal` preset ships none either).
- One client protocol (DSH's SDK shape) instead of three, adding what that one lacks: `session/cancel`, `approval/answer` keyed by the durable id, `session/authority`, a catalog-returning `initialize`.
- No lower-bound attach cursor on the wire (DSH's shape too); MiniDSH adds a gap repair bounded at both ends and a host-enforced page ceiling. Pages omit the trace tier where DSH packs it, which keeps a bare seq a sufficient dedup key.
- Watch sets and a tier-aware drop policy, where DSH has per-follower copies and unbounded queues: a MiniDSH invention, because `session/event` cannot suspend its producer.
- Approvals are settled `unavailable` when nobody is left who can see them, recomputed from live connections (DSH's stay pending forever).
- Workspaces are read-only and config-declared; a settings write over the wire must carry the revision it read; no per-user identity.
- Two confinement backends where DSH ships four, with the bwrap profile adopted flag for flag. No Landlock: DSH's is a standalone static C launcher shipped as per-platform npm packages, which a zero-native-dependency tree with no build step cannot carry, and on a 6.6 kernel its own launcher reports `partial` anyway. No Windows backend (§13). MiniDSH also probes a sole platform candidate where DSH skips that, because it records `enforcement` before any command runs rather than failing closed at execution; and Seatbelt roots go in as `-D` parameters rather than through an SBPL escaper — same grant, one fewer thing to get wrong.
- `writableRoots` grants the workspace root ONLY, where DSH's shared list adds `/tmp` and `os.tmpdir()`, and it binds BOTH families as a ceiling where DSH lets bwrap and Landlock spell their own. The reason is local: the temp root is where MiniDSH puts every workspace it tests with, so granting it makes containment vacuous for any session whose cwd is under it — every live arc, and any real `--cwd /tmp/scratch`.
- `SandboxEnforcement` keeps a third value, `none`, where DSH has `full | partial` and raises instead. It earns its place: the no-backend posture is a supported configuration here, not an error.
- Escalation is strictly-wider plus one-shot approval — DSH's gate too; neither has standing grants, allow-lists, or per-workspace trust.
- Tool deadlines are registry-owned rather than a wrapper plugin, because the kernel waterfall cannot substitute a listener's arguments.
- A terminal client ships (DSH deleted its TUI); it is a protocol client on an in-process carrier.
- Plain JSONL through one held descriptor with a session-lifetime write lease; a `.torn` sidecar where DSH salvages a torn tail in place.
- JSON config with two disk layers instead of DSH's YAML and four; composition files read at boot, not watched.
- A delegation opening is an enforced ceiling where DSH relies on the pin alone; `subagent/start|end` live in the parent's LOG where DSH emits runtime events.
- Model roles are a seam here and not upstream; the BASE route is a durable knob separate from the effective route.
- A per-boot `composition/applied` record, which DSH does not keep; a durable `agentPreset` in the header, as DSH does.
- No deterministic tool-result pruner: DSH ships one that runs only once a compaction trigger qualifies; MiniDSH's shipped tools bound their own output, so it is deferred rather than rejected.
- A durable compaction bracket adopted so a paid attempt that produced nothing is explainable, not for a lock; the give-up counter is a fold bounded to the lifecycle.
- Recall of shadowed history is GATED here rather than opt-in. DSH ships `session-query` (a service, a SQLite FTS5 backend, and five model-facing tools including `session_event_read`) but mounts none of it by default, for the cost its own README names: "mounting it adds one concise guidance section and the five schemas to every request". MiniDSH's is one tool, restricted to what a compaction shadowed IN THIS SESSION rather than authorised across sessions by `cwd` equality, and it costs an agent nothing until that agent's first applied compaction — so the schema is present exactly when there is something to read. No semantic verification of a summary anywhere in either system; MiniDSH's verifier verifies artifacts in the world.
- An attachment plane with no image dependency: four media types sniffed from their headers, exactly the user's bytes stored, so the same file has the same id on every machine.
- Retention stated as one rule where DSH is retention-neutral by policy and sweeps only spill; both reach the same three lifetimes, and the sweep itself copies upstream's shape almost exactly — one pass at activation, per-file mtime strictly older than a snapshotted cutoff, length-anchored name shapes, `lstat` throughout, `unlink` plus a non-recursive `rmdir`, ENOENT as success, one `Days` knob whose `0` disables it. It needs none of upstream's trusted-directory and ancestor-permission checks, and the reason is the older divergence: DSH's spill root is an OS temp directory and MiniDSH's is under home.
- A session's name is upstream's log-only `session/title` and its last-wins fold, plus a DERIVED fallback inside that fold, which upstream has no need of: it reads titles through a projection, and MiniDSH reads a bounded file prefix. Only `fallback` is produced here; the vocabulary is complete because a rename must be distinguishable from a generated title in a durable record — upstream's own rule.
- The browser samples scroll ownership immediately before each mutation rather than keeping an "observed-top ledger" of its own writes. It can, because nothing here listens to a scroll event — provided the write lands in the same tick as the sample, which is why streaming scrolls per delta rather than per frame.
- No PTC (DSH's renamed "Code Mode"), no model-written packages (DSH ships them only in its opt-in `cordis` preset, session-scoped and explicitly not a security boundary), no MCP bridge (DSH ships one disabled by default), no session search index, no workspace config layer.

## 13. Known limitations (current)

Authority
- **Windows has no confinement backend and is not getting one**: DSH's is a native write-restricted-token subsystem, permanently `partial`, with two named escapes (an ambient `Everyone` ACE on an external object; an NTFS hard link aliasing one file object across paths). There, under `workspace-write`, the filesystem is fenced and every shell command still costs an escalation and a human decision, and a headless run without `--approve` cannot run a shell at all — upstream's own state before it built that subsystem. The posture is per-call approval or the `danger-full-access` preset, and the terminal's first-ask tip names it.
- `full` is a claim about a PROFILE's completeness, asserted from how the profile is built and proven by a functional probe — not measured per call. Upstream's basis too. Nothing reports `partial` today; the value exists because a caller needing an absolute boundary must not read one as the other. The `shell` row is also outside the spine set, so a live `reconfigure` of it opens a window where `enforcementFor` answers for a world a command will not run in.
- The sandbox's `/dev`, and under `workspace-write` its `/tmp`, are private tmpfs mounts on Linux: nothing written there reaches the host or the editor, which is what keeps the ceiling true, but a path under the host temp root outside the workspace is INVISIBLE rather than read-only, so its denial reads as a missing directory and earns no escalation hint. macOS gets no writable temp at all — Seatbelt does not change the filesystem view, so there is nowhere private to point `TMPDIR` and granting the real temp area would widen the ceiling; a tool needing one must escalate. macOS is proven by CI alone: there is no Mac here, and nothing about interactive use on one is claimed.
- A durable mode switch replaces the persistent shell, so its cwd and environment are gone (`restarted`, and the tool says so); an approved escalation runs in a separate shell for the same reason, and its state does not persist either.
- The runtime-context section is byte-stable for a lifecycle and states what that lifecycle OPENED under, so a mid-session switch reaches the model as a message instead. The one thing that does move it is a `sandbox/mode{resume}` stamp — a host whose confinement genuinely changed under a live agent — which is a real change of the world and costs one prefix-cache invalidation.
- A delegation tool registered by an AGENT PRESET lives in the child's own scope, which `restrict` cannot hide (a scope's own registrations are exempt) and the depth cap's registry read does not enumerate. The cap is a cost bound, not a fence, and this was as true of the name map it replaced.
- The mode vocabulary claims file effects only, and the two families now enforce it differently: the fs fence is a policy check in trusted code over a model-supplied path, while a confined shell is a real kernel boundary. Neither makes escalation anything but voluntary — it depends on the model asking. The audit projects decisions, not attempts, so a refused OR kernel-denied command is a fact in the transcript and not in `--audit` until the model escalates it.
- A module-loaded plugin is arbitrary code; `minidsh config`'s warnings are advisory, and the home layer may widen defaults — never silently.
- A delegated child's tool filter keeps it cheap and focused; what keeps it safe is its `read-only` opening and approvals pinned `never`. `maxDepth` is a cost bound.

Context
- **The shipped DeepSeek default never reaches the pressure trigger** (0.8 of a 1M window); only the overflow recovery can fire on that route. A deployment that wants earlier compaction sets `budgetTokens`.
- A compaction summary is one model call that can be wrong. `history_read` reads the span back, but the model has to decide to ask: the summary's frame names the range and the tool, and nothing forces the call. Its budgets are absolute token counts a deployment sets, not a fraction of the context budget, so a small `budgetTokens` and the shipped defaults are not related.
- The summary's frame names the recall tool from the DEPLOYMENT registry, so a delegation row that explicitly `deny`s `history_read` and lets its children compact writes a durable node naming a tool that child cannot call. An `allow` filter no longer does this — a recall tool survives one, like the delegation tool does — but an explicit deny is a deployment saying children may not recall, and the frame does not know it.
- Offering recall costs steps a session may not need: the tool appears at the first applied compaction whether or not the summary actually dropped anything, and a model that calls it speculatively spends a step and part of its budget on history it already had. The budgets bound the CONTEXT that costs, not the step.
- The frame names the shadowed range as `min–max`, which OVERSTATES it: the span is contiguous in surface order, not in seq, and a second compaction makes the admissible set a union of runs. The tool intersects rather than trusting the range, and its refusal says where the replaced messages actually are.
- A compaction near the threshold is often bought and not used; the record now says which of the seven reasons it was. An explicit `/compact` deferred to a step boundary reports its reason in the log, not in its own RPC result.
- The meter changes units at a compaction (provider-priced before, estimator after; safe in direction); a prompt or tool-set change is metered one step late; an image on a text-only route is still charged as an image.
- A role's route is not what the budget is measured against; a role pointing at a much smaller model can be asked for a summary larger than it can take.
- Workspace instructions are read once per entry, not watched; the two `agent/pre-step` listeners run in row order, and that order is load-bearing (instructions before compaction).

Sessions and stores
- The in-memory log retains the trace tier deliberately (`seq === array index` at many sites); a 400-turn session is tens of MB of heap.
- The spill sweep is ONE pass at load, so a host left running for weeks is not swept until it restarts, and a file that crosses the cutoff mid-run is reclaimed at the next start. It reports nothing on success — the store's contents are the observable fact. A repeated `callId` overwrites.
- A lost attachment object is turn-fatal (`ATTACHMENT_UNREADABLE`, nothing retries) and image validation is header-only.
- Images have one producer and no client upload path: `view_image` reads from the workspace, nothing puts an image in a `user/message`, and the WebSocket carrier's 8 MiB message cap is tighter than either provider's.
- No session deletion and no search (deletion is out of scope, as upstream). A session's name is the recorded `session/title`, else its first prompt; there is no rename and no model-written title, both of which need a projection — a rename lands deep in a long log, and `persistence.list()` reads only a bounded prefix. That prefix is also why a session whose first prompt is larger than 64 KiB lists without a name (`sessions show` still names it, since it holds the whole log).
- The lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts); a process killed inside a reclaim leaves a `.lock.steal` mutex that blocks later reclaims (never a fresh acquisition) until it is removed.
- A turn that loses durability ends, but the agent stays `idle`; reachable only through a provider or driver bug.
- A fork boundary may separate the compaction bracket from the replace that realized it; nothing is lost, the child's log merely stops explaining its surface.

Surfaces
- `session/events` returns whatever range it is asked for, every tier included; the paged path is what every rendering client uses.
- No host-side RPC deadlines and no client request timeout; the backpressure limits are fixed numbers, not a measured policy.
- The browser authenticates nobody (loopback, one-shot token, signed cookie, Host/Origin fence — reachability, not identity); it cannot switch a session's route. Opening a STORED session leaves `compact` and `cancel` enabled although neither can act until a prompt resumes it: the refusal is honest (`no live session "…"`) rather than pre-empted, because liveness is the host's fact and a client that cached it would go stale.
- A reconnecting client loses its paging position and, if it was the only watcher, a pending approval (settled `unavailable`).
- A `session/detach` naming one session narrows an un-narrowed client to nothing; no frame says a session was disposed.
- A rolled-back creation's opening facts still reach a watching client; a prompt delivered between `cancel({disposed})` and the registry detach is dropped and answered as success. Both are deliberate: the fixes would invert documented, test-pinned orderings.
- `--preset` on a headless run leaves the stable prompt section stating the composition default; the injected switch note tells the model.
- The terminal renders plain lines; `ToolResult.value` is not durable.
- On Windows the shell dialect is `pwsh`: PowerShell 7 is required, and a host without it is refused loudly (`SHELL_UNAVAILABLE`), never run under PowerShell 5.1 by another name. A PowerShell command that reads stdin blocks until its deadline.

Delegation and providers
- A delegated child is foreground and sequential; its cost is summed in `subagent/end`, not attributed to the parent's meter; it is disposed with the tool call that made it (its log stays).
- First-request-order replay matching is exact while delegation is serial and undefined the instant it is not.
- A replay reproduces the model's decisions, not the workspace they named: a recorded tool call that chose an absolute path inside the recording's workspace cannot land in a fresh root (the fence rightly refuses it), the turn still completes on the recorded messages and `assertConsumed()` passes — so an arc's prompts pin relative paths, and that steering is a prompt, not a fence.
- No OpenAI or Moonshot adapter; an Anthropic id outside every known family prefix gets conservative facts (200K window), while a dated snapshot of a known family inherits the family's.
- Composition changes need a restart; only `minidsh sessions` reads through the effective composition among the one-off tools.
