# MiniDSH Architecture

MiniDSH is one runtime composed from plugins over a tiny kernel. Everything the model can see is derived from an append-only session log; everything the model can do goes through a guarded tool pipeline and is fenced at the effect boundary by an authority the log records; the model itself is a capability the runtime routes to, not the agent — the route is a durable fact, a purpose may take a different one, and a delegated child runs under an authority it cannot widen, which is how a verifier that can SEE is a composition row rather than a second architecture; bytes the model was shown live beside the log, content-addressed, never in it; every surface (the headless CLI, the JSON-RPC client protocol, the interactive terminal and the browser riding on it) only renders the log and drives the agent registry — a long one by the page, because no client may be handed a whole log — and a session survives its process: it is stored the moment it records a conversation fact, and resume attaches to the stored log append-only and continues. The reference it re-derives from is DeepSeek Harness (DSH); §12 lists where MiniDSH deliberately differs.

## 1. Layers and dependency direction

```
src/app/           application assembly + surfaces: compose.ts (rows + patches + catalog), config.ts
                   (disk layers), settings.ts, headless.ts, cli.ts, serve.ts (stdio protocol host),
                   web.ts + web/ (the browser host and its plain-JS client), present.ts (the one
                   event→line projection), terminal/ (interactive client), home.ts (the home layout)
src/capabilities/  providers and consumers over core seams (never import each other, never app)
src/core/          the spine: Service Definitions + default drivers as plugins
src/kernel/        composition substrate: Context, plugin lifecycle, services, effects, events
src/test-support/  scripted adapter, replay-from-log adapter, composition harness
```

Dependencies point downward only, enforced by `scripts/check-deps.ts` (part of `pnpm check`), which also refuses `event.data as {…}` outside tests — payloads are narrowed with `matches(event, KIND)` so a renamed field is a type error, not a `NaN` on a screen:

| from | may import |
|---|---|
| `kernel` | nothing internal |
| `core/<x>` | `kernel`, other `core` contracts — **except `core/loop`, which nothing imports but `app`** |
| `capabilities/<x>` | `kernel`, `core` (Definitions only; providers never import other providers or consumers) |
| `app` | anything |
| `test-support`, `*.test.ts` | their own layer and below; `test-support` may import `app` to mount real compositions |

A deeper tree is not more architecture: the layers are the whole topology, and a capability is a directory, not a package. The browser client that S7 added is an out-of-process consumer, and it did NOT force a workspace split: it shares no code with the host at all — plain JS, no build step, only the wire between them. A split waits for a consumer that needs to import something.

## 2. Kernel (`src/kernel`)

The kernel realizes the two composability properties from the Cordis paper with the smallest mechanism set DSH actually relies on:

- **Context** — a non-mutating tree. `child({scope?})` derives a context carrying a scope tag; registrations made through a context are attributed to it and unwound with it (registration context = visibility = lifetime). Scopes are flat: a child beneath a scoped context inherits that scope and cannot be re-tagged. A scope disposed early releases its record on the parent. Root-derived scopes read any service; a scope derived from a plugin context reads *through* that plugin's declared and provided keys and may widen only its own set by providing (undone with the provision), never the plugin's — because reload tracking is keyed on `inject`.
- **Services** — `provide(key, value)` is an effect; a key is claimed once per context chain (a child may shadow). `get(key)` is strict: a plugin may only read keys it declared in `inject` or provided itself (its own key is readable, from the plugin context or its scopes, while it is still loading); `tryGet` is the optional read. Keys are typed tokens (`serviceKey<T>('sessions')`), not declaration merging. Deployment-global registries (`llm.registerAdapter`, `invariants.register`) refuse a scoped owner: a per-agent world may not reach into a registry every agent shares.
- **Plugins** — `{ name, inject?, config?, apply(ctx, config) }`. `config` is an optional contract, structurally `{parse(unknown) → C}` (a zod schema qualifies; the kernel imports none): the kernel parses a row's config BEFORE `apply` and hands over the parsed value, so a stale or malformed row fails loud at load as `PLUGIN_CONFIG` naming the plugin. An instance is `pending` until every injected key is provided, then `loading → active`. Its activation epoch is the tuple of providing instances; when a dependency disappears the plugin unloads (effects unwound), when a provider is replaced it reloads. Transitions are serialized per instance. A provider's effects unwind before its dependents unload, so a disposer must not read the services its plugin injected. `settle(filter?)` waits for root-wide quiescence and reports the plugins still pending with their unmet keys and the failed ones with their errors, so boot can fail loud naming the row and the reason; `filter` narrows the report (e.g. to the plugins mounted under one scope, via `PluginHandle.scope`).
- **Effects** — `effect(fn → disposer, label?)` pushes onto the owning instance's disposer stack; disposal is strict reverse order (temporal composability). A disposer runs its synchronous part eagerly, so `off(); register(sameName)` in one tick is legal; only an asynchronous cleanup is what the returned promise still waits on.
- **Events** — typed tokens carry their dispatch mode: `emit` (sync notification, listener exceptions contained), `waterfall` (around-middleware; listeners receive `next()` and may short-circuit; `next()` is single-shot — a second call is `DISPATCH_REENTERED`, so no middleware can run a tool body twice against one durable record), `serial` (awaited in order), `parallel` (`allSettled`, aggregate error). Dispatching with the wrong method is a compile error. A dispatch may carry a `scope`: it reaches unscoped listeners, `global: true` listeners, and the listeners of that same scope — a scoped listener observes its own subject only and never sees a dispatch about another scope or about none. `observe(hook)` sees every dispatch in the preflight, before any listener is selected — the seam runtime invariants hang on, precisely because a listener can always be ordered behind another (`prepend` is an unshift) and an observer cannot; `prepareEmit` splits that preflight from delivery so an observer can reject a fact before it is committed.

There is no loader, HMR, isolate realm, proxy, mixin, or accessor. Registries take the owner context explicitly (`tools.register(ctx, def)`) instead of inferring it through a proxy.

**Scope contract** (`core/scope.ts`). Registration origin decides visibility and lifetime together: through an unscoped context → deployment-global; through an agent's `ctx` (or a plugin mounted on it) → that agent's layer, unwound with it. Tool definitions, guards, prompt sections and variables are layered: a view is the globals plus exactly one agent layer, a local entry shadows a same-named global, and there is no inheritance between scopes. Every event about an agent's operation is dispatched in that agent's scope — `agent/*`, `tools/*`, `approval/request`, `system-prompt/assemble`, `fs/*` — so a listener registered through agent A's context never sees agent B. Subject-less seams (`llm/stream`, `session/*`) and registry-membership notifications (`tools/change`, `agent/created|disposed`) are unscoped and reach only unscoped (or `global`) listeners; a per-agent plugin that needs them registers globally and filters by id. Consumers receive the agent as the operation subject (`tools.get(name, agent)`, `prompt.assemble(agent)`, `FsActor.agent`) and never read services through `agent.ctx`. A per-agent execution world is composed by mounting plugins on `agent.ctx` during `setup(agentCtx, agent)`; `agent` is the unpublished agent (also `agentCtx.scope`), and its session is appendable there — the slot a creator seeds durable opening facts into before the first effect. A service provided in that scope's realm is seen by those plugins alone. Adapter and invariant registries are deployment-global and refuse scoped owners. A scope tag must be an object (the `Agent` itself); a string tag is refused rather than filed globally.

## 4. Canonical facts: the session log

The log is the single source of truth. Envelope `{type, seq, time, data}`, `seq === log.length`, data JSON-lossless and deep-frozen at append. **It has three tiers.** The three **surface** events — `user/message`, `assistant/message`, `tool/result` — carry `surfaceOp: 'append' | {op:'replace', start, end}` and `sourceEventSeqs`; model history is the fold of surface nodes through `deriveEventMessage`, never a filter over raw events, which is what lets a later compaction provider replace a range without mutating history. Every other event is a log-only **fact** the runtime folds (headers, stamps, records, inbox splices) — except the **trace** tier (`TRACE_TYPES`, today `assistant/chunk`), which is recorded for streaming fidelity and replay and never folded by anything at runtime. A trace kind is the bulk of a long session by two orders of magnitude (a 400-turn session: 105k events, 97 % chunks), so every runtime fold walks `Session.facts` — the log without its trace, seqs preserved — while persistence, replay and the wire keep `events`; a seq already in hand indexes `events[seq]` in O(1). With that split, the per-step meter fold at 105k events went from 30 ms to about 1 ms. One fold walks the whole log by design: the session relational-trace invariant's first sight of a seeded session, because it checks seq contiguity and that a chunk sits inside an open step — a once-per-lifecycle cost, not a per-step one.

Vocabulary: `turn/start`, `turn/end{reason}` (`completed | blocked | cancelled | error | max-tokens | max-steps | interrupted`; an `error` names its `code`, e.g. `DURABILITY_LOST`), `step/start`, `step/end`, `user/message`, `agent/options{options, reason: initial|change|resume}` (the BASE route and limits — below), `request/header{provider, model, reasoningEffort?, maxTokens?, temperature?, system, tools; reason: initial|change|resume}` (a header changing at the first step of a resumed lifecycle logs `reason:'resume'`; an unchanged header logs nothing, so the provider prefix cache survives restarts), `request/context{provider, model, contextWindow?, inputModalities?}` (the EFFECTIVE route, the window its adapter advertises, and what it can take as INPUT — below), `assistant/chunk{turn, step, attempt, chunk}` (trace: replay/UI fidelity, never derived; a retried step logs each attempt under its own `attempt`), `assistant/message{message, usage?, interrupted?}`, `tool/call`, `tool/result`, `inbox/spliced`, `approval/asked{id}`, `approval/decided{id, outcome}`, `approval/policy{policy, reason}`, `sandbox/mode{mode, enforcement, reason}` (§7), `authority/preset{name}` (§7 — log-only intent; the knob events that follow are the truth), `composition/applied{hash, layers, rows}` (§9 — log-only, written by the recorder only when it differs from the log's last; configs are hashed, never inlined), `llm/aux-call{purpose, provider, model, maxTokens?, inputSeqs?, usage?, outcome}` (§5 — log-only: a model call that is not a turn), `compaction/start{trigger, budgetTokens, projectedTokens, planned…}` / `compaction/applied{…, startSeq}` / `compaction/end{startSeq, outcome}` (§6 — log-only, one bracket per attempt; the surface `user/message` that follows an `applied` is the mutation), `subagent/start{callId, childId, depth, provider, model, sandbox, approval}` / `subagent/end{callId, childId, reason, usage?}` (§7 — log-only, in the PARENT's session; the child's own steps live in the child's log), `session/end-seed`. The header `{version, id, createdAt, cwd, parentId?, seedLength?, delegatedBy?, delegationDepth?, agentPreset?}` lives beside the log, not in it. `SESSION_FORMAT_VERSION = 0`; adding a field or a kind is additive and does not bump it (a stored log with a NEWER version refuses loudly at load and attach, since resuming it would rewrite its header to the current constant).

**The route is one durable fact, in two records.** `agent/options` is the BASE: what the agent runs from, written at creation (`initial`), by `Agent.configure` (`change`, effective at the next step) and by an override at resume (`resume`), folded by `findLast`. `request/context` is the EFFECTIVE route of the next request plus the window and the input modalities its adapter advertises, written by the driver before the step's `agent/pre-step` listeners and only when the WHOLE record differs from the last one — so a pressure check measures against the route the step will actually use, and every reader (compaction's budget, the terminal's `[ctx …]`, `sessions show`) learns the window from the log instead of from a live adapter. It sits OUTSIDE header equality (neither the window nor the modality set is model-visible), so a capacity change never forces a header snapshot. The gate compares the whole record rather than a named list of fields, because a field added to it would otherwise never be written on a resumed session whose route had not changed — and `inputModalities` absent MEANS text only, so that session would refuse its own images for the rest of its life and `sessions show` would explain it with the wrong reason. An adapter that cannot resolve a model records neither the window nor the modalities, and the next successful step rewrites the record rather than latching the route into "text only". The separation is what makes routing safe: a role rewriting `{provider, model}` on `agent/request` moves the header and the context record, never the base — so a resume rebuilds from the base rather than adopting whatever the last request happened to use.

**What a session opens with.** Agent creation, before publication, writes the session's opening facts: `agent/options{initial}` (the factory), `approval/policy{initial}` and `sandbox/mode{initial}` (each knob's own service, at `agent/created`) and `composition/applied` (the recorder). A resumed session whose log already says writes nothing; a log from before opening records existed gets them at pickup. A DELEGATED child opens differently: its creator stamps both knobs explicitly inside `setup` (`reason:'delegation'`), so the knob services find them already recorded and add nothing (§7). So a stored log always states what its session started under, and under whose authority, before its first effect.

**The durable inbox.** `inbox/spliced` is log-only, op-shaped — `{op:'insert', queue, message, waking?} | {op:'claim', steps, turns} | {op:'clear'}` — never positional: claim drains counts from the *front*, so the fold stays correct when a steer logged during the pre-step await lands before the deferred claim record. Discipline: inserts and clears log at mutation time; the claim record is committed *after* the entered `user/message`s (a crash inside the pre-step window re-delivers a prompt on resume — the accepted failure mode is a rare double-delivery, never a loss) or with the block/stop that consumed it; a disposed-cancel does **not** durably clear (graceful teardown preserves the queue for the next resume — a user/hook cancel does), and an empty clear logs nothing. `foldInbox(events)` reconstructs both queues; the driver restores them silently at attach. The vocabulary is merge-extensible: an unknown event type loads as an opaque log-only record and is skipped by derivation (a client applies the same default), while the three surface kinds are closed and session-owned — a plugin that needs durable state adds a log-only kind, never a surface kind. Changes to the vocabulary are additive.

**Arrival versus rewrite.** A `user/message` that ARRIVES (`surfaceOp: 'append'`) must sit inside an open turn: input is what a turn is made of. One that REPLACES a range is a surface rewrite, not input, and may land between turns — which is what makes `/compact` legal on an idle session. `Surface.apply` throws on a replace naming a node that is not live, in the fold as well as at append, because a reader folding a stream it did not write (a protocol client, a stored log) would otherwise render a plausible WRONG history instead of failing.

**Crash repair closes the surface, not just the logged calls.** The driver commits an assistant message with ALL its tool-call blocks and logs each `tool/call` only when that call's turn comes, so a crash during call *i* of *n* leaves calls *i+1..n* with no call event. `repairInterruptedTail` therefore answers every tool-call block of the open step's assistant message — `TOOL_OUTCOME_UNKNOWN` for a logged call, `TOOL_NOT_STARTED` for one never dispatched (the code the session invariant admits without a pending call) — cancels every approval asked in the open turn and never decided (the audit pair closes exactly once), then closes the step and the turn as `interrupted`. A resumed history is one every OpenAI-compatible wire accepts: an assistant `tool_calls` entry always has its tool message.

**Model-visible ⟺ logged.** Every request the loop sends equals `deriveMessages()` plus the folded `request/header` — every model-visible field outside `messages` (provider, model, system, tools, effort, maxTokens, temperature) is in the header, and adding one to `LlmRequest` means adding it to the header and its canon; a runtime invariant rebuilds both in the `llm/stream` preflight and fails on any divergence. Persistence is a subscriber, stored under `MINIDSH_HOME` (default `~/.minidsh`) as `sessions/<id>.jsonl` with the header as line 1. **A session materializes on its first conversation fact** (DSH's rule): publication takes the write lease and decides the write mode, but a fresh or forked session is written only when its first surface event lands (the snapshot then carries the header and everything so far), so a session that opened, recorded its stamps and was abandoned — every `chat` opened and closed — leaves nothing behind. A `resumed` session **attaches** to its existing file append-only at publication (an offset-tracking scan; a torn final line, the expected crash artifact, moves to a `<id>.jsonl.torn` sidecar in one append rather than being destroyed; corruption deeper than that marks the store `damaged` on read and refuses attach). Every later event appends through one file descriptor held per session (open+write+close per chunk cost ~1 ms each and ~110 s of loop blocking over a 400-turn session; a held descriptor costs ~20 µs), closed at disposal, on quarantine, and when the row unloads. `session/flush` is awaited at every durability checkpoint (§6), where a remembered write error is rethrown — and keeps being rethrown: a failed lease, attach, materialization or append leaves the session permanently un-persisted.

**Single writer per stored session.** Publication takes a `<id>.jsonl.lock` write **lease** (exclusive create; `{pid, host, acquiredAt}`) held until disposal, materialized or not, so a second process resuming the same id is refused before it appends a byte — two interleaved writers would collide seqs and truncate the log as damaged on the next read. A holder is stale only when it is provably dead on THIS host (`ESRCH`; `EPERM` counts as alive, a foreign host cannot be probed at all); everything else refuses naming the holder, degrading to a manual `rm` — never to two writers. Reclaiming a stale lock is the protocol's one two-step (remove, then create), so it runs under its own exclusive-create `.steal` mutex: without it, two reclaimers of one dead holder could both remove and both create, and both would hold the lease. Release removes a lock only after proving it still carries this archive's own payload, and unloading the provider row unwinds every lease and descriptor it holds. Attach compares the stored log against the seed the session actually resumed from (`liveStart`) plus a tail-identity check, so a foreign append landing in the read→publish gap is refused instead of silently adopted. Reads (`load`/`list`, `sessions show`) never lock; `list` reads a bounded header prefix, never a log. Because publication effects run in a contained emit, the loop factory flushes a **resumed** publication inside the creation transaction: a held lease, header mismatch, or damaged attach rejects `agents.resume` before any paid work, rolled back unannounced.

Prefix stability is a corollary, not a feature: because the log is append-only and the header is written only when it actually changes, consecutive requests are append-extensions of their predecessors. The Session 1 live run showed this directly — one `request/header` across seven steps, and 18,816 cache-read tokens against 3,372 uncached input tokens.

## 5. LLM vocabulary and the two adapters

`Message{id, role: system|user|assistant, content: ContentBlock[], source}` where a tool result is a user-role message with `source{kind:'tool', callId}` and an assistant message's source carries `{provider, model, replayState?}`. `ContentBlock = text | reasoning | image{attachment: AttachmentRef, text} | tool-call{id, name, arguments: string} | tool-result{toolCallId, content, isError?}`. The stream is a closed union `block-start | text-delta | reasoning-delta | tool-call-delta | block-end | usage | finish{reason, replayState?}` with `reason ∈ stop | tool-calls | max-tokens | aborted{failure} | error{failure}` and `LlmFailure{message, code, status?, retryAfterMs?, requestId?}` — codes, never message text, are what policies route on. Protocol invariants: usage before finish, exactly one finish, deltas only into open blocks. `TokenUsage` counts are DISJOINT — `inputTokens` is uncached input, and billed prompt is it plus `cacheReadTokens` plus `cacheWriteTokens`; `reasoningTokens` is informational inside `outputTokens`.

**Replay state.** A provider that signs its reasoning (Anthropic's thinking signature, an encrypted reasoning item) needs that state back verbatim or it refuses the next request. It travels as an opaque `ReplayEnvelope{response, blocks?}` on the terminal `finish`, where `blocks` aligns one entry with each opened content block: `BlockAssembler` prunes it in step with any block it drops (a `max-tokens` finish drops incomplete tool calls) and discards a misaligned envelope whole, because a signature attached to the wrong block is worse than none. The driver stores the pruned envelope on the assistant message's source, and `LlmRuntime` strips it from every message bound for a provider other than the one that produced it — inside the terminal continuation, after the reconstruction observer, so the log still records exactly what the model was shown. An adapter re-validates before trusting it.

`LlmRequest.purpose` joins `signal` and `sessionId` as a field the provider never sees: it says why a call is being made when it is NOT a loop step, and is therefore deliberately absent from `RequestHeader` — the canon covers MODEL-VISIBLE fields, and a header carrying `purpose` would claim the model saw something it did not. **A model call that is not a turn** (`core/llm/aux-call.ts`) is `runAuxCall`, which streams, assembles, and appends ONE log-only `llm/aux-call` carrying route, usage, and the answer — a failure recorded before it is thrown, so an abandoned summary explains itself. It writes no `assistant/chunk` on purpose: the replay script groups chunks by (turn, step), and chunks under a loop's numbering would corrupt it silently. It does not copy the request's messages either — they are already in the log, and `inputSeqs` names them.

A cancellation landing before the adapter is entered is normalized by the seam, not left to each adapter: `addEventListener('abort')` never fires on an already-aborted signal, so an adapter waiting on the event alone would hang the agent forever.

Adapters implement `stream(request)` and `resolveModel(model) → {contextWindow, defaultMaxTokens, reasoning:{efforts, defaultEffort?}, inputModalities?}`; effort ids are adapter-owned and opaque elsewhere, and a catalog is ADVISORY (an unlisted id is accepted under conservative defaults, never rejected on membership alone). `Llm.providers()` enriches each catalogued model with its window and modalities, so a surface can meter context from the same facts the runtime does without a second adapter method. **An option the provider cannot honour is refused BEFORE any I/O** — `UNSUPPORTED_OPTION`, `UNSUPPORTED_REASONING_EFFORT`, `UNSUPPORTED_CONTENT` — never dropped, aliased or clamped: the request the log records must be the request the provider served.

Two adapters ship, and the second is what proves the seam rather than describing it:

- **`llm-deepseek`** speaks the OpenAI-compatible `POST /chat/completions` with `stream: true`, `stream_options.include_usage`, `thinking` + `reasoning_effort` (refusing an effort outside `off|low|high|max`, which the provider would silently alias), keys tool-call fragments by wire index, defers block ends, usage and finish to the `[DONE]` sentinel, subtracts cache hits out of `prompt_tokens`, and always sends `reasoning_content` — empty when a turn had none, because in thinking mode with tools attached the provider refuses an assistant tool-call turn that omits it, and a turn another provider produced has none to give.
- **`llm-anthropic`** speaks the Messages API: named SSE events (`message_start` … `content_block_*` … `message_delta` … `message_stop`), thinking blocks that arrive with their text omitted and one `signature_delta`, tool input as `input_json_delta` fragments, usage split across uncached / cache-read / cache-created. Its catalog carries genuinely different facts — 1M windows and adaptive thinking (`output_config.effort`) for the 5 family, 200K and manual `budget_tokens` for Haiku 4.5, `temperature` refused where the API returns 400 — and its serializer rebuilds strict user/assistant turns with tool results first, echoing a signed thinking block only when this provider produced it and the envelope still holds its signature: a foreign or unsigned reasoning block is dropped, never forged.

**Images are a reference plus a descriptor, and the union's growth had to fail loud first.** An
`image` block carries an `AttachmentRef` and never bytes, plus `text`: the descriptor computed once
when the block is built. The descriptor is STORED rather than derived because it is what a route that
cannot take images is actually sent, so freezing it means a later change of wording cannot rewrite
what an old log says the model saw. `core/llm/content.ts` is the one block→text projection
(`blockText`, exhaustive with a `never` default), and `messageText` and both serializers go through
it: a probe against the tree before the variant landed showed that adding it changed nothing at six
separate sites — the meter scored it 0, both wires dropped it, and three surfaces rendered nothing —
and none of those sites was a `switch` the type checker would flag. An image is user- and tool-side
only: `validateStream` refuses an assistant stream that opens or ends one, and it lives there rather
than in `BlockAssembler` because the driver appends `assistant/chunk` and only then pushes to the
assembler, so a refusal there would arrive one line after the durable record it exists to prevent —
and would leave a log the replay oracle could never run.

**Refuse at admission; substitute at projection — both, not one.** A producer refuses to create an
image block when the STEP's route lacks `image` (absent modalities mean text only), before any
attachment or filesystem I/O, so nothing enters history the current route cannot take. An adapter
serializing an image for a model that cannot take it sends `block.text`, because durable history
outlives the model that first consumed it and a session that attached an image must stay usable after
a route change. The two rules cover different moments and neither replaces the other.

**Each adapter resolves refs itself**, per request, through `ctx.tryGet(ATTACHMENTS)` — the same shape
as its per-request credential read, and `tryGet` rather than `inject` so an adapter never REQUIRES a
store. Three outcomes, three answers: a text-only route gets the descriptor; an image-capable route
with no store mounted is `UNSUPPORTED_CONTENT` before any I/O; bytes that are missing or corrupt are
`ATTACHMENT_UNREADABLE`, deliberately not retryable — substituting the descriptor there would tell the
model it was shown a description while the log says it was shown an image. Order inside an adapter is
options first (no I/O), then the reads, then serialization, so a request about to be refused for an
illegal temperature never spends a disk read. Array-shaped wire content is emitted ONLY for a message
that actually holds an image; every image-free message keeps its exact string form, because widening
them all would rewrite the wire for turns serialized before the first image and cost both providers'
prefix cache for the rest of the session.

**An image costs real tokens, and the estimator says so.** `estimateImageTokens(w,h) = min(⌈w·h/750⌉, 1600)`,
measured against Anthropic's own `count_tokens` (96²→19, 512²→364, 1024²→1372, 2048²→1524 capped) and
the conservative side of DeepSeek's bucketed cost on the same images. A text-only route sends only the
descriptor while the meter still charges the image; that over-estimate is in the safe direction and is
recorded in §13.

Retry is a capability on `agent/request-error`, so failed attempts are durable.

## 6. The loop and the tool pipeline

```
followup(m) → next-turn FIFO (wakes)   steer(m) → next-step (wakes)   inject(m) → next-step (no wake)
turn/start
  claim → resolveCallConfig (agent/request) → request/context when changed
        → agent/pre-step (waterfall: reject | enter{messages})   reject ⇒ turn/end{blocked}
  step/start → user/message per entered message
  prompt.assemble → request/header when changed
  CHECKPOINT → llm.stream(frozen request) → assistant/chunk{attempt}* → assistant/message{usage}
       finish error ⇒ agent/request-error (waterfall) → retry (next attempt, same request) | turn/end{error}
  tool calls in model order: tool/call → CHECKPOINT → tools.execute → tool/result
       (cancel ⇒ ABORTED_BEFORE_DISPATCH results; a lost write ⇒ DURABILITY_LOST results, none run)
  step/end → next step while tools owe a request or next-step input exists (≤ maxSteps)
  agent/turn-stopping (serial) → re-read inbox
turn/end{reason} (exactly once) → session/flush → next turn or idle
```

**Durable before every action.** A CHECKPOINT is `session.flush()`: a provider that remembered losing a write says so there, and the turn ends as `turn/end{error, code:'DURABILITY_LOST'}` before the next paid request or tool effect — with every remaining call of the step answered and none of them run, the same shape as a cancellation, so the surface stays balanced for any reader. A lost write used to surface only at turn end, with every effect in between unrecorded. The checkpoint is a dispatch to one listener returning synchronously, so its cost is a microtask.

**The route is resolved once per step, before the pre-step listeners.** A step's `{provider, model, effort, …}` comes from `resolveCallConfig` — the base route through the `agent/request` waterfall — and its `request/context` is written immediately after, so a pressure check at `agent/pre-step` measures against the route and window THIS step will use rather than the last one's. The resolved config is then fixed for the step: every attempt of a retry, and a rebuild after a recovery changed the log, uses it, so a header and its context record can never describe different requests.

**Context management.** `core/metering` is the one definition of pressure, shared by the compaction trigger, the terminal and the CLI: a pure fold over facts the log already holds (a live session passes `facts`; the CLI passes a stored log). It prefers what the provider charged — `inputTokens + cacheReadTokens + cacheWriteTokens`, because `inputTokens` is cache-EXCLUSIVE by the vocabulary's own contract — plus that step's output, plus a ~4-chars/token estimate of every surface node appended since. Session cost totals additionally fold `llm/aux-call` usage, because a compaction summary replays a whole shadowed span and is usually the largest single request a session makes. A `replace`, or a `request/header` landing after the priced call, invalidates the anchor: the priced prefix then describes history or a prompt that is no longer sent, so the whole surface is re-estimated instead. Estimating low right after a compaction is the safe direction, because it cannot make compaction re-trigger on its own output.

The planner's cut must never leave the retained tail beginning with a `tool/result`, and it moves in BOTH directions to get there: forward frees more, but a turn made of tool steps ends `…assistant(tool-calls), tool/result`, so walking forward from inside that run reaches the end of the surface and would decline the compaction entirely — at exactly the step boundaries a tool-heavy turn needs it. When forward runs out it moves backward, and the tail starts at the assistant that owns those results.

Compaction has three ways in and one implementation (`capabilities/compaction-basic`): **pressure** on `agent/pre-step` — the only hook inside an open turn with no step open and no request built; **context-overflow** on `agent/request-error` for `CONTEXT_WINDOW_EXCEEDED`, answered with `{kind:'retry'}`; and **explicit** `compactNow`, from `session/compact` over the wire — deferred to the next step boundary when the agent is running, and drained at `agent/turn-stopping` so a request made during a turn's last step is still honoured. Its budget is the window the log names for the route the next step will use (`request/context`), or a configured `budgetTokens`; its summary goes through the same `resolveCallConfig` every call takes, carrying `purpose: 'compaction'`, so a model role may send it down a cheaper route and the `llm/aux-call` record names whichever route was used. **A summary at least as large as the span it would replace is refused**, in the same no-`await` window that measures it: applying it would pay for a call, hide real history behind a replace, and leave the surface bigger than it found it. It is reachable whenever the plan's head is small and the model answers a short span at length — a live S5 arc measured 4,545 against 4,314. The automatic triggers give up on a session after `maxSummaryFailures` consecutive summaries that produced no compaction — a call that failed, and equally one that came back too long: each attempt replays a whole shadowed span, so a summariser that keeps producing nothing usable would buy a full-budget request at every step forever. A summary lost to a race neither counts nor clears, because the call worked and nothing was learned about the summariser. `/compact` is a human asking again and is never disabled. The summary replays the shadowed conversation verbatim under the CURRENT system prompt and tool schemas, so the prefix is byte-identical to what the loop has been sending and the provider serves most of it from cache. It writes `llm/aux-call`, then `compaction/applied`, then ONE `user/message{source:{kind:'plugin', form:'summary'}, surfaceOp:{op:'replace'}}` citing every shadowed seq.

**Every attempt is bracketed, and the bracket is what makes an attempt explainable.** `compaction/start`
opens once a plan exists and BEFORE the paid call — never earlier, or a session under pressure with
nothing worth compacting would append a record at every step boundary forever — and `compaction/end`
closes it with `{startSeq, outcome}`, where a decline names one of a closed union:
`summary-failed | summary-empty | summary-not-smaller | turn-started | plan-stale | agent-gone | cancelled`.
`startSeq` is the correlation key, free because seqs are already unique and monotonic. This is what
lets `/compact` finally answer WHICH of "declined as too large", "lost its race" and "plan no longer
live" happened — on the idle path in its own result, and on the deferred path in the log, which every
surface now renders. **An orphaned start means the attempt did not close — a crash, a disposal, or a
fork boundary — not specifically a crash**: the `agent-gone` exit exists because the session is already
detached and its descriptor closed, so an end appended there would never reach disk. Crash repair does
not touch `compaction/*`, and the pairing rule reads one way only: an end requires a start.

**The give-up counter is a fold, not a counter.** `foldCompactionFailures(facts, liveStart)` walks back
to the first applied compaction or to this lifecycle's start, whichever is later, counting only the
three summariser-quality reasons and skipping the races entirely — "a summary lost to a race neither
counts nor clears" was always the rule and is now checkable. Both bounds are load-bearing: an applied
compaction is what clears the count, and `liveStart` is what keeps a two-strike counter from becoming
a latch nothing automatic can lift, since only an applied compaction clears it and the triggers that
could produce one are exactly what a give-up disabled. A resume therefore gets a fresh two attempts,
as the in-memory counter it replaces always gave it; what is new is that every attempt is durable.
`summarise` returns a REASON rather than `undefined` — it had four ways to return nothing, and a
cancellation landing in the seconds-long await arrived as the same value a failed summariser did,
which was harmless in a WeakMap a resume cleared and would be a lie in the log.

**No admission lock is needed, and the reason is a property the loop already has.** Upstream
serializes image admission with model selection on a per-agent chain, because a slow decode could
otherwise interleave with a route change that would have refused the image. MiniDSH resolves the route
ONCE per step and writes it before the step opens, and a switch takes effect at the NEXT step, so a
tool body's check-then-use cannot be raced inside its own step.

The hazard is the await, not the mutation. A summary call takes seconds, and a session can start a turn inside that window; a replace landing mid-step would leave the log claiming the model answered a history it never saw. Two answers, both required: an explicit compaction on a RUNNING agent is DEFERRED to the next step boundary rather than raced, and the plan is re-validated against the live surface (`planIsLive`) plus the agent's status in a window with **no `await` in it** — where the record's surface numbers are also measured from the LIVE surface, not from a plan made before the await. There is no durable lock bracket (DSH has one) because MiniDSH's mutation is a single append: a crash leaves an orphan log-only record and an unchanged surface.

The driver therefore builds its request per ATTEMPT, not per step. A recovery listener may legally change the log between attempts, and re-deriving `messages` keeps model-visible ⟺ logged true for every one of them; when nothing changed, the rebuild is identical.

**Spill.** Output too large to be conversation goes to `core/spill` — but only output with NO OTHER HOME. A shell command's stdout is gone when the process exits, so it is saved under `$MINIDSH_HOME/spill/` and the model gets a head/tail excerpt plus the path; a file the model asked to view is already on disk, so the viewer answers with a line range and copies nothing, which is also why the regress (reading a spill file spilling again) cannot start. The shell executor's cap is a MEMORY bound; what the model sees is the tool's decision, and it cannot make it from output the executor already discarded. Retrieval needs no new tool and no authority change: reads are never fenced, in any mode.

**Workspace instructions.** `AGENTS.md` (and `CLAUDE.md`) enter as a durable `user/message`, never a prompt section — sections must be stable within a session for prefix-cache safety, and a repository file is not the composition's to guarantee. Discovery is least-specific first (the home file, then project root down to cwd); identical siblings collapse; when the byte budget is tight, broad files are dropped whole before the nearest one is truncated. The guard against re-entry folds the LIVE SURFACE, not the log: shadowed events stay in the log forever, so a log-based guard would keep the house rules suppressed at exactly the moment a session got long enough to forget them. It enters only into a NON-EMPTY first-step batch, because the driver ends a turn as a natural stop when its first step enters zero messages.

`agent/status` is emitted only on real `idle ↔ running` transitions, after `whenIdle()` waiters are released; one `AbortController` per turn; `cancel(cause)` clears the inbox and aborts; `whenIdle()` is quiescence; dispose = cancel → whenIdle → unwind scope → detach agent → detach session. One `send()` never shares a turn with another. The driver promise is fire-and-forget and reports (`agent/error`, the logger) instead of rejecting unobserved.

Tool execution (every event in the acting agent's scope): validate args → `tools/pre-execute` (`allow | deny | ask`) → monotonic deny-only guards (globals, then the agent's) → `ask` → `approval.request`, anything but `allowed-once` denies → **deadline armed** → `tools/execute` (around-middleware over the body) → body → validate + freeze value → `render` → `tools/post-execute` (`accept{content?} | block{feedback}`) → normalized `ToolExecutionResult` → `tools/result`. Guards run BEFORE the ask: they are synchronous and consent-independent, so a call they would refuse anyway never interrupts a person or spends an `allowed-once` in the log. Every throw becomes an `isError` result with `Error: …` content and `{name, code}` — an error that names its own `code` keeps it, so a policy denial reads as `FS_SANDBOX_DENIED` in the durable record. Only `{name, description, parameters}` of a tool ever reaches the model.

**Deadlines are the pipeline's, not a plugin's.** `ToolDefinition.timeoutMs` declares a budget (omitted takes the registry default, `null` opts out) and the registry enforces it, because the kernel waterfall passes `next()` no arguments — a `tools/execute` middleware cannot substitute the signal the body will see. The clock starts *after* the gate, so a human deliberating over an approval taken at the gate never spends a tool's budget. Consent taken INSIDE a body is different: the registry clock cannot see it, so a body that asks (the shell's escalation) must own its whole deadline — the shell tool declares `timeoutMs: null` and its executor kills the child and returns the tail on its own budget, while the consent itself waits on `ToolExecution.callSignal`, the caller's cancellation without any deadline. A body with a registry deadline that runs out ends as `TOOL_TIMEOUT` with its signal aborted so it can release what it holds, and a late result is discarded.

## 7. Authority

The model proposes, policy decides, the effect boundary enforces, and every decision is a fact in the log. Authority is one plane with four parts.

**One stamp.** `SandboxExecutionPolicy{mode, workspaceRoot}` is resolved per call from `ctx.sandbox`, never assembled by a caller, and shared by every execution world. The mode vocabulary is `read-only | workspace-write | danger-full-access` and governs FILE EFFECTS only — network and process visibility are outside it, so these modes are not a general-purpose security boundary. The workspace boundary needs no event of its own: the immutable `SessionHeader.cwd` recorded at creation IS the root for every call in that session — which is why the wire may not choose it freely (§8). `writableRoots(policy)` is the one allow-list both families derive from, so no two worlds can disagree about what `workspace-write` means. Precedence: an approved one-shot escalation > the session's folded `sandbox/mode` > the composition default.

**Enforcement lives at the effect, not at the gate.** `fs-local` fences `writeText` in process: canonicalize, contain, refuse with `FS_SANDBOX_DENIED` before ANY effect (creating a parent directory is already one), then canonicalize and contain again immediately before the write, because only the last check governs it. Canonicalization decides existence with `lstat` and follows links itself, including DANGLING ones that `existsSync` and `realpathSync` both miss but that the `open()` a write performs does not — the path the fence contains must be the path the effect lands on. A path whose identity the host will not disclose is refused, never trusted by its spelling. It is a check in trusted code over a model-controlled path — the operations are the seam's own and only the target is untrusted, so canonicalize-then-contain is the complete answer for that surface, with one stated edge: a HARD link has no link to follow, so a pre-existing in-workspace name sharing its inode with an outside file passes (the model cannot create one under `workspace-write`). Reads always pass. Because the fence is inside the provider, no tool can be the boundary and no tool needs to know about one; there is no policy plugin at `tools/pre-execute` at all (that seam remains for operators and hooks).

**Kernel-grade isolation of untrusted CODE is the shell's problem, and MiniDSH has no backend for it.** `shell-stdio` enforces nothing, says so through `enforcementFor(mode) → 'none'`, and REFUSES a confined policy with `SANDBOX_UNAVAILABLE` rather than running unconfined: silent passthrough is never legal for a mode the host cannot deliver. The executor never negotiates. The refusal is a reported fact, not a tool failure, and it carries the one legitimate move: the model may retry the SAME command once with `sandbox_permissions` (strictly wider, and only a mode this host could actually run under — consent is never spent on an escalation that would be refused anyway) and a `justification`, `ctx.approval` is the consent step, and the grant covers that one call — it is never recorded as a session switch, so the audit reads it as the `approval/asked{callId}` → `tool/call{callId}` join it is.

**Every decision is durable, and every session says what it opened with.** `sandbox/mode{mode, enforcement, reason}` and `approval/policy{policy, reason}` are log-only, folded by `findLast`, and written by the same discipline for both knobs: the OPENING value at agent creation (`open`, reason `initial`, before publication), a change only when it changes (`setMode`/`setPolicy`, reason `change`), and for the sandbox a `resume` stamp when a resumed session's host enforces differently. `resolve()` still records as a safety net for a session created outside the registry, and `approval.request` records the governing policy before deciding if nothing is recorded yet. A switch IS its event; nothing mutates authority out of band, and a resumed session keeps what it recorded rather than inheriting the deployment default. `enforcement` on the stamp is what the SHELL world reports — the fs fence is in-process and always complete, so it has nothing to report. `ApprovalPolicy` is `ask | never`, and `never` decides `rejected` inside the service before dispatch, so an answerer composed later cannot reopen the gate. The audit pair `approval/asked`/`approval/decided` is logged with a durable id a remote answerer echoes back, cancellation is owned by the seam, an ask left undecided by a crash is closed `cancelled` on resume, and `approval-headless` answers `allowed-once` only under `--approve` — otherwise the fail-closed `unavailable` stands. `minidsh sessions show <id> --audit` projects the whole plane back out of any stored log, opening rows first.

**A fork carries the fence with it.** A boundary that would cut below a delegated session's opening stamps is refused: the header would still call the result a child while its authority re-opened at the deployment default, possibly wider than what it was delegated under.

**A delegated child opens under a ceiling.** A child agent (§6, `capabilities/tool-subagent`) is created with its parent's authority captured BEFORE the first await — a parent that widens itself afterwards widened it for its own future, not for this child — and both knobs are stamped explicitly inside `setup`, before publication, as the child's first `sandbox/mode` and `approval/policy` with `reason: 'delegation'`. That first stamp is a CEILING, and three mechanisms hold it: approvals are pinned `never`, which the approval service enforces before dispatch, so every escalation the child asks for is refused without any answerer being consulted; `setMode`, `setPolicy` and the escalation path through `resolve({mode})` refuse to widen past it (`SANDBOX_CEILING`, `APPROVAL_PINNED`); and the authority invariant rejects a widening stamp pre-commit, so nothing that got past a setter could enter the log either. A `delegation` reason is only ever a knob's FIRST stamp. Narrowing stays legal — a child may fence itself further, and a delegation ROW may narrow it too (`tool-subagent`'s `sandbox` config, applied through `narrowest` where the authority is captured, so `subagent/start` records the mode the child actually opens under rather than the parent's; the parent's audit line is where a human looks first and must not overstate). Widening is not expressible. The ceiling is durable, so a resumed child comes back under it. This is stricter than DSH, whose pin alone enforces (§12).

**Presets select, the knobs decide.** `core/presets` + the `authority-presets` capability are one product-facing selector over the pair: `apply(session, name)` validates, appends the log-only `authority/preset{name}` intent, then writes through `setMode`/`setPolicy` — their change-gating, model-visible note, and closed reason vocabularies stand untouched, and the knob events remain the truth every reader folds. The current preset is **derived** (`presetFor` over the two folds): `custom` is what a non-matching pair displays as, reserved as a table key, never a switch target, never an event payload. The shipped table is two entries — `workspace-write` = workspace-write + ask, `danger-full-access` = danger-full-access + never (`read-only` stays a legal mode no preset selects) — replaceable wholesale from the composition row's config. That pair is upstream's PACKAGE default; what upstream actually ships is its bundle's own composition, which configures the permission stack differently, so this is MiniDSH's choice of a sensible default rather than a copy of a deployment. There is no `defaultPreset`: the deployment default already lives on the sandbox/approval row configs, and a second default would be a second source of truth. Surfaces: `--preset` (pre-boot validated against the *effective* presets row, exclusive with `--sandbox`/`--ask`, refused on commands that cannot apply it), the terminal's `/preset`, and `session/authority {preset}` on the wire, with a derived `preset` field on every `AuthorityView`.

**Consent-by-composition.** A per-agent preset (§9) mounts plugins on the agent scope, and `approval/request` dispatches in the asking agent's scope — so a preset-mounted answerer CAN auto-approve for its own agent (and only its own; a scope never hears another scope's subject). That is not a bypass: whoever writes the composition already holds code-equivalent trust, and the audit still records every asked/decided pair. What a preset structurally CANNOT do is widen enforcement — a `SANDBOX` provided in the scope shadows only scope-mounted plugins, while the fs fence and the shell resolve the global one through their own contexts (asserted by test) — nor reach a deployment-global registry (§2).

The `core-authority` invariant rejects a forged `sandbox/mode` or `approval/policy` before it enters the log, holds every approval to exactly one decision, and holds a delegated session to its ceiling and its pin; the presets capability registers its own invariant (the first capability-owned one) rejecting an `authority/preset` that names no table entry — and `apply` validates on its own, so the refusal stands even where invariants are off.

## 8. Surfaces

A surface is a plugin (or app entry) that injects only `agents` and `sessions` — plus `llm` for the catalog handshake and `sandbox`/`approval` for the authority control plane — owns transport and process exit, and renders from `session/event`. It holds no authority state of its own: a switch it asks for becomes a durable event it then reads back like any other. Every plain-text surface renders through ONE projection, `app/present.ts` (`describeEvent`, `transcriptLines`, `auditLines`), which reads payloads through `matches()` — two drifted copies of that projection once printed `~NaNk → ~NaNk` for a compaction. The browser renders structured DOM per event type instead; that is a different projection, not a second copy of this one, and it duplicates no fold. Both render an image block's descriptor on the `tool/result` that carries it — the only place an image appears, since nothing yet puts one in a `user/message` — and both render the compaction bracket, because a decline's reason is otherwise durable in the log and visible nowhere, reaching only whichever client happened to hold the `session/compact` RPC while every AUTOMATIC decline has no RPC at all. Three surfaces share the one runtime:

- **The headless CLI**: `minidsh run "<task>"`, `minidsh resume <id> "<task>" --headless`, `minidsh fork <id> "<task>" [--at seq] --headless` — boot → `settle()` → `agents.create/resume/fork` → `followup` → `whenIdle` → `flush` → last assistant text on stdout, exit 0 iff the turn completed. Every command boots through one preamble (`prepareBoot`: flags, settings, disk layers, `--preset`, `--agent-preset`), so `config`, `--preset` validation and `sessions` compose the exact rows a boot mounts. `--json` streams `{sessionId, event}` frames (`SessionEventFrame`, defined once beside the vocabulary); `--sandbox <mode>` / `--ask <ask|never>` / `--preset <name>` set this run's authority (explicitly given, they are applied as a durable switch, so they also govern a resumed session that recorded something else; `--preset` is exclusive with the pair and validated pre-boot); `--patch <file>` (repeatable) layers over the composition and `--agent-preset <name>` composes the agent's world (§9); `minidsh config [--json]` prints the *effective* composition with per-row provenance, flagging authority-sensitive rows a layer changed — the authority rows, the invariants, and the effect-boundary rows (`fs`, `shell`, the tools, `spill`) a layer could replace with an unfenced provider — and parses every enabled row's config against its plugin contract, so what a boot would refuse `config` refuses too (exit 1, naming the row and the key); `minidsh sessions list/show` read through the persistence Definition on a bare composition, and `sessions show <id> --audit` projects the authority timeline (preset intents included).
- **The client protocol** (`capabilities/protocol`): JSON-RPC 2.0, DSH's SDK-protocol shape — newline-delimited on a stream carrier, one text message per frame on a socket. Requests `initialize {} → {serverInfo, providers (Llm.providers()), defaultAgentOptions, defaultAuthority, workspaceRoots}`, `session/model {sessionId, provider?, model?, reasoningEffort?} → AgentOptions` (no fields reads the base route; each given field is merged over it as one durable `agent/options{change}`, effective at the next step; a provider this host has no adapter for is refused before it can become a fact), `session/prompt {sessionId?, text, mode?: followup|steer|auto, agentOptions?, cwd?, workspaceId?, path?} → {sessionId, messageId}` (absent id creates; live id delivers — with `agentOptions` applied as that same durable switch; stored id resumes — an in-flight table makes racing prompts share one resume; **`cwd` must be an absolute, existing directory inside the host's `workspaceRoots`**, else `INVALID_PARAMS`: the cwd becomes the immutable sandbox workspace root, so the wire may choose WHERE inside the host's policy, never the policy — `serve --cwd` is the default root. `workspaceId`, with an optional relative `path`, names that place instead and is exclusive with `cwd`; all three are REFUSED alongside a `sessionId`, because where a session works is decided once, at creation. The RESOLVED route is checked for an adapter, not just the caller's overrides — the defaults half of it comes from the settings store, which a remote client can write), `session/attach {sessionId, limit?} → {header, view, page, cursor, damaged?}` and `session/page {sessionId, throughSeq, beforeSeq?, limit?} → {page}` (the attach contract — below), `session/detach {sessionId?}` (no id narrows to NOTHING — a surface that renders one session at a time says so, instead of counting as a candidate answerer for every approval on the host), `sessions/list {workspaceId?} → {sessions}` (live and stored, newest first — a browser has no other way to find one), `settings/describe` / `settings/get {ns}` / `settings/set {ns, patch, expectedRevision, replace?}` (§9), `session/events {sessionId, fromSeq?, toSeq?, limit?, omitTrace?}` (the raw archival read, every tier, defaults unchanged; bounded at both ends it is the gap repair), `session/cancel {sessionId, keepQueued?}` (`keepQueued` leaves the durable inbox alone — one client's cancel is not licence to discard another's queued prompts; the default stays the single-client meaning), `session/compact {sessionId} → {kind: compacted{shadowedNodes, surfaceTokensBefore, surfaceTokensAfter} | scheduled | nothing-to-do}` (a HUMAN command — compaction is deliberately not a model-facing tool; `scheduled` means the agent was mid-turn and it will run at the next step boundary), `approval/answer {sessionId, id, outcome} → accepted|not-pending`, `session/authority {sessionId, sandbox?, approval?, preset?} → {sandbox, approval, enforcement, preset?}` (no arguments reads; each switch IS its durable event; `preset` is exclusive with the pair, read per-request via `tryGet` so a composition without the row simply omits the derived field), `shutdown` (dispose-to-idle: owned turns close as `cancelled` and flush; durable queues survive for the next resume). Notifications `session.event {sessionId, event}`, `session.status {sessionId, status}`, `session.view {sessionId, view}` and `settings.changed {ns, revision}`. Malformed frames are ignored, unknown methods answer `-32601`, stdout is reserved for frames, host logs go to stderr. **One plugin, ONE host, N carriers** — `carriers` on the row's config: `minidsh serve` mounts a stream carrier on real process stdio; the terminal mounts the identical plugin on an in-process duplex pair; `minidsh web` mounts a WebSocket one. Same frames, same semantics, no shared objects, and one ownership plane behind them. Agents created over the wire are owned by the plugin's context; the config (`cwd`, `workspaceRoots`, `workspaces`, `defaultAgentOptions`, `setup` — the per-agent world applied to every agent this surface creates or resumes — and `onClose`) keeps process exit and composition in the app.
- **The attach contract.** A 400-turn session is ~103k events and 17 MB of JSON; serving it in one frame costs ~322 ms of `JSON.stringify` on the host's event loop, and the loopback terminal paid it too. `session/attach` answers with the header, a **message-aligned tail page**, the **cursor** it was cut against, and a `SessionView`; `session/page` walks backwards beneath that cut. The alignment rule: walking back, only `user/message` and `assistant/message` that ARRIVED (`surfaceOp: 'append'`) spend the budget — a `tool/result` is a surface event and not a message, and a compaction summary is not an arrival — and the cut is pulled back to the budget-spending message's own `min(seq, ...sourceEventSeqs)`, so a message is never split from what produced it. A replacement's citations are deliberately NOT honoured: a summary cites every node it shadowed, and dragging those in would defeat paging on exactly the sessions that need it. Two ceilings the wire enforces: a client-supplied `limit` is clamped, and an event ceiling bounds a page beside the message budget. The ceiling cuts at a message-group boundary where one has been walked, and at the current event's own group start where none has — a range holding no ARRIVED message (a stretch of log-only facts, a tail of nothing but tool results) otherwise had no legal cut anywhere and the whole log came back, ceiling or not. **Pages never carry the trace tier**, so `Session.facts` IS the page source; that is what turns 17 MB into ~58 KB, and it is also what makes a bare seq a sufficient dedup key. `throughSeq` is a postcondition, not a hint — a page anchored past the cursor is refused, because it would interleave with the live tail while the log grows. There is **no lower-bound cursor**, by design: a reconnecting client re-attaches and replaces its window; a hole inside one connection is repaired with `session/events` bounded at both ends. Attach subscribes the connection BEFORE the page is cut, and the client drops anything at or below the cursor, so an overlap is free and a gap is not. A cold read never resumes the session: opening a transcript to look at it must not start an agent, take its lease, or change what is being looked at. Cold sources are kept parsed in a small LRU, because a cold read is a whole-file parse (~167 ms, ~28 MB) and backward paging asks again.
- **`SessionView`** is the live control plane widened to exactly what a client holding one PAGE cannot fold for itself: `{status, context?, pendingApprovals, authority, options?, route?}`. Each field is a projection of durable facts computed by whoever already owns that fold — with one liveness rule: `pendingApprovals` is empty for a session read COLD, because a cold read never resumes, so `repairInterruptedTail` has not closed its undecided asks and a crash artifact would otherwise be offered to a browser as a live Allow/Deny for a question nothing is waiting on (`core/metering`, the approval pair, the authority folds, `agent/options`, `request/context`); `session.view` re-publishes it whenever a durable fact moves one. **No surface node list crosses the wire, because no client folds the surface** — `foldSurfaceSeqs` on a tail slice throws by design, and after one compaction the node order is not seq order, so a client that tried would render a plausible wrong history. Neither shipped client needs it: both render the log in seq order.
- **Multi-client.** The host is per-DEPLOYMENT; a `ClientConnection` owns only its frame sink and its watch set. A fresh connection receives every session and narrows on its first `session/attach` — a `session/detach` naming one session narrows an un-narrowed client to NOTHING, because a set of attached ids cannot express "everything except this". A disconnect disposes nothing — a browser refresh reattaches to a running agent. `shutdown` is host-wide and therefore carrier-gated: stdio and the loopback pair keep it, a socket does not. Approvals are broadcast (the durable `approval/asked` IS the frame) and the first answer wins across clients. Who could answer is recomputed from the LIVE connections after every watch-set change — an attach as much as a detach or a disconnect — and a question no connected client can see any more is settled `unavailable`. Snapshotting the answerers when the question was asked was wrong in both directions: a client that arrived afterwards was never counted, though the attach frame shows it the question and it can answer; and a client that narrowed away stayed the sole answerer for a session it no longer received, parking the agent on something nobody would ever be shown. `session/prompt` gains `mode: 'auto'`, resolved by the host against the live agent in the tick it delivers — a client choosing steer-vs-followup from an observed status cannot win that race with two clients.
- **A delegated child is its parent's while the parent is running it.** One predicate — the header names a `delegatedBy` that is still live, and this host did not itself resume the child — carries two rules. The child is READ-ONLY over the wire: `session/prompt`, `session/cancel`, `session/compact` and the SWITCHING forms of `session/model` and `session/authority` are refused naming the parent (their argument-less read forms are not — the refusal is about driving, and an error saying "it can be read" must not answer a read), because the answer a delegation returns is whatever the child last said, so a prompt from a surface does not add a turn, it silently becomes the answer to a task it never saw. And its stream reaches only a client that attached to it by name, never every un-narrowed client: a client attached to the PARENT sees the delegation as the parent's own log tells it, through `subagent/start` and `subagent/end`. Reads stay open throughout — `sessions/list` shows a child with its lineage, and attaching to one is how a human watches it. A child this host RESUMED is the host's to drive, which is how a surface reaches a finished one; its authority is still fenced by the ceiling its log records.
- **A client repairs a hole in pages too.** A gap read is bounded at both ends AND limited, looping until it catches up: a repair that asked for everything from its cursor would undo the paging the rest of the surface is built on. A client that has not attached yet applies nothing — the page it is about to receive already contains those events.
- **Backpressure is tier-aware, and it is a MiniDSH invention.** `session/event` is a synchronous contained emit, so a listener cannot suspend the loop the way a pull-based pump could; the choice is an unbounded buffer or a drop policy, and the three tiers are what make a drop policy statable. Over a per-connection soft limit the TRACE tier is dropped (`assistant/message` carries the same text durably a moment later); facts and surface events are never dropped, and past a hard limit the socket is closed as `slow-client` so the client reattaches to a fresh page. Liveness is a WebSocket ping; there are no host-side per-method deadlines.
- **The interactive terminal** (`app/terminal`): a protocol *client* — streaming render straight from durable `assistant/chunk` text deltas, every other line from the shared projection, typed input steers a running turn, `y/N` answers approval frames (and says so when an answer lands on a prompt nothing is waiting on), `/sandbox` and `/ask` switch authority over the wire, `/compact` shrinks context, Ctrl+C cancels then exits. It shows context pressure as `[ctx 34% · 12.4k/32k]` and `/model [<provider>/]<model> [effort]` switches the route over the wire. **It retains nothing of the session**: the meter arrives in `session.view`, because a client holding one page cannot fold it, and a second copy of that projection is exactly what once printed `~NaNk → ~NaNk`. The denominator is the window the session's own `request/context` names (the catalog's answer until the first one lands), so a mid-session switch to a smaller model immediately meters against the smaller window; a deployment's own `budgetTokens` is policy the wire does not carry, so the line answers "how full is the window" and the `[compacted …]` line answers "and the runtime acted". Attaching to a stored session (`minidsh chat` / `resume` / `fork` interactive) is prepared host-side by the app assembly; the client then drives the live session over the wire and renders a `session/attach` PAGE first — a session that fits in one renders exactly as it always did, a longer one prints `… N earlier events` and `/history` pages back, instead of dumping megabytes into a terminal.
- **The browser** (`minidsh web`, `app/web.ts` + `app/web/`): the same protocol over a WebSocket, plus a static client of plain hand-written ES modules — there is no build step, so no TypeScript and no bundler reaches the browser. It renders structured DOM per event type (its own projection, duplicating no fold), lists sessions and workspaces, pages backwards, streams, prompts, answers approvals, switches authority and route, compacts, and edits settings. **It is an authority surface** — a client there can write files and run commands — so it binds loopback unless `--host` says otherwise, and `GET /?token=…` exchanges the one-shot launch token printed on stdout for a signed HttpOnly SameSite=Strict cookie before redirecting to a clean `/`; every later request and the upgrade check that cookie behind a Host/Origin fence. The token is spent by the first exchange that succeeds, so a URL left in a shell history is not a standing credential; the cookie it mints is bound to the authority it was minted for. The Host allow-list is built from what was actually bound — and a WILDCARD bind has no authority of its own, so there the fence falls back to "an Origin must match the Host it was sent to", which is the strongest check still meaningful when the host does not know its own names. There is no per-user identity and none is implied: many windows, one principal.

**The log is the interchange format.** A surface, in-process or remote, consumes durable events — on the wire, `{sessionId, event}` verbatim, with core types reaching the client as type-only imports — plus the small live control plane the protocol owns: the status projection, approval answers, cancel/steer. **Approval frames are the durable events**: `approval/asked`/`approval/decided` streaming over `session.event` are the answerable frames, keyed by the durable id; the protocol holds a pending table (first answer wins, disposal fails pending prompts closed, no client ⇒ delegate down the waterfall). There is no DTO layer, no protocol version until a client ships independently of the host, and clients ignore unknown event types. Presentation (`presentCall`) is computed host-side by whoever holds the tool registry; no card is rendered yet, so it still has no caller. Because every durable payload is frozen JSON at append, no in-process object can ever reach a wire.

## 9. Composition and configuration

What MiniDSH *is* is data: the built-in rows plus declarative layers on disk, one algorithm, one record. Four planes stay distinct — **composition** (which plugins, their config), **settings** (user defaults over app assembly), **credentials** (named secrets), **authority** (never configuration: recorded events beat composition defaults by fold precedence, always).

**Home layout** (`MINIDSH_HOME`, default `~/.minidsh`): `sessions/*.jsonl(.torn|.lock)` · `spill/<session>/*.txt` (oversized tool output; bytes never enter the log) · `attachments/v1/objects/<xx>/<sha256>` (image bytes, content-addressed, extension-less and with no sidecar — the LOG is the metadata store) · `composition.json` · `settings.json(.lock|.writing)` (the only file the runtime WRITES, and only through the settings store) · `credentials.json` · `AGENTS.md` (the user's global instructions — model-facing context, never configuration). Paths resolve in `app/home.ts` only (`homeLayout()`, one value per command) and travel down as plugin config (check-deps: nothing below `app` may import the home; ambient `process.env`/`cwd` reads below `app` are by convention reviewed, not gated). No `logs/` until something writes logs.

**Composition.** `Row{id, plugin, config?, disabled?}`; `Patch = {id, config?|disabled?} | {insert: Row[]}`; `applyPatches` replaces a row's whole config, warns and skips unknown ids, appends inserts. `applyLayers` runs it once per named layer, records per-row provenance (a row is marked by a layer only when the patch CHANGED it — restating a row is not a touch), and refuses duplicate ids (a duplicate is half-patchable). Layer order is fixed: **built-ins** (`compose()`, plus rows a surface contributes to the base — serve's protocol row, so a disk patch can target it; disabling it, or replacing the config that carries this surface's live streams, is refused rather than serving a dead socket) → the programmatic **app** layer (`BootOptions.patches`) → **home** `composition.json` → repeatable **`--patch` files**. Direct flags are NOT a final layer: `--sandbox`/`--ask`/`--approve` are inputs to `compose()`, so they live in the built-in base and a disk layer can override them. What makes an explicit authority flag win on `run`/`resume`/`fork` is a different mechanism — `applyAuthority` writes it as a durable per-session switch after creation (§7) — and `serve` and a fresh `chat` do not do that, so there the flag is a composition default like any other. On disk a row's `plugin` is a string: a builtin catalog name (`builtinPlugins`, every shipped plugin by kernel name; the protocol plugin deliberately absent — its config carries live streams — and the composition recorder, which the boot alone may mount), else a module specifier resolved against the file's directory and imported (Node type-strips out-of-repo `.ts`; the module exports exactly one plugin; authors use erasable syntax and import repo modules by absolute `file://` URL). **Every shipped plugin with a config declares its contract** (§2 `Plugin.config`, a strict zod schema over the closed vocabularies), so a typo'd `{mode: "full"}` on the sandbox row or a stale key after a rename fails boot as `<plugin>: invalid config: <key>` instead of settling green. **composition.json is code-equivalent trust** — it loads and runs modules — and it is an input, never a persistence target. There is deliberately no workspace-level layer: a repo-controlled file that could reconfigure the sandbox row is a trust decision deferred. Upstream is a caution here, not a precedent — its trust markers grade AGENT PRESET roots, not repo config, while it does ship repo-controlled tiers (a skill root table where project roots outrank user roots, and hooks that execute shell with no approval gate). It fences that with an explicit rule instead: its own `DSH_*` namespace is denied to project-discovered configuration, with no opt-out. The home layer may patch even authority-sensitive rows — it IS the deployment — but never silently: `minidsh config` flags them by row id **and by capability** (a layer's `insert` picks its own id, so an inserted `approval-headless{approve:true}` — blanket consent — is flagged by its plugin name), and a session's recorded authority still beats any widened default on resume (regression-pinned).

**The composition record.** Every boot appends a `composition-record` row *outside* the layers (its config is the descriptor OF the effective rows — no layer can remove the record of what the layers did). On agent creation, pre-publication, it appends log-only `composition/applied{hash, layers, rows:[{id, plugin, disabled?}]}` iff it differs from the log's `findLast` — the `request/header` discipline, so a resume under an unchanged composition logs nothing and a fork inherits its parent's stamp. Configs are hashed (canonical key order, sha256/16), never inlined; a config that cannot snapshot to JSON hashes by presence, so per-boot closures don't churn the hash. A surface's own rows (serve's protocol row) and per-run flags are part of the effective composition, so a session resumed under a different surface legitimately re-stamps.

**Runtime recomposition.** `mount()` returns the `Composition` handle (provided on the root as an app-only service): `insert` (duplicate ids refused, settled awaited — a bad config fails the call, not a silent dead row), `remove` (the kernel cascade parks dependents pending), `reconfigure` (validate the new config against the row's contract FIRST, then dispose and remount — a rejected edit keeps the last good instance running; the kernel reloads on provider change, not config change, so a fresh instance IS the mechanism). Row changes are serialized (two overlapping changes to one id would each mount an instance; the loser's `provide` throws `SERVICE_DUPLICATE` while its live twin keeps its registrations). A fixed spine set `{session, llm, tools, prompt, agent, loop, persistence}` refuses removal/reconfiguration while agents are live, naming them — the runtime half of "what a layer must not override". `persistence` is in it for a sharper reason than the rest: its per-session state, leases and descriptors die with the plugin instance, so swapping it under a live session would stop durable writes.

**Agent presets.** `composition.json` may declare `agentPresets: {name: DiskRow[]}` — named per-agent worlds mounted on the agent scope during creation (`--agent-preset` on run/chat/resume/fork/serve; `ProtocolConfig.setup` for agents the wire creates). Registrations and services live and die with the agent (§2 scope contract); the factory's scoped fail-loud settle gates unmet deps and bad configs; the enforcement boundary holds structurally (§7 consent-by-composition), and a preset row that reaches into a deployment-global registry fails its agent's setup. Wire-level preset selection is deferred until a client needs it.

**Settings.** `settings.json` `{agent: {provider?, model?, reasoningEffort?, maxSteps?, maxTokens?, temperature?}, revisions?}`, zod-validated, resolved ONCE at process entry with fixed precedence flags → `MINIDSH_MODEL` → file → the pure built-ins (`defaultAgentOptions()` is env-free), then passed down as `BootOptions.agentDefaults`. On resume it sits in the *defaults* tier: the log's folded `request/header` wins, so a settings edit can never rewrite what a session recorded (regression-pinned). A per-session route is not settings either: `agent/options` is a durable session fact a surface switches through `session/model`, and settings only seed what a NEW agent starts from.

**Settings at runtime (`core/settings` + `settings-local`).** The Definition exists because a remote WRITER now does; a value passed down at boot is all a CLI ever needed. Which namespaces exist is app assembly — the boot claims `agent`, with the PURE BUILT-INS as its `base`, because the store re-applies `settings.json` as its own user layer and a base with that file already merged in would apply it twice. What outranks the store (`MINIDSH_MODEL`) cannot be expressed by two layers at all — a user layer always beats its base — so it travels separately and is applied above whatever the store resolves, through the same `mergeAgentOptions` every other switch takes. The store owns the document: every write re-reads it inside a lock (so the echoed revision is checked against what is on disk NOW, and a second process editing the same file is noticed rather than clobbered), validates the MERGED value against the owner's schema before persisting (a rejected edit changes nothing), and replaces the file by rename (a crash leaves the old document, never half a new one). `initialize.defaultAgentOptions` and the create path read the store LIVE where one is mounted, so editing the default edits what the next session gets. The model-role table stays a capability row's config, not settings: composition is hashed into each session's record, so a session says what world it ran in.

**What accumulates, and what may ever remove it.** One rule decides all three stores: **content is
never swept; an affordance may expire.** An attachment is content — a log names it as something the
model saw — and it is content-addressed and shared across resumes and forks, so a per-session cascade
would delete bytes another session still references. A session log, parent or child, is content AND
the only script its arc replays from; deleting one needs an authority above the append-only seam, and
this system does not have one, so nothing here infers deletion from disposal or detach. A spill file
is an affordance — the log names it as a place to look, and the excerpt beside it is already the truth
of what the model saw — so it is the one store a sweep may touch, and that sweep is not built yet.
When it is, it must be age-based and per-file (a fork inherits locators, so lifecycle scoping is
wrong), shape-matched to names its own writer generated, `lstat` so a link is never followed, and
never a recursive directory delete — on Windows it gets no ownership guard at all, so the shape match
is the whole defence. The table exists so the next store added is a visible omission rather than a
silent one:

| store | class | lifetime |
|---|---|---|
| `sessions/` (including delegated children) | content, and the replay oracle | never removed by the harness |
| `attachments/v1/objects/` | content, shared by address | never removed |
| `spill/<session>/` | affordance | age-swept (designed, not built) |

The shipped authority default is `workspace-write` + `ask`: the filesystem is genuinely fenced and the shell must be escalated, which is the boundary, not an inconvenience to route around. Environment: `DEEPSEEK_API_KEY` (a credential *reference* resolved through `ctx.credentials`), `DEEPSEEK_BASE_URL` (the adapter's own), `MINIDSH_HOME`, `MINIDSH_MODEL`.

## 10. Verification

Tests mount real compositions through the kernel; only the model is scripted (`test-support/scripted-adapter`) or replayed from a recorded session log (`test-support/llm-replay`, which derives the script from `assistant/chunk` groups per (turn, step), drops finish-less groups — a crash mid-stream the agent never acted on — and asserts every recorded call was consumed. It replays EVERY terminally-finished attempt by default, failures included, because a recovery that changed the log must happen again: eliding an overflow would leave the replayed session with a history the recording never had (`acted-on` mode stays for a composition with no recovery listeners). A second cursor serves out-of-loop calls from their `llm/aux-call` records, keyed by `request.purpose` and refusing to serve one purpose's record to another's request, and `assertConsumed()` covers both — so a compacted log replays its compaction, at the same point, with the same summary). Because the replay script is derived from the same JSONL the harness persists, **a live session log is its own test oracle** — including sessions that retried or crashed: recording costs one real run. It is the oracle for the session that WROTE it: a delegated child is a different session making its own calls through the same seam, so it replays from its own log, and sessions are matched to logs in first-request order (a replayed child gets a fresh id, but the order agents first ask in is the order the recording delegated in). A session that asks with no log left fails naming what is missing — one shared cursor used to serve it the parent's next recorded step, so every assistant message from the delegation onward was a different message than the one recorded, while `assertConsumed()` passed on arithmetic. The protocol is tested byte-level over an in-memory duplex pair; the terminal's render folds are pure functions plus scripted end-to-end runs over the loopback carrier.

Runtime invariants — the session relational trace (seq contiguity, turn/step balance, numbering, call/result pairing; pre-commit, so a rejected event never enters the log), agent status no-repeat, and request reconstruction (an `observe`r in the `llm/stream` preflight, so no listener however ordered can run ahead of it) — run in every test *and* in live runs, because `compose()` mounts them by default. End-to-end verification asserts the world (re-run the test suite, byte-compare untouched files), never the agent's self-report. **Cross-capability claims are tested against the full composition**: a claim about what several capabilities do together at one moment (what a session opens with, when a file appears) is pinned in `app.test.ts` over `bootComposition`, because a partial composition is where such a claim was found false.

Gates: `pnpm check` = `tsc --noEmit` + `oxlint` + `check-deps` (dependency direction + payload discipline) + `vitest`; `pnpm test:e2e` runs the eight live arcs (gated on `DEEPSEEK_API_KEY`, and the routing arc also on `ANTHROPIC_API_KEY`). Seven drive the real runtime as a `minidsh serve` child process over real stdio JSON-RPC through `test-support/serve-process.ts`; the eighth drives a `minidsh web` child over a real WebSocket through `test-support/web-process.ts`:

- `live.e2e.test.ts` — complete a task, SIGKILL mid-turn, resume in a second process (crash repair + byte-prefix attach asserted), finish the work, replay a fresh log keylessly.
- `authority.e2e.test.ts` — with no `--approve`, so every consent is a real decision answered over the wire: an edit inside the workspace lands; one outside it is refused and probed ABSENT on disk; a shell command is refused as unconfinable, the model escalates with a justification, the client approves, and it runs; a `session/authority` switch to `read-only` refuses the next write; and the fresh log still replays keylessly.
- `composition.e2e.test.ts` — a from-disk composition drives the runtime: `MINIDSH_HOME` carries a composition.json inserting a module-loaded tool and a settings.json choosing the route; the tool's real output, the recorded header, the `composition/applied` stamp, and a wire preset switch (intent + both knobs) are asserted from the durable log, which then replays keylessly under the SAME disk composition.
- `context.e2e.test.ts` — a disk `budgetTokens` low enough to cross for real: five turns read bulky files, run a command, and write a summary. The workspace's AGENTS.md demands a file header no prompt ever mentions and the written file carries it; a command's output spills and the model reports a value present ONLY in the omitted middle; the compaction record's shadowed seqs are exactly what the replace cites, all still in the log and all gone from the surface; and the log replays keylessly against a pristine copy of the workspace with both cursors drained. **Its note prompts name the editor tool and forbid both `view_range` and a shell search**, because "reply with the marker token it contains" is answerable by one `Select-String`: a live run did exactly that for all three files, finished in 16 s instead of 45, wrote a correct `summary.txt`, and never crossed the threshold — so nothing compacted and the arc failed having made zero summary calls. The budget is low enough that one bulky file crosses it, but only if the file is read. It also raises `maxSummaryFailures`, because at this budget a compaction is often worth nothing and the runtime is right to say so: the trigger fires on every crossing, but where the planner's cut lands is the model's tool shape, and measured over six live runs **14 of 34 summaries produced no compaction while every run still landed at least three**. At the shipped default of 2, two refusals in a row would switch the automatic triggers off for the remaining turns and the arc would then be asserting against a runtime that had correctly given up. The counter itself is pinned in `compaction-basic/loop.test.ts`; this arc is for the crossing.

- `routing.e2e.test.ts` — two providers through one unchanged loop: a session starts on DeepSeek, switches to Anthropic mid-session over the wire, and the log proves the route is one fact (one `agent/options{change}`, one `request/context` per route with each provider's real window, every assistant message attributed to the model that wrote it, signed thinking only on its own provider's messages). A `compaction` role sends the summary down DeepSeek while the loop is on Anthropic and the `llm/aux-call` names that route; the mixed log then replays keylessly, both providers served from one recorded script, the switch happening again at the same point.
- `delegation.e2e.test.ts` — with no `--approve`, so every consent would be a real decision: the parent delegates a bounded search, the child completes it in its own session (own header lineage, own tool calls), its opening stamps read `reason: 'delegation'`, every approval it asked for was refused without a client being consulted, a wire attempt to widen the resumed child is refused, and the parent then writes the file the child never had the authority to write — decoy byte-identical.

- `verification.e2e.test.ts` — a delegated child sees an image its parent cannot, with every S8 row mounted from a disk `composition.json` (so the arc re-proves the layers too) and no `--approve`. The parent's own `view_image` is refused `UNSUPPORTED_CONTENT` before any file is read; it delegates; the child, routed to the vision model by one `model-roles` entry, reads the PNG under `read-only`/`never` and reports what it saw; the parent writes that line. **The test draws the fixture**, so the expected answer is a fact it knows rather than an assumption about the model — the S5 arc's premise decayed silently for exactly the opposite reason. **The binding is asserted before any answer**, because `model-roles` passes an unknown purpose through silently: a mis-wired verifier row would put the child on the parent's own model, where it would guess from the filename and every answer-shaped assertion would still pass. So the arc first proves the child's route, that its log recorded `image` among that route's modalities, that its `view_image` returned an image block without error, and that the attachment's id equals the SHA-256 of the file the TEST wrote — hashing the stored object against its own id would only prove the store agrees with its own naming rule. Neither log contains base64. A client then attaches to the child by name and its transcript carries the descriptor. The replay pre-seeds the fixture and asserts an object appeared under a replay home that started empty: without that, `view_image` would error, no attachment would be written, the recorded answer would replay anyway, and `assertConsumed()` would pass on arithmetic while nothing under test had run.
- `web.e2e.test.ts` — the browser surface over a real socket, with no `--approve`: the token-for-cookie sign-in, two clients on one host where the one that asked for nothing still sees the whole durable stream, a real consent escalated by the model and granted over the wire (both clients seeing the same durable decision), the transcript paged backwards to seq 0 losing and repeating nothing with the trace tier absent from every page and present in the archival read, then the socket killed mid-turn — the host keeps serving, the agent keeps running, a fresh connection reattaches past where the old one died and finishes the work. The fresh log replays keylessly.

Every session close requires all seven live runs green. **Run them on an idle machine, and do not let that stand in for a diagnosis.** Two of the failure shapes are latency-shaped (a turn that never ends, a compaction that loses its race to a starting turn), so a host also running a multi-agent workflow is not a neutral place to measure — but a run on an idle machine failed too, and the cause was the model taking a cheaper route than the arc assumed. When an arc does stall, `serve-process`/`web-process` name what the session was parked on: open approvals, the tools it called, the tail of the stream, the last status. "Timed out waiting for turn 1 to end" is what one session had to work from, and it was not enough. The same rule applies to every count an arc asserts — say what the number was and what produced it, or the next failure costs a run to reproduce.

The repository also carries one guard that is not part of MiniDSH: `.claude/hooks/guard-repo.mjs` refuses to link anything to a `node_modules` tree, and refuses a recursive delete of a path that is such a link or holds one. A review subagent junctioned this repo's `node_modules` into a scratch git worktree and then ran `git worktree remove --force`; the delete followed the junction and emptied `node_modules/.bin` out of the live checkout, stopping only where a concurrent test run held files open. pnpm's state file survived, so `pnpm install` reported "already up to date" and repaired nothing. The rule is mechanical for the reason § 13 gives everywhere else: model reasoning is not the boundary.

| New thing | Home |
|---|---|
| a model provider | `capabilities/llm-<p>`: register an adapter on `llm` (from an unscoped owner); refuse an option the wire cannot honour before any I/O, and carry provider-private replay state in the finish's envelope |
| a model-facing capability | `capabilities/tool-<x>`: register on `tools` (+ a prompt guidance section) |
| a plugin's configuration | a strict zod schema on `Plugin.config`; the kernel parses it before `apply`, and `reconfigure` validates before it disposes |
| an execution world (sandbox, remote) | providers for `fs` and `shell`; tools untouched |
| a shell confinement backend | a `shell` provider (or a spawn wrapper inside one) that confines the argv under the stamp and reports the truth from `enforcementFor`; if it needs writable roots the fence does not grant, they go in `writableRoots` — once, for both families |
| an authority knob | a log-only event with a `findLast` fold, an `open` that records the opening value at `agent/created`, and a setter that IS the event, beside `sandbox/mode` and `approval/policy`; never a field a surface holds |
| a bundled authority selection | an entry in the presets table (composition config on the `authority-presets` row); it validates against a delegated session's ceiling and pin BEFORE writing its intent, then writes through the canonical setters, and owns no enforcement — `custom` stays derived-only |
| a capability without a code edit | a row in `composition.json`: builtin name or module specifier; disable/reconfigure by patch; the session records the change via `composition/applied` |
| a user-adjustable default | a `core/settings` namespace registered by the boot (`register(owner, ns, schema, {base})`) if a WIRE client should be able to change it; the row's config via a composition patch if it is capability config — never both, and never authority |
| a secret | a `CredentialRef` (env-var name) in config; the value comes from `ctx.credentials` per operation and never enters a file the repo tracks, a log, or an error |
| a per-agent capability bundle | a named `agentPresets` list in composition.json, mounted on `agent.ctx` at setup (`--agent-preset`, `ProtocolConfig.setup`); a delegated child composes its parent's same setup before its own narrowing |
| a policy or approval answerer | listeners on `tools/pre-execute` / `approval/request`; guards |
| durable state | a new session event type (a fact, or a trace kind in `TRACE_TYPES` if nothing folds it), rendered and replayed from the log |
| a human-facing line for an event | one branch in `app/present.ts`, narrowed with `matches()`; every plain-text surface then has it |
| context for the model | `agent.inject()` or an `agent/pre-step` listener — never ad-hoc prompt text |
| a surface | `app/` or a new package: consume `session/event`, drive `agents`; zero semantics; owns only the live control plane (§8) |
| a carrier | a `Carrier` variant in `capabilities/protocol` beside the stream and WebSocket ones, plus a row config the app builds; the host, its handlers and its ownership plane are already shared, so a carrier owns framing and flow control alone |
| a named place to work | a `workspaces` entry on the protocol row's config (id derived from the canonical root when unnamed). Addressing only: it grants nothing `workspaceRoots` does not, and the resolved path takes the same four checks a raw `cwd` does |
| a remote client (web, IDE, script) | speak the protocol (§8): ndjson JSON-RPC to `minidsh serve`, or JSON-RPC over the WebSocket `minidsh web` serves. `session/attach` for the header, the view and a page; `session/page` backwards under that cursor; dedup by seq, repair a hole with a both-ends-bounded `session/events`, and re-attach (never resume-from-seq) after a reconnect. Render `{sessionId, event}` frames, ignore unknown event types, and name a workspace or a `cwd` inside the host's `workspaceRoots` |
| a per-agent variant | registrations or plugins through `agent.ctx` during `setup` — tools, guards, sections, variables, listeners — visible to that agent alone (§2 scope contract) |
| a delegated child agent | BUILT (§7): `capabilities/tool-subagent`. A different delegation policy is a different tool over the same seams — `agents.create(parent.ctx, {delegatedBy, delegationDepth, signal, setup})`, both knobs opened with `reason:'delegation'` inside setup, `tools.restrict` for the child's view |
| context management | BUILT (§6): `core/compaction` + a provider. A new policy is a different provider on `COMPACTION`; a new trigger is a listener that calls it |
| a context-pressure number | `core/metering`, a pure fold over `Session.facts` — never a field a surface holds, and never a second definition beside it |
| oversized tool output | `core/spill` + a store, consumed by the TOOL that produced it (the bound belongs where the text still exists). Output that is already a file is not spill: answer with a range |
| context for the model from a file | a capability that enters a durable `user/message` at `agent/pre-step`, guarded on the LIVE surface so a compaction re-enters it (`workspace-instructions`) |
| an attachment / binary plane | BUILT (§5): `core/attachments` + `attachments-local`. A new KIND of attachment adds a media-type family and a header probe; it does not add a seam |
| a producer of non-text content | a tool that refuses on the STEP's route (`foldRequestContext(...).inputModalities`) before any I/O, bounds itself against `imageLimits` over the LIVE SURFACE, commits durably, and only then returns a block (`tool-view-image`) |
| a verifier | BUILT: a second `tool-subagent` row with its own `toolName`, `purpose`, `description` and a narrowing `sandbox`, plus the matching `model-roles` entry. The two rows must be patched TOGETHER — an unknown purpose passes through silently to the parent's base route, and a verifier on the parent's own model is a verifier that cannot see |
| a model role (cheap / verifier / vision) | BUILT (§6): a `purpose → route` entry in the `model-roles` row's config. A NEW purpose is a caller passing one to `resolveCallConfig`; the base route is never rerouted, and `request/header`, `request/context` and `MessageSource` attribute whatever ran |
| a model call outside the loop (summary, verification) | BUILT (§5): `resolveCallConfig(agent, {purpose})` for the route, then `runAuxCall` — one log-only `llm/aux-call` with route, usage, result and the seqs it was fed; bare `llm.stream` is neither durable nor replayable |

If a new thing has no row here, that is an architecture question to settle before implementation.

## 12. Divergences from DeepSeek Harness

- Own kernel instead of Cordis (DSH uses a small subset; proxies, realms, loader, HMR are dispensable at this scale). Each plugin's config contract is a structural `{parse}` on the plugin (DSH: a schemastery `Config` per plugin, validated by its Loader) — same guarantee, no kernel dependency on a schema library.
- One package with a dependency gate instead of several hundred (`pnpm-workspace.yaml` globs `packages/*/*` over 49 group directories; `packages/client` alone holds 44 — S7's "~150" understated it by two to three times).
- Sequential tool execution; no scheduler.
- Persistent shell over piped stdio with marker framing instead of a PTY.
- One client protocol instead of DSH's THREE (a GUI wire, an SDK stdio protocol, and ACP — a deliberately reduced automation surface, constrained to a public vocabulary so it cannot grow private methods). MiniDSH's follows the SDK shape and adds what THAT one lacks: `session/cancel` (upstream's GUI wire has one; only its stdio protocol does not, where a client abandons a turn by closing the process), `approval/answer` keyed by the durable id (DSH's GUI wire uses a gateway-minted event id plus a client id and keeps its durable id host-side), `session/authority`, and a catalog-returning `initialize`.
- **The attach protocol has no lower-bound cursor on the WIRE, which is upstream's shape too** — its `follow` request carries only an address and a message budget, and every reconnect replaces the window from a fresh snapshot. Two qualifications S7 got wrong and S7.5 checked against the source: the JSDoc promising a "last committed sequence already held by the caller" is real, verbatim, in two upstream files, so it is a documented intent and not a stray; and a lower-bound read does exist one layer BELOW the wire (`SessionPersistence.readFrom(id, fromSeq)`, for "consumers that resume from a known sequence"). MiniDSH still declines a resume-from-seq attach, because the host would owe a retention promise it does not make — but it declines it as a choice, not because upstream lacks the idea. What MiniDSH adds: a gap repair bounded at BOTH ends (upstream's repair page is upper-bounded only), a host-enforced ceiling on the page budget (upstream validates only positivity, so any client can ask for the whole log) and an event ceiling beside the message budget (upstream's page is unbounded in bytes, as its own docs acknowledge).
- **Pages omit the trace tier where DSH packs it.** Upstream losslessly packs runs of consecutive delta chunks into one row for page and snapshot records, and expands them back on read; packing is a page/snapshot shape, not something the live path ever emits. MiniDSH omits them: nothing here renders historical chunks — the terminal streams live ones and the replay reads the stored JSONL — and omission is what keeps a bare **seq** a sufficient dedup key, where a packed record spanning many seqs forces upstream's range-based cursor algebra.
- **Watch sets, where upstream has none.** Each upstream follower allocates its own global listener, its own unbounded queue and its own frozen copy of the whole event array, so N tabs are N full copies. MiniDSH filters per connection from one broadcast. That is a MiniDSH invention, not an upstream pattern.
- **A drop policy, where upstream has four unbounded queues.** Upstream's outbound path is a per-connection serialized write chain that suspends the producer and head-of-line blocks every logical stream; there is no high-water mark and no drop policy anywhere. MiniDSH cannot suspend its producer — `session/event` is a synchronous contained emit — so it drops the droppable tier and closes a client that falls further behind. Designing past the reference, deliberately.
- **No RPC deadlines**, matching upstream, which has none on its browser path at all; liveness is a ping and cancellation is a disconnect. MiniDSH adds none either — S7 claimed a client-side request timeout, and neither shipped client implements one.
- **Approvals are settled when nobody is left who can see them.** Upstream broadcasts, takes the first answer and cancels the losers exactly as MiniDSH does — but a client disconnect settles nothing there, so a request whose last holder vanished stays pending and its agent waits forever; upstream's own notes call that an accident rather than a design. MiniDSH settles it `unavailable`, and recomputes who could answer from the LIVE connections after every watch-set change rather than snapshotting them when the question was asked (§8). Upstream's mitigation is the other half of the same idea and MiniDSH already has it: the open questions ride in the attach frame, so a client that arrives late is shown them.
- **A disconnect is not a shutdown, and `shutdown` is carrier-gated.** Upstream's agents are host-owned too, and this is nearer convergence than S7 recorded: upstream's shutdown is process-wide, but it exists only on the SDK stdio protocol, where the one peer IS the spawned process — its GUI wire ships no shutdown method at all. MiniDSH reaches the same place with one rule instead of two protocols: a socket client may not end a host other clients are using.
- **Workspaces are read-only and config-declared.** Upstream registers them durably with UUID ids and a whole CRUD namespace (create/rename/delete/reorder/archive). MiniDSH declares them in the host's config, deriving an id from the canonical root when none is given. Both agree on the load-bearing parts: the session header stores a cwd and no workspace id, the edge is derived by canonical-path equality, and **the registry gates nothing** — no trust marker, no permission, and the file fence still comes from the calling session's immutable header cwd.
- **A settings write over the wire must carry the revision it read.** Upstream's `expectedRevision` is optional at every level and an unfenced write is a passing test, so two panes can lose each other's edits. MiniDSH requires it on the wire path. MiniDSH also needs neither of upstream's redacting read nor its field-level `mutate`: those exist because secrets live in its settings, and MiniDSH's live in `credentials.json` behind a `CredentialRef`. And MiniDSH ships no equivalent of upstream's `openSettingsDocument` / `openAgentPresetDirectory`, which hand any authenticated caller a native-execution affordance on the host.
- **No durable, `stateVersion`-keyed projection tier.** Upstream has one, but its paging does not use it — every page materialises the whole log and slices, live or cold — and its load-bearing consumer is session LISTING over a SQLite-backed store. MiniDSH's `persistence.list` already reads a bounded header prefix per file, so neither justification applies here. Its in-memory cold-read LRU is the half MiniDSH does copy.
- **No per-user identity**, as upstream has none either: many windows, one principal. MiniDSH's browser surface therefore fences on reachability — loopback by default, a one-shot launch token exchanged for a signed cookie, and a Host/Origin allow-list — rather than pretending to authenticate anyone.
- No confinement backend at all, where DSH ships four (bwrap, Landlock, Seatbelt, a Windows ACL restricted-token runner). MiniDSH keeps DSH's invariant — refuse rather than run unconfined — and ships the seam and the escalation path instead; enforcement is recorded in the stamp so a log never overstates what a host actually delivered (DSH's `sandbox/mode` carries no enforcement level).
- `writableRoots` grants the workspace root only. DSH also grants `/tmp` and `os.tmpdir()` so its confined shell keeps working; MiniDSH has no confined shell, so no asymmetry can arise, and granting the platform temp root would hand the editor authority it has no use for.
- Escalation is strictly-wider plus approval — and that is upstream's gate too, not a divergence. Its `approveEscalation` has exactly three guards (strict widening against the call's effective mode, an approver composed, an agent present); there is no denial registry anywhere in the tree, and its request carries no denial history. S7 recorded a difference that does not exist.
- Tool deadlines are registry-owned rather than a wrapper plugin, because the kernel waterfall cannot substitute a listener's arguments; in exchange every tool has a default budget, where DSH's shipped tools mostly declare none — and a body that takes consent itself (the shell) opts out and owns its clock.
- An interactive terminal client ships. Upstream has no TUI in tree either — only an out-of-tree plugin bundle — but it ships more surfaces than S7 counted: web, a headless profile, an SDK app, a minimal SDK tree and ACP. MiniDSH's terminal is a protocol client on an in-process carrier, DSH's own documented pattern.
- Plain JSONL lines through one held descriptor instead of checksummed zstd frames, chunk-row packing and a 200 ms write-behind; the same materialization rule (a never-appended session is absent), and a `.torn` sidecar where DSH SALVAGES the never-fully-written tail in place, recovering whatever records survive inside its structurally incomplete final frame. (S7 recorded that as "discards", which is wrong twice over: neither system throws those bytes away, and the real difference is that MiniDSH quarantines them to a file instead of reading through them.)
- JSON config files instead of DSH's YAML (`agent.cordis.yml`, `settings.yaml`): zero new dependencies and the house lingua franca, at the cost of comments. Two disk layers (home + `--patch`) instead of DSH's four (bundle → profile → home → `--patch`); profiles and bundles wait for a real second deployment shape. Composition files are read at boot, not watched (DSH's web profile live-patches; its headless profiles apply once, as MiniDSH does).
- A per-session write **lease** where DSH has none for sessions (its JSONL backend guards only the first append with an atomic link; its SQLite backend holds a per-database write lock). MiniDSH's is a session-lifetime lease, so provably-dead-holder reclaim is appropriate — and refusal, not waiting, is the contention behavior.
- Both authority knobs are stamped at session initialization, as DSH does; MiniDSH additionally change-gates the knob events and records `reason` and `enforcement`, and keeps `resolve()` as a stamping safety net for sessions created outside the registry.
- **A delegation opening is an enforced ceiling.** DSH copies the parent's explicit override and pins approvals to `never`, and the pin is the whole enforcement — it states that a later programmatic child-side switch would win, and tests that it does. MiniDSH pins the same way and additionally refuses the widening itself, in the setters, in the escalation path, and in the authority invariant pre-commit. The pin is what makes the model's own path impossible; the ceiling is what makes a composition's path impossible too, and it costs one comparison.
- **`subagent/start|end` live in the parent's session log.** DSH emits them as runtime (Cordis) events and finds children by scanning stored headers through a projection. MiniDSH has no projections, so the parent's log is where a human looks: the two records name the child, its depth, its route and its authority, and `sessions list` shows the lineage. The child's own steps stay in the child's own log either way.
- **Model roles are a seam here and not upstream.** DSH's `purpose` is an adapter-visible classifier, and each auxiliary producer (compaction, title) carries its own optional provider/model pair. MiniDSH routes every out-of-loop call through one `resolveCallConfig`, so a `model-roles` row maps `purpose → route` for all of them at once — and `purpose` still never reaches a provider.
- **The base route is a durable knob.** DSH's per-session route lives in the logged `request/header` (whose `config` carries provider, model, effort and the sampling scalars, under the same initial/resume/change reasons) plus a LIVE `ModelSelectionRef` behind two waterfall listeners. There is no `model/selection` EVENT — S7 recorded one — so upstream's durable half is the header alone, which makes this divergence sharper than the doc claimed rather than weaker. MiniDSH separates the BASE (`agent/options`) from the EFFECTIVE route (`request/header` + `request/context`), because a role rewriting a request must not become what a resume rebuilds from.
- Two adapters (a direct DeepSeek one and a direct Anthropic one) where DSH has a direct DeepSeek adapter and one generic adapter wrapping an external multi-provider library, with Anthropic and OpenAI as its configured routes. The seam is the same (`registerAdapter`, one owner per provider id); MiniDSH writes the second wire itself rather than taking a dependency, which is what makes the vocabulary's claims — replay envelope, disjoint cache counts, refused options, real per-model windows — testable against two genuinely different protocols.
- A per-boot `composition/applied` record, which DSH does not keep — and, like DSH, a durable `agentPreset` in the session header, so a resume or a child composes the world its history was made under.
- No `defaultPreset` on the presets capability (DSH ships one): the deployment default already lives on the sandbox/approval row configs.
- Settings resolve at boot into plain values AND, since S7, through a runtime seam for the wire writer that justified one. DSH's owner scope is four methods (`get, watch, update, replace`), not two; MiniDSH matches that and diverges on the fence (§12) and on secrets, which never enter this store.
- No separate deterministic tool-result pruner (DSH ships one). Summary compaction is what bounds ACCUMULATED history; spill is what bounds one incoming result. A pruner is a cheaper first pass before paying for a summary, deferred rather than rejected.
- **A durable compaction bracket, adopted for a different reason than upstream's.** DSH brackets compaction to hold a lock; MiniDSH's mutation is a single append, so no compaction can ever be half-applied and it needs no lock — the reason S8 added `compaction/start`/`end` anyway is that a paid attempt which produced nothing was previously invisible, and the record of WHY is what `/compact` and the give-up counter both wanted. MiniDSH then goes further than upstream in one place and stops short in another: the give-up counter is a fold over those records where DSH's stays an in-memory `WeakMap` a resume forgets, but MiniDSH bounds the fold to the current lifecycle deliberately, because an unbounded one is a latch only a human `/compact` could lift.
- **An attachment plane with no image dependency.** DSH decodes with Sharp/libvips, normalizes to 2048² and 4 MiB, and keeps a per-route request-image cache; MiniDSH sniffs four media types from their headers in 35 lines and stores exactly the bytes it was given. Two consequences follow that upstream cannot have: the id addresses the user's own bytes, so the same file has the same id on every machine (upstream's identity is encoder-build dependent, its own README's largest replay hazard), and "was the original kept?" never arises. The cost is stated rather than hidden — a truncated-but-well-headed file is admitted here and refused by the provider — and the per-route projection is deferred until a route needs a budget different from the stored one.
- **Retention is a rule MiniDSH states and upstream declines to.** DSH is retention-neutral for attachments and sessions by written policy, and sweeps only spill. MiniDSH reaches the same three lifetimes through one sentence (§9) rather than three separate silences, and records the sweep's constraints before building it. Upstream's own invariant — collect what can be re-derived from the log, never what cannot — is the same rule under a different name.
- One spill capability instead of DSH's three (store / local provider / post-execute policy): the threshold lives on the tool that produced the output, and there is no second store consumer yet. Spill goes to home, not the OS temp directory, because a durable `tool/result` naming a path is a lie once a reboot deletes it. And spill applies to output with no other home — DSH's post-execute policy would only ever see text its tools had already clipped.
- Compaction accepts an absolute `budgetTokens` beside DSH's ratio; the window itself is now a logged fact on both sides (`request/context`, written on route or capacity change, outside header equality), so a pressure trigger replays without an out-of-band budget.
- Workspace instructions ship without DSH's nested re-discovery after fs calls and without `.local.md` overlays: one durable entry per session, re-entered only if a compaction shadowed it.
- Folds are per-read over `Session.facts` rather than DSH's incremental, revision-keyed projections; the facts view removes the trace tier from every fold. S7 measured the case for projections and declined it (§12).
- No Code Mode, workspace config layer, or session projections until a session needs them. No client upload path for attachments: the producer is a workspace read, so nothing crosses a frame, and the carrier's 8 MiB message limit is tighter than either provider's (a 6.4 MiB image both APIs accepted is 8.6 MiB of base64).
- **No semantic verification of a compaction summary, and upstream has none either.** DSH checks a summary three MECHANICAL ways and asks no model to judge another model's output anywhere in its tree. MiniDSH's verifier is therefore its own move, justified by PROJECT.md rather than by parity, and it verifies artifacts in the world rather than the harness's own summaries.

## 13. Known limitations (current)

- **No host can confine the shell, so `workspace-write` buys the filesystem a real fence and the shell an approval.** The seam is complete — the stamp, `enforcementFor`, the refusal, the escalation, the durable record — but every platform reports `none`, so a shell command under a confined mode always costs a round trip and a human decision. A backend (§11) is what removes that, not a change to the plane.
- **The audit projects decisions, not attempts.** A shell command refused as unconfinable is a reported fact rather than a denial, so it appears in the transcript but not in `sessions show --audit`; it becomes an audit row only once the model escalates it and someone answers. Every denial code and every approval outcome do appear.
- **The mode vocabulary claims file effects only.** Network access is unrestricted in every mode and process visibility is unspecified; these are not general-purpose security modes. `enforcement` on the stamp is the shell world's report alone.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell; nothing coerces it, and nothing should.
- The fence is a policy check in trusted code, not a kernel boundary: it is complete for paths a tool passes through `ctx.fs` (hard links excepted, §7), and says nothing about code the shell runs.
- **The in-memory log retains the trace tier, deliberately.** `Session.facts` keeps every runtime fold off the chunks and no page carries them, so the wire no longer depends on them at all — but `session.events` still holds them: measured at ~28-30 MB of heap for a 400-turn session (103k events). Evicting would break `seq === array index`, which 16 call sites depend on (seq generation, the session invariant, the attach identity check, `snapshot`, `sliceForkSeed`, `deriveMessages`), for a bounded saving on the largest session anyone has run. DSH's live session is uncapped for the same reason and it declines retention at both durable layers. Revisit when a real deployment shows a session long enough to matter.
- **A workspace is a name for a directory, not a permission.** `workspaceRoots` is still the allow-list; `workspaces` only saves a client from knowing host paths, and its roots take the same four checks a raw `cwd` does. The registry is read-only and config-declared: no CRUD over the wire, and nothing durable to keep in step.
- A PowerShell command that reads stdin still blocks until its deadline (PowerShell has no stdin redirect operator); bash commands run with stdin from `/dev/null` and cannot.
- **A turn that loses durability ends, but the agent stays `idle`.** After `DURABILITY_LOST` every later turn ends the same way at its first checkpoint; there is no terminal agent state a surface or a parent could read, and a rejected `turn/end` append would likewise leave an agent that reports idle and cannot run. Both are reachable only through a provider or driver bug.
- **The shipped DeepSeek default still never reaches the pressure trigger.** DeepSeek advertises a 1,000,000-token window for every model, so the default `thresholdRatio` of 0.8 puts automatic compaction at ~800k projected tokens: on that route, out of the box, only the `CONTEXT_WINDOW_EXCEEDED` recovery can fire. The windows are now real per route — an Anthropic Haiku 4.5 session meters against 200K, and the log says so — and a deployment that wants to compact earlier still sets `budgetTokens`.
- **The compaction record carries three numbers, in two units.** `projectedTokens` is what the threshold compared and is provider-priced when the meter had usage to price it with; `surfaceTokensBefore`/`surfaceTokensAfter` are estimator units and are the only pair it is valid to compare. A subtraction across the two scales is not a quantity, which is why there is no single "saved" figure.
- **An explicit `/compact` can be paid for and not applied.** If a turn starts during the summary call, the replace can no longer land safely; the request is re-armed for the next step boundary, but the summary that was already bought is discarded. The same is true of a summary that comes back at least as large as the span it would replace: the refusal is right — a compaction that grows the surface is worse than none — but the call is already paid for, and `/compact` answers `nothing-to-do` without saying which of the two it was.
- **The meter changes units at a compaction.** Before one, the projection is the provider's own billed prompt plus an estimate of what followed; after one, it is a whole-surface estimate, because the billed prefix no longer describes what is sent. `retainRatio` is therefore measured in estimator units and the threshold that fired was measured in provider units. The error is in the safe direction (it cannot re-trigger on its own output) and the next request re-prices, but the knob is approximate by construction.
- **A prompt or tool-set change is still metered one step late.** The pressure check runs at `agent/pre-step`, and the step's `request/header` is written after it, so a system-prompt or tool-set change taking effect at step N is priced against the old anchor at step N and re-estimated at N+1. The ROUTE is no longer late: `request/context` is written before the pre-step listeners, so the budget a pressure check compares against is the window of the route that step will use.
- **Every command validates the whole boot preamble**, including `config`: a broken `settings.json` or a bad `--sandbox` value is exit 2 on `run`, `chat`, `serve` and `config`; `sessions` treats a broken settings file as a warning, because reading a stored log must not depend on it.
- **A compaction summary is one model call that can be wrong, and nothing brings the originals back.** The shadowed history is still in the log and `compaction/applied` names every seq of it, but no tool reads a shadowed span, so a poor summary is not recoverable from inside the session. This is the failure the routing arc hits intermittently — measured 4 of 11 runs at this tip and 1 of 4 at the S7.5 tip, so it predates S8 — and what S8 changed is only that the failure now names itself: "after 4 applied compaction(s) shadowing [3, 5, 3, 9] node(s)". A recall tool is the answer and is S9's; a second model judging the first is not, because it would be one unverified call checking another.
- **The surface's pairing rule lives in the planner, not the session.** `Surface.validate` checks contiguity and citation only; a second surface writer could commit a replace that separates a tool call from its result. Refusing it in the session invariant is deferred until a second writer exists. Likewise a fork boundary may separate `compaction/applied` from the replace that realized it, leaving a child whose advisory record describes a mutation its surface never received — and S8's bracket adds two more cut points of the same character (`start`|`applied` and `applied`|`end`), so a forked child can also carry an unpaired start. The acceptance is unchanged: nothing is lost and nothing crashes, the log merely stops explaining that child's surface. Refusing such a boundary in `sliceForkSeed`, the way it already refuses an open turn, is the fix when a fork of a compacting session is a thing anyone actually does.
- **The give-up counter is durable within a lifecycle and deliberately not across one.** Every attempt is now recorded — which trigger fired, against what budget, and why it produced nothing — but `foldCompactionFailures` is bounded to `liveStart`, so a resume still gets a fresh two attempts. That is a choice, not an oversight: only an applied compaction clears the count, and the automatic triggers that could produce one are exactly what a give-up disabled, so an unbounded fold would be a latch that only a human `/compact` could lift and that every fork of the session would inherit.
- **`compactNow` on a running agent does not compact now.** It is deferred to the next step boundary, because no re-check after a seconds-long summary await can make a mid-flight request safe. A session that never takes another step never compacts.
- **Spill files are never collected yet.** The RULE is decided (§9 — an affordance may expire, and spill is the one store a sweep may touch), but the sweep is not built, so a long-lived home accumulates `spill/<session>/` directories. Session disposal must never be what removes them: a fork inherits its parent's locators without re-owning them, so the sweep has to be age-based and per-file when it lands. A repeated `callId` overwrites rather than refusing, and a write that fails part-way leaves the partial file while the model is told the output was not retained.
- **A role's route is not what the budget is measured against.** Compaction's budget is the window the log names for the LOOP's route (`request/context`), while its summary may take a role's route with a different window: the threshold protects the conversation, and the summary is a separate call whose own cost is recorded in `llm/aux-call`. A role pointing at a much smaller model can therefore be asked for a summary larger than it can take — the call fails, the record explains it, and history is left alone.
- **Workspace instructions are read once per entry, not watched.** A file edited mid-session takes effect only if a compaction shadows the entry and it is re-read; a workspace with no instruction files is re-walked once per turn.
- **Both `agent/pre-step` listeners run in row order, and that order is load-bearing.** `workspace-instructions` registers before `compaction`, so it WRAPS it: the instructions guard folds the live surface after a compaction has landed, and re-enters them in the same step (measured three times out of three). S7's claim that a compaction shadows them for one step was backwards. Nothing pins the order, though — a composition that mounted a second compaction provider ahead of the instructions row would get the behaviour the old sentence described.
- **`--preset` on a headless run leaves the stable prompt section stating the composition default.** The preset is applied after creation, so the runtime-context section renders the opening stamp (the default) for the session's life while the effective mode is the preset's; the injected switch note tells the model, and enforcement is right. Feeding the preset's pair into `compose()` would close it.
- **Images have one producer and no client upload path.** `view_image` reads from the workspace, which needs no transport; a client cannot attach one. The wire would be the binding constraint anyway: MiniDSH's own carrier caps a message at 8 MiB, and a 6.4 MiB image both providers accepted is 8.6 MiB of base64. Nothing puts an image in a `user/message`, so §8's rendering covers the `tool/result` case alone.
- **A lost attachment object is turn-fatal.** An image block whose bytes are gone or corrupt fails the request with `ATTACHMENT_UNREADABLE`, which nothing retries, and it will fail every later request on that session identically. That is deliberate — substituting the descriptor would tell the model it was shown a description while the log says it was shown an image — but there is no quarantine and no recovery. Upstream is fail-loud here too and its own quarantine design is still only proposed.
- **Image validation is header-only.** MiniDSH takes no image dependency, so `INVALID_IMAGE` is a signature-and-header check: a truncated-but-well-headed file is admitted and refused by the provider instead. Measured — the first 40 bytes of a 96×96 PNG still probe as 96×96.
- **The meter charges an image on a route that cannot send it.** After a route change, an image serializes as its ~60-character descriptor while `estimateImageTokens` still charges up to 1,600. The error is in the safe direction (it can only make compaction fire earlier) and it is the same class as the unit change §13 already records below; a route-aware estimate is the fix and it would cost the estimator its purity.
- **`maxDepth` is a cost bound, and the tool filter is not a boundary.** The cap is now a fact about the child's world again — every registered delegation tool name is denied at the cap, not just the one that was called — but a tool filter still grants nothing and forbids nothing at the authority plane. A verifier's allow-list is there to keep it cheap and focused; what keeps it safe is its `read-only` opening and approvals pinned `never`.
- **A `/compact` deferred to the next step boundary still cannot report its reason.** The reason is durable in `compaction/end` and rendered on every surface, but the `CompactionOutcome` carrying it is returned to a listener that discards it, so the client that typed `/compact` while a turn was running learns it by watching the log rather than from its own RPC result. The request itself is still in-memory and still lost across a crash.
- **No OpenAI or Moonshot adapter.** The seam is proven by two genuinely different wires; a third (OpenAI's Responses API, with its encrypted reasoning items, or Moonshot's OpenAI-compatible endpoint with per-model thinking rules) is ordinary work against a settled contract, not a new question.
- **A delegated child is foreground and sequential.** One child at a time, blocking its own tool call; no background jobs, no continuable children a parent can message, no scheduler (DSH has all three). A child cannot delegate deeper than the cap (default 2), and the delegation tool is hidden from it so the cap cannot be reached by accident.
- **A child's cost is summed, not attributed per step.** `subagent/end` carries the child's total usage, and the parent's own meter does not include it: the parent's context pressure is about the parent's request, while the money spent is in the child's log. `sessions show <child>` is where a child's steps are read.
- **An unlisted Anthropic model gets conservative facts** (200K window, adaptive thinking, no sampling): the catalog is advisory, so an id it does not know is accepted rather than refused, and a wrong guess surfaces as a provider 400 rather than a silent clamp. The cost is real and one-sided — a 1M-window model routed by an id the catalog lacks compacts about five times earlier than it needs to — so a deployment using a model outside the shipped list should add it rather than rely on the default.
- **A delegated child is disposed with the tool call that made it.** Its log stays (that is where its steps are read), but the live agent is gone, so a surface can only reach it by resuming it — under the ceiling its log records.
- **`session/events` still returns whatever range it is asked for, every tier included.** It is the archival read — replay, `sessions show`, gap repair — and a caller that asks for a whole 400-turn log gets 17 MB and ~322 ms of stringify. The paged path (`session/attach` / `session/page`) is what every rendering client uses; nothing stops a script from asking for the log.
- **There are no host-side RPC deadlines.** A handler that hangs hangs that request; liveness is the WebSocket ping and a client-side timeout. DSH has none either, so there is no shape to copy — a deadline policy here would be unguided invention.
- **The backpressure limits are fixed numbers, not a measured policy.** The soft and hard byte limits are defaults on the carrier config; nothing tunes them from observed behaviour, and the drop rule is proven by forcing the limits rather than by stalling a real peer.
- **The browser surface authenticates nobody.** A one-shot token, a signed cookie, a Host/Origin fence and a loopback default make it hard to reach by accident — they do not make it multi-user. Anyone holding the cookie drives an agent with the same authority as the person who launched it.
- **A replay reproduces the model's decisions, not the workspace they named.** Every live arc replays its recorded log into a FRESH working directory, so a recorded tool call that chose an absolute path inside the recording's workspace cannot land: the fence refuses it (correctly — it is outside the replay's root), the turn still completes on the recorded messages, and `assertConsumed()` still passes, so the only symptom is a file that never appears. Observed once, in the web arc. The arcs' prompts now name relative paths explicitly, and 25 recorded file arguments over six later runs were relative without exception — but the steering is a prompt, not a fence. The exposure is a property of replaying into a different root, not of the oracle.
- **A compaction near the threshold is often worth nothing, and the runtime pays for finding out.** The trigger fires on a crossing, but what a summary saves is decided by where the planner's cut lands, and the cut is the model's tool shape: a bulky `tool/result` in the shadowed head is a 90 % cut, a head of short messages is a wash. Measured on the S5 arc at an 8,000-token budget, 14 of 34 summaries produced no compaction, and two applied ones shrank the surface by 3 %. The aux call is bought before any of that is known, and nothing in the record says which of "declined as too large", "lost its race" or "plan no longer live" happened — only that a `llm/aux-call` has no `compaction/applied` beside it. That, plus the give-up counter this can trip, is why the arc raises `maxSummaryFailures`.
- **A reconnecting client loses its paging position.** Re-attach replaces the window with a fresh tail page, so a reader ten pages back returns to the tail. DSH accepts the same trade; the alternative is a resume cursor the protocol deliberately does not have.
- The terminal renders plain lines: `presentCall` still has no caller and `ToolResult.value` is not durable — both deferred until the first structured card is rendered.
- Interactive `resume`/`fork` attach is prepared host-side by the app assembly (the wire equivalent — `session/prompt` with a stored id — is what `serve` clients use; a wire-level fork method does not exist yet. Upstream's IS implemented, taking an optional `atSeq`, so this is a plain gap waiting for a client that needs it — not the mirrored deferral S7 called it).
- A `steer` delivered to an idle agent wakes it (send semantics); the surface decides mode by observed status, so a steer racing turn-end becomes a fresh turn's prompt.
- **The lease degrades to manual cleanup at its edges.** A pid-reused or foreign-host lock holder cannot be probed, so the refusal names the holder and asks for an `rm` — fail-safe, never two writers. A `SIGKILL`ed process leaves a lock its successor reclaims only on the same host; one killed *inside* a reclaim leaves the `.steal` mutex, which blocks further reclaims (never a fresh acquisition) until it is removed.
- **`minidsh sessions` reads through the effective composition, but nothing else does.** `list`/`show` mount the layered `persistence` row so the CLI's read path cannot disagree with its write path; other one-off tooling that hand-mounts a provider would have to do the same.
- **Composition changes need a restart.** Files are read at boot; a running process keeps its composition and `Composition.reconfigure` is programmatic (no file watch, no HMR). The recorder makes the change visible per session, not live.
- **`minidsh config`'s authority warnings are advisory.** The home layer may widen row defaults (it is the deployment, code-equivalent trust); the guarantees are that recorded per-session authority always beats the widened default, and nothing is silent — not that the file cannot say it.
- **A module-loaded plugin is arbitrary code.** The composition file is exactly as trusted as `compose.ts`; the loader adds no sandbox, and must not pretend to.
- **A rolled-back creation's opening facts still reach a watching client.** `session/created` is withheld and no file is written, but every pre-publication append emits `session/event`, so an un-narrowed client sees `agent/options` (and the rest of the opening) for a session it can never attach to and `sessions/list` will never show. Suppressing delivery until publication would be a one-line change and is deliberately NOT made: four assertions depend on those frames arriving, and they are what a client watching from before a session existed is entitled to see.
- **No frame says a session was disposed.** A client attached to a session whose agent is gone keeps its watch and its last view; it learns by re-attaching (which reads the stored log) or from `sessions/list`. That is enough for both shipped clients and a notification would be new protocol surface for a state nothing acts on.
- **A reconnecting client still loses a pending approval.** The answerer set is live rather than snapshotted, so a second client rescues a question — but a lone browser that reloads is, for that instant, nobody watching, and the question settles `unavailable`. A grace period is the only fix and it would be invention: upstream's answer here is to hang.
- **A `session/detach` naming one session narrows an un-narrowed client to nothing.** A watch set is a set of attached ids; it cannot express "everything except this one". Both shipped clients detach-all before attaching, so neither meets it.
- **The browser rebuilds its whole transcript on every applied event.** A page can hold up to `MAX_PAGE_EVENTS`, so a long session's tab does O(n²) DOM work over its life. Incremental append is the fix and it is not made here: this file changed under a session with no browser available to look at it, and S7's own record is that four defects in this client were found by a browser and by nothing else.
- **A prompt delivered to an agent between `cancel({disposed})` and its registry detach is dropped, and answered as success.** `send()` returns early once disposal begins while `AGENTS.get(id)` still resolves, so the wire reports `{sessionId, messageId}` for a message nothing will deliver, and nothing durable records the loss. Making the agent unaddressable first would invert the disposal order §3 documents and a test pins (world first, then the registry); the reachable window is a turn unwind, and the delegated-child path that made it easiest to hit is now closed by the read-only rule (§8).
