# MiniDSH Architecture

One runtime composed from plugins over a tiny kernel. Everything the model can see is derived from an append-only session log. Everything the model can do goes through a guarded tool pipeline, fenced at the effect boundary by an authority the log records. The model is a capability the runtime routes to, not the agent: the route is a durable fact, a purpose may take a different one, and a delegated child runs under an authority it cannot widen. Bytes the model was shown live beside the log, content-addressed, never in it. Every surface only renders the log — by the page, because no client may be handed a whole one — and drives the agent registry; a session survives its process.

This is the architecture contract: what each layer owns, what it may not own, and where a new thing goes. History lives in `BLUEPRINT.md` §4 (beside this file) and the commits; usage lives in the root `README.md`. §12 lists deliberate differences from DeepSeek Harness (DSH), §13 what is knowingly missing. Section numbers are cited from code comments and are stable.

## 1. Layers and dependency direction

```
src/app/           application assembly + surfaces: compose.ts (rows + patches + catalog), config.ts (disk layers),
                   settings.ts, headless.ts, cli.ts, serve.ts (stdio protocol host), web.ts + web/ (the browser
                   host and its plain-JS client), present.ts (the one event→line projection), terminal/, home.ts
src/capabilities/  providers and consumers over core seams (never import each other, never app)
src/core/          the spine: Service Definitions + default drivers as plugins
src/kernel/        composition substrate: Context, plugin lifecycle, services, effects, events
src/test-support/  scripted adapter, replay-from-log adapter, composition harness
```

Three rules, enforced by `scripts/check-deps.ts` (part of `pnpm check`):

| from | may import |
|---|---|
| `kernel` | nothing internal |
| `core/<x>` | `kernel`, other `core` contracts — **except `core/loop`, which nothing imports but `app`** |
| `capabilities/<x>` | `kernel`, `core` (Definitions only; providers never import other providers or consumers) |
| `app` | anything |
| `test-support`, `*.test.ts` | their own layer and below; `test-support` may import `app` to mount real compositions |

Second, an event payload outside tests is read through `matches(event, KIND)`, never `event.data as {…}`, so a renamed field is a type error rather than a `NaN` on a screen. Third, **core is acyclic at file level**: core packages depend on each other freely (agent ↔ sandbox, session ↔ llm, sandbox ↔ shell), and each package's vocabulary — `events.ts`, `types.ts` — sits below its service, so no file's value imports close a loop.

A deeper tree is not more architecture: the layers are the whole topology, and a capability is a directory, not a package. The browser client shares no code with the host — plain JS, no build step, only the wire between them.

## 2. Kernel (`src/kernel`)

The two composability properties from the Cordis paper, with the smallest mechanism set DSH relies on. No loader, HMR, isolate realm, proxy, mixin or accessor; registries take the owner context explicitly (`tools.register(ctx, def)`).

- **Context** — a non-mutating tree. `child({scope?})` derives a context carrying a scope tag; registrations through a context are attributed to it and unwound with it, so *registration context = visibility = lifetime*. Scopes are flat: a child beneath a scoped context inherits that scope and cannot be re-tagged. A scope derived from a plugin context reads *through* that plugin's declared and provided keys.
- **Services** — `provide(key, value)` is an effect; a key is claimed once per context chain (a child may shadow). `get(key)` is strict — only keys declared in `inject` or provided by this plugin — and `tryGet` is the optional read. Keys are typed tokens (`serviceKey<T>('sessions')`), not declaration merging. Deployment-global registries refuse a scoped owner.
- **Plugins** — `{ name, inject?, config?, apply(ctx, config) }`. `config` is a structural `{parse(unknown) → C}` contract (a zod schema qualifies; the kernel imports none), parsed BEFORE `apply`, so a malformed row fails loud as `PLUGIN_CONFIG` naming the plugin. An instance is `pending` until every injected key is provided, then `loading → active`; a vanished dependency unloads it, a replaced provider reloads it. Transitions are serialized per instance. A provider's effects unwind before its dependents unload, so **a disposer must not read the services its plugin injected**. `settle(filter?)` waits for quiescence and reports pending plugins with their unmet keys and failed ones with their errors.
- **Effects** — `effect(fn → disposer, label?)` pushes onto the owning instance's disposer stack; disposal is strict reverse order. A disposer runs its synchronous part eagerly, so `off(); register(sameName)` in one tick is legal.
- **Events** — typed tokens carry their dispatch mode: `emit` (sync, exceptions contained), `waterfall` (around-middleware; `next()` is single-shot, so no middleware can run a tool body twice against one durable record), `serial`, `parallel`. The wrong method is a compile error. A dispatch may carry a `scope`, reaching unscoped listeners, `global: true` listeners, and listeners of that scope. `observe(hook)` sees every dispatch in the preflight, before any listener is selected — the seam runtime invariants hang on, because a listener can always be ordered behind another and an observer cannot. `prepareEmit` splits that preflight from delivery, so an observer can reject a fact before it is committed.

**Scope contract** (`core/scope.ts`). An unscoped context registers deployment-global; an agent's `ctx` registers into that agent's layer, unwound with it. Tool definitions, guards, prompt sections and variables are layered — the globals plus exactly one agent layer, a local entry shadowing a same-named global, no inheritance between scopes. Every event about an agent's operation is dispatched in that agent's scope (`agent/*`, `tools/*`, `approval/request`, `system-prompt/assemble`, `fs/*`); subject-less seams (`llm/stream`, `session/*`) and registry-membership notifications are unscoped. Consumers receive the agent as the operation subject and never read services through `agent.ctx`. A per-agent execution world is composed by mounting plugins on `agent.ctx` during `setup(agentCtx, agent)` — where the agent is still unpublished and its session appendable, the slot a creator seeds durable opening facts into before the first effect. A scope tag must be an object (the `Agent` itself).

## 4. Canonical facts: the session log

The log is the single source of truth. Envelope `{type, seq, time, data}`, `seq === log.length`, data JSON-lossless and deep-frozen at append.

**Three tiers.** The three **surface** events — `user/message`, `assistant/message`, `tool/result` — carry `surfaceOp: 'append' | {op:'replace', start, end}` and `sourceEventSeqs`; model history is the fold of surface nodes through `deriveEventMessage`, which lets a compaction provider replace a range without mutating history. Every other event is a log-only **fact** the runtime folds — except the **trace** tier (`TRACE_TYPES`, today `assistant/chunk`), recorded for streaming fidelity and replay and never folded at runtime. Trace is the bulk of a long session by two orders of magnitude, so every runtime fold walks `Session.facts` (the log without its trace, seqs preserved) while persistence, replay and the wire keep `events`; a seq indexes `events[seq]` in O(1).

**Vocabulary** (27 kinds): `turn/start`, `turn/end{reason: completed | blocked | cancelled | error{code,message} | max-tokens | max-steps | interrupted}`, `step/start`, `step/end`, `user/message`, `agent/options{options, reason: initial|change|resume}`, `request/header{provider, model, reasoningEffort?, maxTokens?, temperature?, system, tools; reason}` (written only when it changes, so a provider prefix cache survives restarts), `request/context{provider, model, contextWindow?, inputModalities?}` (`inputModalities` absent MEANS text only), `assistant/chunk{turn, step, attempt, chunk}` (trace), `assistant/message{message, usage?, interrupted?}`, `tool/call`, `tool/result`, `inbox/spliced`, `approval/asked{id}`, `approval/decided{id, outcome}`, `approval/policy{policy, reason}`, `sandbox/mode{mode, enforcement, reason}`, `authority/preset{name}` (intent; the knob events that follow are the truth), `composition/applied{hash, layers, rows}` (configs hashed, never inlined), `llm/aux-call{purpose, provider, model, maxTokens?, inputSeqs?, usage?, outcome}`, `compaction/start|applied|end`, `subagent/start|end` (in the PARENT's log), `session/title{title, messageSeqs, source: fallback|provider|user}` (log-only, last-wins; only `fallback` is produced today and the vocabulary is complete anyway, because a rename must be distinguishable from a generated title in a durable record), `session/end-seed`.

The header `{version, id, createdAt, cwd, parentId?, seedLength?, delegatedBy?, delegationDepth?, agentPreset?}` lives beside the log. `SESSION_FORMAT_VERSION = 0`; adding a field or a kind is additive, and a stored log with a NEWER version refuses loudly at load and attach. An unknown event type loads as an opaque log-only record and is skipped by derivation. A plugin that needs durable state adds a log-only kind, never a surface kind.

**The route is one durable fact, in two records.** `agent/options` is the BASE, written at creation, by `configure`, and by an override at resume; folded by `findLast`. `request/context` is the EFFECTIVE route of the next request, written before the step's `agent/pre-step` listeners and only when the WHOLE record differs from the last — so a field added to it must be written on a resumed session whose route never changed, or it reads as absent for that session's life. It sits outside header equality, so a capacity change never forces a header snapshot, and every reader learns the window from the log rather than a live adapter. An adapter that cannot resolve a model records neither window nor modalities, and the next successful step rewrites the record instead of latching "text only". A role rewriting `{provider, model}` moves the header and the context record, never the base.

**What a session opens with.** Agent creation, before publication, writes `agent/options{initial}`, `approval/policy{initial}`, `sandbox/mode{initial}` and `composition/applied`; a resumed session whose log already says writes nothing. A DELEGATED child's creator stamps both knobs inside `setup` (`reason:'delegation'`). A stored log always states what its session started under, and under whose authority, before its first effect.

**The durable inbox.** `inbox/spliced` is op-shaped — `{op:'insert', queue, message, waking?} | {op:'claim', steps, turns} | {op:'clear'}` — never positional; a claim drains counts from the front. Inserts and clears log at mutation time; the claim record is committed after the entered `user/message`s, so a crash inside the pre-step window re-delivers a prompt on resume — a rare double-delivery, never a loss. A disposed-cancel does not durably clear, so teardown preserves the queue; an empty clear logs nothing. A RESUMED agent is woken at publication iff a waking insert is still queued; a fork is a passive branch and is never woken by creation.

**Arrival versus rewrite.** A `user/message` that ARRIVES must sit inside an open turn. One that REPLACES a range is a surface rewrite, not input, and may land between turns — which makes `/compact` legal on an idle session. `Surface.apply` throws on a replace naming a node that is not live, in the fold as well as at append.

**Crash repair closes the surface.** The driver commits an assistant message with ALL its tool-call blocks and logs each `tool/call` only when that call's turn comes, so `repairInterruptedTail` answers every tool-call block of the open step's assistant message — `TOOL_OUTCOME_UNKNOWN` for a logged call, `TOOL_NOT_STARTED` for one never dispatched — cancels every approval asked in the open turn and never decided, then closes the step and the turn as `interrupted`. A resumed history is one every OpenAI-compatible wire accepts.

**A `session/event` listener may not append synchronously.** Delivery is where persistence writes its line, the protocol streams its frame and the relational invariant commits its staged trace. A nested append reaches all three BEFORE the event that caused it, and a log whose seqs run N+1, N is `damaged` on the next resume. A listener that must append queues it on a microtask.

**Model-visible ⟺ logged.** Every request the loop sends equals `deriveMessages()` plus the folded `request/header`; a runtime invariant rebuilds both in the `llm/stream` preflight and fails on any divergence.

**Persistence is a subscriber**, storing `sessions/<id>.jsonl` under `MINIDSH_HOME` (default `~/.minidsh`) with the header as line 1. A session **materializes on its first conversation fact**: publication takes the lease and decides the write mode, but a fresh or forked session is written only when its first surface event lands, so a `chat` opened and closed leaves nothing behind. A `resumed` session attaches append-only; a torn final line moves to a `.torn` sidecar, deeper corruption marks the store `damaged` and refuses attach. Later events append through one descriptor per session. `session/flush` is awaited at every durability checkpoint and is where a remembered write error is rethrown — and keeps being rethrown. It does not `fsync`: the modelled failure is a crash, which the page cache survives, and a power loss lands in the torn-tail repair.

**Single writer per stored session.** A `<id>.jsonl.lock` lease (exclusive create, `{pid, host, acquiredAt}`) is held from publication to disposal, so a second process resuming the same id is refused before it appends a byte. A holder is stale only when provably dead on THIS host (`ESRCH`); everything else refuses naming it, degrading to a manual `rm`, never to two writers. Reclaiming runs under its own `.steal` mutex. Attach re-checks the stored log against the resume seed plus a tail identity, so a foreign append in the read→publish gap is refused. Reads never lock, and a resumed publication is flushed inside the creation transaction, so a held lease or a damaged attach rejects `agents.resume` before any paid work.

Prefix stability is a corollary: the log is append-only and the header written only when it changes, so consecutive requests are append-extensions of their predecessors — what the providers' prefix caches reward.

## 5. LLM vocabulary and the two adapters

`Message{id, role: system|user|assistant, content: ContentBlock[], source}`, where a tool result is a user-role message with `source{kind:'tool', callId}` and an assistant message's source carries `{provider, model, replayState?}`. `ContentBlock = text | reasoning | image{attachment, text} | tool-call{id, name, arguments} | tool-result{toolCallId, content, isError?}`. The stream is a closed union `block-start | text-delta | reasoning-delta | tool-call-delta | block-end | usage | finish{reason, replayState?}` with `reason ∈ stop | tool-calls | max-tokens | aborted{failure} | error{failure}` and `LlmFailure{message, code, status?, retryAfterMs?, requestId?}` — codes, never message text, are what policies route on. Protocol invariants: usage before finish, exactly one finish, deltas only into open blocks. `TokenUsage` counts are DISJOINT: billed prompt is `inputTokens + cacheReadTokens + cacheWriteTokens`. `RETRYABLE_CODES` is the default recovery set (`RATE_LIMIT`, `SERVER`, `TIMEOUT`, `TRANSPORT`, `EMPTY_RESPONSE`, `STREAM_CLOSED`): each is a failure after which nothing but trace chunks was appended, so the next attempt re-derives an identical history.

**Replay state.** A provider that signs its reasoning needs that state back verbatim. It travels as an opaque `ReplayEnvelope{response, blocks?}` on the terminal `finish`; `BlockAssembler` prunes it in step with any block it drops and discards a misaligned envelope whole. The driver stores it on the assistant message's source, and `LlmRuntime` strips it from every message bound for another provider — inside the terminal continuation, after the reconstruction observer, so the log still records exactly what the model was shown.

`LlmRequest.purpose` joins `signal` and `sessionId` as a field the provider never sees, and is absent from `RequestHeader`. **A model call that is not a turn** is `runAuxCall`: it streams, assembles, and appends ONE log-only `llm/aux-call` carrying route, usage and answer, recording a failure before throwing it. It writes no `assistant/chunk` and does not copy the request's messages (`inputSeqs` names them).

Adapters implement `stream(request)` and `resolveModel(model) → {contextWindow, defaultMaxTokens, reasoning:{efforts, defaultEffort?}, inputModalities?}`. Effort ids are adapter-owned and opaque elsewhere; a catalog is ADVISORY — an unlisted id is accepted under conservative defaults, and a known family's prefix lends its facts to a dated snapshot. **An option the provider cannot honour is refused BEFORE any I/O** (`UNSUPPORTED_OPTION`, `UNSUPPORTED_REASONING_EFFORT`, `UNSUPPORTED_CONTENT`) and never dropped, aliased or clamped: the request the log records must be the request the provider served. Retry is a capability on `agent/request-error`, so failed attempts are durable.

- **`llm-deepseek`** — the OpenAI-compatible `POST /chat/completions` with `stream: true`, `stream_options.include_usage`, `thinking` + `reasoning_effort`; tool-call fragments keyed by wire index; block ends, usage and finish deferred to `[DONE]`; cache hits subtracted out of `prompt_tokens`; `reasoning_content` always sent, empty when a turn had none, because in thinking mode with tools attached the provider refuses an assistant tool-call turn that omits it.
- **`llm-anthropic`** — the Messages API: named SSE events, thinking blocks arriving with one `signature_delta`, tool input as `input_json_delta` fragments, usage split across uncached / cache-read / cache-created. Its catalog carries per-model facts measured against the live API rather than read from documentation: windows of 1M or 200K, output caps of 128K or 64K, effort sets that differ by minor version, adaptive effort (`output_config.effort`) versus manual `budget_tokens`, and `temperature` refused with a 400 on some models and accepted on others. Its serializer rebuilds strict user/assistant turns with tool results first, echoing a signed thinking block only when this provider produced it.

**Images are a reference plus a descriptor.** An `image` block carries an `AttachmentRef`, never bytes, plus `text`: the descriptor computed once when the block is built and STORED, because it is what a text-only route is actually sent, and freezing it means a later change of wording cannot rewrite what an old log says the model saw. `core/llm/content.ts` is the one block→text projection (`blockText`, exhaustive with a `never` default). An image is user- and tool-side only: `validateStream` refuses an assistant stream that opens one. **Refuse at admission; substitute at projection — both**: a producer refuses to create an image block when the STEP's route lacks `image`, before any I/O, and an adapter serializing one for a model that cannot take it sends `block.text`, because durable history outlives the model that first consumed it. Each adapter resolves refs itself, per request: a text-only route gets the descriptor, an image-capable route with no store mounted is `UNSUPPORTED_CONTENT` before any I/O, and missing or corrupt bytes are `ATTACHMENT_UNREADABLE`, deliberately not retryable. Array-shaped wire content is emitted ONLY for a message holding an image. The meter charges an image as `min(⌈w·h/750⌉, 1600)`.

## 6. The loop and the tool pipeline

```
followup(m) → next-turn FIFO (wakes)   steer(m) → next-step (wakes)   inject(m) → next-step (no wake)
turn/start
  claim → resolveCallConfig (agent/request) → request/context when changed
        → agent/pre-step (waterfall: reject | enter{messages})   reject ⇒ turn/end{blocked}
  step/start → user/message per entered message
  prompt.assemble → request/header when changed
  CHECKPOINT → llm.stream(frozen request) → assistant/chunk{attempt}* → assistant/message{usage}
       finish error ⇒ agent/request-error (waterfall) → retry (next attempt, same request) | turn/end{error}
  tool calls in model order: tool/call → CHECKPOINT → tools.execute → tool/result
       (cancel ⇒ ABORTED_BEFORE_DISPATCH results; a lost write ⇒ DURABILITY_LOST results, none run)
  step/end → next step while tools owe a request or next-step input exists (≤ maxSteps)
  agent/turn-stopping (serial) → re-read inbox
turn/end{reason} (exactly once) → session/flush → next turn or idle
```

**Durable before every action.** A CHECKPOINT is `session.flush()`. A provider that remembered losing a write says so there, and the turn ends `turn/end{error, code:'DURABILITY_LOST'}` before the next paid request or tool effect, with every remaining call answered and none run — the same shape as a cancellation, so the surface stays balanced.

**The route is resolved once per step**, before the pre-step listeners, with `request/context` written immediately after, so a pressure check measures against the route and window THIS step will use. The resolved config is fixed for the step: every retry attempt uses it, so a header and its context record can never describe different requests, and a switch takes effect at the NEXT step. The driver builds its request per ATTEMPT, because a recovery listener may legally change the log between attempts.

`agent/status` is emitted only on real `idle ↔ running` transitions; one `AbortController` per turn; `cancel(cause)` clears the inbox and aborts; `whenIdle()` is quiescence; dispose = cancel → whenIdle → unwind scope → detach agent → detach session. The driver promise is fire-and-forget and reports (`agent/error`) instead of rejecting unobserved.

**Tool execution**, every event in the acting agent's scope: validate args → `tools/pre-execute` (`allow | deny | ask`) → monotonic deny-only guards (globals, then the agent's) → `ask` → `approval.request`, anything but `allowed-once` denies → **deadline armed** → `tools/execute` (around-middleware over the body) → body → validate + freeze value → `render` → `tools/post-execute` (`accept{content?} | block{feedback}`) → normalized result → `tools/result`. Guards run BEFORE the ask, so a call they would refuse anyway never interrupts a person. Every throw becomes an `isError` result with `{name, code}`. Only `{name, description, parameters}` of a tool ever reaches the model.

**Deadlines are the pipeline's.** `ToolDefinition.timeoutMs` declares a budget (omitted takes the registry default, `null` opts out) and the registry enforces it, because the kernel waterfall passes `next()` no arguments. The clock starts *after* the gate. A body whose deadline runs out ends as `TOOL_TIMEOUT` with its signal aborted, and a late result is discarded. Consent taken INSIDE a body (the shell's escalation) waits on `ToolExecution.callSignal` — the caller's cancellation without any deadline — and such a tool owns its whole clock (`timeoutMs: null`).

**Context pressure** is `core/metering`, one definition shared by the compaction trigger, the terminal and the CLI: a pure fold over facts the log already holds. It prefers what the provider charged plus a ~4-chars/token estimate of every surface node appended since; a `replace`, or a `request/header` landing after the priced call, invalidates the anchor and the whole surface is re-estimated. Session totals additionally fold `llm/aux-call` usage. Estimating low right after a compaction is the safe direction.

**Compaction** has three ways in and one implementation (`compaction-basic`): **pressure** on `agent/pre-step` (the only hook inside an open turn with no step open and no request built); **context-overflow** on `agent/request-error` for `CONTEXT_WINDOW_EXCEEDED`, answered `{kind:'retry'}`; and **explicit** `compactNow`, deferred to the next step boundary when the agent is running. Its budget is the window the log names for the route the next step will use, or a configured `budgetTokens`; its summary goes through `resolveCallConfig` with `purpose: 'compaction'`, so a model role may send it down a cheaper route. The summary replays the shadowed conversation verbatim under the CURRENT system prompt and tool schemas, so the prefix stays byte-identical to what the loop has been sending. It writes `llm/aux-call`, then `compaction/applied`, then ONE `user/message{source:{kind:'plugin', form:'summary'}, surfaceOp:{op:'replace'}}` citing every shadowed seq. The planner's cut never leaves the retained tail beginning with a `tool/result`. The summary's frame names the union of every seq range this session's compactions have shadowed, and names the recall tool when one is mounted.

**Every attempt is bracketed.** `compaction/start` opens once a plan exists and BEFORE the paid call; `compaction/end{startSeq, outcome}` closes it with `applied` or a decline from a closed union — `summary-failed | summary-empty | summary-not-smaller | turn-started | plan-stale | agent-gone | cancelled`. The applied record carries three numbers in two units: `projectedTokens` is what the threshold compared; `surfaceTokensBefore`/`surfaceTokensAfter` are estimator units and the only pair it is valid to compare, which is why there is no single "saved" figure. **A summary at least as large as the span it would replace is refused.** The automatic triggers give up after `maxSummaryFailures` consecutive fruitless summaries, counted by a fold bounded to this lifecycle and cleared by an applied compaction; `/compact` is a human asking again and is never disabled.

**The hazard is the await, not the mutation.** A summary call takes seconds and a session can start a turn inside that window. Two answers, both required: an explicit compaction on a RUNNING agent is deferred to the next step boundary, and the plan is re-validated against the live surface (`planIsLive`) plus the agent's status in a window with no `await` in it — registry identity first, because it alone says whether an append is legal at all. There is no durable lock bracket, because the mutation is a single append.

**Bounded recall** (`capabilities/tool-history`). `history_read{fromSeq, toSeq}` renders shadowed nodes through `deriveEventMessage`, restricted to the union of `compaction/applied.shadowedSeqs` for THIS session minus its own prior results: not a log reader, not a session search, and it cannot reach another session. It is registered in the deployment globals — so a summary can name it by tag — and hidden from each agent by a `TOOLS.restrict` on that agent's own scope, lifted at its first applied compaction, so a session that never compacts never carries the schema. Two budgets, because recalled text re-enters the live surface: a call over `maxCallTokens` is REFUSED rather than truncated, so the recorded arguments always describe what came back, and the per-session spend is a FOLD over the log rather than counter state — durable across a resume, exact on replay, and monotonic, so recall cannot refill itself by compacting.

**Spill.** Output too large to be conversation goes to `core/spill` — only output with NO OTHER HOME. A shell command's stdout is gone when the process exits, so it is saved and the model gets a head/tail excerpt plus the path; a file the model asked to view is already on disk, so the viewer answers with a line range. The executor's cap is a MEMORY bound; what the model sees is the tool's decision. Retrieval needs no new tool and no authority change: reads are never fenced.

**Workspace instructions.** `AGENTS.md` (and `CLAUDE.md`) enter as a durable `user/message`, never a prompt section — sections must be stable within a session, and a repository file is not the composition's to guarantee. Discovery is least-specific first (the home file, then project root down to cwd); when the byte budget is tight, broad files are dropped whole before the nearest one is truncated. The guard against re-entry folds the LIVE SURFACE, not the log, so a compaction that shadowed the entry re-enters it. It enters only into a NON-EMPTY first-step batch: an `agent/pre-step` listener may add to a batch and never create one, or it revives turns that should have closed.

## 7. Authority

The model proposes, policy decides, the effect boundary enforces, and every decision is a fact in the log.

**One stamp.** `SandboxExecutionPolicy{mode, workspaceRoot}` is resolved per call from `ctx.sandbox`, never assembled by a caller, and shared by every execution world. The mode vocabulary governs FILE EFFECTS only; network and process visibility are outside it. The workspace boundary needs no event of its own: the immutable `SessionHeader.cwd` recorded at creation IS the root for every call in that session, which is why the wire may not choose it freely (§8). `writableRoots(policy)` is the one allow-list both families derive from, and it is a CEILING rather than an equality — a family may grant LESS, never more, so what both keep is "no host file outside these roots is modified". Precedence: an approved one-shot escalation > the session's folded `sandbox/mode` > the composition default.

**Enforcement lives at the effect, not at the gate.** `fs-local` fences `writeText` in process: canonicalize, contain, refuse with `FS_SANDBOX_DENIED` before ANY effect (creating a parent directory is already one), then canonicalize and contain again immediately before the write. Canonicalization decides existence with `lstat` and follows links itself, including dangling ones. It is a check in trusted code over a model-controlled path, with one stated edge: **a HARD link has no link to follow**, so a link inside the workspace whose inode lives outside it passes the fence and the write lands outside (reproducible; §13). Reads always pass. Because the fence is inside the provider, no tool can be the boundary and no tool needs to know about one; there is no policy plugin at `tools/pre-execute` at all.

**Isolation of untrusted CODE is the shell's problem, and the backend is a spawn wrapper inside the shell provider.** `shell-stdio/confine/` picks one mechanism by platform — `bwrap` on Linux, `sandbox-exec` on macOS, none on Windows — and PROBES it functionally before claiming anything, running the real `read-only` profile around `true` from the same builder a real wrap uses. Never a `which` and never a version: a backend that is installed and cannot enforce is the case that matters, and `enforcement` is RECORDED at agent creation, before any command exists to fail closed. What the probe answers is what `enforcementFor` reports and what the stamp carries. A host with no usable mechanism REFUSES a confined policy with `SANDBOX_UNAVAILABLE` rather than running unconfined.

Both mechanisms apply only at spawn and are inherited across `execve`, so the persistent child is wrapped once and bound to the SESSION's policy. The two ways the effective policy can differ get different answers: a durable `setMode` replaces the child and the result says `restarted` — never `reset`, a real neighbouring field that would tell the model its own command killed the shell — while an approved ONE-SHOT escalation is not a session fact at all and runs in a throwaway child that leaves the persistent one its policy and its state.

The bwrap profile is `--ro-bind / / --dev /dev --unshare-pid --proc /proc --die-with-parent --new-session`, plus `--tmpfs /tmp` and a `--bind` per ceiling root under `workspace-write`. Two of those flags close escapes that need no write at all: `--unshare-pid` against a procfs magic link out of the read-only bind, `--new-session` against `TIOCSTI` into the terminal that started the harness. The Seatbelt profile is `(allow default)` `(deny file-write*)` and one re-allowed subpath per ceiling root, with roots passed as `-D` PARAMETERS so no workspace spelling can close the profile string. Seatbelt cannot make a new session, so **a confined child is spawned `detached` on POSIX** — `setsid`, which is `--new-session` by another name — closing the terminal escape on both backends. `TMPDIR` points at whatever writable temp the profile granted.

**A one-shot escalation may not outlive the scope that granted it.** It is never wrapped (`danger-full-access` never is), so it is the one child that is both unconfined and running under the widest authority a session grants. It leads its own POSIX process group, and every group an escalation opened is reaped at disposal — not just the child, because a command that backgrounds and disowns something exits at once and leaves its descendant behind.

**The escalation path.** A refusal is a reported fact rather than a tool failure, and it carries the one legitimate move: retry the SAME command once with `sandbox_permissions` (strictly wider, and only a mode this host could run under) and a `justification`. `ctx.approval` is the consent step; the grant covers that one call and is never recorded as a session switch, so the audit reads it as the `approval/asked{callId}` → `tool/call{callId}` join it is. The justification is model-written text a person reads before answering, so the approval seam strips control characters and clamps it (§3). A shell whose binary will not start refuses as `SHELL_UNAVAILABLE` naming the binary and the remedy, never as a command that printed nothing; a failing WRAPPER is `SANDBOX_UNAVAILABLE` instead, so the model keeps the escalation path on exactly the host that has a backend. **On a confined host the kernel refuses the write instead, and that reads like any other failing command** — so the mounted backend's own denial dialect, never a cross-backend union, earns the same escalation hint. A hint and never a classification, and deliberately incomplete: under bwrap a path beneath the ephemeral `/tmp` is invisible rather than read-only.

**The plane records; a capability speaks.** No service here writes model-facing prose: a switch IS its event, and `context-runtime` turns that event into the durable message the model reads (one per agent per microtask, so a preset moving both knobs says it once). The runtime-context section is a fold of the log and of nothing else — it states the stamp THIS lifecycle opened under, `enforcement` included, so a shell world swapped under a live agent cannot rewrite the prefix a provider's cache is keyed on. It names the CANONICAL workspace root, the one the fence and every denial name.

**Every decision is durable.** `sandbox/mode{mode, enforcement, reason}` and `approval/policy{policy, reason}` are log-only, folded by `findLast` (and by `openingSandboxStamp`/`openingApprovalPolicy` where a lifecycle's opening is what matters): the OPENING value at creation (`initial`, before publication), a change only when it changes (`change`), and for the sandbox a `resume` stamp when a resumed session's host enforces differently. `enforcement` is what the SHELL world reports — the fs fence is in-process and always complete. Nothing mutates authority out of band, and a resumed session keeps what it recorded rather than inheriting the deployment default. `approval-headless` answers `allowed-once` only under `--approve`; otherwise the fail-closed `unavailable` stands. `minidsh sessions show <id> --audit` projects the whole plane back out of any stored log.

**A delegated child opens under a ceiling.** A child (`capabilities/tool-subagent`) is created with its parent's authority captured BEFORE the first await, and both knobs are stamped inside `setup`, before publication, with `reason: 'delegation'`. That first stamp is a CEILING held three ways: approvals pinned `never` and enforced before dispatch; `setMode`, `setPolicy` and the escalation path refusing to widen past it (`SANDBOX_CEILING`, `APPROVAL_PINNED`); and the authority invariant rejecting a widening stamp pre-commit. Narrowing stays legal, and a delegation ROW may narrow it too. The ceiling is durable, so a resumed child comes back under it, and a fork boundary that would cut below a delegated session's opening stamps is refused.

**Presets select, the knobs decide.** `apply(session, name)` validates against a delegated session's ceiling and pin, appends the log-only intent, then writes through `setMode`/`setPolicy`. The current preset is DERIVED from the two folds; `custom` is what a non-matching pair displays as. The shipped table is `workspace-write` = workspace-write + ask and `danger-full-access` = danger-full-access + never, replaceable from the row's config.

**Consent-by-composition.** A per-agent preset (§9) mounts plugins on the agent scope, and `approval/request` dispatches in the asking agent's scope, so a preset-mounted answerer CAN auto-approve for its own agent. That is not a bypass: whoever writes the composition already holds code-equivalent trust, and the audit still records every pair. What a preset structurally CANNOT do is widen enforcement — a scoped `SANDBOX` shadows only scope-mounted plugins, while the fs fence and the shell resolve the global one — nor reach a deployment-global registry.

The `core-authority` invariant rejects a forged `sandbox/mode` or `approval/policy` before it enters the log, holds every approval to exactly one decision, and holds a delegated session to its ceiling and pin; the presets capability registers its own invariant — the first capability-owned one — rejecting an `authority/preset` that names no table entry.

## 8. Surfaces

A surface injects only `agents` and `sessions` — plus `llm` for the catalog handshake and `sandbox`/`approval` for the authority control plane — owns transport and process exit, and renders from `session/event`. It holds no authority state of its own: a switch it asks for becomes a durable event it reads back like any other. Every plain-text surface renders through ONE projection, `app/present.ts`, which also neutralizes control characters in model-supplied text, because a terminal executes what it is written. The browser renders structured DOM per event type: a different projection, not a second copy, duplicating no fold.

### The headless CLI

`minidsh run "<task>"`, `resume <id> "<task>" --headless`, `fork <id> "<task>" [--at seq] --headless` — boot → `settle()` → create/resume/fork → `followup` → `whenIdle` → `flush` → last assistant text on stdout, exit 0 iff the turn completed.

- One preamble (`prepareBoot`: flags, settings, the disk layers layered ONCE, `--preset`, `--agent-preset`), so `config`, `--preset` validation and `sessions` read exactly the rows a boot mounts.
- One flag table decides which flags take a value, which each command accepts (a flag a command does not list is refused, never ignored) and every usage line. A flag whose VALUE can be wrong is refused in the same words the wire uses: `--cwd` must name an existing directory, `--max-steps` a positive integer, `--at` an integer seq, `--port` a number.
- `--help`/`-h` print usage and exit 0; `--version`/`-v` print `minidsh <version>` and exit 0 before help, boot-free, from the one string `app/version.ts` reads out of `package.json` and passes to both protocol hosts. A preamble failure is exit 2; `sessions` alone downgrades a broken settings file to a warning, because reading a stored log must not depend on it.
- `--json` streams `{sessionId, event}` frames. `--sandbox`/`--ask`/`--preset` set this run's authority and, given explicitly, are applied as a durable switch, so they govern a resumed session too. `--patch <file>` (repeatable) layers over the composition; `--agent-preset <name>` composes the agent's world.
- `minidsh config [--json]` prints the *effective* composition with per-row provenance, flags authority-sensitive rows a layer changed (by capability, so an inserted row is flagged too), and parses every enabled row's config against its plugin contract. `minidsh sessions list/show` read through the effective persistence row; `show --audit` projects the authority timeline.

### The client protocol (`capabilities/protocol`)

JSON-RPC 2.0, DSH's SDK-protocol shape — newline-delimited on a stream carrier, one text message per frame on a socket. Malformed frames are ignored, unknown methods answer `-32601`, stdout is reserved for frames. **One plugin, ONE host, N carriers**: `serve` mounts a stream carrier on process stdio, the terminal mounts the same plugin on an in-process duplex pair, `web` mounts a WebSocket one. Agents created over the wire are owned by the plugin's context.

| method | params → result | rule |
|---|---|---|
| `initialize` | `{} → {serverInfo, providers, defaultAgentOptions, defaultAuthority, workspaceRoots, workspaces}` | the catalog handshake; defaults read LIVE from the settings store where one is mounted |
| `session/prompt` | `{sessionId?, text, mode?: followup\|steer\|auto, agentOptions?, cwd?, workspaceId?, path?} → {sessionId, messageId}` | absent id creates; live id delivers (with `agentOptions` as a durable switch); stored id resumes (racing prompts share one resume). `cwd` must be an absolute, existing directory inside `workspaceRoots` — the wire chooses WHERE inside the host's policy, never the policy; `workspaceId`+`path` names it instead; all three refused alongside a `sessionId`. The RESOLVED route must name a provider this host has an adapter for |
| `session/attach` | `{sessionId, limit?} → {header, view, page, cursor, damaged?}` | the paged attach (below); subscribes the connection BEFORE the page is cut |
| `session/page` | `{sessionId, throughSeq, beforeSeq?, limit?} → {page}` | walks backwards beneath the attach cut; `throughSeq` past the cursor is refused |
| `session/detach` | `{sessionId?} → {}` | no id narrows to NOTHING |
| `session/events` | `{sessionId, fromSeq?, toSeq?, limit?, omitTrace?} → {header, events, damaged?}` | the raw archival read, every tier; bounded at both ends it is the gap repair |
| `sessions/list` | `{workspaceId?} → {sessions}` | live and stored, newest first, the live half winning the union; each carries a derived `title` |
| `session/cancel` | `{sessionId, keepQueued?} → {}` | `keepQueued` leaves the durable inbox alone: one client's cancel is not licence to discard another's prompts |
| `session/compact` | `{sessionId} → {kind: compacted{…} \| scheduled \| nothing-to-do{reason?}}` | a HUMAN command, never a model-facing tool; `scheduled` when mid-turn |
| `approval/answer` | `{sessionId, id, outcome} → {outcome: accepted \| not-pending}` | keyed by the durable `approval/asked` id; first answer wins across clients |
| `session/authority` | `{sessionId, sandbox?, approval?, preset?} → AuthorityView` | no arguments reads; each switch IS its durable event; `preset` exclusive with the pair |
| `session/model` | `{sessionId, provider?, model?, reasoningEffort?} → AgentOptions` | no fields reads the base route; each given field merges as one `agent/options{change}` |
| `settings/describe`, `settings/get`, `settings/set` | `{ns, patch, expectedRevision, replace?}` | `expectedRevision` REQUIRED; a stale or invalid write is the caller's error |
| `shutdown` | `{} → {}` | dispose-to-idle, host-wide, carrier-gated: stdio and the loopback pair may call it, a socket may not |

Notifications: `session.event {sessionId, event}` (the durable event verbatim), `session.status`, `session.view`, `settings.changed`. **Approval frames are the durable events.** There is no DTO layer and no protocol version until a client ships independently of the host; clients ignore unknown event types.

- **The attach contract.** `session/attach` answers with the header, a **message-aligned tail page**, the **cursor** it was cut against, and a `SessionView`. Only `user/message` and `assistant/message` that ARRIVED spend the page budget — a `tool/result` is not a message and a compaction summary is not an arrival — and the cut is pulled back to the message's own `min(seq, ...sourceEventSeqs)`, so a message is never split from what produced it. A replacement's citations are deliberately NOT honoured. A client `limit` is clamped, and an event ceiling bounds a page beside the message budget. **Pages never carry the trace tier**, so `Session.facts` IS the page source and a bare seq is a sufficient dedup key. There is **no lower-bound cursor**, by design: a reconnecting client re-attaches and replaces its window, and a hole inside one connection is repaired with a both-ends-bounded `session/events`. A cold read never resumes the session.
- **`SessionView`** is the live control plane widened to exactly what a client holding one PAGE cannot fold: `{status, context?, pendingApprovals, authority, options?, route?}`. It is empty of `pendingApprovals` for a session read COLD. **No surface node list crosses the wire, because no client folds the surface.**
- **Multi-client.** The host is per-DEPLOYMENT; a `ClientConnection` owns only its frame sink and its watch set. A fresh connection receives every session and narrows on its first attach; a disconnect disposes nothing. Approvals are broadcast and the first answer wins; who could answer is recomputed from the LIVE connections after every watch-set change, and a question no connected client can see any more is settled `unavailable`. A request asked while NO connection could see it is delegated down the waterfall instead of parked.
- **A delegated child is its parent's while the parent is running it.** One predicate — the header names a `delegatedBy` that is still live, and this host did not itself resume the child — carries two rules: the child is READ-ONLY over the wire, and its stream reaches only a client that attached to it by name. A child this host RESUMED is the host's to drive, under the ceiling its log records.
- **Backpressure is tier-aware.** `session/event` is a synchronous contained emit, so a listener cannot suspend the loop: over a per-connection soft limit the TRACE tier is dropped; facts and surface events are never dropped, and past a hard limit the socket is closed as `slow-client` so the client reattaches.

### The two interactive clients

- **The terminal** (`app/terminal`) is a protocol *client*: streaming render straight from durable `assistant/chunk` text deltas, every other line from the shared projection, typed input steering a running turn, `y/N` answering approval frames, and `/sandbox`, `/ask`, `/preset`, `/model`, `/compact`, `/history`, `/sessions`, `/cancel`. It shows context pressure from `session.view` and **retains nothing of the session**. Typed input is sent as `mode: 'auto'`, so the host decides steer-vs-followup in the tick it delivers. Interactive `resume`/`fork` are prepared host-side by the app assembly — there is no wire-level fork method, and a stored id in `session/prompt` resumes.
- **The browser** (`minidsh web`, `app/web.ts` + `app/web/`) speaks the same protocol over a WebSocket, with a static client of plain ES modules and no build step. **Its transcript GROWS rather than being rebuilt**: `SessionWindow` reports which of four shapes it performed — `reset`, `append`, `prepend`, `view` — and a compaction's `replace` appends one note above the messages it shadowed. Scroll ownership is sampled just BEFORE each mutation and never stored, so an append follows a reader at the bottom and leaves one who is not, and a prepend restores `scrollTop` by the height it added. **It is an authority surface** — a client there can write files and run commands — so it binds loopback unless `--host` says otherwise, and `GET /?token=…` exchanges the one-shot launch token for a signed HttpOnly SameSite=Strict cookie before redirecting to a clean `/`; every later request and the upgrade check that cookie behind a Host/Origin fence. The Host allow-list is built from what was actually bound; a WILDCARD bind has no authority of its own, so the fence falls back to "an Origin must match the Host it was sent to", and the printed URL is a loopback authority a browser can open (an IPv6 bind bracketed). A request-target the host cannot parse is answered `400` after the fence, never thrown out of the server callback. There is no per-user identity: many windows, one principal.

## 9. Composition, configuration and packaging

What MiniDSH *is* is data: the built-in rows plus declarative layers on disk, one algorithm, one record. Four planes stay distinct — **composition** (which plugins, their config), **settings** (user defaults over app assembly), **credentials** (named secrets), **authority** (never configuration: recorded events beat composition defaults by fold precedence, always).

**Home layout** (`MINIDSH_HOME`, default `~/.minidsh`): `sessions/*.jsonl(.torn|.lock|.lock.steal)` · `spill/<session>/*.txt` · `attachments/v1/objects/<xx>/<sha256>` (content-addressed, no sidecar — the LOG is the metadata store) · `composition.json` · `settings.json(.lock|.writing)`, the only CONFIGURATION file the runtime writes and only through the settings store · `credentials.json` · `AGENTS.md` (model-facing context, never configuration). Paths resolve in `app/home.ts` only and travel down as plugin config; nothing below `app` may import the home.

**Composition.** `Row{id, plugin, config?, disabled?}`; `Patch = {id, config?|disabled?} | {insert: Row[]}`. `applyPatches` replaces a row's whole config, warns and skips unknown ids, appends inserts. `applyLayers` runs it once per named layer, records per-row provenance (a row is marked by a layer only when the patch CHANGED it), and refuses duplicate ids. Layer order is fixed: **built-ins** (`compose()`, 35 rows, plus rows a surface contributes — serve's protocol row, which a disk layer may target but may neither disable nor reconfigure, since its config carries live streams) → the programmatic **app** layer → **home** `composition.json` → repeatable **`--patch` files**. Direct authority flags are inputs to `compose()`, so a disk layer can override them; what makes an explicit flag win is `applyAuthority`, a durable per-session switch after creation. On disk a row's `plugin` is a builtin catalog name or a module specifier resolved against the file's directory and imported (Node type-strips a `.ts` outside `node_modules`; the module exports exactly one plugin; authors use erasable syntax). Its OWN imports are its own problem — in a checkout it can reach the repo by absolute `file://` URL, and from an installed package there is no repo, so a plugin needing `zod` or a core seam must sit in a directory with its own `package.json` and `node_modules` (§13). **Every shipped plugin with a config declares its contract**, so a stale key fails boot naming the row. **composition.json is code-equivalent trust** and an input, never a persistence target. There is deliberately no workspace-level layer: a repository may say how it likes its code and may not say what the harness is allowed to do. The home layer may patch even authority-sensitive rows — it IS the deployment — but never silently: `minidsh config` flags them by capability.

**The composition record.** Every boot appends a `composition-record` row *outside* the layers. On agent creation, pre-publication, it appends log-only `composition/applied{hash, layers, rows}` iff it differs from the log's last, so a resume under an unchanged composition logs nothing and a fork inherits its parent's stamp.

**Runtime recomposition.** `mount()` returns the `Composition` handle (an app-only service): `insert`, `remove` (the kernel cascade parks dependents pending), `reconfigure` (validate the new config against the row's contract FIRST, then dispose and remount). Row changes are serialized. A fixed spine set `{session, llm, tools, prompt, agent, loop, persistence}` refuses removal or reconfiguration while agents are live.

**Agent presets.** `composition.json` may declare `agentPresets: {name: DiskRow[]}` — named per-agent worlds mounted on the agent scope during creation, recorded as `agentPreset` in the session header so a resume or a child composes the same world. Registrations and services live and die with the agent; the factory's scoped fail-loud settle gates unmet deps and bad configs; a preset row reaching into a deployment-global registry fails its agent's setup.

**Settings.** `settings.json` `{agent: {provider?, model?, reasoningEffort?, maxSteps?, maxTokens?, temperature?}, revisions?}`, zod-validated, resolved ONCE at process entry with precedence flags → `MINIDSH_MODEL` → file → built-ins, then passed down as `BootOptions.agentDefaults`. On resume it sits in the *defaults* tier: the log's folded base route wins. At runtime the boot claims the `agent` namespace with the PURE BUILT-INS as its base (the store re-applies the file as its own user layer), and `MINIDSH_MODEL` travels separately, applied above whatever the store resolves. The store owns the document: every write re-reads it inside a lock, validates the merged value before persisting, and replaces the file by rename. The model-role table stays a capability row's config, not settings.

**Retention: content is never swept; an affordance may expire.** An attachment is content, content-addressed and shared across resumes and forks. A session log is content AND the only script its arc replays from; deleting one needs an authority above the append-only seam that this system does not have. A spill file is an affordance — the excerpt beside it is already the truth of what the model saw — so it is the one store a sweep may touch. `spill-local` sweeps it in **one pass at load**, started there and awaited at disposal, never ON disposal, because a fork inherits its parent's locators. Per file and STRICTLY older than one cutoff snapshotted before the walk. Names are matched against the exact shapes this store generates, never by prefix, so a backup a person put here is not eligible. `lstat` everywhere, so a symlink is skipped rather than followed; `unlink` per file plus a non-recursive `rmdir` of a directory that is empty AND itself older than the cutoff (mtime read before any delete, since deleting bumps it). One knob, `cleanupPeriodDays` (default 30; `0` disables), and every failure is contained: a store's housekeeping may not fail a boot.

| store | class | lifetime |
|---|---|---|
| `sessions/` (including delegated children) | content, and the replay oracle | never removed by the harness |
| `attachments/v1/objects/` | content, shared by address | never removed |
| `spill/<session>/` | affordance | age-swept at load, `cleanupPeriodDays` (default 30) |

**Defaults and environment.** The shipped authority default is `workspace-write` + `ask`, and on a host with a confinement backend an ordinary task under it costs zero prompts. Which mechanism confines the shell is one knob on the `shell` row — `confinement: auto | none | bwrap | seatbelt`, default `auto` — and `shell-stdio` is authority-sensitive, so a disk layer that changes it is flagged by `minidsh config`. `none` is not a weakening but a name for what every host without a backend already does. Environment: `DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY` (credential *references*, from the environment first and then `credentials.json`), `DEEPSEEK_BASE_URL` / `ANTHROPIC_BASE_URL`, `MINIDSH_HOME`, `MINIDSH_MODEL`.

**Packaging.** Development and tests run the `.ts` source natively; Node refuses to strip types under `node_modules`, so what SHIPS is an emit. `pnpm build` (`scripts/build.ts`, also `prepack`) cleans `dist/`, runs `tsc -p tsconfig.build.json` with `rewriteRelativeImportExtensions` so `./x.ts` specifiers become `./x.js`, copies the browser client's four files verbatim, and smoke-imports `dist/app/cli.js` so a broken emit fails the build rather than the user's first run. `package.json` ships `bin`, `dist`, `README.md`, `LICENSE`, `NOTICE` and nothing else — no `main` and no `exports`, so V1 publishes a binary, not an importable surface (BLUEPRINT §3). `bin/minidsh.js` decides by package SHAPE, never by staleness: `../src/app/cli.ts` beside it means a checkout, otherwise `../dist/app/cli.js`; below Node 24 it refuses, naming the version it found. `app/version.ts` resolves `../../package.json` from `import.meta.url`, which holds in both layouts.

## 10. Verification

Tests mount real compositions through the kernel; only the model is scripted (`test-support/scripted-adapter`) or replayed from a recorded session log (`test-support/llm-replay`, which derives the script from `assistant/chunk` groups per (turn, step), replays EVERY terminally-finished attempt, serves out-of-loop calls from their `llm/aux-call` records through a second cursor, and asserts every recorded call was consumed). **A live session log is its own test oracle** for the session that WROTE it; sessions are matched to logs in first-request order. The protocol is tested byte-level over an in-memory duplex pair; the terminal's render folds are pure functions plus scripted runs over the loopback carrier; the browser client's window rules have unit tests, its rendering does not.

Runtime invariants — the session relational trace (pre-commit), agent status no-repeat, and request reconstruction — run in every test *and* in live runs, because `compose()` mounts them by default. **Cross-capability claims are tested against the full composition** (`app.test.ts` over `bootComposition`), because a partial composition is where such claims were found false. End-to-end verification asserts the world, never the agent's self-report.

**Gates.** `pnpm check` = `tsc --noEmit` + `oxlint` + `check-deps` + `vitest`, run by `.github/workflows/check.yml` on ubuntu, macos and windows, followed on every platform by an install smoke: pack the tarball `prepack` builds, install it into an empty directory outside the checkout, and start the installed bin. **A leg that exists to prove something may not go green having proved nothing**, and in a summary a skip and a pass look identical — so `MINIDSH_EXPECT_CONFINEMENT=1` (Linux, macOS) turns a self-skipped confinement test into a failure, and `MINIDSH_EXPECT_SHELL=1` (all three) does the same for a missing shell dialect. `live.yml` runs the arcs on `workflow_dispatch` only, refusing to start without both provider secrets for the same reason.

`pnpm test:e2e` runs the eight live arcs (gated on `DEEPSEEK_API_KEY`; routing also on `ANTHROPIC_API_KEY`). Seven drive a `minidsh serve` child over real stdio JSON-RPC; the eighth drives a `minidsh web` child over a real WebSocket. Both harnesses bound every request with a deadline that names the method, and build the child's environment without `MINIDSH_MODEL`, so an arc's own settings are its only route input.

| arc | what it proves |
|---|---|
| `live` | a task completes, a SIGKILL mid-turn is repaired, a second process finishes the work, and the log replays keylessly |
| `authority` | an edit inside the workspace lands and one outside is refused and probed ABSENT; then the shell, BRANCHING on the enforcement `initialize` reports — unconfined, the command is refused, the model escalates, the client approves and the approved call's own result proves it ran; confined, an ordinary command costs nobody a decision and an outside write leaves no host file while every approval is `rejected`, with the attempt scoped to that turn and naming its target. Finally a switch to `read-only`, where the next write is both attempted and refused |
| `composition` | a from-disk composition inserting a module-loaded tool and a settings.json choosing the route; the tool's output, the header, the `composition/applied` stamp and a wire preset switch asserted from the log, and the keyless replay asserted from the replayed session's own log rather than cursors alone |
| `context` | a real budget crossing; AGENTS.md demands a header the written file carries; output spills and the model both reports a value present only in the omitted middle and is shown to have READ the saved file; the shadowed seqs are exactly what the replace cites |
| `routing` | a session starts on DeepSeek, switches to Anthropic mid-session, and the log proves the route is one fact; a `compaction` role sends the summary down DeepSeek; the mixed log replays from one script |
| `delegation` | a child completes a bounded search under `reason: 'delegation'` stamps, every approval it asked for refused without a client being consulted, and a wire attempt to widen the resumed child refused |
| `verification` | the parent's `view_image` is refused `UNSUPPORTED_CONTENT` while a delegated child, routed to the vision model by one `model-roles` entry, reads a PNG the TEST drew; the binding is asserted before any answer |
| `web` | the token-for-cookie sign-in, two clients on one host, a real consent over the wire, the transcript paged to seq 0 losing nothing, and the socket killed mid-turn with the host still serving |

Every session close requires all eight arcs green, on an idle machine, and a green run is not a diagnosis. When an arc stalls, the harness names what the session was parked on; every count an arc asserts says what produced it. **A live arc's premise is an assumption about the model, and it decays silently** — when an arc has ONE assertion separating the working system from the broken one, ask what the model would answer knowing nothing.

The repository also carries one guard that is not part of MiniDSH: `.claude/hooks/guard-repo.mjs` refuses to link anything to a `node_modules` tree and refuses a recursive delete of a path that is such a link or holds one (CLAUDE.md §8).

## 12. Divergences from DeepSeek Harness (the ones that still shape decisions)

- **Scale and substrate.** Own kernel instead of Cordis, with a structural `{parse}` config contract per plugin rather than a schema library inside it. One package with a dependency gate instead of several hundred; a capability is a directory.
- **Concurrency.** Sequential tool execution, one foreground child at a time, no background jobs — DSH's own `minimal` preset ships none either.
- **The wire.** One protocol (DSH's SDK shape) instead of three, adding `session/cancel`, `approval/answer` keyed by the durable id, `session/authority`, and a catalog-returning `initialize`. No lower-bound attach cursor (DSH's shape too), but a gap repair bounded at both ends and a host-enforced page ceiling; pages omit the trace tier where DSH packs it. Watch sets and a tier-aware drop policy where DSH has per-follower copies and unbounded queues. Approvals settle `unavailable` when nobody is left who can see them; DSH's stay pending forever.
- **Confinement.** Two backends where DSH ships four, with the bwrap profile adopted flag for flag. No Landlock: DSH's is a static C launcher shipped as per-platform npm packages, which a zero-native-dependency tree with no build step cannot carry. No Windows backend (§13). MiniDSH probes a sole platform candidate where DSH skips that, because it records `enforcement` before any command runs rather than failing closed at execution; Seatbelt roots go in as `-D` parameters rather than through an SBPL escaper; and a confined child is put in its own POSIX session, so both backends close the controlling-terminal escape where upstream leaves it to bwrap's flag alone.
- **The ceiling.** `writableRoots` grants the workspace root ONLY, where DSH's shared list adds `/tmp` and `os.tmpdir()`, and it binds BOTH families where DSH lets bwrap and Landlock spell their own — the temp root is where MiniDSH puts every workspace it tests with. `SandboxEnforcement` keeps a third value, `none`: the no-backend posture is a supported configuration here, not an error.
- **Durability.** Plain JSONL through one held descriptor with a session-lifetime write lease; a `.torn` sidecar where DSH salvages a torn tail in place. JSON config with two disk layers instead of YAML and four, read at boot rather than watched. A per-boot `composition/applied` record, which DSH does not keep. No session deletion in either system.
- **Delegation and routing.** A delegation opening is an enforced ceiling where DSH relies on the pin alone; `subagent/start|end` live in the parent's LOG where DSH emits runtime events. Model roles are a seam here and not upstream, and the BASE route is a durable knob separate from the effective route.
- **Context.** No deterministic tool-result pruner: DSH ships one that runs only once a compaction trigger qualifies, and MiniDSH's shipped tools bound their own output. Recall is GATED rather than opt-in: DSH ships `session-query` (a service, a SQLite FTS5 backend and five model-facing tools) and mounts none of it by default, for the cost its own README names — "enabling it adds fixed guidance plus five tool schemas to every model request". MiniDSH's is one tool, restricted to what a compaction shadowed IN THIS SESSION rather than authorised across sessions by `cwd` equality.
- **Surfaces.** A terminal client ships (DSH deleted its TUI) as a protocol client on an in-process carrier. The browser samples scroll ownership immediately before each mutation rather than keeping a ledger of its own writes — which works only while the write lands in the same tick as the sample.
- **Not built.** No PTC (DSH's renamed "Code Mode"), no model-written packages (DSH ships them only in its opt-in `cordis` preset, session-scoped and explicitly not a security boundary), no MCP bridge (DSH ships one disabled by default), no session search index, no workspace config layer, no per-user identity.

## 13. Known limitations (current)

A register, not an essay: each line is a thing a contributor should know before changing the code near it.

**Authority**

- Windows has no confinement backend and is not getting one: DSH's is a native write-restricted-token subsystem, permanently `partial`, with two named escapes (an ambient `Everyone` ACE on an external object, and an NTFS hard link aliasing one file object across paths). There every shell command costs an escalation and a human decision, a headless run without `--approve` cannot run a shell at all, and an escalated command's descendants are not reaped as a group.
- **The fs fence follows symbolic links and cannot follow a hard one.** A hard link created inside the workspace whose inode lives outside it canonicalizes to an in-workspace path, `allowsWrite` returns true, and the write lands on the outside file — reproducible in a few lines against `canonicalPath` and `allowsWrite` directly. Detecting it means reasoning about link counts and inode identity per write, which is not portable; on a confined host the shell is unaffected because the kernel bounds the whole process. It is upstream's edge too (its Windows backend names the same NTFS aliasing escape).
- `full` is a claim about a PROFILE, proven by a functional probe rather than measured per call; nothing reports `partial` today.
- The `shell` row is outside the spine set, so a live `reconfigure` opens a window where `enforcementFor` answers for a world a command will not run in.
- Under bwrap a path beneath the ephemeral `/tmp` is invisible rather than read-only, so its denial earns no escalation hint; macOS gets no writable temp at all, so a tool needing one must escalate.
- **macOS is proven by CI alone** — there is no Mac in this project.
- The shell inherits the harness's environment and the mode vocabulary governs file effects only, so a confined command can read the deployment's provider credentials and reach the network. Deliberate, and upstream's posture too.
- A durable mode switch replaces the persistent shell, so its cwd and environment are gone; an approved escalation runs in a separate shell for the same reason.
- The runtime-context section states what the LIFECYCLE opened under, so a mid-session switch reaches the model as a message; only a `sandbox/mode{resume}` stamp moves the section, at one prefix-cache invalidation.
- A delegation tool registered by an AGENT PRESET lives in the child's own scope, which `restrict` cannot hide and the depth cap does not enumerate: the cap is a cost bound, not a fence.
- The fs fence is a policy check in trusted code over a model-supplied path, while a confined shell is a real kernel boundary — the two families enforce the same mode differently. Escalation is voluntary either way (it depends on the model asking), and `--audit` projects decisions rather than attempts, so a refused command is in the transcript and not in the audit until the model escalates it.
- A module-loaded plugin is arbitrary code; `minidsh config`'s warnings are advisory.

**Context**

- The shipped DeepSeek default never reaches the pressure trigger (0.8 of a 1M window); only the overflow recovery fires on that route unless `budgetTokens` is set.
- A compaction summary is one model call that can be wrong; `history_read` reads the span back, but nothing forces the model to ask.
- The summary's frame names the recall tool from the DEPLOYMENT registry, so a delegation row that `deny`s it and lets its children compact writes a node naming a tool that child cannot call.
- The frame names the shadowed range as `min–max`, which OVERSTATES it; the tool intersects rather than trusting the range.
- The recall tool appears at the first applied compaction whether or not the summary dropped anything.
- The meter changes units at a compaction (safe in direction); a prompt or tool-set change is metered one step late; an image on a text-only route is still charged as an image; a role on a smaller model can be asked for a summary larger than it can take.
- Workspace instructions are read once per entry, not watched, and the two `agent/pre-step` listeners run in a load-bearing row order (instructions before compaction).

**Sessions and stores**

- The in-memory log retains the trace tier deliberately (`seq === array index` at many sites); a 400-turn session is tens of MB of heap.
- The listing memoizes each stored file's summary against its size and mtime, so a repeat `sessions/list` is cheap; the FIRST listing over a large store is still one bounded read per file.
- The spill sweep is ONE pass at load, so a long-running host is not swept until it restarts; a repeated `callId` overwrites.
- An attachment write interrupted between its staging write and its rename leaves a `.part` file under `attachments/v1/tmp/` that nothing reclaims.
- A lost attachment object is turn-fatal (`ATTACHMENT_UNREADABLE`, nothing retries) and image validation is header-only; images have one producer and no client upload path.
- No session deletion and no search, no rename and no model-written title — all of which need a projection, since `persistence.list()` reads only a bounded prefix. That prefix is also why a session whose first prompt exceeds 64 KiB lists without a name.
- Every POSIX process group a one-shot escalation opened is reaped at disposal, addressed by pgid. A group that has entirely exited frees its pid, so a pid-space wraparound within one agent's lifetime could in principle signal an unrelated group — the same unreachable edge the write lease has, needing millions of process creations in between.
- The lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts); a process killed inside a reclaim leaves a `.lock.steal` mutex that blocks later reclaims until removed.
- A turn that loses durability ends but leaves the agent `idle`; reachable only through a provider or driver bug.
- A fork boundary may separate the compaction bracket from the replace that realized it.

**Surfaces**

- `session/events` returns whatever range it is asked for, every tier included; the paged path is what every rendering client uses.
- No host-side RPC deadlines and no client request timeout; the backpressure limits are fixed numbers, not a measured policy.
- The browser authenticates nobody (loopback, one-shot token, signed cookie, Host/Origin fence — reachability, not identity) and cannot switch a session's route.
- Opening a STORED session in the browser leaves `compact` and `cancel` enabled although neither can act until a prompt resumes it: the refusal is honest rather than pre-empted, because liveness is the host's fact.
- A wire client may resume any STORED session, including one whose recorded cwd lies outside `workspaceRoots`: the roots bound where a NEW session may be opened, and a resumed one adopts what its log records.
- A reconnecting client loses its paging position and, if it was the only watcher, a pending approval; a `session/detach` naming one session narrows an un-narrowed client to nothing; no frame says a session was disposed.
- A rolled-back creation's opening facts still reach a watching client, and a prompt delivered between `cancel({disposed})` and the registry detach is dropped and answered as success. Both are deliberate: the fixes would invert documented, test-pinned orderings.
- `--preset` on a headless run leaves the stable prompt section stating the composition default; the injected switch note tells the model. `ToolResult.value` is not durable.
- On Windows the shell dialect is `pwsh`: PowerShell 7 is required and a host without it is refused loudly, never run under PowerShell 5.1 by another name. A PowerShell command that reads stdin blocks until its deadline.

**Delegation and providers**

- A delegated child is foreground and sequential; its cost is summed in `subagent/end`, not attributed to the parent's meter; it is disposed with the tool call that made it and its log stays.
- First-request-order replay matching is exact while delegation is serial and undefined the instant it is not.
- A replay reproduces the model's decisions, not the workspace they named: a recorded call that chose an absolute path cannot land in a fresh root, yet the turn completes and `assertConsumed()` passes — so an arc's prompts pin relative paths, and that steering is a prompt, not a fence.
- An out-of-tree plugin loaded by module specifier resolves its OWN imports from where the file sits. From an installed package there is no repo to reach, and MiniDSH publishes no `main`/`exports`, so such a plugin needs its own `package.json` and `node_modules` (its seams are reachable by deep path into `dist/`). The only extension path any live arc has proved is a fixture inside the repository.
- No OpenAI or Moonshot adapter. A provider catalog is a snapshot: an unknown id gets conservative facts (200K window, 8192 output cap), and a family whose members disagree needs a row per member rather than a prefix.
- Composition changes need a restart; only `minidsh sessions` reads through the effective composition among the one-off tools.
