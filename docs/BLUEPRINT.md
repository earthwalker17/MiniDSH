**The ordering principle: deepen the record before widening the runtime.** Every later capability adds a new kind of effect or a new concurrent actor, and each must be expressible as log facts, under recorded authority, with a recovery rule, so those three come first. One concept runs through the first cluster: a core **effect vocabulary** (what a call is about to do and what it did, written by trusted code from validated arguments, never model prose) with three consumers: the crash record (S14), the consent subject and grants (S15), the audit of effects (S16). Authority precedes jobs because on Windows a background job cannot exist while every shell call is a one-shot escalation. **Checkpoints follow clusters of architectural change** (CLAUDE.md §6): the record and authority planes; the widened runtime; multi-actor and product.

**After S21: children stay foreground.** Background or continuable children wait for evidence that a parent must keep working, or be talked to, while its children run; their recorded home is §3. *Not:* agent teams, mailboxes, schedulers, swarm presets.

**Still refused, with the reason:** model-written extensions (upstream replaced its own with gated plugin installs; `node:vm` is no boundary); an MCP bridge (no demonstrated need); a Windows confinement backend (native bindings, standing ACL changes, `partial` today) and Landlock (a prebuilt native launcher); session deletion (no authority above the append-only seam, none upstream); PTC; a session search index; per-user identity; agent teams.

## 3. Open questions (a decision is pending; the limitations themselves live in ARCHITECTURE §13)

- **`web`'s credential.** The cookie is scoped to a host name, so another server on the same loopback name receives it and its process can replay it (reproduced, S22.5; SECURITY.md). Shapes on the table: serve under a secret path prefix and scope the cookie's `Path` to it; a per-connection token the page holds in memory and sends in the upgrade; what the desktop already does (no jar at all). Each changes what a second tab and a reload need.
- **Signing, then updates.** The four installers are unsigned, so an update is a release page and a person runs the new installer. An identity (Windows: SignPath Foundation, free for OSI projects, or Artifact Signing; macOS: Developer ID plus notarization) is what an updater (electron-updater on GitHub Releases) needs before it can be more than a checksum over a channel whoever publishes a release controls. Repository write access is publish access today (SECURITY.md): tag rulesets or a protected release environment are the owner's settings.
- **What a confined command can reach.** The bubblewrap profile hides the user runtime directory (S22.5). The system bus, a Docker socket, abstract sockets and every loopback service stay reachable, and Seatbelt leaves launchd. A private network namespace would end the loopback half and break every dev-server workflow the browser tools exist for.
- **The deferred audit findings.** S22.5's audit returned 231 findings; every major was fixed, tested or documented. The minors left are of four kinds: tests not yet written (four of twelve named interleavings, the terminal's attach offer, a reconnect or a session switch in a real page, file symlinks); behaviour left as it is (in the terminal a message cannot end in a backslash and a long question is scrolled through before `n` as before `y`; a cancel during the last allowed step ends `max-steps`; 1.2.0 refuses a `settings.json` that sets `maxParallelToolCalls`; a tool-context hook no shipped tool calls); release hygiene that is a repository setting or CI plumbing (write access is publish access, Dependabot does not watch the composite action, `live.yml` keeps no replay evidence of a failure); and one stall nobody explained (one desktop send in nine waited 90 s on a responsive host). None changes what a session is allowed to do.
- **Hands-on validation the release lacks.** No one has run the macOS builds by hand, what Gatekeeper does with a downloaded copy is untested, and the AppImage was driven only unpacked (its own launcher, the keyless suite and one real turn, WSL 2): its FUSE mount was never run.
- **Detached children, when evidence asks.** The S21 panel recorded their home: a `subagent` JobKind whose process is the child (`exited` its run, `kill` its disposal, its output its answer); one `jobs.quiesce` replacing the copied whenIdle → stopAll; root-only; a `job_ids` join on `job_output`. DSH left job-backed children over continuation, not over one-shot children. The primitive they need exists since S21.1 (`Agent.own`), with the idle `/compact` its only consumer.
- **A second surface writer.** Only the compaction planner enforces "a replace never separates a call from its result", and the session invariant admits a `replace`-op `user/message` outside a step but not a `tool/result`. A pruner would be that second writer; the rule moves into the session when one exists.
- **Workspace-lifetime grants.** S15 shipped the session-lifetime shape and the identity any durable grant needs (tool plus exact subject), so only the STORE is open. One that outlives a session cannot live in one log, `settings` may not own authority, and no workspace layer exists: a home-side store keyed by canonical root, COPIED into opening facts, keeps a stored log's audit self-contained.
- **A document input kind.** A PDF block is a vocabulary change (`AttachmentRef`, `ModelModality`, `ContentBlock`, both serializers, the meter); upstream's generic file kind, projected as one handle line and never bytes, gives every model PDF support for nothing.
- **Uploads.** An upload is a new image producer: admission against the step's route at delivery, a store that is never swept, a client-sent ref that could carry a forged `name`. The shape if evidence asks: host-minted upload ids that `session/prompt` cites, plus a retention row.
- **Stopping one child among several.** A child mid-delegation is read-only on every driving method (`protocol/host.ts`). Stopping one is a runtime semantic: which result does the parent's call get?
- **What projection would a rename need?** `session/title` is last-wins, but nothing reads the CURRENT title cheaply: a sidecar, a writer-maintained stamp, or a real projection store (upstream mounts one by default).
- **What does a session present of itself to a provider?** DeepSeek's `user_id` gives each id its own rate budget and OpenAI's `prompt_cache_key` routes its cache; MiniDSH sends neither. One decision for both. Separately, Anthropic caps a request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts.
- **`web_fetch`, and on what boundary.** A dependency-free SSRF guard over `node:https` is feasible: resolve once, refuse the whole answer set if any address is non-public, pin the socket through a validating `lookup`, re-check every hop. Open: HTML extraction without a dependency, the proxy hop, and fetch as the widest exfiltration channel.
- **One egress world, or a fetch per tool?** S18's search fetches in its own body and records nothing; S20's browser fences itself inside Chrome. A shared egress provider could record `effect/recorded{network}` and fence what leaves; per-tool boundaries keep each tool's consent and no common one.
- **Does MiniDSH publish an importable surface?** A module-loaded plugin's own imports do not resolve from an installed package. An `exports` map is a compatibility promise; the first out-of-tree plugin decides. Skills do not need it.
- **A per-boot identity for the lease on Windows.** Linux records `random/boot_id` since S22.5; Windows has nothing without spawning a process, so there uptime still sees a reboot only when the resume comes earlier in the new boot than the lock was taken in the old.
- **A GUI launch's environment on macOS and Linux.** It lacks the login shell's exports and PATH: keys go through `credentials.json`, and agents see the session's PATH. DSH probes the login shell (`$SHELL -ilc`, bounded, delimiter-framed); MiniDSH waits for a macOS build someone validates by hand.
