# MiniDSH Blueprint

What comes next, the route there, what is undecided, and a compact record of how the system arrived. `ARCHITECTURE.md` (beside this file) is the current shape and its limitations; this file is direction and the measurements the architecture map does not carry. Size budget: 30 KB, enforced by `pnpm check` (CLAUDE.md §5). Past 27 KB, compress §4 before adding to it.

## 1. Next session — after V1

V1 is published (§4). Nothing here is urgent and none of it is a feature; the first real need decides the order.

1. **The demo log as a replay fixture.** Record one session doing real work through the installed package, store the log beside the arcs, replay it keylessly in `pnpm check`. A demo that can go stale without failing is a screenshot.
2. **Decide the importable surface** (§3): an `exports` map naming the plugin-facing seams, or the stated rule that an out-of-tree plugin owns its own `package.json`. V1 ships a binary and no `main`.
3. **Publish from CI with provenance.** V1 went up from a developer machine. Trusted publishing (OIDC from a `release.yml` on a `v*` tag, `--provenance`) needs the package to exist, which it now does.
4. **Visual assets.** The README hero image landed on 2026-09-10; a terminal recording, a browser screenshot and a social preview still belong to a session that can look at them.
5. **The routing arc's second failure shape** (the model going off-instruction with the information reachable) is a prompt problem, not a compaction problem; report the two shapes separately until one is fixed.

Verification for any of these is the feature-session gate: `pnpm check` on Windows and under WSL 2 with both `MINIDSH_EXPECT_*` flags, the eight arcs three times on each host, `check.yml` on the branch.

**V1 is** the smallest release a developer can install, point at a repository and use daily without reading the architecture: `chat`, `web` and headless `run` over one runtime; the default preset `workspace-write` + `ask`, under which an ordinary task on a confined host costs zero prompts and an out-of-workspace effect one one-shot approval, both demonstrated against a real model on a real confined host; on Windows, which has no backend, the shell asks per call or the user chooses `danger-full-access`, stated in the README and hinted at the first ask, never silent; keys from the environment or `~/.minidsh/credentials.json`, the first failure naming both; `pnpm check` green on three platforms in CI with an install smoke on each; and the eight live arcs green **three times** before the tag, on two hosts, with the routing arc's flake rate reported rather than hidden. The repetition count is the gate, not the host count: a documented flake is exactly what one lucky run must not be allowed to clear.

**Out of scope for V1**, each with the reason the S8.5 research found: model-written extensions (opt-in even upstream, session-scoped, and its `node:vm` is stated not to be a security boundary); background jobs, continuable children, mailboxes and Agent Teams (upstream's own `minimal` preset ships none; MiniDSH's one-shot foreground child is upstream's one-shot foreground path); parallel tool calls (an optional loop change with modest payoff for three tools); an MCP bridge (shipped disabled upstream); a Windows confinement backend (native bindings, standing ACL mutations, always `partial`) and Landlock (a prebuilt native launcher, and `partial` on a 6.6 kernel anyway); standing approval grants and allow-lists (deferred upstream pending a grant-scope identity); session deletion (upstream has none); PTC / Code Mode; a session search index; per-user identity; a desktop shell.

Ordering rationale: the protocol before any GUI so surfaces never grow semantics; authority before configuration so presets cannot widen permissions silently; the route as a fact before roles and delegation; compaction before delegation because a fork-mode child inherits its parent's surface; verification after routing and after a checkpoint. Hardening checkpoints recur every two feature sessions.

## 3. Open questions (a decision is pending; the limitations themselves live in ARCHITECTURE §13)

- **Background work and parallel tool calls.** Upstream's shapes transfer if ever needed: the inbox as the only queue, an interrupt that parks rather than kills, a producer that must not start work its owner cannot collect, a per-tool `isConcurrencySafe` with results committed in model order. The first real need (a long verification, a watcher) decides.
- **A second surface writer.** Only the compaction planner enforces "a replace never separates a call from its result", and the session invariant admits a `replace`-op `user/message` outside a step but not a `tool/result`. A pruner would be that second writer; the rule moves into the session when one exists.
- **Concurrent children and the replay oracle.** Sessions are matched to logs in first-request order: exact while delegation is serial, undefined the instant it is not (upstream tracks the identical defect).
- **What projection would a rename need?** `session/title` is last-wins and its `source` distinguishes a human's choice from a generated one, but nothing reads the CURRENT title cheaply: a name chosen at seq 5,000 is nowhere near the bounded prefix `persistence.list()` reads. A sidecar, a writer-maintained stamp, or a real projection store; the S11.5 listing cache is a memo of the same bounded read, not a projection. Upstream mounts a projection store by default. The first feature that can choose a name decides it, and a session search index needs the same decision.
- **Two provider facts to design with, not around.** DeepSeek's `user_id` gives each id its own rate budget, a ready-made seam for session identity; Anthropic caps a request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts.
- **Does MiniDSH publish an importable surface?** The composition seam advertises a module specifier as the way to add a capability without a code edit, and that path is checkout-only: an installed package has no `main`/`exports`, so an out-of-tree plugin's `zod` and core-seam imports do not resolve from `~/.minidsh/`. Either an `exports` map naming the plugin-facing surface, or the stated rule that such a plugin owns its own `package.json`. An `exports` map is a compatibility promise, which is why no session has answered it casually.
- **How does a provider catalog stay current?** S11.5 found five Anthropic ids the live API serves that no family prefix matched, each taking a 200K window against a real 1M. The fix was measured rows; the open question is whether a snapshot in source is the right shape or the catalog should be fetched and cached. Nothing decides it until an id changes under a user rather than under a session that can probe.

## 4. Development record

One entry per session: what it decided, and the measurements that still matter. The detail lives in the commits.

- **Docs compaction (2026-09-10 → 09-11).** Documentation only. `PROJECT.md`, `ARCHITECTURE.md` and `BLUEPRINT.md` moved under `docs/` with the README hero image, every reference following (README, community files, issue and PR templates by absolute URL, CLAUDE.md, two scripts, two source comments), a link-and-anchor check proving it. `ARCHITECTURE.md` 95 KB → 74 KB and `BLUEPRINT.md` 27 KB → 21 KB with every heading and table row kept. **What the compression measured:** a first pass told "never delete a contract to make a number" stopped at 90% of the original, exactly where three earlier rewrites had stopped; a second pass with BINDING per-section maxima and a worked example of clause-level cutting reached 52–65% per section, and the parent then restored the rules the agents had listed as their riskiest cuts (several were stated in no section at all, because two sections each cross-referenced the other for them). Nine fixed reviewers then diffed every normative claim of the old text against the new: 1,334 claims enumerated, 235 findings, 124 above narrative — every one of those a rule, a qualifier, a default or a cross-reference that pointed at a section no longer stating the claim — plus one factual error the compression itself introduced (`canonicalPath` called pure); the parent restored them, at a cost of ~7 KB. **The ceiling follows the material, not the wish:** the rules-only content of the architecture document measures ~74 KB after four compactions and a claim-level review, so the permanent budget is 84 KB (the compaction rule bites at 75) rather than the 60 KB first proposed, and BLUEPRINT's is 30 KB; both are enforced by `scripts/check-docs.ts` in `pnpm check` with the internal-link and table-row checks (and `README.md` ≤ 32 KB with the warning at 29, after it was cut from 48 KB to 28 KB for a first-time visitor; a three-lens panel — accuracy against the code, completeness against the old text, first-visitor readability — then found `danger-full-access` gone, the hard-link limitation inverted by compression, and a dozen undefined idioms, all fixed), and CLAUDE.md §5 carries the rule that a document past 90% is compacted in its owning section before anything is added — superseding the V1-era conclusion that 95 KB was settled. Cost: twenty-five subagents in five fixed panels, ~3.5M subagent tokens, two session-limit interruptions.

- **V1 release (2026-09-09).** Publication only. **Gates on the exact bytes that ship:** `pnpm check` on Windows and WSL 2 with both `MINIDSH_EXPECT_*` flags; `check.yml` green on three platforms for both release commits; the packed tarball (119 entries, 251 KB) installed into an empty directory fixed a failing fixture through the installed bin. **The arcs three times per host:** Windows 8/8, 7/8, 8/8; Linux under bwrap 8/8, 8/8, 7/8; `live.yml` ubuntu 8/8, macOS 6/8 then 2/2 filtered. - **S11.5 Hardening checkpoint / release candidate (2026-09-07 → 09-08).** **The first real CI run was red:** two assertions compared a workspace root to itself (`/private/var` vs `/var`; an 8.3 short TEMP), a premise true only on the developer's machine. **Installability:** a `dist/` emit, a `bin` choosing source or `dist/` by package SHAPE, `files` cut to four entries. **Two release-blocking defects from a six-lens audit, verified in the parent:** `minidsh web` parsed the request-target before the Host fence and outside any try/catch, so one unauthenticated malformed line of TCP ended the process; and the shell's escalation `reason` — the MODEL's text — reached the `[y/N]` line unsanitized, where a carriage return and an erase-line repaint the prompt with a milder question. **Four arc assertions could not fail** (an absent line asserted while the model is told the mode changed; the unconfined branch never asserting the approved command ran; a spill needle one multiplication from the prompt; the workspace marker found in the injected message itself). **Authority measured, not argued:** `setsid` probed on a real pty (`echo > /dev/tty` fails under it) is why both confined children are `detached`; a process group outlives its exited leader and stays addressable, which is why one-shot escalation groups are reaped at disposal. Five Anthropic ids matched no prefix and took 200K against a real 1M: a row of measured 400s each. The stored-session listing (5.3 s over 5,000 files, synchronous, on a hot RPC) is memoized per file against size and mtime. **The close-out review found the checkpoint's own worst defect:** compressing `ARCHITECTURE.md` DELETED the fs fence's hard-link edge while leaving the ceiling claim absolute, and the code says it nowhere — S8.5's nineteen lost contracts repeating one session after a lost-contract review was added to prevent it. Restored with four more contracts and the loosened release gate ("green on two hosts" back to "three times before the tag"). **CI found what no local run could:** `minidsh --version | grep -q …` crashed `EPIPE` on macOS alone, present since the bin existed; the `MINIDSH_EXPECT_SHELL` gate had never executed because `check.yml` only triggered on `main`. `live.yml` gained the step that drives a real task through the INSTALLED bin with a fixture that must fail first. - **S11 Confinement & CI (2026-09-06).** **The architecture answer was "nowhere new":** `core/shell` had specified the feature since S3, so S11 added no seam, service, event kind or config plane — one strategy directory inside the shell provider and one knob on an already authority-sensitive row. **The probe is functional, never a `which`:** a bwrap inside a container that forbids user namespaces reports itself perfectly well. The bwrap profile is upstream's, flag for flag. **Why not a hand-rolled backend:** a walk passing only the NEW mount flags failed `EPERM` on exactly the 12 WSL mounts carrying `noexec`; a locked mount may have restrictions added and never removed, and bwrap ORs the existing flags in. **A plan item reversed on evidence:** `writableRoots` did NOT gain the temp root, because every "outside" fixture is a sibling `mkdtemp` under it and granting it would dissolve the workspace/outside distinction; it became a stated CEILING. **A confined host would have been an authority REGRESSION** without the escalation hint firing on the kernel's own denial, not only on `SANDBOX_UNAVAILABLE`. A confined host costs +48 tokens of fixed prefix per request (from +86). Review found a one-shot grant that took the throwaway child only when the world differed, a throwaway stored nowhere so disposal left it running, and both arcs' escape targets under a directory bwrap MASKS. 668 tests; arcs 8/8 three times under bwrap; ~2.1 CNY.

- **S10 Session & product surfaces (2026-09-06).** **The spill sweep** is one pass STARTED at load and awaited at disposal: the plan said synchronous and the probe overturned it (271 ms when half the files go, paid before every first prompt). **A session's name** is a log-only last-wins `session/title` with a first-prompt derivation as the fold's default, so a log written before titles existed still lists under a name; `source` is durable from the first version because a rename must PIN a title against later generation. **The browser stops rebuilding:** one turn cost 197 node insertions and 25 clears before, 16 insertions and no clears after. **What only a real browser found:** streaming yanked a reader who had scrolled away, and the first fix still did, because it deferred the scroll write to an animation frame while sampling before the mutation; the rule is one synchronous write per delta. 636 tests.

- **S9 Context & prompt hygiene (2026-09-05).** Bounded recall of shadowed history, gated on the first applied compaction, its per-session spend a FOLD over the log rather than counter state: durable across a resume, exact on replay, monotonic, so recall cannot refill itself by compacting. **Research overturned the premise:** DSH ships `session-query` and mounts it in no shipped composition, so the divergence is GATING, not absence. **The durable rule planning found:** a `session/event` listener may not append synchronously, because the nested append reaches the file BEFORE the event that caused it and the resumed log is `damaged`. Review found the runtime-context section MOVING mid-lifecycle on a forked session, and refusals charged to the recall budget when the refusal text is what tells the model to retry narrower. **Delegation cost:** four lenses × findings × three verifiers reached 46 agents before the user killed it; the ban had existed since S8.5 and did not hold because nothing made the script state a number. 601 tests.

- **S8.5 Architecture review (2026-09-04 → 09-05).** One bounded workflow against the CURRENT DSH (six primary-source researchers, 192 claims, 228 fetches; verifiers, two auditors, a skeptic). **Research overturned three plans:** extension authoring is opt-in even upstream, so the old S9 was dropped; no session deletion exists upstream; upstream removed the sandbox-mode sentence from its stable prompt after measuring 5 of 12 zero-tool turns. **The audit found** a silent failure on stock Windows (no `pwsh`, every approved command answering `(no output)`) and the constitutional defect: four mandatory documents at ~230 KB. **The diff review found in S8.5's own diff** that the acyclicity gate treated an inline type-only specifier as erased, though Node's type stripping keeps the import and evaluates the module; and that the doc compaction had DELETED nineteen contracts, all restored. 581 tests; docs 196 KB → 112.

- **S1–S8 Foundation through verification (2026-08-22 → 09-02).** The kernel, the core spine, the DeepSeek adapter, JSONL persistence and the headless CLI (S1); two surfaces over one runtime and the durable op-shaped inbox (S2: 11 design corrections before implementation); authority as one replayable plane — one stamp, the fence in the fs PROVIDER, an approval policy enforced before dispatch (S3: untested enforcement is worse than an honest `none`); what MiniDSH *is* became data — home layout, a write lease, credentials, composition.json plus `--patch`, authority and agent presets (S4: `core/presets` is core because a capability may not import a capability); metering, the compaction seam with three triggers and one replacing surface op, spill, workspace instructions (S5: the real compaction hazard is the await, not the mutation); the model as a capability the runtime routes to, the BASE route a durable knob separate from the effective one (S6: DeepSeek refuses an assistant tool-call turn whose reasoning content is missing in thinking mode); the web surface, the paged attach and tier-aware backpressure (S7: a 400-turn session is 103,201 events and 17.0 MB, and a real browser found four things no protocol test could); the attachment plane and a verifier that is a composition row (S8: the descriptor is STORED, so a later wording change cannot rewrite what an old log says the model saw). The hardening checkpoints S1.5, S5.5 and S7.5 found three documented invariants that were not true in code, a crash repair that resumed a history every OpenAI-compatible wire refuses, and a wire client that could prompt a LIVE delegated child so the injected turn silently became the parent's tool result.
