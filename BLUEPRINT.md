# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is unresolved, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## 1. Next session — S5 Context management

Goal: long tasks stay inside the provider's context window without breaking the log's reconstruction guarantees — and resume makes long-lived sessions *likelier*, so this is now the most exposed hole in daily use.

Planned work, in expected dependency order:

1. **Token metering.** The loop already receives `usage` on every `assistant/message`; give the runtime a visible budget: fold cumulative usage per session, expose it to surfaces (a line in the terminal, a field in `session/events` consumers can derive anyway), and let the driver know when a request is approaching the window (`ResolvedModel.contextWindow` exists).
2. **The compaction seam.** A `surfaceOp: replace` provider was designed in S1 and never built: a compaction capability replaces a range of surface nodes with a summary — a log-only summary record plus a `user/message{source.kind:'plugin'}` carrying `{op:'replace', start, end}` — inside the turn, without rewriting history. Decide the trigger (threshold vs explicit), what is summarized first (tool results are the cheap win), and what the summary request itself is (a model call outside the loop: its owner logs a request/result pair — ARCHITECTURE §11 already reserves the shape).
3. **Large-output spill.** A tool result over a size policy goes to a file under the workspace (or home) and the model sees a reference plus a head/tail excerpt — DSH's `spill` subsystem is the precedent to study.
4. **Workspace instructions.** AGENTS.md (and equivalents) injected as context — an `agent/pre-step` listener or prompt section with a stable cache-safe position; decide precedence (workspace file vs composition persona) and record the choice.

Exit criteria: a scripted long session crosses the compaction threshold and continues with correct model-visible history (invariants still reconstruct every request); a spilled tool result is retrievable by the model through a follow-up read; the replay oracle still works on a compacted log; `pnpm check` green; all three live arcs green plus one live long-task arc exercising compaction against the real API.

## 3. Open risks and questions

- **No host can confine the shell.** S3 built the whole seam — stamp, `enforcementFor`, refusal, escalation, durable record — but ships no backend, so every platform reports `none` and a shell command under a confined mode costs a round trip and a human decision. The cheapest real backend is Linux `bwrap` (wrap the argv when the binary exists); Seatbelt and a Windows restricted-token runner are progressively harder, and none can be exercised on the current dev machine. Until one lands, `--sandbox danger-full-access` is what an unattended shell-heavy run actually uses, and it is recorded in the log every time.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell. The live arc shows `deepseek-v4-flash` following it correctly, including when the escalation is then refused; a weaker model may just give up, and nothing should coerce it.
- No compaction (S5): a long session eventually exceeds the context window with no recovery path — and resume makes long-lived sessions *likelier*, so S5 is now the top of the route.
- **No workspace-level config layer, on purpose.** A repo-controlled file that can patch the sandbox row is a trust boundary; DSH marks preset roots with `trust: system|user`. Decide when a real need appears (likely alongside AGENTS.md injection in S5 — the same "what may a workspace tell the harness" question).
- Composition files are read at boot, never watched: a running process keeps its composition. If live reload is ever wanted, DSH's generation stamps + HMR are the precedent — but restart-applies is a fine answer for a local-first harness until evidence says otherwise.
- The settings layer is boot-time app assembly; promoting it to a `core/settings` Definition is DECIDED to wait for the first runtime consumer (S6 model roles). Do not re-litigate; do revisit at S6.
- The protocol serves one client per instance, unpaginated `session/events`, no RPC deadlines — acceptable for stdio and the loopback terminal; the S7 web carrier must solve multi-client mux (DSH's `events.mux` + `session/subscribed{lastSeq}` reconnect-rebuild is the precedent).
- A second adapter whose reasoning must be echoed with a provider signature needs an opaque continuation slot on the reasoning block, and error-time provider fallback is not expressible through `agent/request-error` (retry re-sends the same frozen request) — both S6 decisions.
- **A subagent must not be able to widen its parent's authority.** The plane is per-session and folds from the log, so a child session would fold *its own* — DSH seeds a `source: 'delegation'` stamp into the child precisely so delegation cannot fall back to a wider default. Decide this when the subagent seam lands (S6), not before.
- When to promote to a workspace: the first *independent* out-of-process consumer (`serve`'s clients are external programs, but none ships from this repo yet — the S7 browser client is the likely trigger).
- The session lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts) — fail-safe refusal, documented, acceptable for a local-first harness.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.

## 4. Development record

- **S4 Composition & configuration (2026-08-24)** — Research: two codebase explorers plus a DSH upstream pass (agent-presets/settings/credentials/permission-presets/atomic-write docs and the preset YAML read directly), then an adversarial design verifier with runtime probes on this host. The verifier REFUTED the lease as designed before a line was written: `onPublished` runs in a contained emit, so a second process's refusal would have surfaced only at turn-end flush — after a full paid turn with real tool effects. The fix (the factory flushes a resumed publication inside the creation transaction) also made previously-swallowed attach failures immediate. Other pre-implementation verdicts that shaped the build: `tryGet` bypasses the inject allow-list (the PRESETS-from-the-protocol pattern is house-legal), `AGENT_CREATED` fires before publication so the composition stamp lands in the snapshot exactly once, out-of-repo `.ts` imports type-strip flag-free on Node 24, `EPERM` must count as alive in the lock probe, and the steal needs rename-then-unlink so two reclaimers cannot double-acquire. Three decisions taken with the user: settings resolve at boot in `app/` (the `core/settings` Definition waits for S6's first runtime consumer), agent presets ship as minimal named row lists (DSH's preset directories deferred), and JSON over YAML (recorded divergence). Built in 6 verified phases (home+lease+version guard → credentials → settings → disk composition + record + `minidsh config` → authority presets → Composition handle + agent presets), each committed green. Notable calls: the preset Definition went to `core/presets` because the protocol (a capability) may not import another capability; the recorder row sits OUTSIDE the layers so no layer can remove the record of what the layers did; duplicate row ids are refused (they were half-patchable); serve's protocol row joined the BASE (a disk patch can now target it, and disabling it refuses instead of serving a dead socket); the spine set `{session, llm, tools, prompt, agent, loop}` refuses runtime removal under live agents; and two boundary facts were pinned by test — a preset-provided `SANDBOX` cannot widen the fence (it shadows only scope-mounted plugins), while a preset-mounted approval answerer IS real for its own agent (consent-by-composition, audited, same trust class as editing compose.ts). Also fixed in passing: the stored format version was carried but never checked on the read path, headless runs swallowed every warning, and the shell test teardown survived on timing luck (`rmSync`'s maxRetries never sleeps; MSYS releases its cwd ~100ms after the kill). Verification: `pnpm check` green at 257 tests; live: all three arcs green — the two standing ones plus the new from-disk arc (module-loaded tool executed by the real model, settings-chosen route in the durable header, wire preset switch recorded as intent + both knobs, keyless replay under the same disk composition). The bounded 3-lens review then produced 17 findings, 15 confirmed — the load-bearing ones all in the new durable machinery: `persistence` was missing from the runtime spine (swapping it under a live session silently stopped durable writes while `flush()`, a dispatch with no listeners left, kept reporting success) and its leases outlived the plugin; `attach`'s length guard compared against the *grown* log, so a foreign writer appending in the gap between `persistence.load` and the lease could be adopted silently; the lease steal was a TOCTOU where two reclaimers of one dead holder could both acquire; and `minidsh config`'s authority warning keyed on row id, so a layer inserting `approval-headless {approve:true}` under any other id printed as an ordinary row — blanket consent, silently. All fixed with regressions (261 tests).
- **S3 Effects & authority (2026-08-23)** — Research: DSH `master` still at `b150a55`; its sandbox, filesystem, approval, permission-preset, tool-pipeline, timeout-policy and persistence-catalog docs read directly. Four findings reshaped the plan before a line was written: the stamp is `{mode, workspaceRoot}` with roots *derived* by a shared pure function (not a `writableRoots` field), the fence lives in the fs **provider** rather than at the tool gate (so `policy-workspace` was deleted, not replaced, and no per-tool authority declaration was needed), `ApprovalPolicy` is just `ask | never` enforced before dispatch, and escalation is **model-driven and never automatic** — the executor never negotiates. Three decisions were taken with the user: DSH-faithful escalation over tool-driven auto-approval; `workspace-write` stays the default on a backend-less host (the filesystem is genuinely fenced and the shell must be escalated); and no OS backend this session, because untested enforcement code is worse than an honest `none`. Built in 6 verified phases (vocabulary + approval policy + the shell seam → the fs fence → the shell refusal and escalation → deadlines → surfaces and audit → docs/review/E2E), each committed green. Notable calls: `resolve()` records the stamp when it changes, so every effect is preceded by a recorded stamp without stamping a session that never acts (an abandoned `chat` still leaves no file); a one-shot escalation is deliberately *not* a session switch, and the audit joins it to its command by `callId`; deadlines are registry-owned because the kernel waterfall passes `next()` no arguments, which also corrected a standing ARCHITECTURE claim that a `tools/execute` middleware could substitute the signal; `writableRoots` grants the workspace root only, diverging from DSH's temp grants with a written reason. Verification: `pnpm check` green at 212 tests, including world-asserting fence tests (the denied file and its parent directory must not exist), the escalation matrix, deadline behaviour around a slow approval, and byte-level protocol tests for `session/authority`. Live: the S2 kill/resume/replay arc still green, plus a new authority arc with **no `--approve`** — an edit inside the workspace landed, one outside it was refused and probed absent on disk, `node --version` was refused as unconfinable, the model escalated with a justification, the client approved over the wire and it ran, a `read-only` switch refused the next write, and the fresh log replayed keylessly (~17 s). The first live run earned its keep immediately: it falsified an over-claim that the stamp precedes the `tool/call` record (it precedes the *effect*; the driver writes the call record before dispatch). The 3-lens + batched-verifier diff review then produced 25 verdicts (12 confirmed, 8 duplicates, 3 questions, 2 refuted), all confirmed ones fixed with regressions. The load-bearing one was a genuine fence bypass: `canonicalPath` decided existence with `existsSync`, which FOLLOWS links, so a dangling symlink was invisible to it and the fence contained a name inside the workspace while the write followed the link outside — reproduced on this host with a dangling junction, and closed by deciding existence with `lstat` and following links explicitly. Three more were real: reading authority over the wire stamped a `sandbox/mode`; an approved escalation to `workspace-write` spent consent and was refused anyway (nothing here enforces that mode either); and the prompt's authority block could change mid-session, which `setMode` now prevents by recording what the session opened under before recording the change. The questions were settled as decisions: the approval prompt keeps carrying no copy of the command (the `callId` join is the single source), and the audit projects decisions rather than attempts (ARCHITECTURE §13).
- **S2 Surface contract (2026-08-23)** — Two surfaces over one unchanged runtime, and sessions that survive their process. Delivered the `core/persistence` read Definition with append-only resume (offset-tracking attach, torn tail to a `.torn` sidecar, deeper corruption refuses), `agents.resume`/`fork` as creation modes with crash repair folded into the seed, the durable op-shaped inbox (claim logged after the entered messages, so a crash re-delivers rather than loses), the client protocol as one plugin over two carriers (real stdio and an in-process loopback pair), and the interactive terminal as a protocol client. An adversarial design-verification pass produced 11 corrections before implementation — the load-bearing ones: positional inbox splices corrupt under a steer landing in the pre-step await, graceful shutdown would have durably erased the queue resume exists to restore, and crashed logs broke the replay oracle. The post-implementation diff review found three real defects (dead Ctrl+C on a real TTY, a pasted-lines double-session race, a one-shot flush checkpoint) and settled fork-wake: a fork is a passive branch, born idle.
- **S1.5 Architecture hardening (2026-08-22)** — A falsification pass over the S1 foundation before S2 built on it. Verdict: the shape was right — multimodal, model roles, a second provider, a second surface, sandbox providers and compaction all fit without vocabulary changes — but three documented invariants were not true in code, and were corrected: the scope contract (per-agent layers and agent-scoped dispatch), "model-visible ⟺ logged" (`temperature` in the header), and "the log is its own oracle" (`attempt` on chunks). Also fixed three kernel defects and removed four false affordances. Macro route unchanged.
- **S1 Foundation (2026-08-22)** — The kernel (contexts, plugin instances, reversible effects, a typed scoped event bus), the core spine (event-sourced session, LLM seam, tool pipeline, prompt assembly, agent registry, one loop driver), the DeepSeek adapter, minimal tools, JSONL persistence, and the headless CLI. Every durable architectural question from `PROJECT.md` §7 got a code answer. The live run proved the log is its own test oracle: a real session's JSONL replayed keylessly with every recorded step consumed.
