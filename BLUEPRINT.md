# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is unresolved, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## 1. Next session — S8 Verification capabilities

Goal: make verification a first-class capability, on the two seams S7.5 just proved sound.

1. **Attachments**, per DSH's ordering rules: bytes content-addressed under `MINIDSH_HOME` and stored BEFORE the `user/message` that references them appends; a text descriptor per image so an offloaded attachment stays replayable; blocks carry `{type:'image', attachment:{…}}` and bytes never enter the log; adapters resolve refs at serialization under a per-route size policy. Both adapters already advertise `inputModalities` and neither has anything to send.
2. **A vision verifier as a spawned child** under `read-only`/`never` — a `verifier` model role plus the delegation seam. S7.5 is what makes this safe to build on: a child is now read-only over the wire while its parent runs it, and a child replays from its own log rather than eating its parent's next recorded step.
3. **Verification events**, and with them the durable half of compaction's bookkeeping: failed attempts, which trigger fired, against what budget, and the give-up counter that a resume currently forgets. One vocabulary decision serves both.
4. **A compaction quality check** — the answer to "a compaction summary is one model call that can be wrong", which has been an open risk since S5.
5. **Retention**, decided once for spill files, child session logs and attachment bytes together. Three accumulating stores with one question; deciding it three times is the expensive outcome.

Method that has now paid three times (S1.5, S5.5, S7.5): read every relevant source file first, probe BEFORE planning, then delegate bounded research and a bounded audit. In S7.5 the coordinator's own sixteen probes found nine defects before any agent ran, and the audit's two adversarial skeptics then found two more that five lenses had missed.

## 3. Open risks and questions

- **No host can confine the shell.** S3 built the whole seam — stamp, `enforcementFor`, refusal, escalation, durable record — but ships no backend, so every platform reports `none` and a shell command under a confined mode costs a round trip and a human decision. The cheapest real backend is Linux `bwrap`; none can be exercised on the current dev machine. Until one lands, `--sandbox danger-full-access` is what an unattended shell-heavy run actually uses, and it is recorded in the log every time.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell; nothing coerces it, and nothing should. (Upstream's gate is the same three guards, so this is not a divergence — S7.5 corrected the doc that said it was.)
- **The shipped DeepSeek default still never reaches the pressure trigger.** DeepSeek advertises 1M for every model, so 0.8 of it is ~800k and only the overflow recovery fires on that route. The windows are real per route and logged; a deployment that wants earlier compaction sets `budgetTokens`.
- **A compaction summary is an unverified model call.** Nothing checks it. The seam for the answer exists (a `verifier` role plus a delegated child under `read-only`/`never`); building it is S8's, and S7.5 removed the last reason not to trust that seam.
- **The meter changes units at a compaction.** Safe in direction, approximate by construction. A per-adapter tokenizer would fix it; neither adapter has one, and the two now differ by ~30 % on the same text. Upstream anchors on real usage samples and keeps a heuristic delta separately — the shape to copy when this matters.
- **The in-memory log retains the trace tier, deliberately.** Paging removed the wire half outright. The memory half is ~28-30 MB for a 400-turn session, and evicting would break `seq === array index` at 16 call sites. Upstream's live session is uncapped for the same reason — and it goes further, copying the whole event array per follower observation, which MiniDSH does not.
- **Spill files, child session logs and (from S8) attachment bytes all accumulate, and nothing prunes any of them.** One retention decision, still unmade, now with three consumers. It is S8's first item for that reason.
- **A delegated child is foreground, sequential, one turn — and, since S7.5, not a surface's to drive while its parent runs it.** What is still missing is what upstream has: background jobs, continuable children with a mailbox, and parallel tool calls. The first real need (a long verification, a watcher) is what should decide it. Upstream's transferable rules if it ever lands: the inbox must be the only queue, an interrupt should park rather than kill, and a producer must not start work its owner cannot collect or stop.
- **A second surface writer would need the pairing rule in the session.** Only the compaction planner enforces "a replace never separates a call from its result". Deferred until a second writer exists.
- Composition files are read at boot, never watched: a running process keeps its composition.
- **No host-side RPC deadlines, and the backpressure limits are guesses.** Upstream has neither, so there is no shape to copy; a slow-client incident is what should set them.
- **The browser surface authenticates nobody.** Loopback by default, a one-shot launch token exchanged for a signed cookie, and a Host/Origin fence. Upstream has no per-user identity either, so a multi-principal design would be inventing.
- **No workspace-level CONFIG layer, and a sharper reason than S7 had.** A repo may say how it likes its code and may not say what the harness is allowed to do. Upstream is the caution, not the precedent: it ships repo-controlled tiers (a skill root table where project roots outrank user roots; hooks that execute shell with no approval gate) and fences them with a blanket denial of its own `DSH_*` namespace to project-discovered config.
- **The browser client's DOM has no test and, since S7.5, no browser has looked at it.** Its window rules (dedup, gap repair, re-attach) now have unit tests; its rendering does not, and the Chrome extension was unavailable this session. S7's record is that four defects in this file were found by a real browser and by nothing else, which is why S7.5 fixed its logic and left its rendering alone — including the O(n²) full-transcript rebuild.
- The session lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts) — fail-safe refusal, documented, acceptable for a local-first harness.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.

## 4. Development record

- **S7.5 Architecture hardening & system review (2026-09-01)** — S6 and S7 read as one system, and they had never met. Method: every non-test source file read first, then SIXTEEN local probes which found nine defects before any agent ran, then a bounded upstream-research workflow (6 primary-source areas over the current DSH → an adversarial verifier each → a synthesis) and a bounded audit workflow (5 lenses → 2 whole-set skeptics → a synthesis). The probes decided the work; the skeptics found two things five lenses missed; the research corrected the docs. **What the probes found:** a wire client could `session/prompt` a LIVE delegated child, and because the delegation answers with whatever the child last said, the injected turn silently BECAME the parent's tool result — two clicks away in the browser, which lists a live child as a clickable row; a child's whole stream and its `session.view` were broadcast to every un-narrowed client; the page event ceiling bound only at a message-group boundary and only an ARRIVED message set one, so a range with none returned the whole log (5,000 facts against a ceiling of 2,000); the browser never advanced its cursor across the trace tier it does not store, so every model step spent a gap-repair round trip that could return nothing — and a REAL drop, which is what backpressure does to exactly that tier, was indistinguishable; `transcriptLines` rendered three event kinds where `describeEvent` rendered eleven, so paging back over an authority switch, a denial, a delegation or a compaction showed none of them while watching live showed them all; `publishView` ran O(facts) folds per event for sessions nobody watched; three RFC 6455 frame shapes a server must reject were accepted; `damaged` crossed the wire and neither client rendered it; a configured subagent persona plus any agent preset that registers one made every delegation fail; and one settings.json plus one `MINIDSH_MODEL` resolved to two different routes depending on which surface read it, the CLI's carrying a DeepSeek effort id onto an Anthropic model. **What the audit added that no probe and no lens found:** an approval could be parked FOREVER — a client that was un-narrowed when the question was asked and then made its first attach elsewhere stayed its sole answerer while no longer receiving it (probe-confirmed: `status: running`, nothing left to settle it); and a stored session's attach view offered its undecided asks as live Allow/Deny prompts, because a cold read never resumes and `repairInterruptedTail` has not closed them. **The load-bearing fix is one predicate**: a child whose parent is live and which this host did not itself resume is read-only over the wire AND attach-only on the stream — two rules, one sentence, no new state. The approval fix DELETED a field: answerability is recomputed from the live connections after every watch-set change, which fixes the snapshot in both directions at once. **The replay oracle was the quietest defect**: one cursor served every session, so a replayed delegation fed the child the parent's next recorded step and `assertConsumed()` passed on arithmetic — "a live session log is its own test oracle" was false for every log with a delegation in it, and S8's verifier is exactly that shape. **Deliberately not fixed, with reasons recorded in ARCHITECTURE §13**: a rolled-back creation's opening facts still reach a watching client (four assertions depend on those frames, and the defect is a session a client can never reach); the disposal-window prompt drop (the honest fix inverts a documented, test-pinned ordering); the browser's O(n²) transcript rebuild (no browser was available to verify a rendering change, and S7's record is that only a browser finds those). **Upstream research corrected fifteen claims** about DSH that ARCHITECTURE asserted, of ~200 checked: there is no `model/selection` event (a live ref behind two listeners, which makes MiniDSH's base/effective split a sharper divergence, not a weaker one); DSH SALVAGES a torn tail rather than discarding it; there are three client protocols, not two, and its GUI wire HAS `session/cancel`; its shutdown is stdio-only and its GUI wire has none, so MiniDSH's carrier gating is convergence; `session.fork` is implemented with an `atSeq`, so MiniDSH's absence is a gap and not a mirror; escalation is not grounded in a denial upstream either; its trust markers grade agent-preset roots while it ships repo-controlled config tiers elsewhere; the two-entry preset table is a package default, not what ships; ~150 packages understates by 2-3×; and the lower-bound-cursor JSDoc is real in two files with a `readFrom` seam beneath the wire — MiniDSH still declines a resume cursor, but as a choice. Verification: `pnpm check` green at 488 tests (45 files; up from 465), every reproduced defect now a test, and all seven live arcs green.

- **S7 Web surface (2026-08-31)** — a third surface, and the paging the log had been waiting for. **What the probes settled:** a 400-turn session is 103,201 events and 17.0 MB of JSON, and `session/events` cost 322 ms of `JSON.stringify` on the host's event loop — a page of 300 facts is 58 KB; a cold `persistence.load` is 167 ms and 28 MB; `foldSurfaceSeqs` on a TAIL SLICE throws by design, and after one compaction the live node order is not seq order, which is why no client folds the surface; the log stays a dense zero-based prefix through compaction, fork and repair, which is the precondition the paginator needs; and a hand-rolled RFC 6455 server round-trips a 200 KB frame with Node's own client. **Decisions worth keeping:** the cut deliberately does NOT honour a replacement's citations, because a summary cites every node it shadowed and honouring them would defeat paging on exactly the sessions that need it; the host is per-DEPLOYMENT and a `ClientConnection` owns only a sink and a watch set, which is what makes a disconnect mean "this client left"; backpressure is tier-aware because `session/event` is a synchronous emit that cannot suspend its producer, and the three tiers are what made "droppable" statable; `expectedRevision` is REQUIRED on the settings wire where upstream's fence is opt-in. Three defects the tests found while being written: a detached client stayed in an approval's answerer set; the web host's `Host` check compared the header against itself; and two tests passed vacuously because `waitFor` takes a synchronous predicate. **A real browser run then found four things no protocol test could**, because the arcs drive the wire and never render a DOM: `.banner { display: flex }` beat `[hidden]`; the status line went stale after every turn; the settings pane pre-filled resolved values and saved with `replace`; and the `settings.changed` a write triggers arrives before that write's own response. The 3-lens review + two skeptics produced 12 findings, 10 surviving plus 3 neither lens saw: four WebSocket codec defects, the settings precedence inverted (and the first fix for it wrong too), a lock two processes could steal at once, a terminal that suppressed a message whose chunks the attach cut had swallowed, `--host 0.0.0.0` offered and broken, a launch token called one-shot and never spent, and a browser repair that asked for the whole log from cursor -1. Verification: 465 tests, seven live arcs. Cost: about $0.02.

- **S6 Cognition routing & delegation (2026-08-30)** — the model became a capability the runtime routes to. Two in-memory probes BEFORE planning decided the shape: a global `agent/request` rewriter reaches every agent, so a role would poison a resume unless the base route became its own fact; and a tool body can already create, seed, drive and dispose a child bound to its parent's scope, so the delegation seam existed and needed only a subtractive tool view. Three live provider probes caught the two facts no document stated: **DeepSeek refuses (400) an assistant tool-call turn whose `reasoning_content` is missing in thinking mode**, exactly the shape a turn from another provider has; and **Anthropic's 5 family returns 400 for any `temperature`** while streaming thinking as an empty delta plus one signature. Decisions worth keeping: the BASE route is a durable knob SEPARATE from the effective route, because a role rewriting a request must never become what a resume rebuilds from; `resolveCallConfig` is the one resolution a step and an out-of-loop call share, which makes `model-roles` a five-line listener; the replay envelope is pruned by the assembler in step with dropped blocks and stripped for a foreign provider; a delegation opening is an enforced CEILING where DSH relies on the pin alone; `tools.restrict` lives in the one visibility resolver so a hidden tool is unknown AND refused. The review found 16, 10 surviving: the delegation tool flushed the child before appending `subagent/end`, so the one failure the pair exists to explain was the one it could not explain; a fork below a child's opening stamps kept the lineage while dropping the fence; `AuthorityPresets.apply` wrote its intent before either setter could refuse; the delegation closure became the child's own `Agent.setup`, so a grandchild re-ran its grandparent's opening — and the first fix for that was itself inert. Verification: 394 tests, six live arcs. Cost: about $0.05.

- **S5.5 Architecture hardening & route review (2026-08-28)** — every non-test source file read as one system; runtime probes; a bounded workflow (4 research areas → 4 audit lenses → 2 verifiers; 50 findings, 49 verified). What the probes and the audit found that the tests had not: **crash repair answered logged calls, not the assistant's tool-call blocks**, so a crash during call *i* of *n* resumed a history every OpenAI-compatible wire refuses; every per-step fold walked the whole log, 97 % of which is `assistant/chunk` (`meterSession` 30 ms per pre-step; `appendFileSync` 1 ms per chunk); the composition record made every opened-and-closed chat leave a file; `prepend` is an unshift, so a later middleware silenced the invariant that nothing can silence it; a scope's `provide` widened its plugin's read set for the rest of the process; any wire client could set `cwd: C:/` and get workspace-write over the drive. Decisions: three log tiers named once (surface / facts / trace) — chosen over DSH's incremental projections because one classification serves the runtime, the terminal and S7's paging; materialization on the first conversation fact; durability as a checkpoint before every action; the config contract as a structural slot on `Plugin`; invariants as observers; the wire choosing WHERE inside the host's roots, never the root. Research falsified five claims about DSH and reordered the route: S6 to begin with the route as a durable fact, model roles as composition, spawn-mode children as S6's default, S7 to take the DSH attach shape, and S7.5 added as a recurring checkpoint. Verification: 346 tests, four live arcs, twice.

- **S1–S5 Foundation through context management (2026-08-22 → 08-26)** — the kernel (contexts, plugin instances, reversible effects, a typed scoped event bus), the core spine (event-sourced session, LLM seam, tool pipeline, prompt assembly, agent registry, one loop driver), the DeepSeek adapter, JSONL persistence and the headless CLI (S1); two surfaces over one unchanged runtime and sessions that survive their process, with `agents.resume`/`fork`, crash repair folded into the seed, and the durable op-shaped inbox (S2); authority as one replayable plane — one stamp, the fence in the fs PROVIDER, `ApprovalPolicy` before dispatch, model-driven escalation, deadlines registry-owned (S3); what MiniDSH *is* became data — home layout, a session write lease, credentials, composition.json + `--patch` with provenance, authority presets, agent presets (S4); and context management — `core/metering`, the compaction seam with three triggers and one `surfaceOp: replace`, the out-of-loop model call, spill, workspace instructions (S5). The durable lessons: the log is its own test oracle (S1); design verification before implementation earns its cost — 11 corrections in S2, three refuted load-bearing claims in S5, and the lease refuted as first designed in S4; a fork is a passive branch, born idle (S2); untested enforcement is worse than an honest `none` (S3); `core/presets` is core because a capability may not import a capability (S4); the real compaction hazard is the await, not the mutation (S5). S1.5 falsified the foundation against S2–S8 pressures and found three documented invariants that were not true in code.
