# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is unresolved, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## 1. Next session — S7.5 Hardening checkpoint

Goal: read S6 and S7 as one system and falsify it before S8 builds verification on top of both. The S1.5 / S5.5 pattern, now a scheduled part of the route rather than an exception to it — every two feature sessions, the whole thing is read as one and pressed until something gives.

What makes this one worth doing rather than skipping:

1. **Delegation and a second surface have never met.** A delegated child streams into the parent's log while a browser and a terminal may both be attached; watch sets, the view projection and `subagent/*` were designed independently. What does a client attached to a PARENT see of a child, and what should it?
2. **The host/connection split touched the one surface every live arc drives.** It is the newest load-bearing code in the system and has had exactly one review pass — its own.
3. **The paging contract now has three readers** (terminal, browser, the e2e client) and one algorithm. A cut rule with a message budget, an event ceiling and a group pullback deserves adversarial reading, not just the cases that occurred to its author.
4. **`core/settings` is a new writable plane.** It cannot reach authority or composition by construction; that claim should be attacked, not asserted.
5. **Read every non-test source file first, then probe, then delegate** — the method that paid in S5.5 and S6, where the coordinator's own probes found defects before any agent ran.

Exit criteria: the audit's findings fixed or recorded as deliberate; `pnpm check` green; all seven live arcs green; `ARCHITECTURE.md` and `BLUEPRINT.md` corrected wherever the audit falsified them.

## 3. Open risks and questions

- **No host can confine the shell.** S3 built the whole seam — stamp, `enforcementFor`, refusal, escalation, durable record — but ships no backend, so every platform reports `none` and a shell command under a confined mode costs a round trip and a human decision. The cheapest real backend is Linux `bwrap`; Seatbelt and a Windows restricted-token runner are progressively harder, and none can be exercised on the current dev machine. Until one lands, `--sandbox danger-full-access` is what an unattended shell-heavy run actually uses, and it is recorded in the log every time.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell; nothing coerces it, and nothing should.
- **The shipped DeepSeek default still never reaches the pressure trigger** (ARCHITECTURE §13): DeepSeek advertises 1M for every model, so 0.8 of it is ~800k and only the overflow recovery fires on that route. The windows are now real per route and logged (`request/context`) — an Anthropic session meters against its own — but a DeepSeek deployment that wants earlier compaction still sets `budgetTokens`.
- **A compaction summary is an unverified model call.** Nothing checks it. A bad summary is a bad session from that point on — the shadowed history is still in the log, but nothing brings it back. The seam for the answer now exists (a `verifier` role plus a delegated child under `read-only`/`never`); building it is S8's.
- **The meter changes units at a compaction** (ARCHITECTURE §13). Safe in direction, approximate by construction. A per-adapter tokenizer would fix it and is the natural home for a replaceable estimator — deferred until an adapter has one. Two adapters now exist and neither ships a tokenizer, so the estimate is shared across genuinely different tokenizations (Anthropic's produces ~30 % more tokens for the same text than the older generation): another reason the numbers are a pressure signal, not an accounting.
- **The in-memory log retains the trace tier, and S7 decided that deliberately.** Paging removed the wire half of the problem outright (17 MB and ~322 ms per frame → ~58 KB per page, with no page carrying a chunk). The memory half measured at ~28-30 MB for a 400-turn session, and evicting would break `seq === array index` at 16 call sites — including seq generation, the session invariant and the fork seed. DSH's live session is uncapped for the same reason. Revisit when a deployment shows a session long enough to matter.
- **Durability-before-action is a contract, and a child honours it in its own log.** The driver checkpoints before every model request and every tool dispatch, and a delegated child runs the same driver over its own session — so its checkpoints flush its own log, never the parent's. A child that loses durability ends its turn `DURABILITY_LOST`, which reaches the parent as an `isError` tool result naming it; there is still no terminal agent state (ARCHITECTURE §13).
- **The workspace registry is config, not state.** Named workspaces went over the wire in S7 as addressing only — no CRUD, nothing durable, and no authority: the allow-list is still what decides where a session may work. A mutable registry waits for a deployment that has more than a handful of roots.
- **Spill files are never collected.** A long-lived home grows `spill/<session>/` forever. Session disposal deletes nothing of it; decide alongside the attachment plane (S8), which has the same question about content-addressed bytes — and now alongside child session files, which accumulate the same way.
- **A child is foreground, sequential and cannot be talked to.** One delegation at a time, blocking its own tool call, one turn, one answer. DSH has background jobs, continuable children with a mailbox, and parallel tool calls; MiniDSH ships none of them, because nothing has yet needed a child that outlives the call that made it. The first real need (a long verification, a watcher) is what should decide it.
- **Spill and children both accumulate.** A long-lived home now grows `spill/<session>/` AND a session file per delegated child; nothing prunes either, and `sessions list` shows the children with their lineage rather than hiding them. Retention is one decision for both, still unmade.
- **A second surface writer would need the pairing rule in the session.** Only the compaction planner enforces "a replace never separates a call from its result"; the session invariant does not. Deferred until a second writer (a pruner, a delegation seed) exists.
- Composition files are read at boot, never watched: a running process keeps its composition. Restart-applies is a fine answer for a local-first harness until evidence says otherwise.
- **No host-side RPC deadlines, and the backpressure limits are guesses.** DSH has neither, so there is no shape to copy; the soft/hard byte limits are defaults nothing tunes, and the drop rule is proven by forcing the limits rather than by stalling a real peer. A slow-client incident is what should set them.
- **The browser surface authenticates nobody.** Loopback by default, a one-shot launch token exchanged for a signed cookie, and a Host/Origin fence make it hard to reach by accident. They do not make it multi-user: anyone with the cookie drives an agent with the authority of whoever launched it. Upstream has no per-user identity either, so a multi-principal design would be inventing rather than following.
- **No workspace-level CONFIG layer, and a stated reason.** S5 reads workspace instruction files but treats them as model-facing context only: a repository may say how it likes its code and may not say what the harness is allowed to do. A repo-controlled file that could patch the sandbox row remains a trust decision nobody has needed yet.
- **The browser client did not force a workspace split.** It shares no code with the host — plain JS, no build step, only the wire between them — so the trigger for splitting packages is still a consumer that needs to IMPORT something.
- The session lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts) — fail-safe refusal, documented, acceptable for a local-first harness.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.

## 4. Development record

- **S7 Web surface (2026-08-31)** — a third surface, and the paging the log had been waiting for. Method: the four docs and every S7-relevant source file read first, then five local probes BEFORE planning, then a bounded upstream research workflow (6 areas → an adversarial verifier each → one synthesis), then eight phases each committed green. The probes decided the design and the research corrected it. **What the probes settled:** a 400-turn session is 103,201 events and 17.0 MB of JSON, and `session/events` cost **322 ms of `JSON.stringify`** on the host's event loop — a page of 300 facts is 58 KB; a cold `persistence.load` is 167 ms and 28 MB; `foldSurfaceSeqs` on a TAIL SLICE throws by design, and after one compaction the live node order is `[28, 18, 23, 25]`, so seq order is not render order — which is why no client folds the surface and the folds a paged client cannot do moved host-side instead; the log stays a dense zero-based prefix through compaction, fork (seed AND child) and `repairInterruptedTail`, which is the precondition the paginator needs and the invariant upstream's own verifier called most likely to break on a reimplementation; and a hand-rolled RFC 6455 server round-trips a 200 KB frame with Node's built-in client, so the carrier costs no dependency. **What the upstream research falsified** (five S7 assumptions, all from BLUEPRINT §1): there is no `fromSeq` gap repair — no lower-bound cursor exists anywhere in DSH's wire protocol, a reconnect replaces the window from a fresh snapshot, and the JSDoc that says otherwise is contradicted by the interface beside it (almost certainly what seeded the assumption in S5.5); "seq as the only dedup key" is false upstream because a packed chunk row spans many seqs, and is true here only BECAUSE pages omit the trace tier; `stateVersion`-keyed projections are unsupported twice over — upstream's paging materialises the whole log and slices every time, its projection tier serves session LISTING over SQLite, and its one API pairing a projection watermark with a ranged read has no production caller; RPC deadlines do not exist on upstream's browser path at all; and per-client watch sets are a MiniDSH invention (upstream gives each follower its own listener, its own unbounded queue and its own frozen copy of the log). Adopted verbatim where upstream was simply right: the message-alignment rule (only ARRIVED user/assistant messages spend the budget; the cut pulls back to the group start), `throughSeq` as a consistent-cut postcondition, listen-before-snapshot, the duplicate/overlap rules, the workspace addressing contract, and the token→cookie+Origin handshake. Decisions worth keeping: the cut deliberately does NOT honour a replacement's citations, because a summary cites every node it shadowed and honouring them would defeat paging on exactly the sessions that need it; the host is per-DEPLOYMENT and a `ClientConnection` owns only a sink and a watch set, which is what makes a disconnect mean "this client left" instead of "dispose its work"; backpressure is tier-aware because `session/event` is a synchronous emit that cannot suspend its producer, so the only choices were an unbounded buffer or a drop policy — and the three tiers are what made "droppable" statable; `expectedRevision` is REQUIRED on the settings wire where upstream's fence is opt-in and enforced nowhere. Three real defects the tests found while being written: a client that DETACHED stayed in an approval's answerer set, so a session whose last watcher detached and then disconnected kept its question parked forever; the web host's `Host` check compared the header against ITSELF, making the DNS-rebinding fence a no-op; and two of my own tests passed vacuously because `waitFor` takes a synchronous predicate and an async one is never `undefined`. Verification: `pnpm check` green at 459 tests (44 files; up from 394), and all seven live arcs green — the new one driving a spawned `minidsh web` over a real WebSocket with two clients, a real consent granted over the socket with no `--approve`, backward paging to seq 0, and a socket killed mid-turn whose work a reconnecting client finished.

- **S6 Cognition routing & delegation (2026-08-30)** — The model became a capability the runtime routes to. Method: the coordinator read every S6-relevant source file and all four docs first, then ran two in-memory probes BEFORE planning (they decided the shape: a global `agent/request` rewriter reaches every agent, so a role would poison a resume unless the base route became its own fact; and a tool body can already create, seed, drive and dispose a child bound to its parent's scope, so the delegation seam existed and needed only a subtractive tool view). A bounded research workflow (7 primary-source areas over the current DSH and the live provider docs) then supplied the vocabulary; its verifier pass hit the session limit, so the remaining claims were settled by three live probes against the real APIs instead — which is what caught the two facts no document stated plainly: **DeepSeek refuses (400) an assistant tool-call turn whose `reasoning_content` is missing in thinking mode**, exactly the shape a turn from another provider has (the serializer now always sends it, empty when there is none), and **Anthropic's 5 family returns 400 for any `temperature`** while streaming its thinking as an empty `thinking_delta` plus one `signature_delta`. Six phases, each committed green. Decisions worth keeping: the BASE route is a durable knob (`agent/options`) SEPARATE from the effective route (`request/header` + `request/context`), because a role rewriting a request must never become what a resume rebuilds from; `resolveCallConfig` is the one resolution a step and an out-of-loop call share, which is what makes `model-roles` a five-line listener rather than a subsystem; the replay envelope is pruned by the assembler in step with dropped blocks and stripped by the runtime for a foreign provider, so signed reasoning is never forged or misaligned; a delegation opening is an enforced CEILING (setters, escalation path, and the invariant pre-commit) where DSH relies on the approval pin alone — the pin stops the model, the ceiling stops the composition; `tools.restrict` lives in the one visibility resolver so a hidden tool is unknown AND refused; `subagent/start|end` go in the PARENT's log because MiniDSH has no projections to find children with. Verification: `pnpm check` green at 394 tests (40 files; up from 346); six live arcs green — run once before the review and again after it — the two new ones proving a mid-session provider switch with mixed history and a delegated child whose every escalation was refused without a client being consulted. The 3-lens diff review + per-finding skeptics produced 16 findings, 10 surviving verification and all fixed (plus 4 the skeptics refuted on reachability whose behaviour was wrong anyway): the delegation tool flushed the child before appending `subagent/end`, so the one failure the pair exists to explain was the one it could not explain; a fork below a child's opening stamps kept the lineage while dropping the fence; `AuthorityPresets.apply` wrote its intent before either setter could refuse; the delegation closure became the child's own `Agent.setup`, so a grandchild re-ran its grandparent's opening — and the first fix for that was itself inert, because a WeakMap storing `undefined` is indistinguishable from an absent key under `??`; `runTask` and the wire's create path carried a settings effort across a route change the flag had made; `--agent-preset` never reached the header it was declared for; and four Anthropic-adapter facts (the second overflow message, a dated snapshot's alias, an advertised effort unusable at the default cap, an unrefused over-cap `maxTokens`). Cost: about $0.05 of live API calls across probes, smoke runs and twelve arc runs.

- **S5.5 Architecture hardening & route review (2026-08-28)** — Method: every non-test source file read as one system; runtime probes on this host; a bounded workflow (4 DSH research areas → 4 audit lenses → 2 adversarial verifiers; 50 findings, 49 verified, 1 refuted); then six phases, each committed green, a 3-lens diff review, and all four live arcs. What the probes and the audit found that the tests had not: (1) **crash repair answered logged calls, not the assistant's tool-call blocks** — a crash during call *i* of *n* resumed a history every OpenAI-compatible wire refuses, so the resumed session was bricked; (2) every per-step fold walked the whole log, 97 % of which is `assistant/chunk` in a 400-turn session — `meterSession` cost 30 ms at every pre-step, and `appendFileSync` cost 1 ms per chunk (~110 s of loop blocking per such session); (3) the composition record made every opened-and-closed chat leave a file; (4) approval policy had no opening record while sandbox stamped lazily, and the docs called it one discipline; (5) `prepend` is an unshift, so a later middleware silenced the "nothing can silence it" invariant; (6) a scope's `provide` widened its plugin's strict-read set for the rest of the process; (7) the shell's escalation consent raced the registry deadline; (8) guards ran after consent; (9) any wire client could set `cwd: C:/` and get workspace-write over the drive; (10) the terminal printed `~NaNk → ~NaNk` for a compaction because two drifted copies of one projection read payloads through casts; (11) a typo'd `{mode:'full'}` settled green and then failed every write as an INVARIANT error. Decisions: three log tiers named once (surface / facts / trace) with `Session.facts` as the fold view — chosen over DSH's incremental projections because one classification serves the runtime, the terminal and S7's paging, and projections can still land on top; materialization on the first conversation fact (DSH's rule), which is also what let both authority knobs open eagerly at creation — the S3 reason for a lazy stamp was that eager stamping littered files, and that reason is gone; durability as a checkpoint before every action (DSH's checkpoint policy), with `DURABILITY_LOST` a turn reason; the config contract as a structural slot on `Plugin` rather than per-`apply` checks, so `reconfigure` can validate before it disposes; invariants as observers; deployment-global registries refusing scoped owners (DSH's preset mount audit); the wire choosing WHERE inside the host's roots, never the root. Research falsified five claims the docs made about DSH: its delegation stamp is not an enforced ceiling (the approval pin enforces), the signed-reasoning slot is a response-level envelope not a block field, there is no model-role seam upstream, the context window IS logged upstream (`request/context`), and `events.mux`/`session/subscribed{lastSeq}` is not the current attach shape (`follow()`/`page()` is) — all corrected in ARCHITECTURE §12 and the route. Route changes: S6 reordered to begin with the route as a durable fact; model roles as composition, not settings, with `core/settings` moved to S7; spawn-mode children as S6's default; S7 gets the DSH attach shape, workspace ids and paging; S7.5 added as a recurring checkpoint; S8 inherits the attachment ordering rules. The 3-lens diff review + verifier then found 2 real and 14 minor (none load-bearing, one downgraded): `minidsh config` approved a composition boot refuses (it never parsed row configs — now it does, exit 1 naming the row); the host's own default cwd was recorded raw while a wire-chosen one was canonical (a relative `--cwd` would have moved the fence root on resume from another directory — now canonical everywhere); a scope's provision undo keyed on read-through rather than its own set; a `DURABILITY_LOST` turn was reported twice; an already-cancelled shell exec returned a success-shaped result; the effect-disposer/unwind pair could run a cleanup twice; provenance compared configs by reference; the payload-cast gate pinned a spelling; the terminal announced an approval twice; and two doc contradictions about the S6 seed (the setters cannot open a child truthfully — a direct append in `setup` can). All fixed the same session except the one-step lag of the meter's header rule and the `serve --agent-preset` widening, which are documented. Verification: `pnpm check` green at 346 tests (37 files; up from 318), `check-deps` now also gates payload casts; per-step meter fold 30 ms → ~1 ms and per-chunk append ~1,070 µs → ~20 µs on this host; the abandoned-session probe leaves no file; the audit opens with both knobs before any decision; all four live arcs green, twice (before and after the review's fixes).
- **S5 Context management (2026-08-26)** — `core/metering` (one pure pressure fold), `core/compaction` + `compaction-basic` (pressure, overflow-retry and explicit `/compact`, one `surfaceOp: replace` that shadows a range while the log keeps everything), `core/llm/aux-call` (a model call that is not a turn, one log-only record, `LlmRequest.purpose` non-model-visible), spill for output with no other home, workspace instructions as a durable message guarded on the live surface. A pre-implementation design verifier refuted three load-bearing claims: the driver had to build its request per ATTEMPT (overflow-triggered compaction was otherwise impossible), the replay oracle had to replay every attempt (a recorded recovery could never re-happen), and spill had to live where the text still exists (a post-execute listener never sees more than a tool already emitted). The real compaction hazard is the await, not the mutation: an explicit compaction on a running agent is deferred and the plan is re-validated in a window with no `await`. The session invariant was deliberately relaxed (a replace may land between turns). The review then found 20 more, four load-bearing — the planner declining exactly when a tool-heavy turn needed it, and a pre-step throw durably eating the user's prompt.

The review found 15 defects in the new durable machinery, all fixed with regressions.

- **S2 Surface contract (2026-08-23)** — Two surfaces over one unchanged runtime, and sessions that survive their process: `core/persistence` with append-only resume, `agents.resume`/`fork` with crash repair folded into the seed, the durable op-shaped inbox, the client protocol as one plugin over two carriers, the terminal as a protocol client.
