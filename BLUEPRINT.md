# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is unresolved, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## 1. Next session — S6 Cognition routing & delegation

Goal: the model stops being *the* agent and becomes a capability the runtime routes to. S5 made a long session survivable; S6 makes a session able to spend the right model on the right question, and to hand bounded work to a child that cannot outgrow its parent.

Planned work, in expected dependency order:

1. **A second adapter.** A generic OpenAI/Anthropic-compatible provider, so "provider-neutral" is a claim two implementations have to agree on rather than one. Two shapes S1.5 and S3 already flagged will bite here: a reasoning block needs a provider-opaque continuation slot (a model whose thinking must be echoed with a signature), and `ResolvedModel` carries no modality facts.
2. **Model roles.** `agent/request` listeners rewriting `{provider, model}` — identity is the exact route plus the `purpose` tag S5 added, not a role registry. The first real consumers are already here: compaction's summary should be able to run on a cheap route, and a verifier needs its own. This is also the first *runtime* consumer of settings, so the `core/settings` Definition question (parked since S4) is answered here rather than re-litigated.
3. **The subagent seam.** An in-process child with scoped tools and an authority it can never widen. The plane folds per session, so a child would fold its OWN — DSH seeds a `source: 'delegation'` stamp into the child precisely so delegation cannot fall back to a wider default. S5's compaction matters here: a child must inherit bounded context, not a parent's whole history.
4. **Bounded parallel tools.** Only if a subagent needs it; sequential execution is still the shipped answer.

Exit criteria: a session routes two different models through one unchanged loop, with mixed-model history correctly attributed in `request/header` and `MessageSource`; a subagent completes bounded work under an authority strictly no wider than its parent's, proven by a refusal; `pnpm check` green; all four live arcs green plus one live delegation arc against the real API.

## 3. Open risks and questions

- **No host can confine the shell.** S3 built the whole seam — stamp, `enforcementFor`, refusal, escalation, durable record — but ships no backend, so every platform reports `none` and a shell command under a confined mode costs a round trip and a human decision. The cheapest real backend is Linux `bwrap`; Seatbelt and a Windows restricted-token runner are progressively harder, and none can be exercised on the current dev machine. Until one lands, `--sandbox danger-full-access` is what an unattended shell-heavy run actually uses, and it is recorded in the log every time.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell; nothing coerces it, and nothing should.
- **The shipped default never reaches the pressure trigger** (ARCHITECTURE §13): DeepSeek advertises 1M for every model, so 0.8 of it is ~800k and only the overflow recovery fires out of the box. Per-model windows become meaningful at S6 with a second adapter; until then a deployment sets `budgetTokens`.
- **A compaction summary is an unverified model call.** Nothing checks it. A bad summary is a bad session from that point on — the shadowed history is still in the log, but nothing brings it back. A verifier role (S6/S8) is the first honest answer; a "compaction quality" check would be the second.
- **The meter changes units at a compaction** (ARCHITECTURE §13). Safe in direction, approximate by construction. A per-adapter tokenizer would fix it and is the natural home for a replaceable estimator — deferred until an adapter has one.
- **Spill files are never collected.** A long-lived home grows `spill/<session>/` forever. Session disposal deletes an empty session log but not its spill; decide alongside the attachment plane, which has the same question about content-addressed bytes.
- **A subagent must not be able to widen its parent's authority.** The plane is per-session and folds from the log, so a child session would fold *its own* — DSH seeds a `source: 'delegation'` stamp into the child precisely so delegation cannot fall back to a wider default. This is now an S6 deliverable, not a deferred question.
- The settings layer is boot-time app assembly; promoting it to a `core/settings` Definition is DECIDED to wait for the first runtime consumer — S6 model roles, which is now next. Do not re-litigate; do settle it there.
- Composition files are read at boot, never watched: a running process keeps its composition. Restart-applies is a fine answer for a local-first harness until evidence says otherwise.
- The protocol serves one client per instance, unpaginated `session/events`, no RPC deadlines — acceptable for stdio and the loopback terminal; the S7 web carrier must solve multi-client mux (DSH's `events.mux` + `session/subscribed{lastSeq}` reconnect-rebuild is the precedent). Compaction makes the unpaginated read *worse*, not better: the log keeps growing while the surface does not.
- A second adapter whose reasoning must be echoed with a provider signature needs an opaque continuation slot on the reasoning block — an S6 decision.
- **No workspace-level CONFIG layer, and now a stated reason.** S5 reads workspace instruction files but treats them as model-facing context only: a repository may say how it likes its code and may not say what the harness is allowed to do. A repo-controlled file that could patch the sandbox row remains a trust decision nobody has needed yet.
- When to promote to a workspace: the first *independent* out-of-process consumer (the S7 browser client is the likely trigger).
- The session lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts) — fail-safe refusal, documented, acceptable for a local-first harness.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.

## 4. Development record

- **S5 Context management (2026-08-26)** — Research: the current DSH upstream read directly (compaction Definition + `compaction-basic`, `token-meter`, `spill`/`spill-local`/`spill-policy`, `agent-instructions`, the config catalog), then a pre-implementation adversarial design verifier with runtime probes on this host. It earned the session three times over, refuting three load-bearing claims before a line was written. (1) The driver change was not optional but MANDATORY: with the old per-step frozen request, a compaction answering `CONTEXT_WINDOW_EXCEEDED` re-sent stale messages and the turn died on "request messages diverge from deriveMessages()". (2) The replay oracle could not reproduce an overflow recovery at all — `deriveReplayScript` kept only the last attempt, so the failure vanished, compaction never re-triggered, and the recorded summary was never consumed; replaying every terminally-finished attempt is now the default. (3) The whole spill design was wrong: a `tools/post-execute` listener can never see more than 16k, because both shipped tools truncate inside their bodies, and a read of the spilled file would spill again forever. Spill moved to where the text still exists, with a sharper rule — spill is for output with NO OTHER HOME, so the shell spills and the file viewer answers with a line range. The verifier also refuted "no lock bracket needed" as stated: the real hazard is a runtime TOCTOU across the summary await, reproduced live (a `/compact` on an idle agent whose replace landed mid-step, with the log then claiming the model answered a history it never saw), answered by deferring an explicit compaction on a running agent and re-validating in a window with no `await` in it. Four decisions taken with the user: both compaction triggers, ship `/compact`, spill to home, one live arc. Built in six verified phases, each committed green. Notable calls: metering is a pure module rather than a service (no lifecycle, and a fold a protocol client must also run cannot live behind a ctx key); `COMPACTION` carries `compactNow` alone, because the pressure path's only caller is the provider's own listener; the session invariant was deliberately RELAXED — an arriving user message still needs an open turn, a replace is a rewrite and may land between turns, which is what makes `/compact` legal on an idle session (the genuine tightening this session added is elsewhere: `Surface.apply` now throws on a replace naming a dead node); `LlmRequest.purpose` joins `signal` and `sessionId` as a non-model-visible field, and the header canon's comment now says so; and the summary request replays the shadowed conversation under the CURRENT system prompt and tools, so the provider serves most of it from cache. Two rules the tests forced: the retained tail is a fraction of what is ACTUALLY there capped by a fraction of the budget (a budget above the live surface would otherwise decline exactly when overflow asked for progress), and one pairing rule suffices in both directions. Three defects fixed in passing, all found by this work rather than looked for: `Surface.apply` silently destroyed the LAST node on a replace naming a dead one (`splice(-1, …)`), so a client folding a stream it did not write would render a plausible wrong history; a cancellation landing before an adapter was entered hung the agent forever, because `addEventListener('abort')` never fires on an already-aborted signal — now normalized by the seam; and the terminal's `/cancel` sat below the unknown-command branch and could never run. Also: a module could not be called `aux.ts`, because AUX is a reserved DOS device name that git's `open()` cannot touch on Windows. Verification: `pnpm check` green at 318 tests; all four live arcs green, including the new S5 arc — a real 14k budget crossed, a summary replacing a real range, a spilled command output the model retrieved a mid-file value from, an AGENTS.md rule obeyed in a written file, and a keyless replay with both cursors drained (~25 s). The bounded 3-lens review then produced 20 findings, 4 load-bearing, and the two worst were both silent: `planCompaction` DECLINED whenever the retained tail was all `tool/result` — the shape `agent/pre-step` sees at every step boundary of a tool-heavy turn — so automatic compaction did nothing at 130 % of budget with no error anywhere (the cut now moves backward when forward runs off the end); and `workspace-instructions` could throw out of `agent/pre-step` via `fs.resolve`, which reaches the driver AFTER the claim is committed, durably eating the user's prompt and bricking every later one because the condition is a property of the cwd. Also fixed: a failing summariser bought a full-budget request at every step forever (now a per-session failure budget); `afterTokens` omitted the summary it had just inserted and subtracted estimator units from provider units (now three fields in two clearly-labelled scales); session cost totals ignored every out-of-loop call; the terminal retained every `assistant/chunk` and re-folded them per line (5.5 s and 215 MB at 300k events); an explicit `/compact` that lost the exit race was paid for and dropped; `{kind:'scheduled'}` was never honoured if the turn ended; and a compaction could complete on a disposed agent and write three records into a detached log. Three claims were retracted rather than defended — `Spill.contains` had no consumer and is gone, the terminal's denominator is now stated as the model's window rather than a budget the wire does not carry, and "the invariant was sharpened" was simply wrong.
- **S4 Composition & configuration (2026-08-24)** — What MiniDSH *is* became data: home layout + a session write lease, a credentials seam, boot-time settings, `composition.json` + `--patch` layers with provenance and a `composition/applied` record, authority presets, the runtime `Composition` handle, and per-agent presets. A design verifier REFUTED the lease before implementation — `onPublished` runs in a contained emit, so a second process's refusal would have surfaced only at turn-end flush, after a full paid turn with real effects; the fix (the factory flushes a resumed publication inside the creation transaction) also made previously-swallowed attach failures immediate. Decisions: settings resolve at boot in `app/` (a `core/settings` Definition waits for a runtime consumer), agent presets are minimal named row lists, JSON over YAML. Load-bearing calls: the preset Definition lives in `core/presets` because a capability may not import another capability; the recorder row sits OUTSIDE the layers so no layer can remove the record of what the layers did; `persistence` joined the spine because its per-session state and leases die with the plugin instance. The 3-lens review then found 15 real defects in the new durable machinery — a swapped `persistence` silently stopping durable writes while `flush()` still reported success, an `attach` length guard comparing against the grown log, a lease-steal TOCTOU, and `minidsh config`'s authority warning keying on row id so an inserted blanket-consent row printed as ordinary. All fixed with regressions.
- **S3 Effects & authority (2026-08-23)** — Authority became one complete, replayable plane: a single stamp with roots derived by a shared pure function, the fence in the fs **provider** rather than at the tool gate, `ApprovalPolicy` enforced before dispatch, and escalation that is model-driven and never automatic. Decisions: DSH-faithful escalation over tool-driven auto-approval; `workspace-write` stays the default on a backend-less host; no OS backend this session, because untested enforcement is worse than an honest `none`. `resolve()` records the stamp when it changes, so every effect is preceded by a recorded stamp without stamping a session that never acts. Deadlines are registry-owned because the kernel waterfall passes `next()` no arguments. The live run earned its keep immediately by falsifying an over-claim about stamp ordering, and the review found a genuine fence bypass: `canonicalPath` decided existence with `existsSync`, which FOLLOWS links, so a dangling symlink let the fence contain a name inside the workspace while the write landed outside it — reproduced on this host, closed by deciding existence with `lstat`.
- **S2 Surface contract (2026-08-23)** — Two surfaces over one unchanged runtime, and sessions that survive their process: `core/persistence` with append-only resume, `agents.resume`/`fork` as creation modes with crash repair folded into the seed, the durable op-shaped inbox, the client protocol as one plugin over two carriers, and the terminal as a protocol client. A design-verification pass produced 11 corrections before implementation — positional inbox splices corrupt under a steer landing in the pre-step await, graceful shutdown would have durably erased the queue resume exists to restore, and crashed logs broke the replay oracle. Post-implementation review settled fork-wake: a fork is a passive branch, born idle.
- **S1 + S1.5 Foundation and hardening (2026-08-22)** — The kernel (contexts, plugin instances, reversible effects, a typed scoped event bus), the core spine (event-sourced session, LLM seam, tool pipeline, prompt assembly, agent registry, one loop driver), the DeepSeek adapter, minimal tools, JSONL persistence, and the headless CLI. The live run proved the log is its own test oracle: a real session's JSONL replayed keylessly with every recorded step consumed. S1.5 then falsified the foundation against S2–S8 pressures: the shape held — multimodal, model roles, a second provider, a second surface, sandbox providers and compaction all fit without vocabulary changes — but three documented invariants were not true in code and were corrected (the scope contract, "model-visible ⟺ logged", and "the log is its own oracle").
