# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is unresolved, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## 1. Next session — S9 Extension authoring and governance

Goal: let a capability be written by the model and admitted by the harness, on the seams S8 just
proved.

1. **Model-written extensions behind approval.** Upstream's three gates are human approval, a
   non-persistent lifetime, and scoped disposal — and NONE of them is a quality judgement, which is
   the point: authority is the boundary, not assessment. Its vm is explicitly not a security
   boundary and it says so twice; MiniDSH must either accept bash-equivalent trust openly or pay for
   a real one, and pretending is the one option that is closed.
2. **Validate at registration, not at use.** A malformed tool schema fails where it is registered,
   with an error that teaches the correct call. Cheap, and it is the half of upstream's design worth
   copying without its generated API catalog.
3. **A recall tool for shadowed history** (`history{fromSeq,toSeq}`), cut from S8 with its reasoning:
   it re-inflates the surface a compaction just shrank, so it needs a per-session budget and the
   spill/excerpt discipline before it can ship. It is the answer to the risk below that a bad summary
   is unrecoverable — a better answer than a second model judging the first.
4. **The spill sweep**, also cut from S8. The RULE is decided and written down (ARCHITECTURE §9); what
   is left is one age knob, one startup sweep, and the shape-matching that makes deleting from a
   durable home safe.
5. **Pixels in a browser**, if a surface wants them: an HTTP route on `minidsh web` behind the cookie
   fence, not a wire method — measured, because one 5 MiB image is ~6.8 MiB of base64 against a
   carrier whose outbound hard limit is 8 MiB, and the browser rebuilds its whole transcript on every
   applied event.

Method, now four-for-four (S1.5, S5.5, S7.5, S8): read every relevant source file, probe BEFORE
planning, then delegate bounded research and a bounded audit. In S8 fourteen local probes and a
five-lens design panel corrected the plan in eleven places before a line was written — and two of the
panel's own HIGH findings were then refuted by a probe, which is why the probes come first.

## 3. Open risks and questions

- **No host can confine the shell.** S3 built the whole seam — stamp, `enforcementFor`, refusal, escalation, durable record — but ships no backend, so every platform reports `none` and a shell command under a confined mode costs a round trip and a human decision. The cheapest real backend is Linux `bwrap`; none can be exercised on the current dev machine. Until one lands, `--sandbox danger-full-access` is what an unattended shell-heavy run actually uses, and it is recorded in the log every time.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell; nothing coerces it, and nothing should. (Upstream's gate is the same three guards, so this is not a divergence — S7.5 corrected the doc that said it was.)
- **The shipped DeepSeek default still never reaches the pressure trigger.** DeepSeek advertises 1M for every model, so 0.8 of it is ~800k and only the overflow recovery fires on that route. The windows are real per route and logged; a deployment that wants earlier compaction sets `budgetTokens`.
- **A compaction summary is still an unverified model call, and the answer is recall rather than a second opinion.** S8 looked for the verifier this line used to promise and found the premise wrong: upstream has no semantic verification anywhere, and its own proposed note diagnoses the problem as one artifact playing two roles — the summary carries no reference to what it shadows and no tool reads a shadowed span back. So S8 built the durable half (every attempt, its trigger, its budget and why it produced nothing) and left the recall tool to S9 with its own hazard attached: it re-inflates the surface a compaction just shrank. **Measured, and it bites**: the routing arc fails on this intermittently — 4 of 11 runs at the S8 tip, and 1 of 4 at the S7.5 tip, so it predates S8 — and the shape is always a summary that dropped something the next turn needed. What changed is that the failure now names itself in one run instead of costing a re-run to reproduce.
- **A compaction near the threshold is often bought and not used, and now the record says why.** Measured on the S5 arc: 14 of 34 summaries produced no compaction, because a summary is refused when it is at least as large as the span it would replace, and where the planner's cut lands is the model's tool shape rather than anything the runtime chooses. The aux call is paid for before that is knowable — that part is unchanged and probably unchangeable. What changed is that `compaction/end` names which of the seven reasons it was, every surface renders it, and `/compact` returns it on the idle path.
- **The meter changes units at a compaction.** Safe in direction, approximate by construction. A per-adapter tokenizer would fix it; neither adapter has one, and the two now differ by ~30 % on the same text. Upstream anchors on real usage samples and keeps a heuristic delta separately — the shape to copy when this matters.
- **The in-memory log retains the trace tier, deliberately.** Paging removed the wire half outright. The memory half is ~28-30 MB for a 400-turn session, and evicting would break `seq === array index` at 16 call sites. Upstream's live session is uncapped for the same reason — and it goes further, copying the whole event array per follower observation, which MiniDSH does not.
- **Retention is decided and only partly built.** One rule (ARCHITECTURE §9): content is never swept, an affordance may expire. Attachment objects and session logs are content — content-addressed and shared, and the only oracle an arc replays from — so nothing removes them, and deleting a session would need an authority above the append-only seam that this system does not have. Spill files are the one store a sweep may touch and the sweep is S9's. Upstream reached the same three lifetimes and rejected the unification by name; the thing to resist is a per-session cascade, because a fork inherits spill locators without re-owning them.
- **First-request-order replay matching breaks the moment two children can run at once.** MiniDSH matches a delegated child's log to a live session by the order agents first ask, which is exact while delegation is serial and undefined the instant it is not. Upstream uses the identical rule and tracks the same defect as `XXX(concurrent-subagents)`. Latent, not absent — and S8 added a second delegation row, so a composition can now have two.
- **Two provider facts worth knowing before the next adapter change.** DeepSeek publishes per-model concurrency (2500 for the flash models, 500 for pro) and a `user_id` parameter that gives each id its own budget — a ready-made seam for session identity that will otherwise be bolted on later. Anthropic caps a whole request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts; S8's per-request image budget keeps a session far below it, but the code path is unguarded for anything else that grows a request.
- **A delegated child is foreground, sequential, one turn — and, since S7.5, not a surface's to drive while its parent runs it.** What is still missing is what upstream has: background jobs, continuable children with a mailbox, and parallel tool calls. The first real need (a long verification, a watcher) is what should decide it. Upstream's transferable rules if it ever lands: the inbox must be the only queue, an interrupt should park rather than kill, and a producer must not start work its owner cannot collect or stop.
- **A second surface writer would need the pairing rule in the session.** Only the compaction planner enforces "a replace never separates a call from its result". Deferred until a second writer exists.
- Composition files are read at boot, never watched: a running process keeps its composition.
- **No host-side RPC deadlines, and the backpressure limits are guesses.** Upstream has neither, so there is no shape to copy; a slow-client incident is what should set them.
- **The browser surface authenticates nobody.** Loopback by default, a one-shot launch token exchanged for a signed cookie, and a Host/Origin fence. Upstream has no per-user identity either, so a multi-principal design would be inventing.
- **No workspace-level CONFIG layer, and a sharper reason than S7 had.** A repo may say how it likes its code and may not say what the harness is allowed to do. Upstream is the caution, not the precedent: it ships repo-controlled tiers (a skill root table where project roots outrank user roots; hooks that execute shell with no approval gate) and fences them with a blanket denial of its own `DSH_*` namespace to project-discovered config.
- **The browser client's DOM has no test and, since S7.5, no browser has looked at it.** Its window rules (dedup, gap repair, re-attach) now have unit tests; its rendering does not, and the Chrome extension was unavailable this session. S7's record is that four defects in this file were found by a real browser and by nothing else, which is why S7.5 fixed its logic and left its rendering alone — including the O(n²) full-transcript rebuild.
- The session lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts) — fail-safe refusal, documented, acceptable for a local-first harness.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.

## 4. Development record

- **S8 Verification capabilities (2026-09-02)** — the binary plane, and a verifier that is a composition row. **The plan was falsified before it was written**: fourteen local probes (including real calls to both providers), a seven-area primary-source study of the current DSH with an adversarial verifier per area, and a five-lens design panel with two skeptics over the plan itself — eleven corrections, and two of the panel's own HIGH findings then refuted by a probe. **What the probes decided.** A constructed `image` block pushed through the tree at 19bda63 changed NOTHING at six sites — the meter scored it 0, both serializers emitted byte-identical wire messages, `describeEvent` and `transcriptLines` rendered the text only, and the browser's `row()` returned `undefined` outright — and none of them was a `switch` the type checker would flag, so the guards had to land before the variant. The reconstruction invariant forbids splicing bytes into `messages`, which killed one resolution design; `request/context` is written before `step/start`, which settled where a producer reads its route; `tool-subagent` mounts twice cleanly, which settled that a verifier is configuration. Live: DeepSeek's vision model reads a generated 4-quadrant PNG correctly and takes streaming, tools and thinking with it, while `deepseek-v4-flash` answers a 400 that must never be string-matched; Anthropic validates the DECLARED media type against the bytes and caps a side at 8000 px; and image cost is `min(⌈w·h/750⌉, 1600)`, measured on `count_tokens` (96²→19 … 2048²→1524 capped). One probe refuted a HIGH the panel had built on a doc sentence: a 4000×3000 image inside an Anthropic `tool_result` is **downscaled, not rejected** — that rule is scoped to the computer-use toolsets. **What research corrected in the plan.** "One retention decision" was the wrong shape and upstream rejected that unification by name; DSH has no semantic verification anywhere, and its own proposed note says the answer to a bad summary is RECALL, not judgement; putting a ref in the content union creates a dependency edge whose answer is a type-only import plus an error class routed on `code`; and admission-refuses-while-projection-substitutes is BOTH rules, because durable history outlives the model that first consumed it. **The best finding came from a skeptic and was not about images**: `Fs.readBytes` emitting `fs/observed` would have handed the model a read-before-edit token for bytes it never saw — `view_image` on `src/app.ts`, refused as not-an-image, would still have licensed a blind editor overwrite of that path, because the observation map is keyed by path alone. `readBytes` emits nothing, and a test pins it. Three more the lenses caught: `runAuxCall` flattened an `LlmError` to `AUX_CALL_FAILED` and `summarise` returned `undefined` four different ways, so a Ctrl-C in the summary await would have been recorded as a summariser failure and counted — harmless in a WeakMap a resume cleared, a lie the moment it became durable; the `request/context` change gate compared three named fields, so a field added to it would never be written on a resumed session and "absent means text only" would have refused a vision session's own images forever; and an image-only tool result serialized as the literal string `(no output)` on both wires. **Decisions worth keeping**: the descriptor is STORED in the block, so a later change of wording cannot rewrite what an old log says the model saw; the refusal of an assistant-side image lives in `validateStream` and not `BlockAssembler`, because the driver appends the chunk first and a refusal there would arrive one line after the record it exists to prevent — and would leave a log the replay oracle could never run; the give-up counter is a fold bounded to the lifecycle, because an unbounded one is a latch that only a human `/compact` can lift and every fork inherits; and nothing new ships in `compose()` but a service row, so the model-facing tool surface is still three. Verification: `pnpm check` green at **564 tests** (50 files; up from 492), all **eight** live arcs green, and the new arc run four times with identical evidence — `view_image, verify, str_replace_editor` / child on `deepseek-v4-flash-vision-exp` with `["text","image"]` recorded / `"red, green, blue, white"` / attachment id equal to the source digest. Cost: about $0.02. **The one failure it did not cause**: the routing arc fails intermittently on a model-recitation assertion, so a worktree at 19bda63 was built and installed to attribute it — it fails there too (1 of 4, on the sibling assertion), and what S8 adds is that the failure now reads `after 4 applied compaction(s) shadowing [3, 5, 3, 9] node(s)` instead of a bare count.

- **S7.5 Architecture hardening & system review (2026-09-01)** — S6 and S7 read as one system, and they had never met. Method: every non-test source file read first, then SIXTEEN local probes which found nine defects before any agent ran, then a bounded upstream-research workflow (6 primary-source areas over the current DSH → an adversarial verifier each → a synthesis) and a bounded audit workflow (5 lenses → 2 whole-set skeptics → a synthesis). The probes decided the work; the skeptics found two things five lenses missed; the research corrected the docs. **What the probes found:** a wire client could `session/prompt` a LIVE delegated child, and because the delegation answers with whatever the child last said, the injected turn silently BECAME the parent's tool result — two clicks away in the browser, which lists a live child as a clickable row; a child's whole stream and its `session.view` were broadcast to every un-narrowed client; the page event ceiling bound only at a message-group boundary and only an ARRIVED message set one, so a range with none returned the whole log (5,000 facts against a ceiling of 2,000); the browser never advanced its cursor across the trace tier it does not store, so every model step spent a gap-repair round trip that could return nothing — and a REAL drop, which is what backpressure does to exactly that tier, was indistinguishable; `transcriptLines` rendered three event kinds where `describeEvent` rendered eleven, so paging back over an authority switch, a denial, a delegation or a compaction showed none of them while watching live showed them all; `publishView` ran O(facts) folds per event for sessions nobody watched; three RFC 6455 frame shapes a server must reject were accepted; `damaged` crossed the wire and neither client rendered it; a configured subagent persona plus any agent preset that registers one made every delegation fail; and one settings.json plus one `MINIDSH_MODEL` resolved to two different routes depending on which surface read it, the CLI's carrying a DeepSeek effort id onto an Anthropic model. **What the audit added that no probe and no lens found:** an approval could be parked FOREVER — a client that was un-narrowed when the question was asked and then made its first attach elsewhere stayed its sole answerer while no longer receiving it (probe-confirmed: `status: running`, nothing left to settle it); The approval fix DELETED a field: answerability is recomputed from the live connections after every watch-set change, which fixes the snapshot in both directions at once. **The replay oracle was the quietest defect**: one cursor served every session, so a replayed delegation fed the child the parent's next recorded step and `assertConsumed()` passed on arithmetic — "a live session log is its own test oracle" was false for every log with a delegation in it, and S8's verifier is exactly that shape. **Deliberately not fixed, with reasons recorded in ARCHITECTURE §13**: a rolled-back creation's opening facts still reach a watching client (four assertions depend on those frames, and the defect is a session a client can never reach); the disposal-window prompt drop (the honest fix inverts a documented, test-pinned ordering); the browser's O(n²) transcript rebuild (no browser was available to verify a rendering change, and S7's record is that only a browser finds those). **Upstream research corrected fifteen claims** about DSH that ARCHITECTURE asserted, of ~200 checked: there is no `model/selection` event (a live ref behind two listeners, which makes MiniDSH's base/effective split a sharper divergence, not a weaker one); DSH SALVAGES a torn tail rather than discarding it; there are three client protocols, not two, and its GUI wire HAS `session/cancel`; its shutdown is stdio-only and its GUI wire has none, so MiniDSH's carrier gating is convergence; `session.fork` is implemented with an `atSeq`, so MiniDSH's absence is a gap and not a mirror; escalation is not grounded in a denial upstream either; its trust markers grade agent-preset roots while it ships repo-controlled config tiers elsewhere; the two-entry preset table is a package default, not what ships; ~150 packages understates by 2-3×; and the lower-bound-cursor JSDoc is real in two files with a `readFrom` seam beneath the wire — MiniDSH still declines a resume cursor, but as a choice. **The 3-lens diff review then found a HIGH defect this session had itself introduced**, and all three lenses found it independently: the browser's new `noted()` advanced the cursor OFF the queue that every other cursor mutation shares, so a chunk arriving during an in-flight repair pushed the cursor past the surface event that had revealed the hole — the client losing an `assistant/message` on exactly the path the method was added to protect, and invisible to every existing test because they all await each apply. The lesson is the one S5 already recorded in another form: the hazard is the await, not the mutation. Two more of its findings were real (a read form refused by a guard meant for writes; a persona rename that gave up the shadowing it was supposed to keep), eight were refuted. Verification: `pnpm check` green at 492 tests (45 files; up from 465), every reproduced defect now a test. **Closing it took a second sitting, because the seven arcs kept failing differently and the failures were not in the code the session had changed.** Four shapes, from the recorded runs: a compaction whose summary came out 5 % BIGGER than the span it replaced (a real defect — fixed in the runtime, which now refuses one); a run where the arc found no compaction at all; a `turn 1` that never ended, timing out after 180 s with nothing to say about where; and a replayed web arc whose `notes.txt` never appeared. - **S7 Web surface (2026-08-31)** — a third surface, and the paging the log had been waiting for. **What the probes settled:** a 400-turn session is 103,201 events and 17.0 MB of JSON, and `session/events` cost 322 ms of `JSON.stringify` on the host's event loop — a page of 300 facts is 58 KB; a cold `persistence.load` is 167 ms and 28 MB; `foldSurfaceSeqs` on a TAIL SLICE throws by design, and after one compaction the live node order is not seq order, which is why no client folds the surface; the log stays a dense zero-based prefix through compaction, fork and repair, which is the precondition the paginator needs; and a hand-rolled RFC 6455 server round-trips a 200 KB frame with Node's own client. **Decisions worth keeping:** the cut deliberately does NOT honour a replacement's citations, because a summary cites every node it shadowed and honouring them would defeat paging on exactly the sessions that need it; the host is per-DEPLOYMENT and a `ClientConnection` owns only a sink and a watch set, which is what makes a disconnect mean "this client left"; backpressure is tier-aware because `session/event` is a synchronous emit that cannot suspend its producer, and the three tiers are what made "droppable" statable; `expectedRevision` is REQUIRED on the settings wire where upstream's fence is opt-in. Verification: 394 tests, six live arcs. Cost: about $0.05.

- **S5.5 Architecture hardening & route review (2026-08-28)** — every non-test source file read as one system; runtime probes; a bounded workflow (4 research areas → 4 audit lenses → 2 verifiers; 50 findings, 49 verified).
