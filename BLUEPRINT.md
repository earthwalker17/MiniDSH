# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is unresolved, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## 1. Next session — S6 Cognition routing & delegation

Goal: the model stops being *the* agent and becomes a capability the runtime routes to. S5 made a long session survivable and S5.5 made the foundation say what it does; S6 makes a session able to spend the right model on the right question, and to hand bounded work to a child that cannot outgrow its parent.

Planned work, in dependency order — reordered by S5.5's research, which found the route itself to be the first seam:

1. **The route as one durable fact.** Today `Agent.options` is the base, the rewritten `request/header` is the effective route, resume folds the latter back into the former, and `compaction-basic` reads a third copy. First: a log-only `request/context{provider, model, contextWindow}` written on route or capacity change (DSH's shape — outside header equality, so a replay reads the window from the log instead of pinning `budgetTokens`); the aux call takes the same resolved route as the loop (`agent/request` with `purpose`); resume rebuilds from the base route, not the last rewrite; `budgetFor` reads the per-request route.
2. **A second adapter** (a generic OpenAI/Anthropic-compatible provider), with the vocabulary DSH actually uses: `finish.replayState` carried on the assistant message's source (a response-level opaque envelope, NOT a field on the reasoning block — the docs said otherwise until S5.5), `TokenUsage.cacheWriteTokens`, `LlmErrorCode.UNSUPPORTED_OPTION` (adapters throw rather than drop an option or a block), `ModelInfo.inputModalities`, genuinely per-model context windows.
3. **Model roles** as a `model-roles` capability row (composition config, hashed by the record — never settings): `agent/request` listeners rewriting `{provider, model}` by `purpose` and by turn; the first consumers are compaction's summary on a cheap route and a verifier on an independent one. `purpose` may not change wire bytes — an adapter expresses a purpose through header-canon fields. DSH has no role seam (its `purpose` is only an adapter-visible classifier); this is MiniDSH's design, and it is attributed as such.
4. **The subagent seam**, spawn-mode (an empty child) as the default. S5.5 already gave `setup(agentCtx, agent)` the unpublished child. S6 adds: `SessionHeader.delegationDepth` and a delegation parent DISTINCT from fork `parentId` (gated by the format version; a resumed child must not delegate as top-level); `CreateAgentOptions.authority` seed + `signal` (an aborted delegate call rolls the transaction back); reason `'delegation'` in both knob vocabularies and the authority invariant, plus an explicit opening form on the setters (`open(session, {mode, reason})`) so a seed need not append the stamp itself — today the setters write the deployment default as `initial` first, and only a direct append in `setup(agentCtx, agent)` opens truthfully; the child opens under the parent's EFFECTIVE pair with approval pinned `never` — DSH's stamp is not an enforced ceiling, the pin is what enforces — plus a MiniDSH ceiling check in `setMode`/`resolve`; `tools.restrict` (a subtractive scoped view, own layer exempt — guards cannot hide a tool from the model); context-runtime renders the approval policy and a delegation statement; `subagent/start|end` in the parent's scope; the result as the delegate's tool result; cancel forwarded as `{kind:'parent'}`; the agent-preset name recorded durably (DSH keeps it in the header) so a child can re-join its parent's world. Per-session protocol subscription is S7's, so a delegation arc's client filters by session id.
5. **Bounded parallel tools** only if a subagent needs it; sequential execution is still the shipped answer.

Exit criteria: a session routes two different models through one unchanged loop, with mixed-model history correctly attributed in `request/header`, `request/context` and `MessageSource`; the compaction summary runs on a route the log names; a subagent completes bounded work under an authority strictly no wider than its parent's, its opening stamps reading `reason:'delegation'` in `sessions show --audit`, and a widening attempt on it refused and recorded; `pnpm check` green; all four live arcs green plus one live delegation arc against the real API.

## 3. Open risks and questions

- **No host can confine the shell.** S3 built the whole seam — stamp, `enforcementFor`, refusal, escalation, durable record — but ships no backend, so every platform reports `none` and a shell command under a confined mode costs a round trip and a human decision. The cheapest real backend is Linux `bwrap`; Seatbelt and a Windows restricted-token runner are progressively harder, and none can be exercised on the current dev machine. Until one lands, `--sandbox danger-full-access` is what an unattended shell-heavy run actually uses, and it is recorded in the log every time.
- **Escalation depends on model compliance.** A model that ignores the refusal guidance simply cannot use the shell; nothing coerces it, and nothing should.
- **The shipped default never reaches the pressure trigger** (ARCHITECTURE §13): DeepSeek advertises 1M for every model, so 0.8 of it is ~800k and only the overflow recovery fires out of the box. `request/context` (S6.1) and a second adapter's real windows are what make the trigger meaningful; until then a deployment sets `budgetTokens`.
- **A compaction summary is an unverified model call.** Nothing checks it. A bad summary is a bad session from that point on — the shadowed history is still in the log, but nothing brings it back. A verifier role (S6/S8) is the first honest answer; a "compaction quality" check would be the second.
- **The meter changes units at a compaction** (ARCHITECTURE §13). Safe in direction, approximate by construction. A per-adapter tokenizer would fix it and is the natural home for a replaceable estimator — deferred until an adapter has one.
- **The in-memory log retains the trace tier.** S5.5 took every runtime fold off the chunks (`Session.facts`), but `session.events` still holds them: ~57 MB per 100k chunks, and `session/events` serves them all to an attaching client as one frame. Retention and paging are one decision, made at S7 with the attach protocol.
- **Durability-before-action is now a contract.** The driver checkpoints before every model request and every tool dispatch. An S6 child's effects interleave with its parent's; the child must honour the same checkpoint, and a `DURABILITY_LOST` child must be visible to its parent — there is no terminal agent state yet (ARCHITECTURE §13).
- **The wire's workspace root is an allow-list until S7.** `session/prompt.cwd` must lie inside the host's `workspaceRoots` (default: serve's cwd). DSH's registered workspaces with ids are the shape a remote carrier needs.
- **Spill files are never collected.** A long-lived home grows `spill/<session>/` forever. Session disposal deletes nothing of it; decide alongside the attachment plane (S8), which has the same question about content-addressed bytes.
- **The agent-preset name is not durable.** Resume and fork need `--agent-preset` re-supplied, and an S6 child cannot re-join its parent's per-agent world; DSH keeps the preset id in the session header. An S6 item.
- **A second surface writer would need the pairing rule in the session.** Only the compaction planner enforces "a replace never separates a call from its result"; the session invariant does not. Deferred until a second writer (a pruner, a delegation seed) exists.
- Composition files are read at boot, never watched: a running process keeps its composition. Restart-applies is a fine answer for a local-first harness until evidence says otherwise.
- The protocol serves one client per instance, unpaginated `session/events`, no RPC deadlines, no backpressure — acceptable for stdio and the loopback terminal; S7's web carrier owns all four.
- **No workspace-level CONFIG layer, and a stated reason.** S5 reads workspace instruction files but treats them as model-facing context only: a repository may say how it likes its code and may not say what the harness is allowed to do. A repo-controlled file that could patch the sandbox row remains a trust decision nobody has needed yet.
- When to promote to a workspace: the first *independent* out-of-process consumer (the S7 browser client is the likely trigger).
- The session lease degrades to manual cleanup at its unreachable edges (pid reuse, foreign hosts) — fail-safe refusal, documented, acceptable for a local-first harness.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.

## 4. Development record

- **S5.5 Architecture hardening & route review (2026-08-28)** — Method: every non-test source file read as one system; runtime probes on this host; a bounded workflow (4 DSH research areas → 4 audit lenses → 2 adversarial verifiers; 50 findings, 49 verified, 1 refuted); then six phases, each committed green, a 3-lens diff review, and all four live arcs. What the probes and the audit found that the tests had not: (1) **crash repair answered logged calls, not the assistant's tool-call blocks** — a crash during call *i* of *n* resumed a history every OpenAI-compatible wire refuses, so the resumed session was bricked; (2) every per-step fold walked the whole log, 97 % of which is `assistant/chunk` in a 400-turn session — `meterSession` cost 30 ms at every pre-step, and `appendFileSync` cost 1 ms per chunk (~110 s of loop blocking per such session); (3) the composition record made every opened-and-closed chat leave a file; (4) approval policy had no opening record while sandbox stamped lazily, and the docs called it one discipline; (5) `prepend` is an unshift, so a later middleware silenced the "nothing can silence it" invariant; (6) a scope's `provide` widened its plugin's strict-read set for the rest of the process; (7) the shell's escalation consent raced the registry deadline; (8) guards ran after consent; (9) any wire client could set `cwd: C:/` and get workspace-write over the drive; (10) the terminal printed `~NaNk → ~NaNk` for a compaction because two drifted copies of one projection read payloads through casts; (11) a typo'd `{mode:'full'}` settled green and then failed every write as an INVARIANT error. Decisions: three log tiers named once (surface / facts / trace) with `Session.facts` as the fold view — chosen over DSH's incremental projections because one classification serves the runtime, the terminal and S7's paging, and projections can still land on top; materialization on the first conversation fact (DSH's rule), which is also what let both authority knobs open eagerly at creation — the S3 reason for a lazy stamp was that eager stamping littered files, and that reason is gone; durability as a checkpoint before every action (DSH's checkpoint policy), with `DURABILITY_LOST` a turn reason; the config contract as a structural slot on `Plugin` rather than per-`apply` checks, so `reconfigure` can validate before it disposes; invariants as observers; deployment-global registries refusing scoped owners (DSH's preset mount audit); the wire choosing WHERE inside the host's roots, never the root. Research falsified five claims the docs made about DSH: its delegation stamp is not an enforced ceiling (the approval pin enforces), the signed-reasoning slot is a response-level envelope not a block field, there is no model-role seam upstream, the context window IS logged upstream (`request/context`), and `events.mux`/`session/subscribed{lastSeq}` is not the current attach shape (`follow()`/`page()` is) — all corrected in ARCHITECTURE §12 and the route. Route changes: S6 reordered to begin with the route as a durable fact; model roles as composition, not settings, with `core/settings` moved to S7; spawn-mode children as S6's default; S7 gets the DSH attach shape, workspace ids and paging; S7.5 added as a recurring checkpoint; S8 inherits the attachment ordering rules. The 3-lens diff review + verifier then found 2 real and 14 minor (none load-bearing, one downgraded): `minidsh config` approved a composition boot refuses (it never parsed row configs — now it does, exit 1 naming the row); the host's own default cwd was recorded raw while a wire-chosen one was canonical (a relative `--cwd` would have moved the fence root on resume from another directory — now canonical everywhere); a scope's provision undo keyed on read-through rather than its own set; a `DURABILITY_LOST` turn was reported twice; an already-cancelled shell exec returned a success-shaped result; the effect-disposer/unwind pair could run a cleanup twice; provenance compared configs by reference; the payload-cast gate pinned a spelling; the terminal announced an approval twice; and two doc contradictions about the S6 seed (the setters cannot open a child truthfully — a direct append in `setup` can). All fixed the same session except the one-step lag of the meter's header rule and the `serve --agent-preset` widening, which are documented. Verification: `pnpm check` green at 346 tests (37 files; up from 318), `check-deps` now also gates payload casts; per-step meter fold 30 ms → ~1 ms and per-chunk append ~1,070 µs → ~20 µs on this host; the abandoned-session probe leaves no file; the audit opens with both knobs before any decision; all four live arcs green, twice (before and after the review's fixes).
- **S5 Context management (2026-08-26)** — `core/metering` (one pure pressure fold), `core/compaction` + `compaction-basic` (pressure, overflow-retry and explicit `/compact`, one `surfaceOp: replace` that shadows a range while the log keeps everything), `core/llm/aux-call` (a model call that is not a turn, one log-only record, `LlmRequest.purpose` non-model-visible), spill for output with no other home, workspace instructions as a durable message guarded on the live surface. A pre-implementation design verifier refuted three load-bearing claims: the driver had to build its request per ATTEMPT (overflow-triggered compaction was otherwise impossible), the replay oracle had to replay every attempt (a recorded recovery could never re-happen), and spill had to live where the text still exists (a post-execute listener never sees more than a tool already emitted). The real compaction hazard is the await, not the mutation: an explicit compaction on a running agent is deferred and the plan is re-validated in a window with no `await`. The session invariant was deliberately relaxed (a replace may land between turns). The review then found 20 more, four load-bearing — the planner declining exactly when a tool-heavy turn needed it, and a pre-step throw durably eating the user's prompt.
- **S4 Composition & configuration (2026-08-24)** — What MiniDSH *is* became data: home layout + a session write lease, a credentials seam, boot-time settings, `composition.json` + `--patch` layers with provenance and a `composition/applied` record, authority presets, the runtime `Composition` handle, per-agent presets. The design verifier refuted the lease as first designed (a refusal surfacing only at turn-end flush, after a paid turn); the factory now flushes a resumed publication inside the creation transaction. Load-bearing calls: `core/presets` is core because a capability may not import a capability; the recorder row sits outside the layers; `persistence` joined the spine. The review found 15 defects in the new durable machinery, all fixed with regressions.
- **S3 Effects & authority (2026-08-23)** — Authority became one replayable plane: one stamp with roots from a shared pure function, the fence in the fs PROVIDER, `ApprovalPolicy` enforced before dispatch, model-driven escalation that is never automatic, deadlines registry-owned because the kernel waterfall cannot substitute a listener's arguments. No OS backend, because untested enforcement is worse than an honest `none`. The review found a real fence bypass (a dangling symlink passed `existsSync`), closed by deciding existence with `lstat`.
- **S2 Surface contract (2026-08-23)** — Two surfaces over one unchanged runtime, and sessions that survive their process: `core/persistence` with append-only resume, `agents.resume`/`fork` with crash repair folded into the seed, the durable op-shaped inbox, the client protocol as one plugin over two carriers, the terminal as a protocol client. Design verification produced 11 corrections before implementation (positional inbox splices corrupt under a steer in the pre-step await; graceful shutdown would have erased the queue resume restores). A fork is a passive branch, born idle.
- **S1 + S1.5 Foundation and hardening (2026-08-22)** — The kernel (contexts, plugin instances, reversible effects, a typed scoped event bus), the core spine (event-sourced session, LLM seam, tool pipeline, prompt assembly, agent registry, one loop driver), the DeepSeek adapter, minimal tools, JSONL persistence, the headless CLI. The live run proved the log is its own test oracle. S1.5 falsified the foundation against S2–S8 pressures: the shape held, but three documented invariants were not true in code (the scope contract, "model-visible ⟺ logged", "the log is its own oracle") and were corrected.
