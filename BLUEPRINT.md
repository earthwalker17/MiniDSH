# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is still an open question, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape and its known limitations; this file says what comes next and why, and keeps the measurements the architecture map no longer carries.

## 1. Next session — S11.5 Hardening checkpoint = V1 release candidate

Goal: read the whole system once more as one thing, then decide whether it is installable. This is the release gate, and the two feature sessions behind it (S10 surfaces, S11 confinement) are the ones it has to reconcile.

1. **Every source file read as one system**, then probes — the S8.5 and S7.5 shape: the numbers (services, log kinds, rows, RPC methods) re-derived rather than trusted, core acyclicity re-checked, and the two authority-sensitive sets in `cli.ts` re-proved equivalent now that a `confinement` knob has joined them.
2. **A bounded audit**, agent count fixed before launch, verified in the parent.
3. **The eight arcs three times on an idle machine** — and now on TWO hosts, since a confined Linux run and an unconfined Windows run exercise different branches of the authority and web arcs. Plus once in CI.
4. **A `prepack` emit to `dist/`.** Node refuses type-stripping under `node_modules`, so the `.ts` source cannot be `npx`-installed as it stands; dev and tests keep running the source. Then a dry `npm pack` install, which is what decides npm-vs-clone-only for V1.
5. **The first real CI run.** `check.yml` and `live.yml` are written and locally reasoned about but have never executed: nothing here can run a GitHub runner. The Linux leg's `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` is the specific unknown — expected to work on `ubuntu-latest`, unverified on the hosted image, and if it does not the leg goes RED by design rather than quietly proving nothing.
6. **Documentation size.** `ARCHITECTURE.md` is 109 KB against the 90 KB S8.5 compacted it to. It is still rereadable, but the trend is one way and the checkpoint is where to reverse it.

Verification: `pnpm check` on Windows and under WSL 2; the arcs as above; a dry install.

**V1 is** the smallest release a developer can install, point at a repository, and use daily without reading the architecture: two interactive surfaces (`chat`, `web`) and one headless entry (`run`) over one runtime; the default preset `workspace-write` + `ask`, under which an ordinary task on a confined host costs zero prompts and an out-of-workspace effect one one-shot approval — both now demonstrated against a real model on a real confined host — and on Windows, which has no backend, the shell asks per call or the user chooses the `danger-full-access` preset, stated in the README and hinted at the first ask, never silent; keys from the environment or `~/.minidsh/credentials.json`, with the first failure naming both; `pnpm check` green on three platforms in CI and the eight live arcs green three times before the tag, the routing arc's flake rate reported rather than hidden.

**Out of scope for V1**, each with the reason the S8.5 research found: model-written extensions (opt-in even upstream — only its `cordis` preset — session-scoped, and its `node:vm` is stated five times not to be a security boundary; three vocabulary generations in ten weeks); background jobs, continuable children, mailboxes and Agent Teams (upstream's own `minimal` preset ships none; MiniDSH's one-shot foreground child is upstream's one-shot foreground path); parallel tool calls (an optional loop change with modest payoff for three tools); an MCP bridge (shipped disabled upstream); a Windows confinement backend (native bindings, standing ACL mutations, always `partial`) and Landlock (a prebuilt native launcher, and `partial` on a 6.6 kernel anyway); standing approval grants and allow-lists (deferred upstream pending a grant-scope identity); session deletion in the persistence seam (upstream has none anywhere: "session deletion needs its own lifecycle"); PTC / Code Mode; a session search index; per-user identity; a desktop shell.

Ordering rationale: the protocol before any GUI so surfaces never grow semantics; authority before configuration so presets cannot widen permissions silently; the route as a fact before roles and delegation; compaction before delegation because a fork-mode child inherits its parent's surface; verification after routing and after a checkpoint. Hardening checkpoints recur every two feature sessions, and the next one is the release gate.

## 3. Open questions (a decision is pending; the known limitations themselves live in ARCHITECTURE §13)

- **Background work and parallel tool calls.** Upstream's shapes are transferable if ever needed — the inbox as the only queue, an interrupt that parks rather than kills, a producer that must not start work its owner cannot collect, a per-tool `isConcurrencySafe` with results committed in model order. Nothing in the V1 route needs them; the first real need (a long verification, a watcher) decides.
- **A second surface writer.** Only the compaction planner enforces "a replace never separates a call from its result", and the session invariant admits a `replace`-op `user/message` outside a step but not a `tool/result`. A pruner would be that second writer; the rule moves into the session when one exists.
- **Concurrent children and the replay oracle.** Sessions are matched to logs in first-request order, which is exact while delegation is serial and undefined the instant it is not (upstream tracks the identical defect). Latent while one child runs at a time.
- **Two provider facts to design with, not around.** DeepSeek's `user_id` parameter gives each id its own rate budget — a ready-made seam for session identity; Anthropic caps a whole request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts. Neither is used yet.
- **What projection would a rename need?** S10 shipped the vocabulary a rename writes into — `session/title` is last-wins and its `source` already distinguishes a human's choice from a generated one — but not the reading. A name chosen at seq 5,000 is nowhere near the bounded prefix `persistence.list()` reads, so a rename needs somewhere to read the CURRENT title cheaply: a sidecar beside the log, a stamp the writer maintains, or a real projection store. Upstream has the last of those and mounts it by default; MiniDSH has none and does not need one until something can choose a name. The first feature that does — a rename, or a model-written title — decides it, and it is the same decision a session search index would need.
- **Install at V1.** The route says npm with a `prepack` emit; "clone-only" is the honest alternative for a reference implementation. Decided at S11.5 with the dry `npm pack`.

## 4. Development record

- **S11 Confinement & CI (2026-09-06).** The shell stopped costing a human decision per command, and the tree ran somewhere other than one Windows machine for the first time. **The architecture question was answered before any code and the answer was "nowhere new":** `core/shell` had specified this feature since S3 — enforce what `enforcementFor` claims, refuse what you cannot enforce, bind the persistent child to its policy — and ARCHITECTURE §11 already carried the row. So S11 added no seam, no service, no event kind and no configuration plane: one strategy directory inside the shell provider (`confine/`), one knob on a row that was already authority-sensitive, and the `enforcement` field that had been in the stamp since S3 and had always read `none`. **The probe is functional and that is the whole point:** the real `read-only` profile around `true`, from the builder a real wrap uses — never a `which`, because a bwrap inside a container that forbids user namespaces reports itself perfectly well. MiniDSH probes even a sole candidate where DSH skips that, because it RECORDS enforcement at agent creation, before any command exists to fail closed. **The bwrap profile is upstream's, flag for flag,** and two of those flags close escapes that need no write at all: `--unshare-pid` (a procfs magic link out of the read-only bind) and `--new-session` (TIOCSTI into the terminal that started the harness — CVE-2017-5226's shape, and the review caught its absence). **What the probes settled before implementation:** on the WSL 2 target, 33 of 34 submounts accept the recursive read-only remount and writes to `/tmp`, `/mnt/c`, `/home`, `/run`, `/dev` and `/usr` are all refused `EROFS`. The method mattered more than the number — a first walk passing only the NEW flags failed `EPERM` on exactly the 12 mounts carrying `noexec`, because a locked mount may have restrictions added and never removed. bwrap ORs the existing flags in. That is the argument against a hand-rolled backend, not a footnote. Sixteen further probes fixed the argv, the ordering (`--tmpfs /tmp` before the bind, which is what lets a workspace UNDER `/tmp` survive — every arc's shape), the 9 ms spawn cost, and that cwd is inherited so no `--chdir` is needed. **A decision reversed a written plan item, on evidence.** BLUEPRINT §1 had promised `writableRoots` would gain the temp root, as DSH's shared list does. It did not: granting it would flip 17 assertions across 6 files and, far worse, dissolve the workspace/outside distinction structurally, because every "outside" fixture in this repository — including all eight live arcs — is a sibling `mkdtemp` under `os.tmpdir()`, and a real `--cwd /tmp/scratch` would then be fenced by nothing. `writableRoots` became a stated CEILING instead: a family may grant less, never more, which is exactly what lets bwrap mount private tmpfs over `/dev` and `/tmp` without widening anything. DSH sets the precedent (its own bwrap ignores its shared list for an ephemeral tmpfs) and pins parity semantically rather than literally. **Upstream had no answer for the one thing MiniDSH has and it does not:** a persistent shell WITH a per-call escalation. DSH's persistent shell has no escalation at all and refuses a mode change while a shell is open. So: the child is bound to the session's policy, a durable `setMode` replaces it and reports `restarted` (never `reset`, which tells the model its own command killed the shell), and a one-shot grant runs in a throwaway child that leaves the persistent one alone. **A confined host would have been a REGRESSION for authority without one more thing.** `tool-shell` printed its escalation guidance only on `SANDBOX_UNAVAILABLE` — so once the OS starts refusing writes instead, nothing tells the model the one legitimate move and "an out-of-workspace effect costs one one-shot approval" stops being reachable exactly where the sandbox works. A kernel denial now earns the same hint, matched against the mounted backend's own dialect, as a hint and never a classification. **What the arcs measured, and what one of them cost.** The routing arc's prompts said "read alpha.txt" and named no tool; the only thing keeping the model on the editor was that no host could confine a shell, so a confined host quietly turned it into an arc about tool choice — 1 to 5 compactions per run against 2 before, failing in the replay oracle rather than in anything it claims to test (1 of 3 on Linux). ARCHITECTURE §10's warning arriving exactly as written, and what decayed the premise was the system getting better. The prompts now name the editor, which is the fix the context arc already carried; back to 3 of 4. Two supporting measurements taken rather than guessed: a confined host costs **+86 tokens of fixed prefix per request**, cut to **+48** by dropping one bullet that duplicated a notice the model already gets when it is true. **What the bounded review found that the tests could not** (four reviewers, count fixed before launch, every finding verified in the parent): a one-shot grant took the throwaway child only when the granted world DIFFERED from the live child's — and on a host that confines nothing every world is the same one, so an escalated `cd` persisted into the session's shell while the tool said the opposite; the throwaway child was stored nowhere, so `dispose()` reaped the persistent shell and left the escalated command — the widest authority a session ever grants — running behind it; BOTH arcs' escape targets sat under `os.tmpdir()`, which bwrap MASKS, so the write failed as a missing directory rather than a refusal (that one failed live on Linux exactly as predicted); and the authority arc's containment claim counted shell calls across the whole session, where turn 3 had already made one, so a model that gave up produced a green branch. Also: `process.ts` held three raw NUL bytes, which made the most safety-critical file of the session BINARY to git and invisible to ripgrep. **Verification at close:** `pnpm check` green on Windows (654 passed, 14 skipped) and under WSL 2 with a real Linux Node 24 and `MINIDSH_EXPECT_CONFINEMENT=1` (667 passed, 1 skipped) — 668 tests, 57 files, up from 636/56. The eight live arcs **8/8 three times on Linux with bwrap active** (172 s, 200 s, 149 s) and 8/8 on Windows, with the routing arc's documented marker-drop flake twice more; about 2.1 CNY of DeepSeek. The confinement claim is exercised against the kernel, not against configuration: a denied write must leave NO host file, which is what separates a `full` stamp from a `none` one. The CI guard was proved in both directions — Linux with `MINIDSH_EXPECT_CONFINEMENT=1` passes 19 tests; Windows with it set FAILS rather than reporting 11 green skips. **What is not proven:** CI itself has never run, because nothing here can start a GitHub runner; macOS is proven by that CI alone and by no Mac; and `ubuntu-latest`'s AppArmor userns knob is expected to lift and is unverified, which is why the Linux leg goes red rather than quiet if it does not.

- **S9 Context & prompt hygiene (2026-09-05).** **Bounded recall** (`capabilities/tool-history`): `history_read{fromSeq,toSeq}` renders shadowed nodes, restricted to the union of `compaction/applied.shadowedSeqs` for THIS session; registered in the deployment globals so a summary can NAME it by tag, and hidden per agent by a `TOOLS.restrict` lifted at that agent's first applied compaction — so a session that never compacts never carries the schema. Its per-session spend is a FOLD over the log rather than counter state, which makes it durable across a resume, exact on replay, and monotonic, so recall cannot refill itself by compacting. **Authority prose moved** out of `core/sandbox` into `context-runtime`; **`Agent.world`** and **`ToolDefinition.tags`** replaced two process globals. **What research overturned:** "upstream ships no recall" was false — DSH ships `packages/session-query/` and mounts it in no shipped composition, for the cost its own README names ("one concise guidance section and five schemas on every request"). So the divergence is GATING, not absence, and gating on the first applied compaction is exactly what removes that cost. **The durable rule planning found:** a `session/event` listener may not append synchronously — persistence writes lines in delivery order and the relational invariant stages its trace across the observer/listener pair, so a nested append reaches the file BEFORE the event that caused it, and a log whose seqs run N+1, N is `damaged` on the next resume. Notes drain on a microtask. **What review found:** the runtime-context section MOVED mid-lifecycle on a forked or resumed session, because `openingSandboxStamp` took the first stamp at or after `liveStart`, which for a lifecycle that wrote none of its own is the next `setMode`; both folds now require `reason !== 'change'`. Three measured recall defects with it, the sharpest being that refusals were charged to the budget — and the refusal text is what tells the model to retry narrower. **The delegation cost more than it should have:** four lenses × findings × three verifiers reached 46 agents before the user killed it, though the 20 finished agents still held three defects the parent had not found. CLAUDE.md §8 had banned per-finding fan-out since S8.5 and the ban did not hold, because nothing made the script state a number; §8 is now countable. **What the arcs measured:** the routing rule — every run where all summaries carried the marker passed with recall called 0×, and every run where one dropped it passed only if recall recovered it. A footer reworded to fire at the failure moment measured 3/6 against the original's 5/6 and was REVERTED: the guess was wrong and the numbers said so. The confinement sentence measured 6/6 with and without, because the arc's own prompt does the sentence's job — that confound is §10's warning about a decaying premise, one session before S11 hit the same thing. **Verification:** 601 tests (53 files); the eight arcs green three times. A first attempt at the closing suite was abandoned at `402 Insufficient Balance`, whose signature is six unrelated arcs failing minutes after the same tree ran 8/8.
