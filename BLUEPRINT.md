# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is still an open question, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape and its known limitations; this file says what comes next and why, and keeps the measurements the architecture map no longer carries.

## 1. Next session — S11 Confinement & CI

Goal: stop the shell costing a human decision per command, and prove the tree on three platforms rather than on this one. Both halves of the same gap: MiniDSH is the only system here with no confinement backend at all, and it has never been built anywhere but Windows.

1. **A confinement backend as a spawn wrapper inside `shell-stdio`** — `bwrap` on Linux first, because it is the cheapest real one and runs under WSL 2 on the dev machine; `sandbox-exec` on macOS behind it. It confines the argv under the stamp and `enforcementFor` reports the truth, so a log never overstates what a host delivered. `writableRoots` gains the temp root under confinement — once, for both families.
2. **A GitHub Actions matrix** (Linux, macOS, Windows) running `pnpm check`; the live arcs gated on a repository secret so a fork's PR does not spend the account.
3. **The Windows posture written down** rather than discovered: per-call approval or the `danger-full-access` preset — upstream's own state before its ACL backend, which is a native subsystem MiniDSH does not copy.

Under a backend, the authority default finally pays off: an ordinary task on a confined host costs zero prompts. Until then §13's first limitation stands, and the terminal's first-ask tip is what carries it.

Verification: `pnpm check` on three platforms in CI; the eight arcs locally and once in CI; the confinement claim exercised for real under WSL 2 (a command that tries to write outside `writableRoots` must fail because the SANDBOX refused it, not because the fence did — that is the whole difference between `partial` and `full`); a bounded diff review with its agent count fixed before launch (CLAUDE.md §8). Check the provider balance before any session that needs `pnpm test:e2e`.

**V1 is** the smallest release a developer can install, point at a repository, and use daily without reading the architecture: two interactive surfaces (`chat`, `web`) and one headless entry (`run`) over one runtime; the default preset `workspace-write` + `ask`, under which an ordinary task on a confined host costs zero prompts and an out-of-workspace effect one one-shot approval — and on a host with no backend the shell asks per call or the user chooses the `danger-full-access` preset, stated in the README and hinted at the first ask, never silent; keys from the environment or `~/.minidsh/credentials.json`, with the first failure naming both; `pnpm check` green on three platforms in CI and the eight live arcs green three times before the tag, the routing arc's flake rate reported rather than hidden.

**Out of scope for V1**, each with the reason the S8.5 research found: model-written extensions (opt-in even upstream — only its `cordis` preset — session-scoped, and its `node:vm` is stated five times not to be a security boundary; three vocabulary generations in ten weeks); background jobs, continuable children, mailboxes and Agent Teams (upstream's own `minimal` preset ships none; MiniDSH's one-shot foreground child is upstream's one-shot foreground path); parallel tool calls (an optional loop change with modest payoff for three tools); an MCP bridge (shipped disabled upstream); a Windows confinement backend (native bindings, standing ACL mutations, always `partial`); standing approval grants and allow-lists (deferred upstream pending a grant-scope identity); session deletion in the persistence seam (upstream has none anywhere: "session deletion needs its own lifecycle"); PTC / Code Mode; a session search index; per-user identity; a desktop shell.

Ordering rationale: the protocol before any GUI so surfaces never grow semantics; authority before configuration so presets cannot widen permissions silently; the route as a fact before roles and delegation; compaction before delegation because a fork-mode child inherits its parent's surface; verification after routing and after a checkpoint. Hardening checkpoints recur every two feature sessions, and the next one is the release gate.

## 3. Open questions (a decision is pending; the known limitations themselves live in ARCHITECTURE §13)

- **Which confinement backend first, and where is it proven?** `bwrap` is the cheapest real backend and runs under WSL 2 on the dev machine; `sandbox-exec` needs a macOS runner. Neither can be exercised on Windows itself. Settled by S11's CI matrix.
- **Background work and parallel tool calls.** Upstream's shapes are transferable if ever needed — the inbox as the only queue, an interrupt that parks rather than kills, a producer that must not start work its owner cannot collect, a per-tool `isConcurrencySafe` with results committed in model order. Nothing in the V1 route needs them; the first real need (a long verification, a watcher) decides.
- **A second surface writer.** Only the compaction planner enforces "a replace never separates a call from its result", and the session invariant admits a `replace`-op `user/message` outside a step but not a `tool/result`. A pruner would be that second writer; the rule moves into the session when one exists.
- **Concurrent children and the replay oracle.** Sessions are matched to logs in first-request order, which is exact while delegation is serial and undefined the instant it is not (upstream tracks the identical defect). Latent while one child runs at a time.
- **Two provider facts to design with, not around.** DeepSeek's `user_id` parameter gives each id its own rate budget — a ready-made seam for session identity; Anthropic caps a whole request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts. Neither is used yet.
- **What projection would a rename need?** S10 shipped the vocabulary a rename writes into — `session/title` is last-wins and its `source` already distinguishes a human's choice from a generated one — but not the reading. A name chosen at seq 5,000 is nowhere near the bounded prefix `persistence.list()` reads, so a rename needs somewhere to read the CURRENT title cheaply: a sidecar beside the log, a stamp the writer maintains, or a real projection store. Upstream has the last of those and mounts it by default; MiniDSH has none and does not need one until something can choose a name. The first feature that does — a rename, or a model-written title — decides it, and it is the same decision a session search index would need.
- **Install at V1.** The route says npm with a `prepack` emit; "clone-only" is the honest alternative for a reference implementation. Decided at S11.5 with the dry `npm pack`.

## 4. Development record

- **S10 Session & product surfaces (2026-09-06).** Four items, and the two that mattered were decided by measurement rather than by argument. **The spill sweep** ships as one pass at load, STARTED there and awaited at disposal — the plan said synchronous, and the probe overturned it: a synchronous pass costs 54 ms over a thousand-file store with nothing to expire and 271 ms when half of it goes, a delay every `minidsh chat` would pay before its first prompt; started instead, boot pays 0.5 ms and disposal waits 218/461 ms (eight files at a time, which halved 930 ms). Per-file mtime STRICTLY older than one snapshotted cutoff, `lstat` throughout, `unlink` plus a non-recursive `rmdir`, ENOENT as success, `cleanupPeriodDays` default 30 with `0` disabling — upstream's shape almost line for line, and none of its trusted-directory checks, because MiniDSH's spill root is under home and not in an OS temp tree. **A session's name** is a log-only `session/title`, last-wins, with a first-prompt derivation as the fold's default; the derivation is the same function the writer uses, so a log written before titles existed still lists under a name. Reading it costs nothing new: `persistence.list()` already read a 64 KiB buffer per file and threw away everything past the first newline, and now walks the complete lines of that same read. **What the upstream check settled before any code:** DSH ships `packages/session/session-title` — the same log-only event with `{title, messageSeqs, source}`, the same `findLast`, and it APPENDS its fallback rather than deriving on read. That reversed a design already drafted the other way (derive-only, no event), and `source` is durable from the first version because upstream's own rule needs it: an explicit rename PINS a title, and automatic generation must be able to see that it did. **The browser** stops rebuilding: the transcript is the seq-ordered log, so an append-only log admits four change shapes and `SessionWindow` now says which — a compaction's `replace` rewrites no row, which upstream's client independently confirms by being `surfaceOp`-blind.
