# MiniDSH Blueprint

Rolling long-term route plus a compact development record. The next session is always at the top; completed work is compressed into the record at the bottom. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## Next session — S2 Surface contract

Goal: prove that surfaces own no harness semantics, by putting a second surface on the same runtime — and make sessions resumable.

Planned work, in dependency order:
1. **`core/persistence` Definition** (`load(id) → {header, events}`, `append`) so the core can seed from a stored log without importing a capability; `persistence-jsonl` becomes its provider. This is the blocker for everything else here. Resume must attach to the existing `<id>.jsonl` append-only — the current `session/created` → whole-file rewrite is the fork path and must not become the resume path — and session publication should follow agent publication (today `sessions.create` emits `session/created` before the agent is registered). `sessions list/show` move onto this Definition.
2. **`agents.resume(id)`** through the existing seed path (the driver already continues turn numbering over a seed), plus CLI `resume` and `fork`.
3. **The client protocol**: newline-delimited JSON-RPC over stdio — requests `initialize`, `session/prompt`, `session/cancel`, `approval/answer`, `shutdown`; notifications `session.event`, `session.status`. It ships as a plugin injecting only `agents`/`sessions`. Ownership (settled in S1.5, see ARCHITECTURE §8): the wire carries session events verbatim as `{sessionId, event}` with core types reaching the client type-only (no DTO layer); the protocol owns its request/notification vocabulary, the status projection, and approval prompts as answerable frames keyed by the durable `approval/asked` id (answerers now receive it); no protocol version until a client ships independently; clients ignore unknown event types. Define the `{sessionId, event}` envelope once and align `--json` with it; `initialize` needs an `Llm.providers()`/models catalog and one `defaultAgentOptions` in `compose.ts` (the defaults live in `cli.ts` today). Decide where tool presentation travels (a `view` field on `tool/call` vs host-side projection) when the first card is rendered, and add `ToolResult.value` to `tool/result` only if a structured card needs it.
4. **An interactive terminal surface** over that protocol: streaming render from `session/event`, approval prompts answered through `approval/answer`, steering mid-turn. (The "wake latch" risk was refuted in S1.5: a followup landing between `cancel()` and convergence already starts the next turn — pinned by a regression.)
5. **Durable inbox**: promote inbox splices to session events so a resumed session reconstructs pending input.

Exit criteria: two surfaces (CLI + terminal) over one unchanged runtime; a session survives process restart and continues; `pnpm check` green; live E2E through the interactive surface.

## Completed — S1.5 Architecture hardening (2026-08-22)

A falsification pass over the S1 foundation before S2 builds on it, against DSH `b150a55` (attachment, LLM, session/compaction, scope, RPC, sandbox and tool contracts re-read) and a 10-agent research/review/verification workflow plus runtime probes. Verdict: the shape is right — multimodal/attachments, model roles, a second provider, a second surface, sandbox providers and compaction all fit without vocabulary or core changes, and the client protocol should share the durable event types rather than own a DTO — but three documented invariants were not fully true in code. Corrected: the scope contract (per-agent layers for tools, guards, sections, variables; agent-scoped dispatch of `tools/*`, `approval/request`, `system-prompt/assemble`, `fs/*`), "model-visible ⟺ logged" (`temperature` in the header), "the log is its own oracle" (`attempt` on chunks, replay keeps the acted-on attempt), pre-commit invariant observation, durable approval ids delivered to answerers with seam-owned cancellation, agent creation as an owner-bound transaction, three kernel defects (scope-record leak, own-service read during load, settle per scope), and four false affordances removed. Everything else was recorded as a decision (ARCHITECTURE §11) or handed to its owning session. Macro route unchanged.

## Open risks and questions

- **The editor/shell authority asymmetry is real today** (ARCHITECTURE.md §13). It is the single most important thing S3 fixes; until then MiniDSH should not be pointed at a workspace whose surroundings matter.
- No compaction (S5): a long session eventually exceeds the context window with no recovery path.
- A second adapter whose reasoning must be echoed with a provider signature needs an opaque continuation slot on the reasoning block, and error-time provider fallback is not expressible through `agent/request-error` (retry re-sends the same frozen request) — both S6 decisions.
- Windows shell confinement has no clean backend; S3 may accept `partial` enforcement on win32 as DSH does.
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.
- When to promote to a workspace: the first out-of-process consumer (the S2 client or the S7 browser client).
