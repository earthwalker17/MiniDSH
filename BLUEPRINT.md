# MiniDSH Blueprint

Rolling long-term route plus a compact development record. The next session is always at the top; completed work is compressed into the record at the bottom. `ARCHITECTURE.md` describes the current shape; this file says what comes next and why.

## Next session — S3 Effects & authority

Goal: make authority a complete, replayable plane — the model proposes, policy decides, and the whole decision surface is durable and inspectable.

Planned work, in dependency order:
1. **The sandbox policy seam**: one per-call stamp `{mode: 'read-only' | 'workspace-write' | 'danger-full-access', writableRoots}` shared by fs AND shell (DSH's single `workspaceRoot` stamp exists precisely to forbid today's asymmetry — ARCHITECTURE §13's first limitation is the thing S3 removes). `policy-workspace` (editor-only, a seam demonstration) is replaced, not extended.
2. **In-process fs fence** enforcing the stamp inside `fs-local`; **shell confinement** where the platform allows — Windows has no clean backend, so accept `partial` enforcement on win32 as DSH does, and say so in the audit surface.
3. **Durable policy switching**: `approval/policy` and `sandbox/mode` as log-only events, so "what could this session do, when" is answerable on replay. The S2 protocol/terminal already deliver interactive approvals (frames keyed by the durable id); S3 adds the policy layer that decides allow/ask/deny — note that today nothing in the default composition produces `ask`, so the S2 approval plumbing is exercised only by tests until S3 lands.
4. **Tool timeouts and guards** (the stdin-blocked shell command currently hangs until the tool timeout resets the shell — give timeouts a real home).
5. **Audit views**: `sessions show` projecting the authority events.

Exit criteria: the shell can no longer write outside the workspace in `workspace-write` mode (probed, not asserted); policy/mode switches are durable events that replay; approval `ask` is produced by policy and answered through both surfaces; `pnpm check` green; live E2E exercising a policy denial + an interactive approval.

## Completed — S2 Surface contract (2026-08-23)

Two surfaces over one unchanged runtime, and sessions that survive their process. Delivered: the `core/persistence` read Definition (`load`/`list`, `damaged` marker) with `persistence-jsonl` providing it — resume ATTACHES to the stored file append-only (offset-tracking scan, torn tail → `.torn` sidecar, deeper corruption refuses attach) while fresh/fork snapshots; session publication moved after agent publication (unpublished sessions claim ids silently; rollback writes nothing); `agents.resume`/`agents.fork` as creation modes (crash repair into the seed, model config folded from the log's own `request/header`, `reason:'resume'` headers, provenance passthrough — `Sessions.fork`'s orphan-publishing affordance removed); the durable inbox (`inbox/spliced` op records, front-draining claims for reorder tolerance, claim logged after entered messages so a crash re-delivers rather than loses, disposed-cancel preserves the queue, fold + silent restore + self-wake); `Llm.providers()`, one `defaultAgentOptions()`, `{sessionId, event}` frames everywhere; the client protocol (ndjson JSON-RPC 2.0 matching DSH's SDK shape + our cancel/approval/catalog additions, approval frames = the durable events against a first-answer-wins pending table, dispose-to-idle shutdown, in-flight resume table) as one plugin with two carriers (`minidsh serve` on real stdio; the terminal's loopback pair); and the interactive terminal (streaming from durable chunks, type-to-steer, y/N approvals, Ctrl+C cancel, transcript render on attach). The post-implementation 3-lens + batched-verifier diff review produced 19 findings (3 real, 12 minor, 2 duplicates, 1 refuted, 1 question), all confirmed ones fixed with regressions — the real three: Ctrl+C was dead on a real TTY (readline never emits SIGINT with `terminal:false`; the handler now lives on the process), pasted lines raced the first prompt's response into two separate sessions (lines are now strictly serialized), and the flush durability checkpoint disarmed after one throw while writes kept being dropped (a session without a live file entry now fails every flush, and a dropped append quarantines the file rather than fabricating a seq gap). The question — fork-wake — was decided: a fork is a passive branch and is born idle; only resume self-wakes. `pnpm check` green at 166 tests; live E2E: a real task over a spawned `serve`'s stdio, SIGKILL mid-turn, resumed by a second process (byte-prefix + repair asserted), finished exactly, fresh log replayed keylessly.

## Open risks and questions

- **The editor/shell authority asymmetry is real today** (ARCHITECTURE.md §13). It is the single most important thing S3 fixes; until then MiniDSH should not be pointed at a workspace whose surroundings matter.
- No compaction (S5): a long session eventually exceeds the context window with no recovery path — and resume makes long-lived sessions *likelier*, so S5's priority rises.
- The protocol serves one client per instance, unpaginated `session/events`, no RPC deadlines — acceptable for stdio and the loopback terminal; the S7 web carrier must solve multi-client mux (DSH's `events.mux` + `session/subscribed{lastSeq}` reconnect-rebuild is the precedent).
- A second adapter whose reasoning must be echoed with a provider signature needs an opaque continuation slot on the reasoning block, and error-time provider fallback is not expressible through `agent/request-error` (retry re-sends the same frozen request) — both S6 decisions.
- Windows shell confinement has no clean backend; S3 may accept `partial` enforcement on win32 as DSH does.
- When to promote to a workspace: the first *independent* out-of-process consumer (the S2 terminal ended up in-process by design; `serve`'s clients are external programs, but none ships from this repo yet — the S7 browser client is the likely trigger).
- The resume liveness guard is process-local; two processes resuming one id would damage the stored log. Single host per `MINIDSH_HOME` is a documented assumption until a per-session lock seam (S4 home-layout work).
- TypeScript 7 native `tsc` is new (GA 2026-07-08); fallback is 6.0.3 with identical checking. No issues so far.
