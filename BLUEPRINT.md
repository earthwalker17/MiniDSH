# MiniDSH Blueprint

What comes next, the route to get there, what is still undecided, and a compact record of how the system arrived. `ARCHITECTURE.md` describes the current shape and its known limitations; this file says what comes next and why, and keeps the measurements the architecture map does not carry.

## 1. Next session — V1 release

S11.5 closed the engineering gate: three-platform CI is green including an install smoke, the tarball installs and runs on two hosts, two release-blocking defects and twenty smaller ones are fixed, and both architecture documents are rewritten. What is left is publication, and nothing in it is engineering.

1. **Flip `private: true` off** in `package.json` and set the version to `1.0.0`. The flag blocks `npm publish` (`EPRIVATE`) and nothing else; `pnpm pack` and a tarball install already work with it on, which is why it survived this long.
2. **`pnpm check` on both hosts, `gh workflow run check.yml`, and `live.yml` once** on the release commit — the same gate every session ends with, on the exact bytes that ship.
3. **`npm publish`**, then a `v1.0.0` git tag and a GitHub release.
4. **The README quick start becomes `npx minidsh chat --cwd <repo>`.** Today it says a clone or a packed tarball; publication is the only thing that makes the shorter line true.
5. **The demo log ships as a replay fixture**, so the demo is a test: record one session that does real work, store it beside the arcs, and replay it keylessly in `pnpm check`. A demo that can go stale without failing is a screenshot.
6. **README and GitHub page polish**, deliberately left until the thing being described is installable.

Verification: `pnpm check` on Windows and under WSL 2; the eight arcs on both hosts; one `live.yml` dispatch; a dry install from the published tarball.

**V1 is** the smallest release a developer can install, point at a repository, and use daily without reading the architecture: two interactive surfaces (`chat`, `web`) and one headless entry (`run`) over one runtime; the default preset `workspace-write` + `ask`, under which an ordinary task on a confined host costs zero prompts and an out-of-workspace effect one one-shot approval — both demonstrated against a real model on a real confined host — and on Windows, which has no backend, the shell asks per call or the user chooses `danger-full-access`, stated in the README and hinted at the first ask, never silent; keys from the environment or `~/.minidsh/credentials.json`, with the first failure naming both; `pnpm check` green on three platforms in CI, an install smoke on each, and the eight live arcs green on two hosts with the routing arc's flake rate reported rather than hidden.

**Out of scope for V1**, each with the reason the S8.5 research found: model-written extensions (opt-in even upstream, session-scoped, and its `node:vm` is stated five times not to be a security boundary); background jobs, continuable children, mailboxes and Agent Teams (upstream's own `minimal` preset ships none; MiniDSH's one-shot foreground child is upstream's one-shot foreground path); parallel tool calls (an optional loop change with modest payoff for three tools); an MCP bridge (shipped disabled upstream); a Windows confinement backend (native bindings, standing ACL mutations, always `partial`) and Landlock (a prebuilt native launcher, and `partial` on a 6.6 kernel anyway); standing approval grants and allow-lists (deferred upstream pending a grant-scope identity); session deletion (upstream has none anywhere); PTC / Code Mode; a session search index; per-user identity; a desktop shell.

Ordering rationale: the protocol before any GUI so surfaces never grow semantics; authority before configuration so presets cannot widen permissions silently; the route as a fact before roles and delegation; compaction before delegation because a fork-mode child inherits its parent's surface; verification after routing and after a checkpoint. Hardening checkpoints recur every two feature sessions, and S11.5 was the release gate.

## 3. Open questions (a decision is pending; the limitations themselves live in ARCHITECTURE §13)

- **Background work and parallel tool calls.** Upstream's shapes are transferable if ever needed — the inbox as the only queue, an interrupt that parks rather than kills, a producer that must not start work its owner cannot collect, a per-tool `isConcurrencySafe` with results committed in model order. Nothing in the V1 route needs them; the first real need (a long verification, a watcher) decides.
- **A second surface writer.** Only the compaction planner enforces "a replace never separates a call from its result", and the session invariant admits a `replace`-op `user/message` outside a step but not a `tool/result`. A pruner would be that second writer; the rule moves into the session when one exists.
- **Concurrent children and the replay oracle.** Sessions are matched to logs in first-request order, which is exact while delegation is serial and undefined the instant it is not (upstream tracks the identical defect).
- **What projection would a rename need?** S10 shipped the vocabulary a rename writes into — `session/title` is last-wins and its `source` distinguishes a human's choice from a generated one — but not the reading. A name chosen at seq 5,000 is nowhere near the bounded prefix `persistence.list()` reads, so a rename needs somewhere to read the CURRENT title cheaply: a sidecar beside the log, a stamp the writer maintains, or a real projection store. The S11.5 listing cache is a memo of the same bounded read, not a projection, and does not answer this. Upstream has a projection store and mounts it by default; the first feature that can choose a name decides it, and it is the same decision a session search index would need.
- **Two provider facts to design with, not around.** DeepSeek's `user_id` parameter gives each id its own rate budget — a ready-made seam for session identity; Anthropic caps a whole request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts.
- **How does a provider catalog stay current?** S11.5 found five Anthropic ids the live API serves that no family prefix matched, each taking a 200K window against a real 1M. The fix was rows, measured against the live API; the question is whether a snapshot in source is the right shape at all, or whether the catalog should be fetched and cached. Nothing decides it until an id changes under a user rather than under a session that can probe.

## 4. Development record

One entry per session: what it decided, and the measurements that still matter. The detail lives in the commits.

- **S11.5 Hardening checkpoint / V1 release candidate (2026-09-07 → 09-08).** The release gate. **The first real CI run was red, honestly:** `check.yml` had never executed, and macOS and Windows both failed the same two assertions that compared a workspace root to itself (`/private/var` vs `/var`; a Windows runner's 8.3 short TEMP) — a premise that held only on the developer's machine, fixed at the test. Three platforms then went green and stayed green with an install smoke on each. **Installability** needed a `dist/` emit, a `bin` that picks source or `dist/` by package SHAPE, and `files` cut to four entries: 207 files and every test became a 232 KB tarball, installed into an empty directory on Windows and under WSL and driven through real tasks. **A six-lens audit, verified in the parent, found two release-blocking defects.** `minidsh web` parsed the request-target before the Host fence and outside any try/catch, so one unauthenticated malformed line of TCP ended the process with every agent it hosted. And the shell's escalation `reason` is the MODEL's own justification, written unsanitized into the `[y/N]` line a person answers — a carriage return and an erase-line repaint that prompt with a milder question above the same keystroke, so the grant is real and its description a forgery. **Four arc assertions could not fail**, which matters more, because the arcs are the release evidence: the read-only switch asserted an absent line while the model is TOLD the mode changed; the unconfined branch never asserted the approved command ran; the spill needle was one multiplication from a formula the prompt hands over; and serializing the whole event array contained the workspace marker because the injected message is IN that array. **Authority was measured, not argued:** Seatbelt cannot make a new session, so macOS was left with the `TIOCSTI` escape bwrap closes — both confined children are `detached` now, with `setsid` probed on a real Linux pty. The one-shot escalation leads its own process group, because a command that backgrounds and disowns something exits at once and left its descendant running under the widest authority a session grants. **Provider facts against the live catalog:** five Anthropic ids matched no family prefix and took a 200K window against a real 1M; each is now a row whose every value is a measured 400. **The stored-session listing was an uncached synchronous scan of every file** on a hot RPC — 441 ms over 1,000 sessions, 5.3 s over 5,000 — now memoized per file against its size and mtime (12.5 s cold, 48 ms warm over 1,000). **Verification:** 676 tests (from 668), green on Windows and under WSL 2 with both expectation gates; the arcs 8/8 four of five times on Linux under bwrap and three times on Windows unconfined. The one failure was the routing arc's documented flake, and its own diagnostic named the cause: 1 of 4 summary nodes carried the marker with recall called 0 times, against runs of 3-of-3 with no calls and 3-of-5 with nine. The rule S9 measured held across every run. Docs: 109 KB to 92, and 33 KB to 22.

- **S11 Confinement & CI (2026-09-06).** The shell stopped costing a human decision per command. **The architecture answer was "nowhere new":** `core/shell` had specified the feature since S3, so S11 added no seam, service, event kind or config plane — one strategy directory inside the shell provider and one knob on an already authority-sensitive row. **The probe is functional and that is the point:** the real `read-only` profile around `true`, never a `which`, because a bwrap inside a container that forbids user namespaces reports itself perfectly well. The bwrap profile is upstream's, flag for flag. **What the probes settled first:** a walk passing only the NEW mount flags failed `EPERM` on exactly the 12 WSL mounts carrying `noexec` — a locked mount may have restrictions added and never removed, and bwrap ORs the existing flags in. That is the argument against a hand-rolled backend. **A written plan item was reversed on evidence:** `writableRoots` did NOT gain the temp root, because every "outside" fixture here is a sibling `mkdtemp` under the temp root and granting it would dissolve the workspace/outside distinction. It became a stated CEILING. **A confined host would have been an authority REGRESSION** without one more thing: the escalation hint fired only on `SANDBOX_UNAVAILABLE`, so once the OS refuses writes instead, nothing told the model the one legitimate move. Measured: a confined host costs +86 tokens of fixed prefix per request, cut to +48. The review found a one-shot grant that took the throwaway child only when the granted world differed, a throwaway stored nowhere so disposal left it running, and both arcs' escape targets sitting under a directory bwrap MASKS. Verification: 668 tests; the arcs 8/8 three times on Linux under bwrap; about 2.1 CNY.

- **S10 Session & product surfaces (2026-09-06).** **The spill sweep** is one pass STARTED at load and awaited at disposal: the plan said synchronous and the probe overturned it — 271 ms when half the files go, a delay every `minidsh chat` would pay before its first prompt. **A session's name** is a log-only last-wins `session/title` with a first-prompt derivation as the fold's default, so a log written before titles existed still lists under a name, and reading it costs nothing new. `source` is durable from the first version because a rename must PIN a title against later generation. **The browser stops rebuilding:** one turn cost 197 node insertions and 25 clears before, 16 insertions and no clears after. **What a real browser found that nothing else did:** streaming yanked a reader who had scrolled away, and the first fix still did, because it deferred the scroll write to an animation frame while sampling before the mutation. The rule is one synchronous write per delta. Verification: 636 tests.

- **S9 Context & prompt hygiene (2026-09-05).** Bounded recall of shadowed history, gated on the first applied compaction, its per-session spend a FOLD over the log rather than counter state — durable across a resume, exact on replay, monotonic, so recall cannot refill itself by compacting. **Research overturned the premise:** DSH ships `session-query` and mounts it in no shipped composition, so the divergence is GATING, not absence. **The durable rule planning found:** a `session/event` listener may not append synchronously, because the nested append reaches the file BEFORE the event that caused it and the resumed log is `damaged`. Review found the runtime-context section MOVING mid-lifecycle on a forked session, and refusals charged to the recall budget — when the refusal text is what tells the model to retry narrower. **The delegation cost more than it should have:** four lenses times findings times three verifiers reached 46 agents before the user killed it. The ban had existed since S8.5 and did not hold, because nothing made the script state a number. Verification: 601 tests.

- **S8.5 Architecture review (2026-09-04 → 09-05).** The system read as one architecture, then one bounded workflow against the CURRENT DSH — six primary-source researchers (192 claims, 228 fetches), verifiers, two auditors and a skeptic. **Research overturned three plans:** extension authoring is opt-in even upstream, so the old S9 was dropped; no session deletion exists anywhere upstream; upstream removed the sandbox-mode sentence from its stable prompt after measuring 5 of 12 zero-tool turns. **The audit found** a silent failure on stock Windows — no `pwsh`, every approved command answering `(no output)` — and the constitutional defect: four mandatory documents at about 230 KB. **The diff review then found in S8.5's own diff** that the new acyclicity gate treated an inline type-only specifier as erased, though Node's type stripping keeps the import and evaluates the module, so the gate could have certified a loop Node runs; and that the doc compaction had DELETED nineteen contracts rather than moving them, all restored. Verification: 581 tests; docs 196 KB to 112.

- **S1–S8 Foundation through verification (2026-08-22 → 09-02).** The kernel, the core spine, the DeepSeek adapter, JSONL persistence and the headless CLI (S1); two surfaces over one runtime with sessions that survive their process, and the durable op-shaped inbox (S2: 11 design corrections before implementation); authority as one replayable plane — one stamp, the fence in the fs PROVIDER, an approval policy enforced before dispatch (S3: untested enforcement is worse than an honest `none`); what MiniDSH *is* became data — home layout, a write lease, credentials, composition.json plus `--patch`, authority and agent presets (S4: `core/presets` is core because a capability may not import a capability); metering, the compaction seam with three triggers and one replacing surface op, spill, workspace instructions (S5: the real compaction hazard is the await, not the mutation); the model as a capability the runtime routes to, the BASE route a durable knob separate from the effective one (S6: DeepSeek refuses an assistant tool-call turn whose reasoning content is missing in thinking mode); the web surface, the paged attach and tier-aware backpressure (S7: a 400-turn session is 103,201 events and 17.0 MB, and a real browser found four things no protocol test could); the attachment plane and a verifier that is a composition row (S8: the descriptor is STORED, so a later wording change cannot rewrite what an old log says the model saw). The hardening checkpoints S1.5, S5.5 and S7.5 falsified the foundation against later pressure, finding three documented invariants that were not true in code, a crash repair that resumed a history every OpenAI-compatible wire refuses, and a wire client that could prompt a LIVE delegated child so the injected turn silently became the parent's tool result.
