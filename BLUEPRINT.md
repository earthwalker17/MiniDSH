# MiniDSH Blueprint

Rolling long-term route plus a compact development record. Four sections, always in this order: what comes next, the macro route, what is still an open question, and a record that is compressed as it ages. `ARCHITECTURE.md` describes the current shape and its known limitations; this file says what comes next and why, and keeps the measurements the architecture map no longer carries.

## 1. Next session — S10 Session & product surfaces

Goal: make a stored session findable and a long one watchable, which is the last thing between the runtime and a developer using it daily without reading the architecture.

1. **The spill sweep.** One best-effort pass at startup, per-file age, shape-matched to the names `spill-local` itself generates, `lstat` and never a recursive delete, never on disposal (a fork inherits locators). ARCHITECTURE §9's retention table already states every constraint; this is the one store a sweep may touch, and it is the last row of that table that says "designed, not built".
2. **Session titles.** A log-only `session/title` with a deterministic first-message fallback that `persistence.list()` reads from its bounded header prefix, so `sessions list` and the browser list stop showing ids alone. An LLM title or a rename needs a projection and waits.
3. **The browser stops rebuilding its transcript on every applied event** (ARCHITECTURE §13), with a real-browser pass — the only thing that has ever found the defects in that client.
4. **`/sessions` in the terminal and `--version`.**

Upstream's `permission.defaultPreset` setting is deliberately NOT mirrored: settings never own authority here, and the deployment default for new sessions is the sandbox/approval row config a `composition.json` patch already sets.

Verification: `pnpm check`; the eight arcs; a real-browser pass for item 3; a bounded diff review. Nothing here needs a new live arc — the `web` arc already drives a real socket, and titles are asserted from a stored log.

**V1 is** the smallest release a developer can install, point at a repository, and use daily without reading the architecture: two interactive surfaces (`chat`, `web`) and one headless entry (`run`) over one runtime; the default preset `workspace-write` + `ask`, under which an ordinary task on a confined host costs zero prompts and an out-of-workspace effect one one-shot approval — and on a host with no backend the shell asks per call or the user chooses the `danger-full-access` preset, stated in the README and hinted at the first ask, never silent; keys from the environment or `~/.minidsh/credentials.json`, with the first failure naming both; `pnpm check` green on three platforms in CI and the eight live arcs green three times before the tag, the routing arc's flake rate reported rather than hidden.

**Out of scope for V1**, each with the reason the S8.5 research found: model-written extensions (opt-in even upstream — only its `cordis` preset — session-scoped, and its `node:vm` is stated five times not to be a security boundary; three vocabulary generations in ten weeks); background jobs, continuable children, mailboxes and Agent Teams (upstream's own `minimal` preset ships none; MiniDSH's one-shot foreground child is upstream's one-shot foreground path); parallel tool calls (an optional loop change with modest payoff for three tools); an MCP bridge (shipped disabled upstream); a Windows confinement backend (native bindings, standing ACL mutations, always `partial`); standing approval grants and allow-lists (deferred upstream pending a grant-scope identity); session deletion in the persistence seam (upstream has none anywhere: "session deletion needs its own lifecycle"); PTC / Code Mode; a session search index; per-user identity; a desktop shell.

Ordering rationale: the protocol before any GUI so surfaces never grow semantics; authority before configuration so presets cannot widen permissions silently; the route as a fact before roles and delegation; compaction before delegation because a fork-mode child inherits its parent's surface; verification after routing and after a checkpoint. Hardening checkpoints recur every two feature sessions, and the next one is the release gate.

## 3. Open questions (a decision is pending; the known limitations themselves live in ARCHITECTURE §13)

- **Which confinement backend first, and where is it proven?** `bwrap` is the cheapest real backend and runs under WSL 2 on the dev machine; `sandbox-exec` needs a macOS runner. Neither can be exercised on Windows itself. Settled by S11's CI matrix.
- **Background work and parallel tool calls.** Upstream's shapes are transferable if ever needed — the inbox as the only queue, an interrupt that parks rather than kills, a producer that must not start work its owner cannot collect, a per-tool `isConcurrencySafe` with results committed in model order. Nothing in the V1 route needs them; the first real need (a long verification, a watcher) decides.
- **A second surface writer.** Only the compaction planner enforces "a replace never separates a call from its result", and the session invariant admits a `replace`-op `user/message` outside a step but not a `tool/result`. A pruner would be that second writer; the rule moves into the session when one exists.
- **Concurrent children and the replay oracle.** Sessions are matched to logs in first-request order, which is exact while delegation is serial and undefined the instant it is not (upstream tracks the identical defect). Latent while one child runs at a time.
- **Two provider facts to design with, not around.** DeepSeek's `user_id` parameter gives each id its own rate budget — a ready-made seam for session identity; Anthropic caps a whole request at 32 MB with a 413 that maps to `INVALID_REQUEST`, which nothing retries and nothing compacts. Neither is used yet.
- **Install at V1.** The route says npm with a `prepack` emit; "clone-only" is the honest alternative for a reference implementation. Decided at S11.5 with the dry `npm pack`.

## 4. Development record

- **S9 Context & prompt hygiene (2026-09-05).** Four things built, two of them decided by measurement rather than argument. **Bounded recall** (`capabilities/tool-history`): `history_read{fromSeq,toSeq}` renders shadowed nodes through `deriveEventMessage`, restricted to the union of `compaction/applied.shadowedSeqs` for THIS session minus its own results and minus anything still live; registered in the deployment globals so a summary can NAME it by tag, hidden per agent by a `TOOLS.restrict` lifted at that agent's first applied compaction, so a session that never compacts never carries the schema. **Authority prose moved** out of `core/sandbox.setMode` — the only `agent.inject` in `src/core` — into `context-runtime`, which now also announces an approval switch (nothing did) and coalesces a preset's two knob changes into one note. **`Agent.world`** split from `setup` (inheritable vs this-agent-only) and **`ToolDefinition.tags`** replaced `tool-subagent`'s two process-global maps. **What the research overturned:** BLUEPRINT §1 said "upstream ships no recall (a proposed note only)" — false. DSH ships `packages/session-query/`: a service, a SQLite FTS5 backend and five model-facing tools including `session_event_read`, mounted by no shipped composition for the cost its own README names — "mounting it adds one concise guidance section and the five schemas to every request". That is exactly the cost gating on the first applied compaction removes, so the divergence is *gating*, not absence. Upstream also settled where authority prose belongs: its audit events "are log-only and do not enter the model transcript", and both knobs contribute to a runtime-context snapshot rather than writing prompt text of their own. **What planning found before any code:** a `session/event` listener may not append synchronously — `persistence-jsonl` writes lines in delivery order and the relational invariant stages its trace across the observer/listener pair, so a nested append reaches the file, the wire and the invariant BEFORE the event that caused it, and a stored log whose seqs run N+1, N is `damaged` on the next resume. The switch note drains on a microtask instead. **What review found:** the runtime-context section MOVED mid-lifecycle on a forked or resumed session — `openingSandboxStamp` took the first stamp at or after `liveStart`, which for a lifecycle that wrote no opening stamp of its own is the next `setMode`; the byte-stability test had only ever forked nothing. Both folds now require `reason !== 'change'`. Three measured recall defects with it: refusals were charged to the budget (two refusals, 74 tokens, nothing read — and the refusal text is what tells the model to retry narrower); a fork whose boundary fell between `compaction/applied` and its replace could read back ten seqs that were all still live; a call bounded at 1500 emitted 1814, because the bound measured the raw span and not the prefixed body it returns. And a delegation `allow` filter hid `history_read` from a child whose summary named it — a recall tool now survives one, as the delegation tool does. **The delegation cost more than it should have:** four lenses × findings × three verifiers reached 46 agents before the user killed it. CLAUDE.md §8 had banned per-finding fan-out since S8.5 and the ban did not hold, because nothing made the script state a number; §8 is now countable, and verification happens in the parent. The 20 finished agents were still worth reading — their `journal.jsonl` held the same opening-stamp defect the parent had found independently plus the three measured ones it had not, and one abandoned probe file that broke typecheck until it was removed. **What the arcs measured.** Context: 6/6 before and after, mean 85 s → 128 s (the model now sometimes calls recall). Routing, the arc this session targeted: 5/6 before, 5/6 after, and the arc now prints on every run how many summary nodes carried the marker, whether `history_read` was offered and how many times it was called. Over twelve post-fix runs the rule is exact: **every run where all summaries carried ALPHA-11 passed with recall called 0×; every run where a summary dropped it passed only if recall recovered it** (called 8× and 1× → passed; called 0× three times → failed). So the arc's flake is summariser fidelity at a 6,000-token budget, backstopped by recall when the model reaches for it. A footer reworded to fire at the failure moment ("before answering that you do not have it") was measured at 3/6 against the original's 5/6 and REVERTED — the guess was wrong and the numbers said so. The confinement sentence: 6/6 with it and 6/6 without, slightly faster without — but the arc's own step-3 prompt says "if a tool refuses, follow the guidance it gives you", which is the sentence's job, so the arc cannot distinguish them and the sentence stays. That confound is the S9 instance of §10's warning that a live arc's premise decays silently. **Verification at close:** `pnpm check` green at 601 tests (53 files, up from 581); the eight live arcs green; `vitest.e2e.config.ts` no longer intercepts console, so an arc's diagnostics reach the terminal on a passing run.

- **S7 Web surface (2026-08-31)** — a third surface and the paging the log had been waiting for. The review found four WebSocket codec defects, an inverted settings precedence, a stealable lock, a launch token called one-shot and never spent. Verification: 465 tests, seven arcs, about $0.02.

- **S6 Cognition routing & delegation (2026-08-30)** — the model became a capability the runtime routes to.
