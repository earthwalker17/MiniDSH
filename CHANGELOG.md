# Changelog

All notable changes to MiniDSH are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/). The session-by-session engineering record, with what each session measured, lives in [`docs/BLUEPRINT.md`](docs/BLUEPRINT.md) §4.

## [1.2.0] — 2026-10-26

Background work, a third provider, web search, skills and a real browser, built across four sessions; then the whole widened runtime was reviewed as one system and what that review found was fixed before release. Read the migration note at the end of this section before upgrading a deployment that sets a temperature, a base URL or an agent preset.

### Added

- **A real browser to check a frontend.** Where Chrome, Edge or Chromium is installed, the model gets five tools:
  - `browser_navigate` opens a page and waits for a dev server that is still starting;
  - `browser_snapshot` reads the page as an accessibility tree with refs;
  - `browser_act` clicks, hovers, types, presses keys and selects, as real input that is refused when the element is hidden, disabled or covered;
  - `browser_screenshot` captures the page, on a vision-capable route only;
  - `browser_evaluate` runs JavaScript in the page.

  Every result opens with what the page logged, failed, blocked or asked since the previous one. Each session gets its own headless browser under a private profile in `~/.minidsh/browser/`, started on first use and gone when the session ends, over a pipe rather than a debugging port. It reaches only localhost and the workspace's own files, plus any `allowHosts` you name in the `tool-browser` row. This is enforced inside the browser (a proxy the harness owns, resolver rules and a `file:` filter) and proved each time it starts. Downloads are refused. A script still running at a call's deadline is stopped, and a page that still does not answer (a loop that re-arms itself) is replaced by a fresh one on the next call; the model is told either way. It asks no consent, so a delegated verifier child can use it: a text-only model hands the look to a `subagent` entry routed to a vision model.

- **Background jobs.** `job_start` runs a long command beside the session — a dev server, a slow test run — and returns at once; `job_output` reads what it wrote since the last read (optionally waiting for it to end) and `job_cancel` stops it and what it started. A job's start and its one end are durable facts in the log; when a job ends on its own its notice arrives in the session and wakes an idle agent, at most eight times in a row before a person says something, and a stop someone asked for never wakes it. A job runs under the session's own authority, never an escalation, a durable switch of the sandbox mode or acceptance ends it, and it ends with its session. If the MiniDSH process dies, the next resume (and `sessions verify` before it) closes each running job as lost and tells the model so.
- **OpenAI as a third provider.** `--provider openai --model gpt-6-luna` (or `/model openai/gpt-6-luna`, or `session/model`) routes a session to OpenAI's Responses API, mid-session included, with `OPENAI_API_KEY` in the environment or `credentials.json`. Nothing is stored at OpenAI (`store: false`): a reasoning model's encrypted reasoning travels back to the same model inside the session log, and is dropped, never forged, for any other. The catalog covers the current GPT-6, GPT-5.6, GPT-5.5, GPT-5.4, GPT-5.2 and GPT-5 mini/nano models with their measured effort sets; an option a model would refuse or silently ignore — an effort it lacks, a `temperature` with reasoning on, an output cap above its own — is refused before anything is sent.
- **Web search, opt-in.** A `composition.json` row (`{"patches": [{"insert": [{"id": "tool-web-search", "plugin": "tool-web-search"}]}]}`) gives the model `web_search`, backed by Tavily (`TAVILY_API_KEY`). Every query asks first: the line you answer names the exact text that would leave the machine, where it goes and under which credential, and a session grant covers only that identical query. Results arrive as a numbered list of titles, URLs and snippets behind a fixed notice that they are untrusted content — never a provider's own summary. A delegated child is not offered the tool, and its pinned approvals would refuse every query anyway. There is no `web_fetch`.
- **Skills: know-how as data.** A folder holding a `SKILL.md` (the open [agentskills.io](https://agentskills.io) format) in `~/.minidsh/skills/`, inside the package, or in a repository's `.agents/skills/` or `.claude/skills/` is listed to the model by name and description, and the model reads one with its ordinary file tools when a task fits. A skill is advice, never a permission: its scripts are shell commands under the session's own authority. A repository's skill never replaces yours or a bundled one (the operator is warned on stderr). Two ship, on Node alone: `office` builds, reads, unpacks and validly repacks .docx, .xlsx and .pptx, and `pdf` reads PDFs and writes simple ones. Real Word, Excel and PowerPoint open what they build.
- **Jobs on every surface.** The session view lists jobs; `job/cancel` stops one over the protocol; the terminal has `/jobs` and `/jobs cancel <id>`; the browser shows a jobs strip with a stop button and per-session badges. A new `control/subscribe` sends every client a per-session summary (status, running jobs, held notices, pending approvals) whatever session it is watching, and a question stays answerable while such a client is connected.

### Changed

- **The default tool set grows by the five browser tools** on a machine with a browser installed, and `minidsh config` lists the `tool-browser` row (flagged when a layer changes it, since `allowHosts` widens what it reaches). A refused image now says that a subagent starts with a conversation of its own; the image bound is the whole conversation's until a compaction.
- **`deepseek-flash` sees images**, as DeepSeek now serves it, in a user message or a tool result; the retired `deepseek-v4-flash` names resolve to it and take the same facts. `deepseek-v4-pro` stays text-only (it accepts an image and ignores it). A DeepSeek id the catalog does not know is treated as text-only with a 131,072-token window rather than the full million.
- **Breaking: DeepSeek refuses `temperature` while thinking.** Thinking is on unless the reasoning effort is `off`, and in thinking mode DeepSeek ignores the temperature without saying so; a request that sets one is now refused before anything is sent, naming the two ways out: effort `off`, or a route to a model that honours a temperature (a recorded temperature cannot be cleared). A `settings.json` with `agent.temperature` and no effort will see its first DeepSeek step refused.
- **Breaking: the model's shell no longer sees `OPENAI_API_KEY`.** The OpenAI adapter is mounted by default, which makes its key one of the harness's own credentials, withheld from every shell command like the DeepSeek and Anthropic keys. A repository script that read it through MiniDSH's shell needs it passed another way.
- **A log written by this version may carry a consent subject 1.1.0 does not know** (a web search's): 1.1.0's `sessions verify` reports such a log invalid rather than misreading it, and 1.1.0 will not resume it; 1.0.0, which records no subjects, ignores it. A home `composition.json` that mounts web search stops 1.1.0 before it reads anything.
- **A key no HTTP header can carry** (a stray line break, a NUL) is refused by its name before any request, for every provider and for web search: the platform's own error for it quoted the value.
- **The consent line shows invisible characters escaped** — zero-width and format characters, bidi controls, the Unicode tag block, private-use code points — in a shell command as in a web query, so what a person approves is every character that runs or leaves.
- **A one-shot run stops what it started.** `minidsh run` (and a delegated child) stops a job still running when its task ends, records it, and says so on stderr; the exit code is unchanged.
- **On Windows a process is killed with its tree** (`taskkill /T`): a timed-out or cancelled command's children no longer outlive it.
- **PowerShell one-shot commands write UTF-8**, as the persistent shell always did: on a host whose console code page is not UTF-8 their non-ASCII output arrived garbled.
- **The Anthropic catalog follows Anthropic's own model listing** (2026-10-25), and a live drift probe now holds it there, as the DeepSeek and OpenAI ones already were. The 5.5 models have rows of their own instead of their predecessors'. Effort `off` is refused where the model cannot turn thinking off (Opus 5.5, Sonnet 5.5, Fable 5 and 5.1). The 4.6–4.8 models are asked to think at a named effort (Opus 4.8, measured, did not think without it); Opus 4.5 thinks on a budget beside its effort. Sonnet 4.5's window is 200K. A temperature beside thinking is refused before anything is sent, since the API refuses it. An id the catalog does not know gets no output cap of ours.
- **DeepSeek errors are classified by their HTTP status first**: a 5xx is retried as a server error even when its text mentions "context"; DeepSeek running out of capacity mid-stream is retried; its content filter ends the turn as a refusal.
- **`llm-retry` gives up on a provider that asks for a long wait**: a `retry-after` past `maxRetryAfterMs` (default 60 s) ends the retries instead of holding the turn, and the failure says how long the provider asked for.
- **The editor reads big files in part.** `view` of a file over 8 MiB shows its first 8 MiB and says how to read the rest with the shell; `str_replace` and `insert` refuse such a file the same way; an empty `old_str` is refused. Reading or writing a FIFO or a device is refused, never waited on.
- **A resume or fork composes the world its session was created in**: under another agent preset it is refused, and over the wire (`serve`, `web`) an explicit `--sandbox`, `--approval` or `--accept` on the host now applies to a resumed session as it did on the CLI.
- **`minidsh config` warns about more**: a provider row a layer changed (its `baseURL` decides where every conversation and its key go) and any plugin loaded from a module path.
- **The office helper stops early.** `office read` stops rendering a document or deck once it is past what `--max-chars` prints (the paragraph counts then read `N+`), as it already did for a workbook, and renders a slide two entries name once; `pack` refuses such a deck.
- **Releases wait for the live suite.** `release.yml` publishes only after a green `check.yml` and an unfiltered green `live.yml` for the tagged commit, runs the same install smoke as `check.yml`, and holds its publish credential in a job that installs no dependency. Contributors: `pnpm lint` fails on warnings.

### Security

Found by the 1.2 checkpoint's review; each fix has a test that failed before it.

- **The file fence on Windows compared names case-insensitively**, and so read a name with the Kelvin sign (U+212A) as the workspace's own `k` directory: a write could land outside the workspace. Containment now compares the canonical path exactly.
- **A write racing a link swap** (another process replacing a workspace directory with a link while the harness writes) could land content outside the workspace; on Linux 13 files did in 49 writes. The harness now checks the file it actually opened, through `/proc/self/fd` on Linux and by inode elsewhere (best effort there), and refuses otherwise. On Linux only an empty file or directory can still be left outside; on macOS and Windows a swap timed between the checks can still let content through.
- **Keys stay out of error text.** A provider or a proxy that echoes the key in an error no longer gets it quoted into the log, the model's view or stderr (all three providers and web search). A base URL carrying a username or password is refused, from config or a `*_BASE_URL` variable. A malformed `credentials.json` is reported by position, never with the parser's message, which quoted the file.
- **The session commands blank invisible characters** (zero-width, bidi, tag and private-use code points) in every line they print, not only consent lines: `sessions list`, `sessions show`, `inspect`, `verify` and the audit. A consent line also escapes every blank that is not an ordinary space, which could carry hidden bits after a visible query.
- **Another user's `.git` above your working directory** (a planted `/tmp/.git`, or a link from there into your own home) no longer makes their `.agents/skills` or `AGENTS.md` part of your workspace, on Linux and macOS; a project marker in a filesystem root (`C:\`, `/`) is ignored on every platform. The operator is told when one is.
- **Hostile files cannot hang or crash the host or its helpers.** A repository `SKILL.md` linked to `/proc` or a FIFO is skipped instead of read forever. The `office` and `pdf` helpers refuse deeply nested or oversized documents with a coded exit, where they used to overflow the stack or exhaust the heap, and no longer take quadratic time on a long word, many short lines or a long run of digits.
- **`minidsh web` refuses to be framed** by another page (`X-Frame-Options`, `frame-ancestors`, `Sec-Fetch-Dest`), so a local page cannot overlay a signed-in tab.
- **Authority switches are all-or-nothing**: a `session/authority` call, or a host's explicit flags on a resumed session, that a delegated session's ceiling or pin refuses no longer leaves the switches before it applied. The authority invariant also checks where a delegated session's acceptance sits, every field of a recorded decision, and that a decision credited to a standing consent names one live for that exact action.

### Fixed

- **A host out of file descriptors** (EMFILE) refused nothing and could crash on a shell, job or browser spawn; each now refuses, under its usual code, with a message that says it is a moment, not a missing install. A confinement probe that could not run is warned about rather than passing silently for "this host has no backend"; restart once the load passes. A one-shot or job command too long to pass as an argument, or holding a NUL, is refused as the command's (`SHELL_COMMAND_INVALID`), with the way out.
- **A browser call stuck in page code** (a looping getter in a returned value) is stopped at its deadline instead of wedging the page until it was replaced.
- **A cancel at the wrong moment could lose a job's end notice**, and a step that rejected or filtered its input dropped the notices it had claimed. Both now keep them.
- **A tool result of the wrong shape** left a call with no result, which crash repair later had to close; it is now an error result.
- **A compaction summary cut off at its length limit** replaced the history anyway; it is declined. Compaction no longer fires on pressure the system prompt and tool list alone create, which it could not relieve.
- **`exit` as the first shell command** was reported as a broken shell (`SHELL_UNAVAILABLE`); it is the command's own end, reported with its output. A shell session disposed while it restarted into another sandbox mode could leave a shell running.
- **`str_replace` treated `$&` and `$$` in the replacement as patterns**, corrupting the text it wrote.
- **A refused agent creation leaked the session**, so every later attempt in the same host failed "already exists".
- **The DeepSeek and Anthropic stream readers** buffered a stream whose lines end in CRLF (a proxy's) until it failed; two DeepSeek tool calls sharing a stream index were merged into one; a base URL with a trailing slash doubled it.
- **An Anthropic tool call whose arguments were not a JSON object** was replayed to the model as a call with no arguments.
- **A relative `MINIDSH_HOME`** moved with each session's working directory; it is resolved once.
- **The WebSocket carrier** could queue one large answer past its hard limit, and kept a closed socket open while its peer stopped reading. `minidsh web` failing to listen (a port in use) leaked everything it had started.
- **The terminal's first output could race its attach**; settings that fail to parse are `SETTINGS_INVALID`.

### Migration from 1.1

- **Sessions.** The log format is unchanged: 1.2 resumes and forks 1.1 sessions. Going back, do not resume with 1.1.0 a session that ran background jobs: 1.1.0 continues an unfinished job without closing it as lost, so its model may believe a dead job is still running. 1.1.0 refuses a session in which web search ever asked for consent.
- **Now refused before anything is sent, saying why:** a DeepSeek temperature while thinking and a resume or fork under a different agent preset (both used to pass silently); an Anthropic temperature beside thinking and effort `off` where a model cannot turn thinking off (the API refused them); a base URL carrying a password (every request failed, quoting it).
- **Credentials.** The model's shell no longer sees `OPENAI_API_KEY`.

**On versioning.** Some of the changes above turn a silent degradation into a refusal (a temperature the provider would have ignored, a password every error quoted, a hostile document that used to hang a helper). This project ships such a change in a minor release: a silent degradation or a leaked secret may become a refusal without a new major version. Everything else follows Semantic Versioning.

## [1.1.0] — 2026-09-27

The record and authority planes, built across three sessions, reviewed as one system and released: durable execution you can read cold, consent that says what will run, and a shell that runs on every platform under an honest boundary.

### Added

- **Read a stored session without resuming it.** `minidsh sessions verify <id>` says whether a log is intact — `ok`, `interrupted` (a crash a resume will close) and `torn` exit 0; `damaged`, `invalid` (a rule the runtime holds every write to is broken) and a newer, unreadable format exit 1 — and `sessions inspect <id>` reports what each part of the log was written under, the authority it ends under, undecided approvals, queued input, children, cost, and exactly what a resume would append. Neither takes the session's lock nor writes a byte, so both are safe on a log another process holds, and such a log reads as *in flux* rather than crashed. `--json` on each.
- **Salvage a damaged session.** `minidsh fork <id> --salvage` branches a log whose bytes are unreadable past some point from what is still readable, leaving the original untouched; every tool call it cannot account for is marked outcome-unknown, the fork records where its source stopped, and the command says so on stderr, because damage between turns leaves the model nothing to see.
- **The audit shows what calls did.** `sessions show --audit` now lists each file write and shell command the providers recorded (path and hash, mode, enforcement, exit status), each call whose outcome was lost with a crash, and, for a crashed session nobody has resumed, what a resume would record — marked as such, and never for a session another process is still running.
- **An approval says what the runtime will do, not what the model said about it.** The line a person answers now carries a *subject* the harness builds from the validated call arguments — the command, and the mode and enforcement it would run under — plus the whole call as the log recorded it, up to a bound past which the surfaces refuse the shortcut and point at `sessions show <id> --json` rather than hiding a command's tail. The model's justification sits beside that, never in place of it. Control characters in a subject are escaped rather than flattened, so two different commands can never render as one line.
- **A yes can outlive one call without outliving the run.** Where the host offers it, `a` in the terminal (or the browser's button) extends a one-shot approval to that exact action — same tool, same command, same authority — for the rest of that run of the session. It is a durable event, it is offered by the runtime rather than invented by a surface, it dies the moment any authority knob moves or the run ends (a resume or a fork asks again, once), and `/grants` and `/revoke <id>` list and withdraw it. A near-miss asks again: this is not a policy language.
- **A session can accept the enforcement its host can actually deliver.** `--accept none` (or `/accept none`, or the browser's control, or `session/authority`) records that this session will run a shell command a host cannot confine — under its own sandbox mode, with the in-process file fence intact. On Windows, which has no confinement backend, that replaces paying a `danger-full-access` escalation per command, which used to drop the file fence as well. It is inert wherever a backend exists, it applies only to the mode it was given for, and a delegated child inherits it as a pin it cannot change.
- **Decisions record who made them**: policy, a standing consent (and which one), a person, or an automatic answerer. `sessions show --audit` and both clients print it.
- **An unattended run can approve exactly what a deployment declared.** `approval-headless` takes an `allow` list of exact subjects, answered `auto` — a middle rung between `--approve` (all of them) and the fail-closed default (none).
- **Crash repair closes every bracket the log left open** (from the durable-execution work that preceded this): an interrupted delegation, an interrupted compaction, and the tool calls of an interrupted step, with a durable fact recorded between a tool's approval gate and its body so repair can tell "never started" from "outcome unknown". Effects that land — file writes and shell commands — are recorded by the provider that caused them, after the fact.

### Security

- **`--accept` on `serve`, `web` and `chat` now does something.** It was accepted, advertised and dropped before reaching the sandbox, so wire-hosted sessions kept refusing. It now applies, and a weakened acceptance is written into the log of every session it opens, for every mode a command can be confined under, so a stored session says what it accepted (a line, or `full` by its absence), a resume keeps it, and an approved escalation never runs under one the log does not name. A delegated child's acceptance applies to the mode it was delegated for; any mode it narrows into is strict.
- **A shell refusal is on the record as a refusal.** On a host that cannot confine the shell, an unescalated command's refusal is now a coded error result (`SANDBOX_UNAVAILABLE`, same words) instead of a successful one, so the audit and every surface show it as refused.
- **A shell child no longer inherits this deployment's provider keys.** The harness builds the child's environment instead of passing its own through, withholding every credential name a provider row declared (including one a config file renamed; the list is read at every spawn) and every `MINIDSH_*` — and nothing for merely looking like a secret: a `GOOGLE_APPLICATION_CREDENTIALS` or an API key you set for your own tools is yours and reaches your shell. On Windows the names are compared the way the environment compares them. This is defence in depth, not a boundary: reads are still unfenced, so a credentials file remains readable, and any secret the deployment did not declare passes through.
- **Measured: a confined shell writes through a hard link that already exists in the workspace**, because the operating system confines paths; the documents had said a confined host was unaffected. Under bubblewrap and under Seatbelt alike (a test in `pnpm check` now measures both), and neither lets a confined command create such a link across the workspace boundary, nor write an outside file by its outside path because it also has a workspace name.
- **The terminal neutralizes the streamed answer.** Every line the terminal printed went through the control-character filter except the one a person reads most, the model's own streamed text; an escape sequence in it could repaint the line above the next `[y/N]`. It is filtered like the rest, and the log is untouched.
- **A client can no longer answer an approval in a session it does not watch.** `approval/answer` now applies the same visibility rule that decides which connections are asked in the first place.

### Fixed

- **A detached session refuses appends.** After a session was detached, an append still succeeded in memory while persistence had already closed its file and dropped the event without an error: the log in memory and the log on disk could part ways silently. The store now closes the session before `session/disposed`, and a later append throws `SESSION_CLOSED`.
- **The browser shows every event the terminal shows.** The browser's event projection was an untested hand-copy of the terminal's and had drifted: a step's effective route (`request/context`) and a delegated child's route never appeared in the browser. The projection is now a typed, DOM-free module (`web/rows.js`) that a test holds to the terminal's visibility, kind by kind.
- **`resume <id> --json` and `fork <id> --json` without `--headless` are refused** instead of printing the interactive terminal where a script expected frames.
- **A content-less DeepSeek stream that named no finish reason** ended as an empty message the retry policy never saw; it is `EMPTY_RESPONSE`, and retried, like the same stream with one.
- **`sessions verify` and `inspect` on an odd log.** A malformed salvage claim passed `verify` and crashed `inspect`; the claim is now held to its shape at every append. A log whose only unfinished thing is a compaction bracket (an ordinary quit mid-`/compact`) is described as an open bracket, not as a crash.
- **`sessions show --audit` would list an escalation refused past a delegation ceiling** with the other authority denials (no shipped path produces one: a delegated child's approval pin refuses the ask first).

### Changed

- **A checkpoint is on disk.** The session log is `fdatasync`ed at every durability checkpoint (and a new log's directory entry, on Linux and macOS), so crash repair can tell a call that never passed its approval gate from one that may have run even after a power cut. Measured cost per checkpoint: 0.7–3.6 ms (median) on Windows NTFS, 2.4–10 ms under WSL 2, varying with host load; a tool call pays up to two. A flush never reports a write synced that no sync covered, and a torn tail is never truncated unless its sidecar copy is complete.
- **Forking a session another process is still running** answers every tool call it left open as outcome-unknown, never "not started": that process may still run it.
- **Each part of a log says what wrote it.** Every new, resumed or forked session opens its segment with a record of what its writer guaranteed, and the composition record names the build (`minidsh 1.1.0`); crash repair trusts only those claims, so logs from 1.0.0 are still read and repaired, conservatively, and 1.0.0 reads a 1.1.0 log (checked against the published package). The session format's rule is written down: the header's version is the only format mark, and a malformed line is damage, not a newer format.
- **The default model is `deepseek-flash`**, the id DeepSeek lists. `deepseek-v4-flash`, the 1.0.0 default, is unlisted but still accepted and served as the same model, so a stored session or a setting naming it keeps working; the log records the id that was requested.
- **Releases are published from CI.** A `v*` tag runs the whole gate, packs, drafts the GitHub release, publishes through npm trusted publishing (no token anywhere), installs the public package and verifies its provenance attestation before the release goes public. The live workflow's Linux and macOS legs now fail, rather than branch, when the host cannot confine the shell.
- `docs/ARCHITECTURE.md` corrected in about twenty places where the code did not honour the text (what Windows really costs per shell command, what crash repair does not close, what a tool deadline does to its body, how the format version is stamped). `docs/BLUEPRINT.md` carries the post-1.0 route. `references/` is new: a curated, pinned map of DeepSeek Harness with a ledger of what MiniDSH assumes about it.

## [1.0.0] — 2026-09-09

The first public release: the smallest MiniDSH a developer can install, point at a repository and use daily without reading the architecture.

### Added

- **One runtime, three ways in.** `minidsh run` (headless), `minidsh chat` (terminal) and `minidsh web` (browser) over one runtime, plus `minidsh serve`, a JSON-RPC host on stdio. The terminal and the browser are protocol clients and hold no semantics of their own.
- **A kernel and a spine.** A small composition kernel — contexts, plugin lifecycle, typed services, effects that unwind, typed events with four dispatch modes — and eighteen service definitions over it. Everything the model can see and do is a plugin row; a boot composes thirty-five of them.
- **The session log as the only truth.** An append-only JSONL log with twenty-seven event kinds in three tiers; resume and fork from any stored log; crash repair that closes an interrupted turn; a single-writer lease; model-visible history that is, by a runtime invariant, exactly what the log derives.
- **Authority as a durable plane.** Sandbox modes, an approval policy and named presets, every switch and every decision an event; file writes fenced inside the filesystem provider; shell commands confined by bubblewrap on Linux and Seatbelt on macOS, each probed before it is claimed; a one-shot escalation path; delegated children that open under a ceiling they cannot widen; `sessions show --audit` to read the whole plane back.
- **Two providers, one vocabulary.** DeepSeek and Anthropic adapters over a provider-neutral stream, with signed-reasoning replay state, prefix-cache-stable requests, measured model catalogs, and options refused before any I/O rather than silently dropped. The route is a durable fact a session can change mid-conversation, and a `model-roles` row sends a purpose (a compaction summary, a delegated child, a vision verifier) down a different route.
- **Context management.** A pure meter over the log; compaction with three triggers, a durable bracket and a replacing surface operation that leaves history intact; bounded recall of what a compaction shadowed; spill for oversized tool output; workspace instructions from `AGENTS.md`.
- **Delegation and vision.** A `subagent` tool with its own session and log; a verifier that can see, as a second row of the same tool on a vision route; a content-addressed attachment plane.
- **Composition from disk.** `~/.minidsh/composition.json` layers over the built-ins with per-row provenance and a per-boot `composition/applied` stamp in every session; `settings.json` for user defaults; credentials by name only.
- **Verification.** 676 tests mounting real compositions, green on Ubuntu, macOS and Windows in CI with an install smoke on each; eight live end-to-end arcs against real providers, run from a manually dispatched workflow and on both development hosts before every release.

### Known limitations

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §13. The ones most likely to matter on day one: Windows has no shell confinement backend, so every shell command there costs one approval; confinement bounds file effects only, not the network or the environment; the filesystem fence cannot follow hard links.
